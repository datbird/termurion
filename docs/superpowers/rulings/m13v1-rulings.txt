Path judge, round 3 rulings (judge-rulings-r3.md)
- A path the person picks in a file dialog at that moment may be on a share (LocalPath::person_picked, localfs::picked): their own choice, as in every Windows app. Only the function that opens the rfd::FileDialog makes one, on its result, and it takes no path from its caller (a guard test, per function, proven on planted texts; person_picked is private to localfs::picked). The dialog and outside entry points are split: load_arrangement_file / import_recording_dialog pick; load_arrangement_path / import_recording_at (Explorer, the launch pipe, the command line) judge at the read. Every other path stays judged and refused. Cost if wrong: a share picked in a dialog connects.
- Drive kinds: DRIVE_FIXED, REMOVABLE, CDROM and RAMDISK are local when the device is one name after \Device\ that is not Mup or a name ending in Redirector (RAM disks and VeraCrypt volumes pass); REMOTE, UNKNOWN and NO_ROOT_DIR are refused; GetDriveTypeW's answer is passed through, a REMOTE once seen stays REMOTE. Unknown reparse tags stay refused. Cost if wrong: an unusual network driver that reports a fixed type under a plain device name would pass.
- Start folders on a share: home plus a banner naming the share (as built). Cost if wrong: a typed start folder on a share (13p's old typed-UNC ruling) starts in home with a banner instead.
- A relative link target is joined onto the path already redirected by earlier links and the walk goes on from the resolved target (netpath::local_chain), as Windows resolves it. Cost if wrong: a chain of relative links ending on a share lets the judge open an unjudged component.
- '.' and '..' are collapsed lexically FIRST, as Win32 does (RtlGetFullPathName_U) before any link is resolved; the walk then runs on the collapsed path, re-judging each link target, and never pops a component of a redirected path. A verbatim path (\\?\, \??\) with a '.' or '..' step is refused unread (Win32 does not collapse it). Cost if wrong: none known; such verbatim paths are not typed by people.
- ShellExecute takes files only as a LocalPath (localfs::open_with_shell); semantic_ui::shell_open takes URL targets only (semantic::shell_url refuses paths, drive paths, network paths and file: links), which is the guard's only exception. Porthole document file links are judged (LocalPath::judge) before the question and again at the answer, before Explorer or the shell sees them; prompted::local_path_ok is no longer their gate (porthole::link_target only sorts the text). Semantic History files are judged again at the open with its own rule (LocalPath::semantic). Cost if wrong: a document link or a Semantic History run that the judge refused could open a share file and send the person's hash; the price of the rule is a refused link nobody could have judged.
- TOCTOU (decision): probes open by path after a per-call judge. A local account that can swap a folder for a junction inside the window between the judge and the probe can redirect one probe. Accepted: the window is one call, every poll judges again, and a same-account attacker gains nothing. Cost if wrong: on a shared machine another local user flapping a junction in a folder Tandem probes repeatedly (a shared repo, C:\Users\Public) can eventually win the race and capture a hash.
- The guard now also counts fs::exists, ShellExecuteW(Ex), FindFirstFile(Ex)W, GetFileAttributes(Ex)W, set_permissions, hard_link and symlink_file/dir, and treats #[cfg(any(..test))] items as live code. Its proof compared planted texts against an OWN list that always reported something, so it proved nothing; it now checks each planted case alone. Cost if wrong: a probe API the scan does not name slips past the guard until its name is added (the scan is by text).

Task 5 (default terminal)
- The handoff gate is Tandem's own (4 per second, 16 live panes), the caller must pass the one peer rule (api_peer::judge_peer, shared with the launch pipe's server check: same user, same Windows session, same elevation and integrity, no AppContainer or restricted token), handles are typed, the title is bounded and cleaned, and a handoff while Tandem closes is refused. -Embedding runs only while Tandem is the default with its pack and no Tandem answers the launch pipe; it makes no window until a handoff arrives and ends after 15 s with none. Cost if wrong: a script opening more than 4 consoles in one second loses the rest with a banner; a Windows build that passes an unexpected handle kind makes every handoff refuse (checklist row 13).
- No test registers the real COM class or writes the real registry (the brief's ignored round-trip test is not written). Cost if wrong: the COM round trip is covered only by the on-screen checklist (rows 8 to 13).
- Make Terminal Default restores the saved pair only while the pair is still Tandem's. Cost if wrong: none known; a pair chosen elsewhere is never overwritten, so the person chooses again.
- LocalServer32 holds only the quoted exe path; COM appends -Embedding itself (Microsoft's LocalServer32 doc). launch::parse takes -Embedding alone or twice (an older registration's value plus COM's) as the one COM start. Cost if wrong: a registration written in an older shape needs the startup repair once before a cold start works.
- Startup repair of the handoff class (P11), the scheme repair's rule: only while the pair is Tandem's, only the LocalServer32 value of Tandem's own class in the shape Tandem writes, only when the exe it names is not this one and is gone (judged before it is probed). An older Tandem's value for this same exe takes the plain form. Cost if wrong: none known; another live copy keeps its registration.
- An -Embedding start never drops a request it accepted on the launch pipe: a launch, link or file opened during its wait makes it the main instance at once. Idle for 15 s, it first stops serving the pipe (every request read is handed on before the stop returns, and the name is then free) and the handoff class, then ends on the next pass unless something arrived. If another Tandem took the pipe in that gap, the waiting launches go to it. Cost if wrong: a COM call already inside EstablishPtyHandoff at the moment of that last pass can still be lost (its console closes).
- The caller's executable (OpenConsole.exe or conhost.exe) is not checked: with the user, session and integrity rule it adds little. Cost if wrong: another same-user, same-session, same-integrity process that is not the console host can hand off a console (it could open a tab by the launch pipe anyway).

Task 6 (Jump List)
- The items BeginList reports as removed are the removals since the last list (the SDK's CustomJumpList sample, Firefox and Chromium keep them): each report is merged into a kept list (newest 256), saved as %APPDATA%\Tandem\Recents\removed.json with the recents list's bounds, and read at the first rebuild, so a removed item never comes back, after later commits or a restart. Cost if wrong: none; if Windows reports cumulatively the merge changes nothing.

Task 7 (staying resident, R3)
- R3 fix 1: closing the last window no longer ends Tandem when "Quit when all windows are closed" is off (iTerm2 AD:915-942, resident::after_last_window). Tandem stays with its notification area icon (shown whatever StatusBarIcon says: resident::icon_wanted joins 13g's rule, never replaces it). The grace period (MinRunningTime, default 10 s) keeps a quit-when-closed Tandem running when the person has not touched it: a key in a session, Close, or a window they closed counts as touching. The grace note goes to the host log. Cost if wrong: a hidden window's memory while resident; a quit-when-closed Tandem the person did not touch stays up for 10 s.
- R3 fix 2: the Windows-only "a window opens when nothing else would show" startup rule is gone (startup::plan follows iTerm2). Only Restore Hotkey Window with no hotkey window, and openNewWindowAtStartup off, open nothing and Tandem starts resident. OpenUntitledFile does not decide a launch window: iTerm2's launch path never reads it (AD:2463-2470); only the icon click and a second bare start do (AD:1150). Cost if wrong: a person who had the old behavior for those settings now sees only the icon.
- B7: the resident path is end_sessions_keep_host: the same host kills its shells and keeps serving, the empty state is written WITHOUT freezing later saves, and leave_resident touches no state. The quit paths and logoff keep their calls. Cost if wrong: the last window's shells end as a Quit would end them (the host stays); a person who wanted them kept must use the Keep jobs settings.
- B11: the hidden window is the one made at the first tab: open_window_with reuses it for every window kind (a hotkey window too, which keeps it hidden and off the taskbar), and a tab made by any other route (a link, a tray command, a script, the API) wakes it at the next loop pass (wake_from_resident, first in about_to_wait), so no entry point leaves a tab in a hidden window. reopen never focuses a hidden empty window. Cost if wrong: a tab made by another route shows after one loop pass.
- Fix (review r1): a hotkey window that is the last window goes resident too while "Quit when all windows are closed" is off (AD:915-942 stays whenever the key is off); the window that is closing is not counted as a terminal left. A hotkey window left beside another window still means no last window. Cost if wrong: none known.
- Decision: the transparency surface of the kept window is the old one; a window that wants alpha is recreated by the existing check_alpha_surfaces path as for any first window. Cost if wrong: a window that wants alpha is recreated once.
- Decision: no write_out_state(keep) helper (P13): the one process teardown (teardown_process, run after the event loop on every exit, 13u S6) already restores the keyboard layout, the hook and the icon for quit_confirmed, the last-window Quit branch and logoff. Cost if wrong: none seen; the helper would repeat what the teardown does.

Task 8 (shutdown, Downloads folder)
- R3 fix: a Windows shutdown now asks when a quit would (iTerm2 AD:993-1036). WM_QUERYENDSESSION is answered by the one end-of-session subclass (13q logout_ui, B8): the app decides within 1 s (a timeout counts as ask); with a reason to ask, Windows is told "Tandem is asking whether to quit." (ShutdownBlockReasonCreate, only while there is something to ask, destroyed on OK, Cancel, a cancelled session and window destroy) and the quit question shows after the procedure returned FALSE. OK quits as Quit does; Cancel keeps Tandem and Windows does not retry (the person restarts the shutdown). With NeverBlockSystemShutdown on, or nothing to ask, Tandem answers TRUE. WM_ENDSESSION runs the one Logoff event: Quit's write-out (settings, state, notes, frames, logs, archives), then the shells end when KillSessionsOnLogout says so and are left as Quit leaves them otherwise. Cost if wrong: Windows' own shutdown screen shows Tandem until the person answers or shuts down anyway.
- DownloadsDirectory (P19): used only when absolute, local (path judge) and a probe-free test file can be made in it; else Windows' Downloads folder (FOLDERID_Downloads) on the same terms, else the profile folder; one banner says why. A redirected Downloads on a share is refused. Cost if wrong: a download folder on a NAS or mapped drive is ignored.
- ShowSuiteNameInDockIcon (R2): stored and shown, does nothing (no -suite instances; 13y). Cost if wrong: the setting has no effect.

Task 7 fixes (review r1)
- B11 as ruled (item 3): ONE function, `wake_from_resident`, is called first by every entry point that makes a tab while resident; the per-pass poll is gone. A tab of a profile (links, Jump List, launch NewTab, tray New Tab, API CreateTab, file opens, handoff, all through `add_tab`) is queued as a profile window, which `open_window_with` makes from the hidden window with every step (size, place, style, profile window, transparency, space). Arrangement tabs, an imported recording and a buried session wake the window in place with the default profile's steps. Going resident puts the window back to a plain, non-maximized, non-full-screen one, so a reopen never shows the last window's look. `tab_making_sites_are_all_classified` fails when a new place pushes a tab without a classification. Cost if wrong: an in-place wake uses the default profile's window steps, not the profile of the first restored tab.
- Undo (item 4): closing the last window by its close button, Close Tab or Close ends the undo capture with its sessions before the shells are killed; nothing dead or orphaned reaches the Undo Close stack. Cost if wrong: none known.
