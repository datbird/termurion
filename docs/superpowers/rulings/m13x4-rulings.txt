P22 amendment (Task 5, preflight B1): `Page.getResourceTree` and `Page.getResourceContent` are in
`browser_world::ALLOWED` (the one list `devtools_send` and the host's `devtools_call_in` both read;
17 methods). They are host-initiated reads only: Tandem's Rust code calls them through
`App::devtools_read`, which first asks `devtools::refusal` (the narrower second gate: the two
methods, exactly the argument shape Tandem builds). No page or isolated-world message reaches a
DevTools sender; the `frameId` and `url` of a content read come from Tandem's own resource tree
read. Replies are page-derived data: a reply over `devtools::MAX_RESOURCE` (4 MiB of JSON text, as
`ViewGate::admit` weighs a ScriptDone) is an error, and `devtools::Budget` caps a read job at
`MAX_TOTAL` (64 MiB). `Page.enable` was already sent by the world setup.

Task 4 finding I1 (ruled: fix, safer than iTerm2): a navigation cancels a pending plain-text,
page-content or reader-loader call. `browser_reader::State.epoch` is bumped by `reset()`; a call
captures it first, and its answer is dropped (nothing cached, null page content, "the page changed"
for the loaders) when it moved. iTerm2 (`RMM:35-61`) caches the late answer for the new page.

Task 6 (View Source page, preflight B2, P12, P13):
- `browser_pages::{new_nonce, response_headers}` are pub; the source page is answered by
  `App::browser_source_answer` (called first by `browser_local_request`) under the same per-response
  nonce CSP as the other local pages. `resources/browser/view-source.html` is the iTerm2 file with
  recorded edits: `<script nonce="{{NONCE}}">`, `const currentURL = {{URL_JSON}};` (a JSON string with
  `<`, `>`, `&` as \u escapes, P12), and the link maker turns only a parsed http(s) URL into a link
  (`resolveURL` returns null otherwise; was: any text starting with `http` raw, which let an
  `http://x onmouseover=...` value add an attribute through the page's own second linkify pass).
- `view_source::request` takes the pending source only for a document request of exactly
  `iterm2-about:source` (B2); any other context is a 404 that leaves it, `source?x`/`source#f` is a
  404 that logs "Invalid source URL". A document request from a frame cannot be told from the main
  frame here; `frame-ancestors 'none'` refuses the frame, and the pending source is per pane and set
  just before the navigation.
- `BrowserView.pending_source` is `Option<view_source::Pending {raw, url}>` (not `Option<String>`):
  the page needs the viewed URL and the per-load nonce, so it is built at serve time. `Pending::new`
  refuses a source over `MAX_SOURCE` (= devtools::MAX_RESOURCE, 4 MiB); the escaped page can be up to
  about 6x that (P13). Own one-pass filler instead of `fill_template` (which fills its own CSS first
  and takes the common css as a parameter here).
- The page gets no bridge use: `browser_pages::route` knows no `source` page (tested). `NewWindow`
  links go through the existing `nav_gate_tab`; it already refuses every listed URL, no change.
