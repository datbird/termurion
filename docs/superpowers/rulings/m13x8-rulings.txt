m13x8 rulings (browser pages and extensions)

Pre-flight (B1-B12, P1-P17, S1-S8 with 13x7; all accepted). Pages go through the one browser_pages::route path (nonce CSP, frame-ancestors 'none'); copied pages stay byte-identical with exact-once, fail-closed load-time patches (inline handlers moved by patch); the plan's per-page secret scheme is dropped (the message's source is the check). Manifest names reach a page through inert_files::display_text, never innerHTML. Extensions: never auto-loaded from an imported profile, never in Dev Null panes, a native permission prompt (prompt_ui::InputGuard) before enabling, untrusted manifests and files parsed in-process with caps. Page-initiated navigation (a user click on a hostile page included) never reaches iterm2-file:, iterm2-ssh: or settings with power (webhost::nav_verdict is the one owner). Downloads: inert_files dangerous-type rename and a rate cap through the existing owners; the DownloadStarting ban is lifted for the one owner only. No Tandem script runs in an iterm2-file: or iterm2-ssh: page. Bounded reads, json! arguments only, per-pane state in BrowserView.

R13x8-1 (Task 1). A web page cannot open iterm2-file: or iterm2-ssh: by a user click (navigation_allowed refuses a web source; B5); frames never navigate to them (frame_nav_cancelled); browser_message drops every message from a file or ssh page, by pane state and by the message's own source; browser_js::wrap returns before any Tandem script on those pages.
R13x8-1 addendum (Task 1 review I1). The page root is set when the file or ssh navigation COMMITS (the Source change), never at its start; a subresource is answered only when its top document is the committed root. A navigation that never commits leaves no root a web page could use.
R13x8-1 click-out (Task 1 review M3, residual accepted for now). A file or ssh page may still leave by a person's click to the web (navigation_allowed returns true for a user click from those sources, as iTerm2's file pages link out). A hostile local or remote HTML file can put data it reached (for example globals of a .js file in its own tree, loaded by <script src>) into a link URL and get it sent on one click. The alternative, refusing user clicks from file/ssh sources to non-local schemes and opening them with run_external instead, is open for Robert; flagged.
R13x8-2 (Task 2). The error page's content is the pane's own state (pending_error, set from the failure and the URL NavigationStarting named), never a URL's; the URL is escaped in both slots and cut keeping the end of its host; Try Again acts only on a trusted click; at most 5 error pages per 10 s per pane.
R13x8-2 (Task 2 review I1). A navigation that failed but got a server's answer (HttpStatusCode >= 100, read on failure too: a 4xx or 5xx ends with IsSuccess false) shows the server's own page, never Tandem's error page (iTerm2's didFailProvisionalNavigation never fires for an HTTP error response). The engine's values for 404, 500 and 204 need the runtime probe.
R13x8-2 (Task 2 review M1). pending_error is dropped by any start or commit of a page other than iterm2-about:error, so a later document request for the error page never takes a stale one.
R13x8-2 (Task 2 review M2). Every substituted value in a page slot is escaped with { as &#123;, so no later fill (the nonce) can match inside it; page() fills in one pass.
R13x8-3 (Task 2, certificates). A certificate error cancels the load (ServerCertificateErrorDetected answers CANCEL, never ALWAYS_ALLOW) and the error page shows. Task 2 review M4: a runtime without ICoreWebView2_14 fails closed: the browser view that asked for fail_cert_errors is not made (the pane's restart budget then gives up with its banner), so Edge's interstitial and its "continue anyway" never appear. Cost: browser panes need WebView2 Runtime 1.0.1245 or later.

Merge with 13x7 (2026-10-11).
R13x87-1. 13x7's scripts never act on a local page: the autofill detector returns first on any page that is not http or https (one more exact-once, fail-closed patch), the password button was already https only, and 13x8's wrap returns before both on a file or ssh page. A fill or a password write is refused on any page that is not https.
R13x87-2. A sign-in challenge for a local scheme is cancelled on the spot (browser_basic_auth::space_of knows http and https only): no prompt, no lookup, no picker.
R13x87-3. NavigationStarting keeps 13x7's order: verdict, 13x6 sync gate, per-navigation hooks, epoch after both.

R13x8-4 (Task 4, onboarding). The two onboarding pages are served through the one browser_pages::document path (nonce CSP, frame-ancestors none) as exact-once, fail-closed patched copies (inline onclick moved to one delegated listener that ignores an untrusted click). The per-page secret scheme stays dropped: the SECRET slot is empty and the check is the message's source (the pane's main frame, WebView2's Source) equal to the page whose own buttons send that action. Actions change settings only through the existing owners (Globals::set + apply_edit, set_session_values, the shared profile + Edit::Changed, remarry); profile writes are limited to one a second per pane; replies are guarded scripts of fixed words and bools; nothing is logged. A web page cannot post (source check) and a loaded onboarding page does nothing until a trusted click on it. parse() takes no secret (deviation from the brief's signature); the welcome page serves the redirect (nonce on its one script) until NoSyncBrowserOnboardingCompleted.

R13x8-5 (Task 3 rulings, recorded in Task 4's round). A person's click on a WEB page's file: link is refused (stricter than iTerm2; file_redirect_allowed). Any Mark of the Web, whatever zone, makes a file's page script-free (untrusted CSP), as does SVG/XML and every markup subresource. Sandbox CSP by type: trusted HTML runs script only in an opaque origin that reaches nothing; PDF and unknown types are escaped text in a pre (no plugin). Images, video, audio, SVG and XML documents are served as themselves (an iTerm2 deviation: FH:143-157 shows them as text). Hidden = the attribute or a leading dot. File reads run on a pool of 2 workers, 64 MB cap. Task 3 review I1: a file is opened ONCE; the root check, kind, size, bytes, Mark of the Web and MIME type all come from that handle's final path (GetFinalPathNameByHandleW), never a second look at a path. R13x8-3 note: a runtime without ICoreWebView2_14 now shows its own banner (key webview2-old) and the view is not remade.

R13x8-6 (Task 5, settings page). The settings page is served by the app (browser_settings_answer, live ad-blocker state and the pane's Dev Null flag) through the same nonce CSP path (frame-ancestors none), as an exact-once, fail-closed patched copy: every inline onclick/onchange moved to one delegated click listener and one change listener that ignore an untrusted event; the extension rows (hidden today) build name, description and version by textContent and the id by a data attribute, never innerHTML (B2). The per-page secret is dropped (SECRET slot empty); the check is the message's source, the pane's own main-frame URL, and a typed closed action set with 2 KiB string bounds. Nothing the page sends names a settings key: link opening writes only the two keys link_pref_writes returns (NoSyncOpenLinksInApp and its selection, values true/0/1 or removed), a choice picks Tandem's browser or the default browser for a web link and names no scheme or program. Passwords: Manage Passwords opens the 13x7 manager (open_password_manager); the page never lists or shows a password. Permissions: a link to iterm2-about:permissions (13x6's page and queue); no second writer. Clear Cookies / Clear All Data act on the pane's own view profile (a Dev Null pane clears the Dev Null store) and the database erase uses the pane's own store. DataCleared only counts after a request from the settings page. Replies are built from JSON values (status_script/alert_script/link_ui_script), run guarded to the settings page.
R13x8-6 residual (B11, recorded): Clear Cookies / Clear All Data keep the page's own confirm() as their only confirmation (no native ConfirmWindow); with the next rule the page is reachable only from Tandem's menu, a Tandem page or the address bar, and each is limited to once a second. A native confirm is a follow-up if wanted.
R13x8-6 navigation (B5): webhost::navigation_allowed refuses a navigation to iterm2-about:settings, onboarding-setup or onboarding-profile from any source that is not an iterm2-about: page (a web page by click, script or redirect, about:blank, a file page); Tandem's own load and a typed address (no source, user) pass. nav_gate (page-supplied URLs, new-tab requests, restore) blocks them. Known limit: a Back step from a web page onto the settings page is a non-user navigation from a web source and is refused (reload the page from the menu).
R13x8-5 correction: the Mark of the Web is a judged by-name read of the handle's verified final path (the handle is asked again for its path afterwards and a changed answer serves nothing), not a read relative to the handle.
R13x8-4 addendum (Task 4 review): Finish and Continue are host-driven. The page no longer navigates; Tandem completes onboarding (or handles the profile switch) and then loads the welcome / setup page itself, so a lost race cannot loop the welcome redirect. The write limiter is keyed per action (Create, Switch, other).

R13x8-7 (Task 6, settings page: search engine, ad blocking, proxy)
- A search or suggestion template set from the page must be https (not http: the page is the one place Tandem can
  insist), hold exactly one "%@", have a host with no user info, no white space, control or hidden character, and be
  at most 2048 bytes. javascript:, data:, file:, iterm2-* and every other scheme are refused. The query is
  percent-encoded by browser::search_url when used (as iTerm2's urlQueryAllowed: "&" and "=" stay, so a typed query can
  add parameters to the search request, as in iTerm2). A template already saved or imported keeps the older rule
  (browser::template_ok, http allowed) and is not rewritten.
- The filter list address from the page: https only (adblock::list_url_ok), 2048 bytes. The download, its 8 MiB cap, its
  deadline and the compile caps are the existing owner's (adblock_app); Update Now only sets its force flag.
- Proxy: the host passes adblock::proxy_host_ok before it is written and proxy_args judges it again; the port is 1..65535.
  The proxy NTLM residual (13x7 FLAG 15) is untouched. No credential is read or sent to the page.
- Network settings (proxy switch/host/port, ad blocking switch, list address, Update Now) are limited to one per second
  each, since each rebuilds the browser views or starts a download.

R13x8-8 (Task 5 review I1, Task 6)
- Tandem's own Back or Forward (WebView::go_back/go_forward) sets a one-time flag (3 s); the first navigation that starts
  after it, if it is a history navigation, is Tandem's own (by_tandem) and so may load a power page (settings,
  onboarding steps). A page's history.back()/go() carries no flag and stays refused. No banner on the allowed path.
- Clear All Data (which also erases bookmarks and history) asks on Tandem's own window (Then::BrowserClearData, input
  guarded, closed window = Cancel) before anything is cleared; one question at a time. Clear Cookies keeps the page's
  confirm() only (cookies only; a sign-out is recoverable).

R13x8-9 (Task 7, downloads)
- One owner in the host: the DownloadStarting handler and the two operation handlers sit between two marker comments in webhost_win.rs, and a source test pins that the download types appear nowhere else (the old blanket ban is lifted for that region only). A view without ViewSetup::downloads (tool, popover, Quick Look) cancels a download on the spot and hides Edge's bubble. The view has its own PermissionLimiter and pending cap for downloads (not shared with permissions or sign-in), and a download's URL over MAX_URL is cancelled. A running download dies with its view (shut cancels the operations).
- The app writes nothing under the page's name while the download runs: WebView2 is told a hidden `.Tandem.<uuid>.download` file in the Downloads folder (inert at every step, found by ssh_local::sweep_stale if Tandem dies). On completion the app picks the final name AGAIN (destination: clean_name of the decoded last URL component, cut to 150 characters keeping the type, inert_files::neutralized for the dangerous list, ssh_local::final_destination with prompt false, refused_write, download_path_ok on the canonical parent), then ssh_local::finish_with marks the file with inert_files::mark_strict (zone 3, HostUrl only for an http(s) URL under 2 KiB with no control character) and renames it. A drive that keeps no streams: the file is removed and the download fails ("Failed to quarantine"). Nothing is opened or run; Show in folder selects the file in Explorer.
- Flood control: at most 3 running per pane and 8 in all, and a download that starts within 3 s of the pane's previous one (refused ones included) is denied with a banner (13x6: repeat automatic downloads are denied; there is no user-gesture signal in DownloadStarting, so a person's two clicks inside 3 s lose the second). Cost if wrong: a rare second legitimate click is blocked once.
- Dev Null panes: downloads are REFUSED with a banner (writing to Downloads would break "writes nothing"). Cost if wrong: use a normal browser pane. An ask-first or a cleared scratch folder is a follow-up if wanted.
- The downloads page (iterm2-about:downloads, also Menu > Downloads) is Tandem's own page through the one nonce-CSP path, a power page (a web page cannot navigate to it), message source and pane URL both must be the page, a closed action set (list, cancel, remove, showInFolder) naming a download by id only; every name and host drawn goes through display_text and textContent. Menu > Downloads is a Tandem addition (iTerm2 has none).
- Nothing is logged beyond fixed words; the Download rows hold names for the person's list only.

R13x8-10 (Task 8, bookmark tags and Edit Bookmark)
- The tag table and the key-value table are created with iTerm2's text. rusqlite's bundled SQLite is built with
  foreign key enforcement ON by default (iTerm2's engine runs none), which refuses every tag insert and bookmark
  delete ("foreign key mismatch": the reference is to the implicit rowid of a table keyed by url). bring_up turns it
  OFF on every connection; nothing in Tandem turns it on. remove_bookmark and clear_bookmarks delete the tag rows
  in the same transaction (an iTerm2 bug fixed: a reused rowid inherited the old tags).
- Tags: display_text, trimmed, 64 characters, 32 per bookmark; a search takes at most 16 tags; every text is a bound
  parameter and a term's % and _ are literal. A tag read back from a file is cleaned again. The page's tag array is
  bounded in route (16 x 64 characters).
- Edit Bookmark is a native always-on-top Tandem window opened only by the person's Add Bookmark action (never a
  page event, so no InputGuard), never in a Dev Null pane (the bookmark is not kept there). One at a time; a
  navigation of its pane or the pane closing closes it. Delete asks through the one alert queue
  (Then::BookmarkDelete, a closed question is Cancel) and acts only on the open editor's own bookmark.
- Bookmark URLs stay as stored. Opening one is navigate_known / nav_verdict as before (Task 7 of 13x); this task
  adds no opener. javascript: bookmarklets: iTerm2's WebView would run one from the bookmarks page; Tandem's
  nav_verdict refuses javascript:, data:, iterm2-file:, iterm2-ssh: and settings from a bookmark (a bookmark never
  runs with power). Cost if wrong: a bookmarklet does nothing. Add Bookmark only offers http and https pages anyway.
- The key-value table is created and never read or written (WebView2 extensions keep Chromium's storage).

Task 9 (the ssh page and View for remote files).
R13x8-9. mime: the extension table stays one owner, mime_ext.rs (preflight B7); mime_types.rs is not created. mime_for_extension now consults iTerm2's main table, then its OpenAI table (ETM:9-31, 21 pairs; the plan counted 22). Cost if wrong: none.
R13x8-9 ssh: a remote file is served through file_serve::file_answer, the one serving path of file pages, as a downloaded file: UNTRUSTED_CSP (sandbox, no script), nosniff, escaped text for unknown types. Tandem's own answers (no-connection page, error pages) carry the sandbox policy and nosniff. The URL only selects among the registry's sessions; the path reaches Transfers::download as one typed argument; no connection or credential prompt can start from a URL. Cost if wrong: a remote .html page cannot run its own script.
R13x8-9 limits: 64 MB buffer, at most 8 jobs per browser view and 16 in all (a page of many images gets the error page for the rest). A folder is not stat'ed before the prompt (iTerm2 does): its page says "Only a file can be shown." Cost if wrong: a folder named like a picture asks View and then says so.
R13x8-9 open: View opens the tab through open_in_browser_pane (the one open path); the first URL is App::ssh_view_url, set only by open_ssh_view after view_url_ok and taken by start_browser_pane, so no link, page, arrangement or restored URL can start an ssh page. Cost if wrong: none.
R13x8-9 dropped: a view dropped or made again (browser_reset_world) and a pane that goes abandon their page jobs (the transfer is cancelled, nothing is answered); a session that ends fails its waiters and the page gets the error text. Probe ssh_page_serves_text_and_a_closed_view_completes_the_deferral is written and NOT run.

R13x8-12 (Task 10, browser extensions). WebView2's own extension support replaces iTerm2's WebExtensionsFramework (Q39). The preflight B2/B3 rules replace the plan's "load every folder under the root, active ids from the profile": a folder reaches AddBrowserExtension only when (a) the person chose it (or its parent) in the native folder picker, which is the only writer of the root key, (b) the person pressed Enable in a guarded native window listing the manifest's permissions and every site (host_permissions and content script matches), scrolled to its end, for THIS saved profile, and (c) its manifest.json still hashes to what was shown. Approvals live in %LOCALAPPDATA%\Tandem\browser-extensions.json (owner-only, bounded), keyed (saved profile Guid, folder, manifest hash), written only on a worker after the window's Enable. A profile key that arrives by import, sync or Dynamic Profile can name a root or active ids but approves nothing, so nothing loads. Cost if wrong: a changed script file with an unchanged manifest.json keeps its approval (only the manifest is hashed).
R13x8-12 scope: AreBrowserExtensionsEnabled is set for Store::Browser only; Store::BrowserDevNull and the default store never get extension support, and the sync, the picker and the page arms refuse a Dev Null pane. Zip and crx are not supported (an unpacked folder only), so src/extract.rs is not involved and no outside tool runs. The sync runs at view creation, on the settings page's GetExtensions, after each add and after a toggle; it never asks a question, only choosing a folder does. A root that cannot be read (missing drive, network path) changes nothing and removes nothing.
R13x8-12 text: manifest name, description, version, permissions and sites are parsed in-process (256 KiB, depth 16, 64 entries of 128 characters, name 100, description 300, version 32), run through inert_files::display_text, and reach the settings page as JSON built with serde_json into the patched textContent/dataset renderer; the id must be 32 letters a to p. Nothing but counts is logged.
R13x8-12 removal and isolation: browser_extension_remove is the one owner (WebView2 Remove, the approval's id, the active id and this run's folder map together). A message whose source is chrome-extension: reaches no handler (browser_message), and navigation_allowed refuses a settings, onboarding, file or ssh load from such a page. The settings page gained a Choose Folder button inside the still-hidden extensions section (SHOW_EXTENSIONS stays "display: none;"): the writer's ruling that the section is hidden holds, so the picker is reached only by flipping that one flag; the person-chosen-folder rule needs a control, and the controller decides whether to show it. Cost if wrong: extensions cannot be loaded from the UI until that is decided.
R13x8-14 (Task 10 review I1, fix round). Every Tandem browser profile shares ONE WebView2 profile (Store::Browser; no ProfileName per Tandem profile, and giving each its own would split cookies and logins, which is Robert's call), so an extension added for one Tandem profile is installed and enabled for all of them and WebView2 has no per-profile switch. Ruling: approval is per SHARED WebView2 profile. Approvals are keyed by the constant browser_extensions::STORE, not the saved profile's Guid; the approval window says "It is loaded into all browser profiles that share this browser data, never into Dev Null windows." The on/off switch is shared too and lives in the approvals file (Approval.enabled; the profile key Browser Extension Active IDs is kept in the schema for parity but no longer consulted). The sync runs for EVERY non-Dev-Null browser view, with or without a chosen root: it keeps the extensions of all approved folders whose manifest still hashes to the approval (wherever they are) plus the unapproved ones it only asks about after a Choose Folder, and removes every installed id outside that set, so deleting an approval, a folder or the approvals file unloads it and no orphan stays running. An approval written by the earlier build (keyed by a profile Guid) no longer matches: that extension is removed at the next sync and must be approved again. Cost if wrong: a person who wanted an extension in one Tandem profile only gets it in all of them (the window says so); a removable drive that is absent removes its extension and its approval.
R13x8-15 (Task 10 review I2): the approval window lists optional_permissions and optional_host_permissions too, under "It may ask later for:" (same caps and display_text as the others), because chrome.permissions.request can grant them at run time with a prompt WebView2 may not show. Cost if wrong: none.
R13x8-16 (Task 10 review minors): an extension that asks for debugger or nativeMessaging (now or later) gets a WARNING line at the top of the approval window naming what it can do; it is still the person's choice (not refused). Reveal in Explorer refuses a Dev Null pane (NOT_ALLOWED) like the picker. The settings page's GetExtensions is always answered (an empty list for a Dev Null pane or an unreadable root). Cost if wrong: none.
R13x8-13 (Task 9 review I1, I2). I1: a navigation from an iterm2-file: or iterm2-ssh: page to another local page is judged by webhost::listing_click_ok. A served file (any file page whose path does not end in "/") and every ssh page go to no local page; only a user click on a Tandem-made folder listing (path ends in "/") may go to an entry of the same scheme and authority inside the committed root (WebView::set_local_root, set by the app at each commit: a page committed inside the old root keeps it, any other file page starts a new one, leaving file pages ends it), so ".." above the root is refused. A reload of the page itself (Try Again, F5, same URL up to the fragment) always goes on. ssh has no listings (folders are refused), so an ssh page has no outgoing local link at all; the session (user, host, port) check is therefore the whole-page rule. Cost if wrong: a listing's ".." row at the root does nothing (the address bar still works).
R13x8-13 I1 r1: the rule judges the FINAL target. A `file:` link clicked in a local page is mapped to its `iterm2-file:` form (iterm2_file_url) before listing_click_ok runs, so it is refused from an ssh page and a served file and kept inside the committed root from a listing; a `file:` URL with no `iterm2-file:` form (UNC, no drive) goes nowhere from a local page. file_redirect_allowed refuses a source that is an ssh page or a served file (path not ending in "/"); only about pages, no source, Tandem's own load and a Tandem listing may redirect.
R13x8-13 I2: a page's transfer is Transfers::download_file_only: it ends at the first stat with ssh_page::NOT_A_FILE when the path is a folder or not a regular file, before any Zip is sent. Win-click download and Download Files still zip a folder.

PLAN DECISIONS (Task 11 records each Decision of the plan once; where a task ruling above changed it, the entry says so).
Ruling (D1): emoji in copied pages become Segoe Fluent Icons glyphs at serve time (browser_pages::glyph_page; a CSS content emoji keeps its place and gains the icon font; a trailing U+FE0F is consumed; values substituted into a page are never rewritten). - cost if wrong: a glyph code may read differently from the emoji.
Ruling (D2): cert-error.html, dev.html and the Demos pages are not shipped (unused or debug-only in iTerm2). - cost if wrong: none for release parity.
Ruling (D3): a certificate error cancels the navigation and shows the error page, never a continue-anyway (see R13x8-3). - cost if wrong: a self-signed local server cannot be visited, as in iTerm2.
Ruling (D4): the error page texts (describe(status)) are Tandem's, since there is no system source for WebKit's descriptions. - cost if wrong: wording differs from macOS.
Ruling (D5): the error page escapes the failed URL in both slots (iTerm2 inserts it raw), see R13x8-2. - cost if wrong: none.
Ruling (D6): a file: navigation is cancelled in NavigationStarting and redirected to iterm2-file: (WebView2 could show file: itself). - cost if wrong: WebView2's own file viewers (PDF) are not used for file: URLs; a PDF shows as escaped text.
Ruling (D7): an iterm2-file: failure answers a 404 (iTerm2 fails the scheme task and shows nothing). - cost if wrong: a blank page instead of the previous page staying.
Ruling (D8): files over 64 MB are not served as file pages (and the ssh page buffer is capped at 64 MB). - cost if wrong: large logs cannot be viewed this way.
Ruling (D9): onboarding's Switch uses remarry (the session takes the profile) instead of iTerm2's divorce-and-copy that keeps the session guid. - cost if wrong: a session-local override made before switching is dropped.
Ruling (D10): settings page alerts and replies are built as JSON strings (status_script is JSON-quoted, not iTerm2's single-quote form). - cost if wrong: none.
Ruling (D11): the secret-less clearCookies/clearAllData copies iTerm2 injects at commit are not injected; the per-page secret scheme is dropped everywhere and the message's source (main frame, URL equal to the page) is the check (pre-flight B1, R13x8-4). - cost if wrong: none; the check is stronger than a secret a page could be handed.
Ruling (D12): download decisions are WebView2's (Chromium's) rules; the name and destination are iTerm2's with Tandem's safety rules (R13x8-9, R13x8-11). - cost if wrong: some types iTerm2 downloads (for example audio/ogg) play in the page instead.
Ruling (D13): downloads report through banners, notifications and the iterm2-about:downloads page (a Tandem extra reached by its URL only; Menu > Downloads was removed for 1:1 parity, R13x8-11). - cost if wrong: no menu entry for the list.
Ruling (D14): bookmark tags are parsed from a comma-separated field in Edit Bookmark. - cost if wrong: a tag cannot contain a comma.
Ruling (D15): the key-value table is created with iTerm2's text and never read or written (R13x8-10). - cost if wrong: none; WebView2 extensions keep Chromium's storage.
Ruling (D16): the ssh page buffers the remote file, up to 64 MB, before answering (no progressive display). - cost if wrong: larger remote files cannot be viewed this way.
Ruling (D17): iterm2-file: and iterm2-ssh: pages are sandboxed (R13x8-1, R13x8-5): an opaque origin, no connections, no form posts, subresources only from the committed root, no script-started navigation. - cost if wrong: a local HTML file that fetches its own data files or posts a form does not work as in iTerm2.
Ruling (D18): only the person, Tandem or an iterm2-about: page can start a file:, iterm2-file: or iterm2-ssh: load; a web page's click on a file: link is refused too (R13x8-5, stricter than the plan). - cost if wrong: a web page cannot open a local file view, which iTerm2 allows.
Ruling (D19): a download name goes through 14d's clean_name and must land directly in Downloads (R13x8-2 of the plan, applied in R13x8-9). - cost if wrong: a name with a Windows-forbidden character is changed (a:b becomes a_b).
Ruling (D20): foreign keys are OFF (explicit pragma in bring_up), a bookmark's tags are deleted explicitly in the same transaction. R13x8-3 of the plan said Tandem runs no pragma; that premise was wrong (rusqlite's bundled SQLite turns foreign keys on by default, libsqlite3-sys sets SQLITE_DEFAULT_FOREIGN_KEYS=1), so R13x8-10 supersedes it. - cost if wrong: none.
