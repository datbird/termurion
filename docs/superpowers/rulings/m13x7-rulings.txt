m13x7 rulings (browser autofill and passwords)

Task 3 review I1: the native autofill question answers Fill only to a pointer click. Every keyboard event except Escape (Cancel) and every input-method event is dropped for the whole life of that window (pwm_app autofill_key_dropped), so Tab never reaches Fill and Space or Enter never press it. The question text says so. Cost: a keyboard-only person cannot fill from this question (they can cancel).

Task 3 review M1 (residual): the target field is not re-validated at write time. "Visible fields only" holds at collection; after the person confirms, the page can move the requested id or name onto a hidden element. Not an escalation: only the approved types go, to the approved origin, which owns that DOM.

Task 3 review M2: the scripted-click probe step now dispatches untrusted clicks at the element under the button and at every element, so it does exercise the isTrusted check.

Task 4: the browser scope is a separate store (Scope::Browser: Tandem-Browser/ targets, untagged 1Password items minus iTerm2-tagged, LastPass groups outside the terminal groups, adapter mode "browser", own source key). Scope code lists names only and never reads a secret. Matching an entry to a page (exact normalized origin, https only) is not in this task: account names from imported or synced sources are untrusted text and must be matched by the later origin task, never by substring or suffix.

Task 5: the password writer writes a password only into a visible password field, on an https page whose exact origin and navigation epoch are the ones bound at pick time (PwPage), main frame only, checked when queued, when started, after the probe and inside the page script. iTerm2's "not a password field, fill anyway?" confirm is NOT built (B4: no Enter-answers-OK window the page can influence; the field is page-chosen). A refused write shows a toast. Cost: a person cannot force a password into a text field.
Task 5: credential-to-origin matching is one function, browser_password::account_matches (first word must be exactly https://host[:port], ASCII, exact compare, no path, no http, no substring or suffix; non-ASCII hosts do not match). Task 6 uses it; do not write a second.
Task 5 (B10): the password call text and the DevTools parameters are built in Secret buffers (call_js_secret, evaluate_params_secret) and wiped on drop. Residual: WebView2, the DevTools pipe and the renderer hold further copies; Tandem does not claim zeroed.
Task 5 review I1: the UTF-16 copy of the DevTools parameters that devtools_call_in hands to COM is a WideSecret (exact size, wiped on drop), for every DevTools call; the closure owns it, so a call queued before the view exists wipes it when it runs or when it goes with the view. The residual list above (WebView2, the pipe, the renderer) is now complete for Tandem's own copies.
Task 5 review M2: an account named with a Unicode host never matches (no IDNA crate); store a hand-typed IDN account in punycode (xn--...). Punycode compares byte-exact. M4: the "visible" test is a heuristic (1x1, off-screen, clip-path and covered fields pass); residual like Task 3 M1, only the bound origin's own DOM receives the credential.
Merge with 13x6: the autofill question uses the one input guard, prompt_ui::InputGuard (1 s, restarted on refocus, keys, clicks, touch and IME), through ConfirmWindow::guard_input; Fill is a pointer click only and Escape the only key, held back while the guard waits. The navigation epoch moves only for a navigation that passed nav_verdict and the 13x6 sync gate (Starting); a parked navigation moves nothing, its release moves it. The question names the origin with browser_perms::origin_label, as the permission prompt does.

R13x76-1 (Task 6). The browser password manager over a page lists only accounts whose name is exactly that page's https origin (Task 5's account_matches, the one matcher); the rest are hidden (iTerm2 lists everything and has no "use anyway"), and an http page or no page lists nothing. Cost: a store entry for another site cannot be picked from this page; the Settings page of 13x8 gets an empty list until it names a different rule. The account Add starts with, and the one the manager preselects, is the page origin.
R13x76-2 (Task 6). The pick binds the page (origin + navigation epoch) when the person presses Enter, before the secret is fetched, and checks account_matches against it again; Enter User Name binds the same way. enter_password and enter_username refuse browser panes and broadcast skips them, so no pty path can carry a page secret and no page path an unbound one.
R13x76-3 (Task 6). The browser store has its own worker, source info, source key and authentication; a refusal or unlock touches only its store; a screen lock revokes both.
R13x77-1 (Task 7). password-button.js stays byte-identical; button_patched applies nine exact-once, fail-closed patches: https-only and same-origin-frame guard, closed shadow root, isTrusted plus elementFromPoint (tandemReal), label as ::after generated content, step aside for the autofill button's host. A press only REQUESTS (opens the native manager bound to the exact https origin and epoch); the arm asks the store nothing, so 0 or N accounts look the same. A frame's message never carries a focus id.
R13x77-2 (Task 6 review M1, class rule). The manager opened by a page's button (PwmOpen.from_page) carries prompt_ui::InputGuard (PwmWindow::guard_input), the one owner; a lured click plus Return cannot fill. Task 6 review I1: open_pwm_now returns `session` on its four failure paths so a picker's challenge is answered.

R13x78-1 (Task 8, B6). No silent credential supply: LookupSaved's result only PREFILLS the prompt; Supply follows only a person's PromptResult::Submitted or PickerResult. This departs from the plan's tests (saved lookup then Supply) and iTerm2 (BAC:292-300). Lookups are never made over http. Cost: a saved sign-in needs one click (OK) each time.
R13x78-2 (Task 8, B5). Challenges are held per pane: one open prompt, MAX_QUEUED 4 waiting, MAX_PER_NAV 16 per navigation epoch, and the pending count and rate of webhost::PermissionLimiter (the one owner of deferral caps, S4); the rest are answered Cancel. A realm over 256 or a host over 253 characters is refused (Cancel), never cut. SpaceKey::shown_realm/shown_origin are the inert, end-keeping texts Task 9 must show (S5).
R13x78-3 (Task 8). Only a shown pane is asked: Event::Visible(false) cancels everything held (ClosePrompt then Cancel); a challenge arriving while hidden is cancelled. Cost: switching tabs during a sign-in cancels it (the page shows its 401).
R13x78-4 (Task 8). A fresh navigation, a failed one (MainEndedWithoutResponse) and Event::Reset (pane close, browser_reset_world) cancel every held challenge and bump the epoch; late results for those ids give nothing. This replaces iTerm2's "late lookup result gives Cancel": the Cancel is emitted at the move. MainCommitted cancels nothing. A parked 13x6 navigation produces no MainProvisionalStarted (S3): Task 10 must answer its BasicAuth with Cancel.
R13x78-5 (Task 8). Challenges over http are WARNED, not refused: PromptRequest.cleartext is set for Basic over http, nothing is offered to remember (the store matches https only), no lookup. A proxy challenge (is_proxy) is prompt-only, never main, never saved, and PromptRequest.proxy tells Task 9 to name the proxy (space.host is the proxy). Task 10 supplies is_proxy.
R13x78-6 (Task 8, P10). Credential copies: at most one awaiting credential, one last_entered per space (MAX_SPACES 16, oldest dropped), one saved prefill per held challenge; all dropped on every terminal path and on Reset. A credential that came from the store (prefill submitted unchanged) is never persisted.

R13x77-3 (Task 7 review I1, class rule as Task 3 I1; corrects R13x77-2's "cannot fill"). A manager opened by a PAGE request has no keyboard default: only arrows, Home, End, Page keys and Escape reach it (Return, Space, Tab, Delete, Ctrl+C, typed keys and input-method text are dropped), the Win+B/U/C chords are never taken, and picking an account needs a pointer click or a tap (after the 1 s guard). A manager opened by the person (menu, shortcut) keeps normal keys. Cost: no typing in the search field of a page-opened manager. prompt_ui::InputGuard::drops_chord holds a Win chord from the key hook until the guard is armed, for every guarded window that takes chords (the Win+U path skipped the guard).
R13x79-1 (Task 9, B5). The sign-in prompt is a native Tandem window (basic_auth_ui::AuthWindow) whose text is browser_basic_auth::prompt_heading: the real origin (or the proxy) through SpaceKey::shown_origin, the server's realm only after REALM_LABEL as inert capped text, the cleartext warning for Basic over http. It carries prompt_ui::InputGuard (one owner). A prefilled prompt has no Enter default until the person has typed or clicked OK. Secrets are edited in place with secret_field (no egui text copies) and wiped on drop.
R13x79-2 (Task 9, B7). Store jobs are Job::Auth on the browser worker with no window; Reply.owner is None; pwm_reply routes through PwmState::route_reply first (store replies queued in store_replies for Task 10, info per scope, ownerless Prompt/Pick dropped = Cancel). A locked store (unlocked_without_prompt false) answers a miss or a failed save at once and never prompts.
R13x79-3 (Task 8 review I1, I2, M1). A rejected stored (saved or picked) credential is never prefilled or resent (at most the typed user name stays; Remember stays off); stored credentials never become "last typed". A pane is not shown until Visible(true). A person's Cancel silences that origin for COOLDOWN 60 s (no 13x6 cooldown owner exists to reuse; this is the one). A Coordinator dropped without Reset hands Cancel for everything it held to its on_drop sink.

R13x710-1 (Task 10, NTLM/Negotiate, Windows integrated authentication). WebView2 is made with --auth-server-allowlist=tandem-no-integrated-auth.invalid (webhost::browser_arguments, appended to the proxy argument; EnvOptions.args is unchanged and still pinned) and AllowSingleSignOnUsingOSPrimaryAccount explicitly false. Chromium otherwise sends the person's Windows credentials to intranet-zone hosts with no question when the list is empty; with a non-empty list only a host that cannot exist is eligible. An NTLM or Negotiate challenge therefore reaches the coordinator like any other (is_basic false: prompt only, never looked up or remembered). Cost: no silent single sign-on to intranet sites. Runtime proof (probe integrated_challenges_reach_the_app) is written, #[ignore], and could not run here: ssh sessions are session 0 and the desktop probe is not to be run; run it by hand.
R13x710-2 (Task 10, proxy). Whether WebView2 names the proxy or the site in a proxy's 407 is unproven (probe proxy_challenge_reports_the_proxy, ignored, not run). Fail safe: while BrowserProxyEnabled is on, no challenge is looked up or remembered; one whose URI is the proxy's host and port is also flagged proxy (the prompt names the proxy).
R13x710-3 (Task 10, deferrals). Every BasicAuthenticationRequested is set to Cancel first, so WebView2's own dialog never shows and a failure leaves it cancelled; only a view with ViewSetup::basic_auth holds it, within the pending count and rate of the SAME PermissionLimiter and pending total as permissions (perms + auths). A challenge text over 1024 characters or a cut URI is cancelled. answer_basic_auth completes once (a token is removed first); Some hands the credential over through a wiping UTF-16 copy and the password is wiped after; a view going away (shut) cancels every held one. In the app each token is held in AuthPane.slots under the challenge id and answered through Coordinator effects only; a navigation, the 13x6 sync gate parking one (Event::Parked cancels what the pane holds), the pane hidden, browser_reset_world, pane close, a view replaced (different view id), a lookup older than 15 s and a dropped coordinator (DROPPED, answered on the next pass) all Cancel.
R13x710-4 (Task 10, navigation facts). Event::Committed (ContentLoading) and Event::Response (WebResourceResponseReceived, main document only: URI equal to the last main-frame NavigationStarting's with the fragment stripped, and no Sec-Fetch-Dest other than document) carry the NavigationId; ViewSetup::main_responses needs the Document filter track_document_method adds. NavTracker holds a commit until the final non-3xx response or completion and delivers the response first. Accepted: a same-URL subresource request could be taken for the document's response where Sec-Fetch-Dest is not sent (plain http to a non-localhost host); it can only mark the person's own typed sign-in for that origin accepted or rejected, never read or send a credential, and nothing is remembered over http.
R13x710-5 (Task 10, picker and store). The picker is opened with the challenge's https origin (PwmOpen.pick_page): the list shows only accounts for that exact origin (account_matches) and a pick for any other is refused; no https origin lists nothing. Saving asks the BROWSER store's authentication only (authorize_save). A lookup honors REQUIRE_OPEN and REQUIRE_EVERY (every = never silent). The picker re-prompt starts with Remember off. Store replies are drained by basic_auth_tick; the coordinator's on_drop sink is set.
R13x710-6 (Task 10, cooldown). One shared per-key cooldown (src/cooldown.rs: monotonic milliseconds, 60 s, 256 keys, expired entries then the oldest evicted) serves the 13x6 permission prompt and the sign-in prompt (Task 9 review: R13x79-3 confirmed).
