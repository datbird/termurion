TWEAKS 9: Ruling: the shortcut key (iTerm2's Cmd) is a Keys setting "ShortcutKey": 0 Ctrl+Shift (default), 1 Win, 2 Ctrl+Alt. It is stored as an integer and read with the schema default, so a person who never chose it gets Ctrl+Shift on upgrade and a person who chose Win (or any value) keeps it - cost if wrong: an existing user who relied on Win must pick Win once.
TWEAKS 9: Ruling: Ctrl, Shift and Alt are shared out as three pairs. Cmd is the chosen pair, Cmd+Shift is all three (Ctrl+Shift+Alt+X, no collision with plain Cmd+X), Cmd+Option is the remaining pair (Alt+Shift with Ctrl+Shift, Ctrl+Shift with Ctrl+Alt). The default window switch modifier is Cmd+Option, so it needs a pair - cost if wrong: Alt+Shift+digit can toggle the keyboard layout on a machine with several layouts if Alt and Shift are released without the digit.
TWEAKS 9: Ruling: a Cmd chord with no pair (Cmd+Ctrl such as the profile shortcuts and Ctrl+Cmd+arrows, Cmd+Option+Shift) stays on the Win key in every mode, shown as Win+...; the hook takes it as before and leaves every Win chord that has a pair to Windows (Win+D, Win+L) - cost if wrong: those few chords still collide with Windows.
TWEAKS 9: Ruling: key bindings, imports, exports, saved profiles and menus.toml keep iTerm2's Cmd notation (COMMAND flag, "cmd" in the schema). Only display (menus, tab/pane/window numbers, composer help, the bindings table) and the physical press change. A binding written as a literal Ctrl+Shift+X shows the same label as Cmd+X in Ctrl+Shift mode and loses to a bound Cmd+X - cost if wrong: such a literal binding is shadowed.
TWEAKS 9: Ruling: key reporting. A Ctrl+Shift press that is a bound Cmd chord (a menu command, a key mapping, a number shortcut, the Leader, a workgroup peer key) is Tandem's, whatever keyboard protocol the program enabled (kitty flags, CSI u, modifyOtherKeys, raw): iTerm2's main menu performKeyEquivalent runs before the terminal's key handler (PTYTextView.m:731) and Cmd chords are never sent to a program. A press that is not bound is not taken: it goes to the terminal with Ctrl and Shift as pressed, so Ctrl+Shift+letter reaches a program that asked for it under CSI u and sends what it always sent under legacy reporting - cost if wrong: a program cannot receive a Ctrl+Shift+letter that is also a Tandem shortcut (Ctrl+Shift+C, V, F, T, D, W, K).
TWEAKS 9: Ruling: AltGr is Ctrl+Alt to Windows. A press with Ctrl and Alt held that types a character is never taken as a shortcut, in any mode, so AltGr+Q still types "@"; Ctrl+Alt is warned about in the settings page and the choice's label - cost if wrong: a shortcut on a character key AltGr also uses cannot be pressed on that layout.
TWEAKS 9: Ruling: the pointer follows the setting: Ctrl+Shift (or the mode's pair) held with a click is Cmd+click (open link, Cmd+drag), as the Win key is in every mode; mouse reports to programs keep the physical modifiers - cost if wrong: Ctrl+Shift+click no longer extends a selection the way Shift+click does.
TWEAKS 9: Ruling: the password manager, AI chat and cockpit windows keep their Win chords (Win+B, Win+U, Win+W); they are separate windows with their own chord tables and are not part of the main shortcut mapping yet - cost if wrong: those few shortcuts still use Win and their tooltips say Win.
TWEAKS 9: Ruling: the settings recorder records a press of the shortcut key's own modifiers as Cmd (what the binding will be matched as), so a recorded Ctrl+Shift+D is stored as Cmd+D.
