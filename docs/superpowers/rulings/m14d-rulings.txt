Ruling: 14d-R1 the zip refusals added by Task 4 (a name that is not UTF-8, a non-ASCII name without the UTF-8 flag, a Unix entry with no file type bits, any Explorer-parsed component, over 100000 entries or 2 GiB claimed, and the Info-ZIP Unicode Path and Comment extra fields 0x7075 and 0x6375) apply to the 11d Scripts import as well: one checker for every archive - cost if wrong: some macOS-made or Python-made script zips are refused with the entry named.
Ruling: 14d-R2 a single-stream download whose remote delivers more than the size its stat claimed fails (iTerm2 reads to an empty reply); without it a remote claims 10 bytes, passes the free-space check and fills the disk - cost if wrong: a file that grows during a Win-click download fails.
Ruling: 14d-R3 a stream with no claimed size is bounded by free space: before each write the job fails if the drive would drop below 1 GiB free - cost if wrong: a large size-less download stops 1 GiB short of a full disk.
Ruling: 14d-R4 claimed sizes in a folder zip are never trusted alone: the claimed total must fit in free space minus 1 GiB before tar.exe runs, and tar.exe runs in a Job Object that a watch kills (every 250 ms) when the extracted tree exceeds the claimed total plus 1 percent (at least 1 MiB) or the drive is down to 1 GiB free; the partial tree is removed and the job fails - cost if wrong: a zip bomb fills the system drive, or an honest archive whose directory understates its size is stopped.
