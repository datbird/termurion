Fix round 4: Ruling: an Invoke Script Function trigger that passes captures to iterm2.run_coprocess(commandLine:) is the person's own installed script calling an API that takes a whole command line by design (iTerm2 parity, trusted code); Tandem adds no refusal there, while every command line Tandem builds from a template (Semantic History, Smart Selection, Run Command, Run Coprocess, Run Silent Coprocess, Capture Output, the file-drop coprocess) goes through the one cmd.exe builder and its context-free refusal - cost if wrong: a person's script that forwards captures into run_coprocess can be injected by the program whose output it reads, as in iTerm2.
Task 6 fix round 1: Ruling: cmd.exe, conhost, forfiles, wt, sh, zsh, rundll32, regsvr32, msiexec and certutil (matched by the resolved program's file name, any folder, any extension) are never URL handlers, whatever the URL - cost if wrong: a person who wanted one of them as a handler (for example cmd.exe /c start) must use a small program or a .cmd file instead (a .cmd file still gets the batch refusal).
Task 6 fix round 1: Ruling: a URL handler template's session variables are bound to markers and put back after the split, so each is one argument (or part of one) and never the program; one holding a cmd_unsafe character or what the program would read as syntax is refused - cost if wrong: a handler template that relied on a variable supplying several arguments, or naming the program, no longer runs.
Task 6 fix round 1: Ruling: "URL Handler Command Failed" shows only when the handler program cannot start; a non-zero exit is noted in its Script Console entry, never a banner (explorer.exe exits 1 after handing a URL off) - cost if wrong: a handler that starts and then fails is not reported on screen.
