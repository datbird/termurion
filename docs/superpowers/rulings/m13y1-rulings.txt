Ruling: workgroups in the person's own settings file are the person's; every import path (Import All, remote prefs, Dynamic Profiles) marks its workgroups Imported at ingest and the mark is stored in WorkgroupsImported (a list of ids). An edit never clears it; only the editor's explicit "Trust this workgroup" does. Remote prefs cannot carry or clear marks (workgroup::mark_foreign_write), a plist and the API never write the workgroup keys - cost if wrong: malware running as the person can edit settings.toml directly, as it can profiles.toml today.
Ruling: no import carries workgroups yet (iTerm2 stores them as binary data and Import All drops binary values); the task that adds that import must set the Imported mark with Model::add_from or mark_foreign_write - cost if wrong: an imported workgroup would run as the person's.
Ruling: the model never holds what the write point would drop or trim; save re-reads the stored value into memory and workgroup::check is the editor's limit test - cost if wrong: the editor and the stored value would disagree.
