UI parity sweep, package S (the Settings window). Source of truth: the xibs and view controllers in the iTerm2 reference clone (commit 64791fc), read by scripts/gen-ui-labels.py into schema/ui_labels.toml; src/ui_labels.rs holds the schema to it. Plan: superpowers/plans/2026-10-14-ui-parity-sweep.md. Audit: superpowers/audits/2026-10-14-ui-settings.md.

Method: S-1 scripts/gen-ui-labels.py finds each control's label from the relatedView outlet, the <name>Label outlet, the control's own title, the static text left of it or above it in its box, or a named text of an xib (the EXTRA table in the script; every text is looked up in its xib so a typo cannot get in). It also records a popup's item titles. 344 controls are in the table, 319 with a label.
Method: S-2 The guard (src/ui_labels.rs) fails on any schema row whose label is not the mapped iTerm2 label, on a popup item that is not (items are compared by tag, an untagged item being tag 0; a popup whose items share a tag is skipped), on a row that draws nothing, and on the "N item(s)" count or the "arrives with its feature's milestone" promise returning to the Settings sources. Before the labels were fixed the guard failed on about 300 rows (about 195 wrong labels and about 115 rows with no label to hold); 169 labels and 9 popup items changed.
Method: S-3 The word mapping is Finder to Explorer, option (the glyph) to Alt, command (the glyph) to Win, control (the glyph) to Ctrl, "^-" to "Ctrl-", Return to Enter, iTerm2 to Termurion. Bare "Control" is NOT mapped (the AI permission "Control Terminal" is the same words).

(c) "Report terminal type:" was listed as drift only; it is now iTerm2's combo box (the field and a menu of vt100, xterm, xterm-new, xterm-256color, ansi, rxvt, linux). (d) Profiles > Web stays a placement difference: Termurion has no Web tab and its Browser rows are on General (m13x rulings); the Bulk Copy sheet therefore has no Web box. (e) The audit counted GPU rendering among the missing controls; it is ruled below (S-6).

Ruled out:
Ruling: S-6 GPU rendering (UseMetal) has no control: Termurion has no renderer but the wgpu one, so a switch between a GPU and a software renderer would switch nothing. The 02 row is n/a with that reason; the sheet "Advanced GPU settings" rows (maximize throughput, disable when unplugged, low power, prefer integrated) stay as built in 13l.
Ruling: S-7 "Log debug info to Console.app" in the Smart Selection editor is not built: Console.app is macOS only, and the playground shows the same decision on screen.
Ruling: S-8 The font features button (`OptionsButtonController`) is built. It shows beside a font's size while that font's ligatures switch is on and offers Contextual Alternates and the font's stylistic sets. The choice is stored after the size in iTerm2's form (`Name 13 {"featureSettings":[{"CTFeatureSelectorIdentifier":2,"CTFeatureTypeIdentifier":35}, ...]}`: AAT type 35 selectors 2n, type 36 selector 1 for Contextual Alternates off), so an iTerm2 settings file round-trips. On Windows the sets are the font's `ss01` to `ss20` (selector 2n is `ssNN`), named from the font's `name` table through the feature's parameters, else "Stylistic Set N"; they are applied as OpenType features when text shapes, and Contextual Alternates off turns `calt` off whatever the global EnableContextualAlternates says. Picking another family starts the choice over, as iTerm2's does. The "This may reduce performance" hint beside Use ligatures is built.
Ruling: S-9 The Touch Bar item list row (Touch Bar Map) draws nothing: macOS only. Page Zoom (Browser Zoom) and the browser extension keys have no control, as before (zoom commands and the approval window write them, m13x).
Ruling: S-10 Rows iTerm2 draws in a sheet or with no label of their own (the hotkey sheet, the working-directory radios, the window size line, the key and trigger tables, the AI keys, the bold color well and the seven bright ANSI wells) keep their schema labels; they are named in the EXEMPT table of src/ui_labels.rs with the reason, and the table is checked so an exempt row cannot be one the xib labels. The Colors wells that iTerm2 labels wear its labels (Defaults:, Cursor:, Selection:, Background, Foreground, Black to White, ANSI Colors:) and the Colors tab draws them in its grid.
Ruling: S-11 Windows wordings kept over iTerm2's, each a named OVERRIDE in the guard: "Desktop:" and "Restore windows to same desktops" (Spaces are virtual desktops), "Exclude from taskbar and Alt+Tab switcher" (no Dock or Cmd-Tab), "Respect shortcuts from Windows keyboard shortcuts" (the macOS System Settings path does not exist), Confirm "Quit Termurion" (the chord is the person's shortcut key). Popup items kept: the Desktop N items, the Alt+Number chord spellings, the Remap modifier items (iTerm2 puts a key glyph before each name), "Left Control" and the Function item, and the Python API methods (the m12 rulings: cookie, not macOS Automation permission).

Built differently from iTerm2:
Ruling: S-12 The window restoration popup's items are iTerm2's; "Open Default Window Arrangement" is disabled until an arrangement is saved, as iTerm2 does (`[WindowArrangements count]`).
Ruling: S-13 "Allow sending of clipboard contents?" is a synthetic row over NoSyncNeverAllowPaste and NoSyncAllowPaste, as iTerm2's PasteboardReporter; the key itself is never stored.
Ruling: S-14 New tabs open at end of tab bar is honored by the New Tab command and the API's CreateTab (`App::add_tab`), where iTerm2's insertion is `PT:12174`; tmux windows, restored tabs and tab drags place themselves as before.
Ruling: S-15 The Title popup is one menu (components, then the registered title functions); the "Components" first item of iTerm2's pull-down is the popup's own text. The AI-generated name item is not offered (not available on Windows). The Edit Session variant omits Job Name with Arguments and Columns x Rows, as iTerm2's does.
Ruling: S-16 "(recommended for this font)": CoreText's CTFontShouldAntiAlias has no Windows twin. The hint reads the font's `gasp` table at the size in pixels per em and shows when the matching range asks for gray-scale or symmetric smoothing; a font with no gasp table does not show it.
Ruling: S-17 Font weight: the member menu lists the family's upright faces by weight (Thin to Black). The regular member is stored as the family name (so the default draws as it always did); another member is stored as its PostScript name, and the renderer reads the weight from the installed face (`Renderer::resolve_weight`, FaceKey.weight). Bold is picked relative to the chosen weight, as `boldVersionOfFont:`. Italic faces are not listed (Allow italic text draws them).
Ruling: S-18 The Settings search indexes the schema rows' labels and sections and the Advanced pane's descriptions; the wells iTerm2 names after a neighbor are listed as "<text> color", as its search index does. Words match by prefix or by a small stem (ing, ed, es, s). Activating a result opens the pane and tab and frames the control for 1.6 s, whichever function draws it: the generic controls frame themselves, and the loops that draw rows with functions of their own frame the row (`RowFlash`; a key drawn with others is framed at the row that draws them, `settings_search::lead`). The list is under the field, not in a child window.
Ruling: S-19 Every Settings text and number field has iTerm2's field menu: "Reset to <default>" ("Reset to Empty Default") and a separator first while the value is not the default (`menuForEvent:` inserts them at the top), then the standard items that mean something on Windows: Cut, Copy and Paste. A chosen item reaches the field on the next frame as the input event egui's text edit takes. The standard menu's macOS services (Spelling and Grammar, Substitutions, Transformations, Speech, Writing Direction, Layout Orientation, AutoFill) are not offered. Sliders have no field editor and no menu.
Ruling: S-20 Bulk Copy copies each tab's schema rows (light and dark variants of the colors when the source keeps separate colors, `shouldAmendKey:`), and a key the source lacks is removed from the destination, as `copyAttributes:`. Hotkey keys are never copied (a second profile would claim the same hotkey window); iTerm2's per-tab key lists differ only by this.
Ruling: S-21 JSON import follows `importJSONProfiles:`: the files are tried in order, and a file that fails raises "Could not Import Profile" ("Import from <path> failed: <reason>") with OK, and Abort while more files follow; OK goes on, Abort (or closing the alert) stops. The alert is temporarily silenceable under NoSyncJSONImportFailed. Save shows the file in Explorer.
Ruling: S-22 Syntax Help (Smart Selection) and Search Syntax Help (profile search) open Termurion's help pages (smart-selection, search-syntax), not iterm2.com: the regular expression dialect is Rust's and the search syntax is Termurion's.
Ruling: S-23 The regular expression visualizer draws iTerm2's railroad diagram: `ICURegexToRailroadConverter` is ported (`regex_railroad`) and the diagram is drawn with the `railroad` crate (iTerm2 uses its own `railroad_dsl` library, whose source is not in the reference clone). iTerm2 shows it in a popover with a web view that the same button closes. (Merge with ui-w: Termurion now does the same, in the WebView2 popover the trigger editor uses (web_popover); the button reads "Open Regular Expression Visualizer" first, "Close Regular Expression Visualization" while the popover is open, then "Open Regular Expression Visualization". Without the web runtime the page is written to the temp folder and opened in the system browser.) An expression that does not compile shows iTerm2's "The regular expression could not be parsed."
Ruling: S-24 Every pane draws its controls in the order of iTerm2's xib, top to bottom and left to right (`scripts/order-schema.py` writes the schema's order from the positions in schema/ui_labels.toml; `ui_labels::rows_are_in_the_xibs_order` holds it). The profile tabs are one list with no section headings, as iTerm2's panes have none; the global pages keep their section headings (iTerm2 shows them as sub-tabs and boxes) with the rows in xib order. Rows iTerm2's xib does not draw stay next to the row they followed. The composites draw at their lead key's place (the font block at Font:, the size line at Columns:). Three older tests that held an order from earlier milestones were changed to the xib's order (Selection, Settings, Remap Modifiers). Mark Alert Action, Alert On Marks in Offscreen Sessions and findMode_iTerm are Stored rows: iTerm2 sets them from menus and no pane draws them.
Ruling: S-25 Parity rows: the existing rows that said "have" got notes, GPU rendering is n/a (S-6), and the rows for surfaces that had none are in 03 section 4 ("Settings window surfaces"; section 5 since the merge with ui-w, whose "Windows and alerts" section is 4); the counts sentence in the roadmap follows (02: 719 have, 90 n/a; 03: 681 have, 13 n/a).
Ruling: S-26 Colors tab: a grid of row headers (Defaults:, Cursor:, Bold:, Underlines:, Links:, Marks:, Faint text:, Minimum Contrast:, Search results:, Selection:, ANSI Colors:, Badge:, Tab:, Pane:) and the controls at their right, with the captions the xib draws (Background and Foreground under each pair of wells, Normal and Bright under the ANSI columns, Transparent and Opaque at the ends of the Faint text slider), under Modes:, Editing: and Color Preset:. The hue and chroma wheel at the right is Termurion's own and stays.
Ruling: S-27 Duplicate Profile names the copy "Copy of <name>" (`ProfilePreferences.CopyOf`) and, as `duplicateProfile:` does, makes it not the default, with no shortcut, no bound hosts and no hotkey window of its own (Has Hotkey off).
Ruling: S-28 Termurion's Settings window keeps these differences from iTerm2: the Python API method names (S-11), the pointer and key tables drawn by the pages' own code, and the macOS-only items of S-7 and S-9.
