Decision (Task 3, frame graph, security rule R13x3-1 class): the graph is built from Client-world messages whose body names ids, so two rules were added to browser_frames::Frames, one path, no second graph. (1) register: an id belongs to the frame that registered it until that frame is gone; another frame naming a taken id is refused (before, a later REGISTER_FRAME moved the id to whichever frame sent it). (2) EVAL_IN_FRAME: the sender id in the body must resolve to the frame the message came from (the host supplies Routed.frame); a body naming another frame as its sender is dropped. Targets stay lookups of registered ids (unknown gives null); ids reach scripts only JSON-encoded (js_string) and only as data compared against the registry. Pure test graph_ids_cannot_be_spoofed (RED before the change). Cost if wrong: an id re-registered by a legitimately new frame under the same id (the script draws a fresh random id per document, so none is expected) would be ignored until gone/navigation.
