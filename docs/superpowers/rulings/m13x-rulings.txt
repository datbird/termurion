Task 3 popovers
- CSP: popover HTML keeps script-src 'unsafe-inline'. iTerm2 runs popover script (the bridge is only useful when page script can call it); the bridge reaches only the built-in functions and the RPCs the page's own API script already has. Cost if wrong: HTML a script author injects into a popover can call those functions. Hardened: no network (CSP), no WebRTC (WEBRTC_OFF_JS runs first in every frame), no DNS prefetch (meta), no navigation, closed bridge message set, 20 calls per second.
- Popover source (P6): the bridge trusts the first source the view reports when it is a data: or an about:blank document, ignoring a #fragment; an about:blank first source may be replaced by one data: source; any other source ends the trust. The value a real runtime reports is printed by the ignored test popover_source_is_recorded (scripts/xt test --lib web_popover -- --ignored --nocapture, interactive session). Not recorded yet: EXTREME over SSH is session 0. Expected: data:text/html;charset=utf-8,... (Chromium reports the data URL it loaded); the code accepts about:blank as well. Checklist row: run the ignored test once in the desktop session and paste its RECORDED line here.
- A link a person clicks in a popover is refused by the view (Event::Refused) and opened only through guard_open (external_uri_run, user gesture only); Open in and the no-runtime Quick Look fallback use the same judge.
