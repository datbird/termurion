Flagged (Task 1, F1, security, latent bug in landed 12c): Ruling: pane ids restart at 1 every launch, so a chat linked to a decimal pane id, and any override stored under one, names a session of an earlier run. On the first chat_db() open of a run, before the overrides load, every chat whose terminal guid is a canonical decimal pane id is unlinked (row re-read, terminal guid None, no notice) and the entries keyed by a pane id are dropped from every row's stored permissions (so a fork of an old chat cannot carry them); load_overrides skips entries keyed by a pane id whatever a row holds. An imported chat's UUID guid is untouched. The 12c tests that stored a grant under guid "7" and expected it after a relaunch now use the non-pane guid "S-7". Cost if wrong: a previous launch's Always Allow silently applies to an unrelated session.
