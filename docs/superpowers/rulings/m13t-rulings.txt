Milestone 13t rulings (profiles and presets). Each line is `Ruling: ... - cost if wrong: ...`. Sections: pre-flight fixes B1 to B6, pre-flight rulings P1 to P23, rulings made while building, decisions from the task reports, final review fixes, deferred minors.

== Pre-flight fixes (accepted by the controller)
B1. Ruling: Bonjour profiles are kept out of the one serializer, not out of `save`: `Store.transient` (a set of guids filled only by `bonjour_ui`) is skipped by `Store::file_profiles`, so `save`, the remote-prefs drift snapshot and Export All all drop them; a profile tagged "bonjour" that arrives by import is an ordinary saved profile; a duplicate of a transient profile is saved without `Bonjour Service Address`; Set as Default is refused for one - cost if wrong: a LAN-advertised host reaches profiles.toml or an export, or settings drift fires on every discovery.
B2. Ruling: a hover preview returns the new `Edit::Preview`, which refreshes panes and redraws but never arms `save_due`, hotkeys or snippets; only a click returns `Edit::Changed`; `SettingsWindow` restores a live preview from its close path and from `save_pending_settings` - cost if wrong: about 0.9 s of hovering writes previewed colors to profiles.toml, and a crash leaves them there.
B3. Ruling: ONE `color_presets::sanitize` reads every preset (custom, find, names, duplicate check, API, Open Quickly): only the 58 color key names, finite components in 0..=1, space only sRGB, P3 or Calibrated, at most 256 custom presets, names of 1 to 64 clean characters; `.itermcolors` reads are bounded to 1 MiB, an XML dictionary root only, 32 files per pick - cost if wrong: a hostile file or an imported Custom Color Presets table costs unbounded memory or draws NaN colors.
B4. Ruling: bindable keys are exactly the schema's color and checkbox rows (and their Light and Dark variants) minus scrubbed keys, Guid, Name and the original guid; at most 32 bindings per profile read, 1024 characters per expression, one evaluation in flight per (pane, key), side effects off, 5 s timeout, no evaluation for a dead pane, entries removed with the pane; a binding's own answer never drops a palette-owned binding - cost if wrong: an imported profile can bind Command or a path key, or a program churning a user variable starts an evaluation per change.
B5. Ruling: an escape-code `SetColors=preset=NAME` resolves the preset for the pane's appearance into the 25 named colors plus the tab color and applies them through the baseline path (`apply_color` plus `color_sets`), so the end of the program restores the profile's colors; Underline, Cursor Guide and Badge are not touched by an escape preset; a pending preset is replaced by a newer one before the frame - cost if wrong: a program's preset would survive a restart as a profile value, or a looping program costs one load per sequence.
B6. Ruling: Edit Session follows the active session through the one focus funnel `App::refresh_route` (`follow_edit_session` compares the focused pane with `edit_follow_seen`), not through the 30 sites that assign focus; the target is cleared when its pane closes and `set_tmux_session` follows it - cost if wrong: Settings stays on a stale session or a closed pane's profile.

P5. Ruling: Bonjour hardening, all pure in `bonjour::profile_for`: the name and description are the service name with control, bidi and zero-width characters removed and cut to 128 chars (empty = refused), a duplicate name gets " (address)" appended; the address must parse as `std::net::IpAddr` and is formatted back from it (never the DNS text), or pass `ssh_url::hostname_ok`; the port is the u16; the user passes `user_is_safe` and is at most 64 chars; `ssh_path` is used only when `ssh_url::scheme_path_usable` and `resolve_program` finds it, else "ssh"; the prototype copy clears "Initial Text" (it would otherwise be typed into an unvetted LAN host at login) but keeps triggers; at most 128 live Bonjour profiles (newer ones ignored, logged once); "bonjour" tagged profiles are excluded from Open All and from multi-open (a rogue LAN host cannot fan out sessions); Found/Lost matching is by service name AND address - cost if wrong: a Bonjour host with an unusual name or an IPv6 link-local scope (needs "%scope", not in the DNS record) does not appear or does not connect.

== Final review fixes
Ruling (final 1): `bonjour::instance_label` tests the '.' byte before slicing, so a crafted PTR name (for example `X\u{e9}ssh._tcp.local`) cannot panic the worker; a fuzz test runs 20000 multi-byte and malformed names - cost if wrong: one LAN answer stops Bonjour for the run.
Ruling (final 1): every buffer handed to DnsServiceBrowse or DnsServiceResolve (the request structure, its name and the cancel handle) has one owner, `bonjour::Requests`; a request is freed only after its last callback marked `Ended` (the browse callback with ERROR_CANCELLED, as Microsoft documents for DnsServiceBrowseCancel; the resolve callback, which runs once); dropping the owner (stop, a failed start or spawn, an unwind) cancels every open request, waits up to 2 s and leaks what has not ended; callbacks catch panics and mark their end last; a completed resolve is never cancelled - cost if wrong: if Windows never calls a cancelled resolve back, cancelled resolves stay counted against the 32 in flight (discovery slows, memory stays bounded) and a stop waits 2 s and leaks a few hundred bytes per such resolve.
Ruling (final 3): the Profiles menu's rows and tree are built only when `profile_menu::generation` moves (the count, order and each profile's `menu_stamp`, renewed by `Profile::set` or `Profile::remove` of Name, Tags or Shortcut and by `Profile::from_values`); `sync_checks` still runs per output batch but then reads one number per profile and builds nothing - cost if wrong: a write that bypasses `Profile::set` (a direct `values.insert` of Name, Tags or Shortcut) leaves the menu stale until another menu-visible write.
