m13x6 rulings (browser permissions and notifications). Entries are appended as tasks land.

Task 1 review minors (security review of 4a114be):

R13x6-O1 (ports 80 and 443). iTerm2's origin string drops port 80 and 443 for ANY scheme
(BPM:260), and Tandem keeps that rule: `http://a.b:443` and `http://a.b` share one key, and so do
`https://a.b:80` and `https://a.b`. Two services on one host (same host, different one of these
two ports) therefore share saved grants. Accepted cost for parity; the host is the same machine
name. Dropping only the scheme's own default port is the stricter alternative and is Robert's call.

R13x6-O2 (punycode). Tandem's origin is always ASCII (`normalize_origin` refuses Unicode hosts).
The permission prompt, the bar, the menu and the permissions page show the normalized origin as it
is, with punycode (`xn--...`). They must never convert punycode to Unicode for display: that
would reopen homograph spoofing.

R13x6-O3 (authority). An authority containing a backslash is refused (None): the browser parses
`https://a.b\@evil.com/` as host `a.b`, a lax parser as `evil.com`. A trailing-dot host
(`example.com.`) is refused, not canonicalized, so it can only be denied and never shares a key
with `example.com`. Both are pinned by `backslash_and_trailing_dot_fail_closed`.

R13x6-T2 (the table). `BrowserPermissions` is the person's own data. No import, export, sync,
remote-prefs, it2 / API or dynamic-profile path reads or writes it (pinned by
`no_import_export_or_sync_path_names_the_table`). The schema is iTerm2's, so it has no Imported
column; because nothing can fill it but the person's own dialog answer, no row is an imported grant.
Readers skip any row that is not exactly a "granted" / "denied" decision of a known type with a
canonical origin of at most 300 bytes and finite dates; a corrupt file is set aside by
`Db::open` and replaced by an empty table (deny). The table holds at most 10,000 rows.

Task 5 review fixes (one permission-write queue, controller class ruling):

R13x6-T5a (one queue). Every profile permission write (a mirrored grant, the start-up sync's
plan, a revoke, a reset) and every read of the profile's states goes through one ordered queue per
WebView2 profile (`perm_queue::ProfileQueue`, one for Browser and one for Dev Null), one at a
time: the next starts only when `Event::PermissionWritten` (or `PermissionStates`) came back. A
revoke or reset starts a new generation: a queued write of the same entry from an older generation
is dropped and an answer waiting behind an older mirrored grant of it becomes a Deny. A failed
write is tried 3 times, then the pages using its origin reload and the sync reads again. The host
never writes the profile when it answers a request.

R13x6-T5b (sync). The start-up sync is done only when a COMPLETE read's plan has landed. An
incomplete read rewrites what it saw and reads again; a read whose view goes is asked again on
another view; 3 failed tries in a row give up (logged, a banner) until the next view of the store
or the next page the person opens. Until it is done, no page of that store loads (R13x6-T5c).

R13x6-T5c (first page). A browser pane's own load and a typed navigation wait, blank, until the
store's sync is done; the sync's end loads them. The setup's own about:blank check is not a page.

R13x6-T5d (Reset reloads). DEVIATION from iTerm2 (`BVC:1075-1079` only resets): the toolbar's
Reset of a Granted Camera, Microphone, Camera and Microphone or Location row reloads the pages
using the origin, after the reset landed, so a running stream or watchPosition stops. It follows
the ledger rule "revocation takes effect immediately for live pages". A Denied row reloads
nothing; a Notification reset reloads nothing (Tandem checks the table at each notification).

R13x6-T5e (sweep). Revoke reloads only after its profile resets were confirmed. The sweep's answer
over a cap (more than 256 origins, an entry over 2048 bytes) or of the wrong shape reloads the
whole pane (fail closed); only a FAILED script falls back to the main origin (iTerm2 `BM:576-583`).
iTerm2-equal limit, recorded: the sweep sees the top document's iframes and resource entries
only, so a revoked origin in a nested iframe (Y embeds Z embeds X), or an iframe navigated after
creation, is not found (task 5 review minor 5).

R13x6-T5f (ruling A wording). Ruling A's "Deny never saved" covers ANSWERS only: the start-up
sync writes a Denied row back as profile Deny (state 2), which matches the table.

Task 6 review fixes (web notifications):

R13x6-T6a (close only itself). A page's close of its notification, and its navigation, clear the
balloon only while `notify::shown_count()` is still the count recorded right after that
notification was shown (`notify::clear_if_shown`); anything shown since, by any caller, is never
the page's to clear. The page is still told its notification closed.

R13x6-T6b (origin label). The origin a notification and a permission question show always keeps
the END of the host and the port: a long host is cut from the left after the scheme, behind an
ellipsis (`origin_label`), as Chromium shows origins. Page text cut to its cap ends with an
ellipsis; zero-width and bidi characters are dropped.

R13x6-T6c (master switch). Web notifications of a granted site are shown even when the profile's
"Notification Center alerts" switch is off (only "suppress alerts in the active session" holds
them): the person granted that site directly. Recorded for Robert; the stricter choice (the
switch also silences sites) is his call.

Ruling R13x6-T8a (Task 8 review gap, recorded after the fact): the toolbar menu shows no icons for the per-site Reset items or Unmute (text only, as the shared menu does for every browser item), so no page-controlled image can appear in it. Cost if wrong: a person looking for a camera glyph reads the word instead.
Ruling R13x6-T8b (Task 8 review gap): the menu's origin line shows the normalized (punycode) origin with hidden characters dropped and the END of a long host kept (browser_perms::menu_origin_line, origin_label), never the page's title or a Unicode host, so the person sees which site the Reset items change. Cost if wrong: a very long host shows with a leading ellipsis.
Ruling R13x6-T9a (Task 9, pre-flight B5): iterm2-about:permissions is a local page served through browser_pages::route and document (nonce CSP with frame-ancestors 'none', replies through the guarded script() that runs only while the pane is still on the page). The two copied files stay byte-identical on disk; five inline onclick handlers and the bare script tag are adapted by exact-once fail-closed load-time patches (HTML_PATCHES, JS_PATCHES) and one Tandem-owned delegated listener that ignores untrusted clicks and reads origin and type from attributes the page set with setAttribute. Revoke, Revoke All and Clear All are typed route replies (Reply::Permission) applied by permission_page_op through the one write queue, only when the pane's own main-frame URL (not the message) is exactly iterm2-about:permissions. Cost if wrong: the host cannot tell a real click from a made-up one (isTrusted is checked in the page; the page is Tandem's own and runs no foreign script under the CSP).
Ruling R13x6-T5g (gate re-review r3, Important): the sync gate runs AFTER nav_verdict (a refused navigation is never parked) and parks only a web page (http or https) or Tandem's own load; file:, iterm2-file:, iterm2-ssh:, data: and any other scheme is cancelled and forgotten. The Parked event carries how the handler judged the navigation (user, redirect, source, by_tandem, history); on release a page's target is judged again with that and its original initiator (browser_restore::parked_load) and is never loaded as Tandem's own. A page's navigation never replaces a target the person is waiting for. Minors: toolbar Reload keeps the page and lets the handler park it (reload_browser_view_by_person; the revoke path still blanks); only a person's act (user, Tandem's own, a history step) restarts a given-up sync; a URL over the cap is cancelled, never parked truncated; iterm2-about: pages are not gated. Cost if wrong: while a sync has given up, a page's own non-web navigation does nothing instead of waiting.

Ruling R13x6-T10a (Task 10, pre-flight B6): there is ONE indicator list, scene::session_indicators (IndicatorKind, IndicatorFacts, in iTerm2's IH:302-321 order), shared by the terminal corner (scene::indicators delegates) and the browser toolbar. No browser_indicators module, no second ORDER, glyph or help table. The strip is part of browser::Geometry (strip, status, status_n; geometry_status, strip_width, place) and browser::hit answers Hit::Status(n); the URL field takes the room left from the same function. The help popover reuses the one text_popover field (open_text_popover_at takes an explicit anchor); pane_gone already drops it. Every fact is Tandem's own state (zoomed tab, broadcast model, marks.alert_next, copy mode, dlog, pin, chat links, show_remembered, disableTopRightIndicators), never a page message, so a page can neither fake nor hide an indicator; a click opens only the help text.
Cost: terminal panes get the same list but are fed only the facts they had (maximized, copy mode, alert-next and remembered-alerts are not yet fed to terminal corners; the glyph/kind/help are ready). The AI help in a browser pane is plain text (links not followed), as the Decision says; the identifier tooltip is not drawn on hover (identifier() exists). Too many indicators are clipped, not scrolled.
Ruling R13x6-T10b (not modeled, each with its reason, review I7): Coprocess for browser panes (no pty; the kind exists for terminals), AllOutputSuppressed (no terminal output), ZoomedIn and Filter (terminal text views only), SecureKeyboardEntry_User and _Forced (macOS only), Channel and BufferingInput (terminal channels, trigger input buffering), ScreenshotMode (terminal lines). The broadcast pair is modeled because 13x2 Task 8 makes browser panes broadcast sources and targets.

Plan decisions (Task 11 records every Decision of the plan; ids D1 to D22; a later ruling above that changed one is named in it):

Ruling R13x6-D1 (native WebView2, no polyfills): permissions, notifications, geolocation and muting use WebView2's native support (PermissionRequested, NotificationReceived, IsMuted, IsDocumentPlayingAudio), not ports of iTerm2's Polyfills/ and AudioMuting/ scripts. None of those scripts is copied. Cost if wrong: geolocation error texts and the Notification object's fine behavior are Chromium's, not iTerm2's polyfill's; the whole page mutes instead of the frames that played.
Ruling R13x6-D2 (Tandem's database decides): the BrowserPermissions table is the only source of truth. WebView2 holds a decision only where a page reads it synchronously (notifications and location, kinds 4 and 3). SUPERSEDED in detail by R13x6-T5a and rulings A and B below: the host sets SavesInProfile false on every answer and a saved Allow of kind 3 or 4 is mirrored with SetPermissionState before the request completes; Deny is never written by an answer; revocation, reset and the start-up sync go through the one write queue. Cost if wrong: one sync per start; a mirror failure is retried 3 times, then the pages reload and the sync reads again.
Ruling R13x6-D3 (camera and microphone never mirrored): each media request is answered from the database by exact type, as iTerm2 (BPM:27). Cost if wrong: none known; WebView2 raises a request per getUserMedia call and Tandem answers it without a dialog.
Ruling R13x6-D4 (kinds nobody decides): SUPERSEDED. The plan completed untouched the kinds iTerm2 never asks about (clipboard read, sensors, downloads, file access, autoplay, fonts, MIDI, window management) so WebView2's own prompt would show. Task 1 review ruled: every kind except 1 to 4 is Deny (route_kind is total, answer_for allows only a saved Granted), the host denies them (unasked_kinds_are_denied_by_the_host) and every start-up read resets legacy grants of kinds 0 and 5 to 12 (0c4012a). Tool, popover and Quick Look views also get Deny. Cost if wrong: clipboard-read Paste buttons and repeat automatic downloads fail where iTerm2 asks (FLAG FOR ROBERT below); no WebView2 prompt ever shows.
Ruling R13x6-D5 (opaque requesters): data:, about:, javascript:, file:, a URL with no authority or a malformed scheme are denied with no dialog and no saving; blob: uses its inner origin; IPv6 hosts keep their brackets. Cost if wrong: a local HTML file cannot get notifications or location (iTerm2 would ask once for all file:// pages together).
Ruling R13x6-D6 (one media question): camera and microphone requests of one origin drained in one tick become one Camera and Microphone question. Cost if wrong: requests split across ticks ask twice (each saved separately).
Ruling R13x6-D7 (closed alert blocks): a closed permission alert window, or one that never shows, blocks the request without saving (R13x67-1): scripts_alerts::Answer::Closed is routed only for Then::BrowserPermission, because 13b's default close answer presses Cancel or else the first button, which here is Allow. Cost if wrong: none known (iTerm2's modal alert cannot be closed without a button).
Ruling R13x6-D8 (kinds iTerm2 never asks): see D4 (superseded). The start-up sync never resets kinds 1 to 4 that the table holds; it resets the rest (D4).
Ruling R13x6-D9 (tool views): requests from tool, popover and Quick Look views are denied (D4). Cost if wrong: none; iTerm2's factory views have no permission manager.
Ruling R13x6-D10 (system switches): the Windows privacy switches (notifications ToastEnabled, location ConsentStore, HKLM, HKCU and NonPackaged) are read from the registry and never prompted; a Deny in any location key means denied. Cost if wrong: a policy-managed machine that sets them elsewhere is read as allowed.
Ruling R13x6-D11 (pre-muting): every new document of an origin that is not allowed starts muted, an allowed one is unmuted (a redirect re-evaluates on its target without resetting the once answers); a play event from a granted origin while muted unmutes. Task 7 review: audio muted until allowed is iTerm2's default, no flag. Cost if wrong: none audible; iTerm2 could let the first moment of sound through.
Ruling R13x6-D12 (Allow Always): saves the row wherever the pane has navigated since (as iTerm2) but unmutes only when the pane still shows the origin asked about, because Tandem mutes the whole view. Cost if wrong: none known.
Ruling R13x6-D13 (audio asks again): every play event from an undecided origin asks again, as iTerm2; 13x2's browser_announce keeps one bar per identifier and answers a duplicate as closed. Cost if wrong: none.
Ruling R13x6-D14 (empty body): a web notification without a body shows its origin as the body (an empty balloon body removes the balloon). Cost if wrong: a line of text iTerm2 does not show.
Ruling R13x6-D15 (one balloon): web notifications use Tandem's one tray balloon; a click reveals the browser pane and nothing else; the page's close clears the balloon only when it is the one on screen (R13x6-T6a). Cost if wrong: no stacking of several web notifications.
Ruling R13x6-D16 (quoting): the permissions page's reply scripts quote arguments as JSON strings (iTerm2 escapes only the apostrophe). Cost if wrong: none.
Ruling R13x6-D17 (offset past the end): an offset past the end of the permission list answers an empty page (iTerm2 would crash). Cost if wrong: none.
Ruling R13x6-D18 (site menu): the site items are spliced before Settings instead of changing browser::menu_items' signature, with no icons (R13x6-T8a). Cost if wrong: a second builder to keep in iTerm2's order.
Ruling R13x6-D19 (help popover): the indicator help popover is 360 by 80 points with the help text, links reduced to labels (R13x6-T10a). Cost if wrong: iTerm2's clickable help links (Unlink from AI Chat, Reveal AI Chat, Stop sending) are not clickable.
Ruling R13x6-D20 (which indicators): the toolbar shows every indicator iTerm2 feeds a browser session that Tandem can compute; the rest never apply (R13x6-T10b). Too many are clipped, not scrolled. Cost if wrong: no horizontal scrolling of an overflowing strip.
Ruling R13x6-D21 (copied files): the two permissions page files stay in resources/browser/ with their headers and iTerm2's GPL-2.0 text beside them (ruling Q5 as amended), PROVISIONAL pending Robert. Cost if wrong: rewriting the two files before a public release.
Ruling R13x6-D22 (pitfall rules kept): GetDeferral is taken and returned at once; a view closed with a pending request completes it with Default; SetPermissionState and GetNonDefaultPermissionSettings are never waited on inside a winit callback; Dev Null panes use BrowserDevNull and the in-memory table and are never mirrored into the Browser profile; origins in the registry, URLs and scripts are data (bound parameters, JSON quoting). Cost if wrong: a leaked request, a frozen window or a cross-profile grant.

Per-task rulings not recorded above:

Ruling R13x6-T1a (Task 1 review): the vocabulary denies every kind except 1 to 4 and answers Allow only for a saved Granted row. Differs from iTerm2 for clipboard read and multiple automatic downloads (FLAGS). Cost if wrong: see the flags.
Ruling R13x6-T3a (Task 3 review): every answer sets SavesInProfile false, so a host refusal can never persist a Deny in the profile for another site; a profile read says whether it was complete (PermissionStates.complete) and posts on every failure path; kind 4 is denied at the host when the runtime lacks ICoreWebView2_24, so WebView2's own toast never bypasses the origin label. Cost if wrong: an old runtime gets no web notifications.
Ruling R13x6-T4a (the prompt): the permission window ignores input for 1 s after it opens and after each refocus; Enter, Escape and Space press nothing; no button is default; only a pointer release or an Alt key (after arming) answers. One prompt per pane, 4 queued per pane, 32 in all, excess denied; a failed save (table full) denies, never grants; a stale navigation epoch denies; an iframe asks "<frame origin> on <top origin>" but the row is keyed by the frame origin alone (iTerm2's key), so a grant to X answers X embedded anywhere. Cost if wrong: an embedded origin's grant is wider than its question read.
Ruling R13x6-RA (ruling A, Task 5): the host keeps SetSavesInProfile false; a saved Allow of kind 3 or 4 is mirrored with SetPermissionState and the request completes from that completion handler; a Deny is never written by an answer (R13x6-T5f). Cost if wrong: if the profile ever refuses the write, the page is asked again.
Ruling R13x6-RB (ruling B, Task 5): a prompt that was closed or dropped denies quietly for 60 s per (pane, origin, type, Dev Null) with nothing saved; a hidden pane's request waits in the bounded queue and is asked when the pane is shown; navigation, pane close or dismissal denies stale waiters and withdraws a question nobody waits on; a late Allow saves nothing. Cost if wrong: a person who closed a prompt by mistake waits 60 s or reloads.
Ruling R13x6-RC (ruling C, Task 5): a saved answer with saves is honored; an origin cut at the length cap makes a read incomplete; one question per (pane, origin). Cost if wrong: none known.
Ruling R13x6-T7a (Task 7 decisions): an opaque origin that cannot be keyed is muted on play with no question (only "Unmute Current Page" is left); Allow Always unmutes by origin match, Allow Once by document epoch plus URL; Back and Forward while the store is unsynced park the current URL, not the history target (superseded by R13x6-T5g, which parks the target). Cost if wrong: a rare path lands on the current page after the sync.
Ruling R13x6-SW (final review M5, service-worker notifications): a second path exists. WebView2 raises ICoreWebView2_24 NotificationReceived for non-persistent notifications only (Microsoft's reference: "for non-persistent notifications"); a persistent one (ServiceWorkerRegistration.showNotification, from the worker or the page) goes to a profile-level NotificationReceived (ICoreWebView2Profile, in the Web Notification API spec, absent from webview2-com 0.39.1) and, unhandled, to WebView2's own default toast, past Tandem's origin label, limits, master switch and table (the mirrored Allow of ruling A grants it). It cannot be routed to post_alert with this SDK, so it is denied, fail closed: every browser view adds a WebResourceRequested filter for COREWEBVIEW2_WEB_RESOURCE_REQUEST_SOURCE_KINDS_SERVICE_WORKER (ICoreWebView2_22) and answers 403 to any request a service worker makes and to any request carrying a Service-Worker header (the worker script fetch), so no service worker installs or runs (webhost::refuse_worker_request); the app's own request handler never sees such a request. Notifications are offered (kind 4 asked) only when both NotificationReceived and that refusal are in place (webhost::notifications_offered), else kind 4 is denied at the host. Probe: service_worker_notifications_are_refused (unrun: a granted origin's register() is refused, no registration, no notification, the script never reached the server). Cost if wrong: sites lose service workers (offline pages, push; push already fails in WebView2, WebView2Feedback #5051); iTerm2's WKWebView is believed to run none either (no web-browser entitlement found in iTerm2's source, unverified). If the probe shows the script fetch is not raised with the SERVICE_WORKER kind, the fallback is to deny kind 4 outright. Residual: a runtime with ICoreWebView2_24 but a failed filter add still has the start-up sync mirror table grants for kind 4 (no such runtime is known: _22 predates _24).

FLAGS FOR ROBERT (decisions that differ from iTerm2 or that only he can make):
1. Clipboard read is always denied. Pages' own Paste buttons that call navigator.clipboard.readText() fail (iTerm2 asks). Ctrl+V into the page still works.
2. Repeat automatic downloads (a page saving several files without a click each) are blocked, where iTerm2 would ask.
3. Reset of a Granted camera, microphone, camera and microphone or location row reloads the pages using the origin (iTerm2 only deletes the row; R13x6-T5d), so a running stream or watchPosition stops at once.
4. A web page can open iterm2-about:permissions as a top-level page (iTerm2 allows it). The page can only show and remove grants, and removing needs a trusted click. Stricter alternative: refuse a non-user, non-Tandem top-level navigation to iterm2-about: other than welcome.
5. Audio is muted until the site is allowed (iTerm2's default too, Task 7 review); the whole page is muted, not the frames that played.
6. WebView2 never stores a decision on its own: only Tandem's table decides; the profile holds a mirrored Allow for notifications and location and is rewritten from the table at each start.
7. Service workers never run in a browser pane (R13x6-SW): a site's offline mode, background sync and service-worker notifications do not work. This closes WebView2's own toast for persistent notifications, which Tandem cannot intercept with this SDK.
8.
