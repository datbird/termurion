m13x6 rulings (browser permissions and notifications). Entries are appended as tasks land.

Task 1 review minors (security review of 4a114be):

R13x6-O1 (ports 80 and 443). iTerm2's origin string drops port 80 and 443 for ANY scheme
(BPM:260), and Tandem keeps that rule: `http://a.b:443` and `http://a.b` share one key, and so do
`https://a.b:80` and `https://a.b`. Two services on one host (same host, different one of these
two ports) therefore share saved grants. Accepted cost for parity; the host is the same machine
name. Dropping only the scheme's own default port is the stricter alternative and is Robert's call.

R13x6-O2 (punycode). Tandem's origin is always ASCII (`normalize_origin` refuses Unicode hosts).
The permission prompt, the bar, the menu and the permissions page show the normalized origin as it
is, with punycode (`xn--...`). They must never convert punycode to Unicode for display: that
would reopen homograph spoofing.

R13x6-O3 (authority). An authority containing a backslash is refused (None): the browser parses
`https://a.b\@evil.com/` as host `a.b`, a lax parser as `evil.com`. A trailing-dot host
(`example.com.`) is refused, not canonicalized, so it can only be denied and never shares a key
with `example.com`. Both are pinned by `backslash_and_trailing_dot_fail_closed`.

R13x6-T2 (the table). `BrowserPermissions` is the person's own data. No import, export, sync,
remote-prefs, it2 / API or dynamic-profile path reads or writes it (pinned by
`no_import_export_or_sync_path_names_the_table`). The schema is iTerm2's, so it has no Imported
column; because nothing can fill it but the person's own dialog answer, no row is an imported grant.
Readers skip any row that is not exactly a "granted" / "denied" decision of a known type with a
canonical origin of at most 300 bytes and finite dates; a corrupt file is set aside by
`Db::open` and replaced by an empty table (deny). The table holds at most 10,000 rows.

Task 5 review fixes (one permission-write queue, controller class ruling):

R13x6-T5a (one queue). Every profile permission write (a mirrored grant, the start-up sync's
plan, a revoke, a reset) and every read of the profile's states goes through one ordered queue per
WebView2 profile (`perm_queue::ProfileQueue`, one for Browser and one for Dev Null), one at a
time: the next starts only when `Event::PermissionWritten` (or `PermissionStates`) came back. A
revoke or reset starts a new generation: a queued write of the same entry from an older generation
is dropped and an answer waiting behind an older mirrored grant of it becomes a Deny. A failed
write is tried 3 times, then the pages using its origin reload and the sync reads again. The host
never writes the profile when it answers a request.

R13x6-T5b (sync). The start-up sync is done only when a COMPLETE read's plan has landed. An
incomplete read rewrites what it saw and reads again; a read whose view goes is asked again on
another view; 3 failed tries in a row give up (logged, a banner) until the next view of the store
or the next page the person opens. Until it is done, no page of that store loads (R13x6-T5c).

R13x6-T5c (first page). A browser pane's own load and a typed navigation wait, blank, until the
store's sync is done; the sync's end loads them. The setup's own about:blank check is not a page.

R13x6-T5d (Reset reloads). DEVIATION from iTerm2 (`BVC:1075-1079` only resets): the toolbar's
Reset of a Granted Camera, Microphone, Camera and Microphone or Location row reloads the pages
using the origin, after the reset landed, so a running stream or watchPosition stops. It follows
the ledger rule "revocation takes effect immediately for live pages". A Denied row reloads
nothing; a Notification reset reloads nothing (Tandem checks the table at each notification).

R13x6-T5e (sweep). Revoke reloads only after its profile resets were confirmed. The sweep's answer
over a cap (more than 256 origins, an entry over 2048 bytes) or of the wrong shape reloads the
whole pane (fail closed); only a FAILED script falls back to the main origin (iTerm2 `BM:576-583`).
iTerm2-equal limit, recorded: the sweep sees the top document's iframes and resource entries
only, so a revoked origin in a nested iframe (Y embeds Z embeds X), or an iframe navigated after
creation, is not found (task 5 review minor 5).

R13x6-T5f (ruling A wording). Ruling A's "Deny never saved" covers ANSWERS only: the start-up
sync writes a Denied row back as profile Deny (state 2), which matches the table.

Task 6 review fixes (web notifications):

R13x6-T6a (close only itself). A page's close of its notification, and its navigation, clear the
balloon only while `notify::shown_count()` is still the count recorded right after that
notification was shown (`notify::clear_if_shown`); anything shown since, by any caller, is never
the page's to clear. The page is still told its notification closed.

R13x6-T6b (origin label). The origin a notification and a permission question show always keeps
the END of the host and the port: a long host is cut from the left after the scheme, behind an
ellipsis (`origin_label`), as Chromium shows origins. Page text cut to its cap ends with an
ellipsis; zero-width and bidi characters are dropped.

R13x6-T6c (master switch). Web notifications of a granted site are shown even when the profile's
"Notification Center alerts" switch is off (only "suppress alerts in the active session" holds
them): the person granted that site directly. Recorded for Robert; the stricter choice (the
switch also silences sites) is his call.

Ruling R13x6-T8a (Task 8 review gap, recorded after the fact): the toolbar menu shows no icons for the per-site Reset items or Unmute (text only, as the shared menu does for every browser item), so no page-controlled image can appear in it. Cost if wrong: a person looking for a camera glyph reads the word instead.
Ruling R13x6-T8b (Task 8 review gap): the menu's origin line shows the normalized (punycode) origin with hidden characters dropped and the END of a long host kept (browser_perms::menu_origin_line, origin_label), never the page's title or a Unicode host, so the person sees which site the Reset items change. Cost if wrong: a very long host shows with a leading ellipsis.
Ruling R13x6-T9a (Task 9, pre-flight B5): iterm2-about:permissions is a local page served through browser_pages::route and document (nonce CSP with frame-ancestors 'none', replies through the guarded script() that runs only while the pane is still on the page). The two copied files stay byte-identical on disk; five inline onclick handlers and the bare script tag are adapted by exact-once fail-closed load-time patches (HTML_PATCHES, JS_PATCHES) and one Tandem-owned delegated listener that ignores untrusted clicks and reads origin and type from attributes the page set with setAttribute. Revoke, Revoke All and Clear All are typed route replies (Reply::Permission) applied by permission_page_op through the one write queue, only when the pane's own main-frame URL (not the message) is exactly iterm2-about:permissions. Cost if wrong: the host cannot tell a real click from a made-up one (isTrusted is checked in the page; the page is Tandem's own and runs no foreign script under the CSP).
Ruling R13x6-T5g (gate re-review r3, Important): the sync gate runs AFTER nav_verdict (a refused navigation is never parked) and parks only a web page (http or https) or Tandem's own load; file:, iterm2-file:, iterm2-ssh:, data: and any other scheme is cancelled and forgotten. The Parked event carries how the handler judged the navigation (user, redirect, source, by_tandem, history); on release a page's target is judged again with that and its original initiator (browser_restore::parked_load) and is never loaded as Tandem's own. A page's navigation never replaces a target the person is waiting for. Minors: toolbar Reload keeps the page and lets the handler park it (reload_browser_view_by_person; the revoke path still blanks); only a person's act (user, Tandem's own, a history step) restarts a given-up sync; a URL over the cap is cancelled, never parked truncated; iterm2-about: pages are not gated. Cost if wrong: while a sync has given up, a page's own non-web navigation does nothing instead of waiting.
