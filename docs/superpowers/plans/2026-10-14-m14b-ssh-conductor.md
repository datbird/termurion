### Decisions (each goes in `m14b-rulings.txt`)

- A timeout on every conductor command written before framing: 30 s from the write or the command's last begin/line; expiry fails setup with Tandem's text. Once framing, only commands whose `timed_when_framed()` is true keep it (14d's file commands except `file zip`), ruling M14-I2: a sleeping laptop must not end SSH integration. Cost: a remote slower than 30 s per setup step fails where iTerm2 would wait; a framed command the remote never answers (other than a file command) waits until the connection ends.
- OSC payloads decode as UTF-8 lossy. Cost: none known; iTerm2 shows mojibake for a non-ASCII home and writes a wrong ZDOTDIR (controller question).
- A rejected SSH_INIT and every abort unhook the DCS parser. Cost: none; iTerm2 swallows output there (controller question).
- No local tilde expansion in ssh arguments. Cost: none; iTerm2's expansion sends a local path to the remote (controller question).
- Files to Copy payloads are sent by 14b (the hook adds them, the startup writes them): the machinery is the injection's (ruling 14b-5). Cost: none.
- `Effect::SendInitialText` does nothing: Tandem sends no Initial Text anywhere yet (14a Resume notes); the arm in `ssh_apply` is where it goes when Initial Text exists (controller ruling pending: which milestone sends Initial Text). Cost: a profile's Initial Text is not typed after SSH setup, as it is not typed in any Tandem session.
- `vars_to_send` keeps the configured order of Environment Variables to Copy; a name stored twice by Env gives its last value (iTerm2 builds a dictionary, `VT100Screen.m:1941-1949`). Cost: none.
- `fail`'s raw `exec_login_shell` line is an `Effect::SessionWrite`, held like typing while writes queue (iTerm2's `conductorWrite` outside `write()`), and an abort drops the held bytes (iTerm2 strands them). Cost: typing made during a failed setup is not sent.
- An interrupted OSC in ground restarts at the new ESC (iTerm2 bug B14 fixed). Cost: none.
- A setup stalled in ground (B5, B6) fails 30 s after its last activity, like a stalled command. Cost: a remote that pauses more than 30 s between a command's end and its next output fails.
- Python 3.7 or later: `python_ok` set and level 1 until 14c Task 1 adds execFramer. Cost: none; the person gets a working shell.
- The saved state is the remote host (user, host) and cwd; `resetForSSH` is `Screen::soft_reset`; modes are not restored at unhook. Cost: modes the local shell set before ssh (bracketed paste, mouse) are not restored when ssh ends; shells set them again at each prompt.
- The hook matches the literal 7-bit `ESC P 2000 p` (the m8a precedent). Cost: an 8-bit DCS start is output.
- Environment variables to copy go out in the configured order; injected variables after them in the injector's order; IT2_BASH_INJECT words in a fixed order. Cost: none (iTerm2's order is arbitrary).
- The ssh_config reader handles Host and HostName only, first match, with `%h`. Cost: Match blocks and Include are ignored for the identity's hostname.
- A repeated `-l` or `-p` keeps the first. Cost: iTerm2 picks one at random.
- The conductor's own writes go straight to the pty, not through Buffer Input. Cost: with Buffer Input on, iTerm2 would hold the conductor too and setup would stall.
- Buffer Input holds typing before the held-write rule (iTerm2 checks the rule first). Cost: typed bytes released from Buffer Input after the unhook go direct, in the same order.
- Coprocess output goes to `conductor.send_keys` while the pane has a conductor (`PK:354-361`, `PS:4639-4642`), so it is held during setup and framed at level 2 (14c). Cost: none (parity).
- The abort text is printed with `print_message` (default colors), iTerm2 appends at the cursor in the current colors. Cost: a different color.
- The recorder scrubs user, host and temp path from recordings. Cost: none.
- Parity rows are found by title.

### Pitfalls for the implementer

- `Pane::pump` borrows `self.pty` across the read loop; collect the chunks first, then route them, or the new `route_output` cannot take `&mut self`.
- The ssh hook must see every byte before `dropping` (Suppress All Output, a muted coprocess), as the tmux hook does, or a muted pane never leaves setup.
- `ssh_pump` runs before `tmux_pump`: output released by the conductor can start tmux control mode.
- Never write a command while a handler runs: `send` inside a transition only enqueues. Tests in Tasks 5 and 6 pin the order; a direct `write` from a handler breaks it (except WriteOnSuccess's `write()` of the code, which is data, as iTerm2).
- `Effect::Write` is never held; `Effect::SessionWrite` is held while writes queue; `Effect::Keys` always goes through `write_session`. Mixing them loses or reorders typing.
- The hop chain (14a's `PaneSsh::chain`) must stay in step with the conductor chain: push in `ssh_hooked`, pop through `ssh_unhook_conductor`; only EndSSH pops conductors without popping hops, because 14a's `end_ssh` already ended them.
- The line prefix, the origin token and environment values are secrets in practice: no `eprintln!`, no log line, no banner.
- `resources/ssh/**` and `tests/fixtures/ssh/*` must keep their bytes: check `.gitattributes` before committing and run `embedded_files_are_iterm2s`.
- The recordings are made on sirtoolio, never on EXTREME, and never against a host; commit the `.bin`, `.in.bin` and `payload.tgz` files with the task.
- `TarJob`'s "/" arithmetic is iTerm2's; port it as written and let the three grouping tests decide.
- `soft_reset` feeds sequences whose replies go to `Screen::replies`; call it before the conductor starts so its replies are not held behind setup.
