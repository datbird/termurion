# P2 macOS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Termurion on macOS is a real Mac app: the native menu bar, the real Cmd key, the hotkey window, notifications, the Keychain with a Touch ID gate, an ad hoc signed `Termurion.app`, and Import from iTerm2 reading iTerm2's live settings, with Windows behavior unchanged. Exit: the owner runs the `.app` on their own Mac.

**Architecture:** The P0 and P1 facades stay. Where macOS has its own backend, the facade picks `platform::macos::<facility>` on macOS and keeps `platform::unix::<facility>` on Linux; a macOS module re-exports what it shares with the Unix one instead of copying it. AppKit is reached through `muda` (menus), `global-hotkey` (Carbon hotkeys) and the `objc2` 0.6 crates already in `Cargo.lock` (through muda); the few delegate and view methods winit 0.30 lacks are added to winit's own classes at run time. The app keeps one key path on every OS: Cmd chords reach winit and go through `shortcut_chord`, so a key mapping beats a menu command as in iTerm2.

**Tech Stack:** Rust 2024, winit 0.30.13, muda 0.20, objc2 0.6 with objc2-foundation 0.3, objc2-app-kit 0.3, objc2-user-notifications 0.3, objc2-local-authentication 0.3, block2 0.6, global-hotkey (the release on the objc2 0.6 line), security-framework (the Keychain), core-foundation-sys 0.8.7 (already a dependency), libc 0.2.

**Spec:** `docs/superpowers/specs/2026-10-31-macos-linux-port-design.md` (binding). Conventions follow `docs/superpowers/plans/2026-11-02-p1-unix-core.md`. Parked items come from `.superpowers/sdd/2026-11-02-p1-unix-core/progress.md`, `final-review.md`, `final-rereview.md` and `final-fix-report.md`. Test status by cause: `docs/port/unix-test-gaps.md`. iTerm2 source for exact wording and behavior: `~/gitrepos/iterm2-ref`.

## Global Constraints

- "Windows behavior unchanged. Every step keeps the Windows build and its tests green." Every task ends with `scripts/win-check` at `windows: 0 errors` and no new warning (the two `fetch_update` deprecations in `session_log.rs` are known). `scripts/xt test --lib` is ON HOLD: each task names its xt step, and it runs only when the owner clears the hold (then full PASS; the known flakes `find::tests::find_over_a_large_buffer_is_quick` and `host::tests::host_launches_and_echoes` may be rerun once). A Windows value is never changed to make macOS work: a platform constant or facade carries the difference.
- "No second copy of any logic. If Mac and Linux need the same thing, it lives once in `platform/unix`." A macOS module re-exports the shared Unix functions (`pub use super::super::unix::chrome::{set_border, ...};`), it never copies them. Linux behavior is unchanged in P2: every Linux check that passed at 380cff24 passes after each task.
- "No `#[cfg(windows)]` sprinkled through `app/`." A cfg lives only in `src/platform/`, `src/lib.rs`, `src/bin/`, `Cargo.toml`, `*_win.rs`, or a `scripts/cfg-audit.allow` entry; `scripts/cfg-audit` exits 0 after every task. App code asks a platform constant or facade (`CMD_IS_A_KEY`, `NATIVE_ACCELERATORS`, `FILE_MANAGER`).
- Unix code never claims success for something it did not do: a missing facility returns `platform::Unsupported`, never a silent `Ok`. The one allowed no-op class is a call with no meaning on that OS, with a doc comment saying why.
- AppKit is called only on the main thread: each macOS entry point takes `objc2::MainThreadMarker::new()` and returns an error (never panics) when it is None. Nothing blocks the UI thread except where the Windows backend already blocks it (the password manager's authentication).
- Menu item names and labels match iTerm2's exact wording where an equivalent exists (`schema/menus.toml` is generated from iTerm2's `MainMenu.xib`; texts are checked against `~/gitrepos/iterm2-ref`).
- Cmd is the real Cmd key on macOS. No Win key (Super) chord runs a Termurion action on Windows or Linux, tests and scripts included.
- Every new process spawn, URL or file open, or fetch funnel gets a `SINKS` token, a `NOT_PANE_TEXT` entry and a planted case in `src/app/semantic_ui.rs`. `dlog!` arguments are `LogSafe`; any task that adds or moves a `dlog!` updates `dlog::CALL_SITES`.
- New dependencies go under `[target.'cfg(target_os = "macos")'.dependencies]` with only the features used; `cargo tree --target aarch64-apple-darwin -d` shows no third `objc2` line (winit's 0.5 and muda's 0.6 only); `licenses::tests::every_dependency_is_listed` passes on macOS.
- Builds: Linux with `~/.cargo/bin/cargo`; macOS on `ssh funtimes` (arm64) through `scripts/check-unix` and `scripts/mac-dev-app`; Windows type check through `scripts/win-check`. Every task checks both Unix hosts.
- VM hand checks (`funtimes-ui`): back up `~/Library/Application Support/Termurion` first and restore it after; target only the Termurion window (`funtimes-ui front` before typing); never press Esc or Cmd-Q while Messages is in front; end with `ssh funtimes 'pgrep -lx termurion; pgrep -lx termurion-host'` empty for this run. `funtimes-ui` sends key code 0 for letters (the right character, the wrong key code), and its Ctrl+Shift chords never match; the menu bar and clicks work.
- Short human comments, no em dashes or emoji anywhere, commits with no host or user names and no attribution lines, work on `main`, do not push. Commit messages start `Port P2: `.

## Decisions (the spec's open calls and the gaps it leaves)

1. **Session host on macOS: no launchd agent (call).** The host stays P1's detached `setsid` process at the same private socket. It already reopens Termurion, survives a crash and refreshes its files hourly against `$TMPDIR` aging. A launchd agent adds an install, an uninstall and a login item for no behavior the owner asked for.
2. **Keys: Cmd is the shortcut key on macOS.** winit's `super_key` is Cmd there. `ShortcutKey::Command` is the only mode on macOS and the Keys page hides the choice; Ctrl+Shift and Ctrl+Alt are plain keys for the program in the pane. The Windows conventions beside iTerm2's chords (F11 full screen, Ctrl+V paste) are off on macOS, since Ctrl+V is literal-next in a shell there. Windows and Linux keep Ctrl+Shift or Ctrl+Alt and never use the Win key.
3. **The chord key on macOS comes from the character, as AppKit matches key equivalents.** It is winit's `logical_key` (macOS's `charactersIgnoringModifiers`) when that is one ASCII character, the shifted ones mapped back to their key; else the key's position (the US layout, as macOS's Command layout does for non-Latin input).
4. **Menu shortcuts are shown natively but run through the one key path.** Items carry native key equivalents (so the bar shows them as iTerm2's does), and the terminal window's view takes every Cmd key-down before the menu does (a `performKeyEquivalent:` added to winit's view class that calls `keyDown:`), except Cmd-` and Cmd-Shift-` (AppKit's window cycling, which Termurion has no command for). So a key mapping beats a menu command and the toolbelt and composer take their chords, as on Windows and Linux. With no Termurion window key, the menu's own equivalents run (Cmd-N, Cmd-Q, Cmd-,).
5. **One menu bar for the screen.** The focused window's bar becomes the app's (`init_for_nsapp` on focus). The Window menu is not handed to AppKit (Termurion lists its windows itself, so there is no second list); the Help menu is (its search field); Services is AppKit's own submenu.
6. **Quit goes through `App::quit` from everywhere.** The menu's Quit Termurion is an ordinary item (`terminate:` in `run_command`, never muda's predefined quit). The Dock's Quit, logout and an AppleScript quit reach `applicationShouldTerminate:`, which answers "later" and sends the app a quit request; the app answers the system once, after its quit question.
7. **Hiding.** On macOS Hide Termurion hides the app, and Hide Others and Show All work (they stay not applicable on Windows). Secure Keyboard Entry stays not applicable in P2 (see Deferred).
8. **The bundle.** Identifier `dev.termurion.Termurion` (kept for good: TCC grants, Keychain items and notification consent are keyed to it); arm64 only (Apple silicon first); ad hoc signed, not notarized (the spec puts notarization later); `LSMinimumSystemVersion` 11.0; `LSApplicationCategoryType` `public.app-category.utilities` (iTerm2's); the usage descriptions are iTerm2's release set (`plists/release-iTerm2.plist`) with "iTerm2" read as "Termurion", plus the Desktop, Documents and Downloads folder ones. `CFBundleShortVersionString` is the numeric part of the Cargo version, `CFBundleVersion` the whole Cargo version. One plist template serves the real bundle and the dev bundle.
9. **No protected folder at launch.** The launch sweep of stale download temps skips the Downloads folder on macOS and runs at the run's first download instead, so a launch never raises the Downloads prompt.
10. **Global hotkeys through the `global-hotkey` crate**, as the spec's table says, with its code in `platform/unix/global_keys.rs` (compiled for macOS now; P3 widens the target for X11). Double-tap hotkeys report Unsupported on macOS in P2 (a global modifier monitor needs the Input Monitoring permission).
11. **The hotkey window's native handle on macOS is the NSView.** `platform::window::view_of` returns the HWND on Windows (the same value `hwnd_of` gives) and the NSView on macOS; menus and the hotkey window take it, and `hwnd_of` stays None on macOS so no other Windows path wakes up. The "previous foreground window" on macOS is a token: our view when Termurion is active, else the negative pid of the frontmost app, which `window::set_foreground` activates.
12. **Notifications through `UNUserNotificationCenter`**, only from inside a bundle (the framework raises an exception without one; outside it the call reports why). The resident icon has no meaning on macOS: the Dock icon is always there and a Dock click reopens (Decision 6's delegate).
13. **The Keychain through `security-framework`, not the `keyring` crate (a deviation from the spec's table).** Termurion's generic calls name a target without a user, and the password manager lists its items; `keyring` can do neither, and `security-framework` is the crate `keyring` itself uses on macOS. An item is a generic password with service = the Credential Manager target and account = the user. The gate is `LAContext` `deviceOwnerAuthentication` with iTerm2's reason "open the password manager".
14. **Downloads are quarantined as iTerm2 does** (`TransferrableFile.m:225-270`: the URL's quarantine properties, agent Termurion, the source URL, type other-download), not with a raw extended attribute. Linux keeps Unsupported (P3).
15. **A Finder alias file is judged by its target**, like a symbolic link (an unresolvable alias is shown, never opened). A file owned by another user (not root) in a folder others can write is shown, never opened (the exec-bit swap the P1 re-review named).
16. **iTerm2's settings are read live, never written live.** Import from iTerm2 reads the `com.googlecode.iterm2` domain through cfprefsd when the picked file is iTerm2's live plist; the custom settings folder refuses `~/Library/Preferences` itself, since writing that file while cfprefsd owns it loses iTerm2's settings.
17. **CI matrix (call): not in P2.** The spec lists it under build hosts, not under P2; adding workflows means pushing, which this plan does not do.
18. **Single instance on macOS comes from LaunchServices** (Finder, the Dock and `open` reuse the running app). A second copy started from the bare binary behaves as on Linux.

## Review Focus

1. A key mapping (profile or global) on a Cmd chord that is also a menu key equivalent, such as Cmd-T bound to Send Text. Expect the mapping to run and the menu command not to (iTerm2 runs key mappings before menu key equivalents). Pinned by `a_cmd_key_down_is_claimed_for_the_key_path` in Task 2 and the mapped Cmd-T in its VM step.
2. Cmd chords on a non-US layout (AZERTY, Dvorak) and a non-Latin one (Russian), and from a VNC client that sends key code 0. Expect the chord the character names on Latin layouts and the US position on non-Latin ones, never "Cmd+A" for every letter. Pinned by `the_chord_key_is_the_character` in Task 1.
3. Termurion started as a bare binary or under `cargo test` touching a bundle-only API (notifications). Expect an error naming Termurion.app, never a crash. Pinned by `notifications_outside_the_bundle_say_so` in Task 6.
4. Quit from outside the menu (the Dock's Quit, logout, `osascript -e 'quit app "Termurion"'`) with a job running. Expect the same quit question; Cancel keeps Termurion and tells the system no, so a logout is not left waiting; OK saves windows, frames, notes and logs. Pinned by `a_terminate_is_answered_once` and `every_quit_path_answers_the_system` in Task 3.
5. Ctrl+V, F11 and Ctrl+Shift+letter at a macOS shell. Expect them to reach the program as keys (Ctrl+V is literal-next), since Cmd is the shortcut key there. Pinned by `windows_key_conventions_are_off_on_macos` in Task 1.
