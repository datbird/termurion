# Flood Flow Control and Fast Parse (1.1.11 addendum) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A flood of output can no longer outrun Termurion: the parser pushes back to the pty, so memory stays flat and the screen and Ctrl+C keep up, and then the per-byte parse is cut until flood MB/s is at or above Ghostty's.

**Architecture:** Task 8c bounds every queue between the program and `Screen::feed`: a byte budget between each pty reader thread and its consumer (local panes and the host's own ptys, Unix and Windows), and a per-session credit window between termurion-host and the app (protocol version 6, `Msg::Consumed`). Task 8d makes printable ASCII cheap: a fast path at the top of `Term::input` and `rule_width`, a bulk `input_ascii` for plain ASCII runs found by vte's ground dispatch, and an SGR skip in the OSC pre-scan. Each fast path keeps the old path behind a switch, and an oracle test compares the two over a corpus. Task 8e (optional) makes the host relay cheaper, only if the bench after 8d needs it.

**Tech Stack:** Rust 2024, vendored `crates/alacritty_terminal` and `crates/vte`, std threads (`Mutex`, `Condvar`, `mpsc`). Tests: `scripts/check-unix --test <filter>` (Linux here and macOS on funtimes), `scripts/xt test --lib -- <filter>` (Windows on EXTREME), `scripts/win-check`.

**Spec:** `.superpowers/sdd/2026-11-20-beat-ghostty/flood-investigation.md` (fixes 1, 2 and 3; binding for causes, sites and expected effects) and the main plan `docs/superpowers/plans/2026-11-20-beat-ghostty.md` (its Global Constraints and Task 8 design, binding). - Byte budgets (exact): `PTY_BUDGET = 1 << 20` (the reader stops reading at 1 MiB queued), `PTY_RESUME = 512 << 10` (it reads again at 512 KiB or less), `WINDOW = 2 << 20` (host to app, unacked bytes per session), `ACK_EVERY = 256 << 10` (the app acks after this many bytes taken), `EXIT_DRAIN_CAP = 200 ms` (host). `WINDOW > ACK_EVERY` must hold (a `const` assertion).

### Task 8c: Output flows back to the pty (medium risk)

#### Design

- **Reader budget (local panes and the host's ptys).** The reader adds a chunk's length to its `Budget` before it sends the chunk; `try_read` and `read_timeout` take it off after a receive. At the top of each read loop turn, after the Undo Close `paused` check, the reader calls `wait_for_room`: when 1 MiB or more is queued it waits until 512 KiB or less is queued, the budget is closed, or `give_up()` says so. It never holds a read chunk while it waits, so the program blocks on the full pty (Unix) or pipe (Windows). The budget is separate from `paused`: Undo Close and inline-file pauses keep their 20 ms loop as they are.
- **Close.** Both `Drop` impls (and Windows `drop_pipes`) call `budget.close()` first, next to `set_paused(false)`: the reader then drains to EOF as today, so the Unix master closes and hangs up the group, and Windows `ClosePseudoConsole` never blocks on a full pipe.
- **Windows console attaches.** `static CONSOLE_WANTED: AtomicUsize` in `windows/pty.rs`, raised by `attached_unless` before it takes `CONSOLE.write()` and lowered (by a guard) when it returns. The Windows reader waits with `every = 10 ms` and `give_up = || CONSOLE_WANTED.load(Acquire) > 0`, so during any attach (prompt watch, Send Signal) it reads past the budget and OpenConsole never blocks. Unix passes `every = 100 ms`, `give_up = || false` (its Drop wakes it through `close`).
- **Host to app window.** `Session.acked: u64` (0 at launch; `from` at `Attach`). `pump` reads a session only while it is not held: held means `s.attached && flow && s.ring.end() - s.acked >= WINDOW`, where `flow` is the client's agreed version `>= FLOW_VERSION`. The live offset sent equals `ring.end()`, so no second counter is needed. A detached session, or one whose client left, is never held (it reads into the ring as today). `Msg::Consumed { id, offset }` sets `s.acked = s.acked.max(offset.min(s.ring.end()))` and then `wake.send(id)`, so a held session pumps again (its reader will not notify: it is waiting for room). An unknown id is ignored.
- **Replay on attach.** The ring bytes from `since` still go in one `Output` as today; since `acked = from`, live output waits until the app has acked to within `WINDOW` of the ring's end.
- **Exit ordering.** Today `Exited` always follows all output, because `pump` drains before it checks the exit. Under the window it may stop early, so `Exited` is sent only when this pump drained (its last `try_read` gave `Empty` or `Closed`) or `EXIT_DRAIN_CAP` has passed since the host first saw the exit (`Session.exit_seen: Option<Instant>`), so a background writer that outlives the shell cannot hold the end (the app's own `END_DRAIN_CAP` then applies as for a local pane).
- **App side.** `Incoming.acked: u64` (set with `end` and `taken` at `attach` and `Attached`). `HostedPty::try_read`, after it adds to `taken`: when the agreed version is `>= FLOW_VERSION` and `taken - acked >= ACK_EVERY`, set `acked = taken` and send `Msg::Consumed { id, offset: taken }` (after the slot lock is dropped). Liveness: when the host is held, `sent - acked >= WINDOW` and `taken - acked < ACK_EVERY`, so more than 1.75 MiB is queued or in flight to the app, which takes it and acks. `read_loop` only queues (now at most `WINDOW` a session) and never waits. The ack goes from whichever thread parses (the Task 8 worker included; `mpsc::Sender` is `Sync`).
- **Paths that read downstream of a pane's read are unchanged** and need no credit of their own: tmux integration (the gateway's read releases credit; its panes' `TmuxIo` inboxes stay as they are), SSH integration (`ssh_q`, held bytes), the coprocess tee (`tee_coprocess`; its input-side `pending` budget is unrelated), session logging (`log_raw` runs on the consumer, so a slow disk slows the program, as it should), Instant Replay (recorded in `pump_tail`).
- **Update across versions.** A new app meets an old host (version 5, sessions kept): `Client::connect` already steps down on `Refused` (not busy), speaks 5, never sends `Consumed`, and hosted panes stay unbounded until that host is replaced (quit with no sessions kept); local panes are bounded. The app logs once `rlog!("session host speaks protocol {v}: hosted output has no flow control")` when `v < FLOW_VERSION`. An old app meets a new host: the host welcomes it at its version and never holds its sessions.
- **What this bounds.** Unparsed output held in the app: at most `PTY_BUDGET` plus one 64 KiB read per local pane and `WINDOW` per hosted session. In the host per session: `PTY_BUDGET` in its pty channel, `WINDOW` in its writer queue, the 4 MiB ring. Ctrl+C: on Unix the line discipline signals the program whatever the output queue holds; afterwards at most about 4 MiB (hosted) or 1 MiB (local) of old output is still parsed, under 70 ms at 65 MB/s.

### Task 8d: Printable ASCII parses fast (low to medium risk)

#### Design

- **a. One-cell fast path.** At the top of `rule_width` (`src/screen.rs:103`): `if (' '..='~').contains(&c) { return Some(1); }`. At the top of `Term::input`: for `' '..='~'` with `fast_ascii` on, the width is 1 and the regional indicator and pictograph checks are skipped (both can only match non-ASCII), then the code goes on as today. Exact because `is_double_width` is false below 0xA1, no ASCII printable is ignorable, zero width, a regional indicator or Extended_Pictographic.
- **b. Bulk ASCII print.** vte patch 4: `Perform::print_ascii(&mut self, run: &str)`, default `for c in run.chars() { self.print(c) }`; `ground_dispatch` passes each maximal run of `' '..='~'` to `print_ascii` and everything else (controls, DEL, non-ASCII) as today, in order. `Handler::input_ascii(&mut self, run: &str)`, default calls `input` per char; `Performer::print_ascii` calls `handler.input_ascii(run)` and sets `preceding_char` to the run's last char. alacritty patch 42: `pub fast_ascii: bool` on `Term` (default true; false sends every char through `input`, for the oracle) and `Term::input_ascii`:
  - Falls back to `input` per char for the whole run when any of these holds: `!fast_ascii`, `TermMode::INSERT`, `!TermMode::LINE_WRAP`, `lr_active()`, `echo_armed`, `print_watch.is_some()`.
  - Otherwise, per row segment: wrap first if `input_needs_wrap` (`wrapline_always`, the same function `wrapline` calls with LINE_WRAP on); take `n = min(rest, columns - col)` chars; stamp the row once (`time`, `alt`, `block`, as `write_at_cursor`); for each cell clear wide-char relations first when its flags intersect `WIDE_CHAR | WIDE_CHAR_SPACER` (move that block of `write_at_cursor` into `fn clear_wide_for_write(&mut self)`, used by both), then write `charsets[active_charset].map(c)` with the template's fg, bg, flags and extra; add `n` to `printed`; leave the cursor on the last written column with `input_needs_wrap = true` when the segment reached the last column, else one past it.
- **c. SGR skip in the OSC pre-scan.** `Scanner.fast_sgr: bool` (default true). In `scan_spans`, at an ESC with the parser in `Ground`, `i > 0` and `bytes[i - 1] < 0x80` (no half character can be held), when `sgr_run(&bytes[i..])` is `Some(n)` the scanner skips the `n` bytes without its parser: a complete `ESC [ [0-9;:]* m` is never held, queried or reported (`Csi::held` and `Csi::query` have no `m` arm without intermediates) and leaves the parser in `Ground`. Anything else (a marker `<=>?`, an intermediate, a cut sequence) takes today's path.
- **Not in scope:** the clock reads in the worker loop (investigation 2d), the grid scroll, shaping.

### Task 8e (optional): The host relay costs less (low risk)

Done only when Task 8d Step 8 says so.

#### Design

- **Notify on the edge only, in the host.** `Pty::set_edge_notify(&self, on: bool)` (both OSes, default off; only `host::launch` turns it on, so local panes keep a notify per chunk and the app's wake logic is untouched). With it on, the reader notifies only when `signaled.swap(true, SeqCst)` was false. The host's `pump`, when `try_read` gives `Empty`, stores `signaled = false` (SeqCst) through `Pty::rearm_notify(&self)` and calls `try_read` once more, continuing if data came; this closes the race where a chunk lands between the empty read and the store. A pump held at the window does not rearm (the ack's `wake.send` pumps it).
- **One frame for waiting chunks.** `pump` joins consecutive chunks of a session into one `Output` up to `MERGE_CAP = 64 << 10` bytes, so the app's chunk stays at most 64 KiB (Task 8's join waits at most one chunk) and offsets stay contiguous.
- **Socket buffers.** `new_socket` (`src/platform/unix/ipc.rs`) and the accepted socket set `SO_SNDBUF` and `SO_RCVBUF` to `SOCKET_BUFFER = 1 << 20`; a refusal is logged and ignored. Windows named pipes are left as they are.
- The read-size measure and the B38400 tty speed of the investigation are not done.

### Task 8f: Repeated words shape once (low to medium risk)

Added after 8c to 8e at the owner's request (performance, CPU, memory and render quality first): investigation fix 4. It does not raise flood MB/s; it lowers the app's CPU per MB and raises fps. Independent of 8c to 8e; land it after 8d (or 8e when done) so the bench compares with that run.

#### Design

- **Where the cost is.** Each frame, `Renderer::draw_with` (`src/render.rs:1769`) keeps last frame's shaped rows by their spans (`shape_hash` `:439`, lookup `:1784-1806`, one frame kept `:1921`), so a scrolled row is not shaped again (1.1.7). In a flood every visible row is new each frame, so each one gets a new `Buffer` (`:1807`), `set_rich_text` (`:1899`) and `shape_until_scroll` (`:1905`; a second pass when `cluster_fixes` finds a ligature, `:1907-1914`). cosmic-text 0.19.0 (crates.io, not vendored; `Cargo.lock` `cosmic-text 0.19.0` with `harfrust 0.5.2`) splits each bidi span into words at line-break opportunities, every whitespace character its own blank word (`shape.rs:970-1075`), and shapes each word on its own with no context from its neighbors (`ShapeWord::build`, `shape.rs:797-858`; `shape_fallback` reads only `line[start_run..end_run]`, `shape.rs:119-201`). The flood's words repeat (the bench's 40-word vocabulary, `scripts/draw-bench:88-98`), so nearly every run shaped in a flood frame was shaped before.
- **Why `AatMapBuilder::compile` runs on every shape.** Termurion gives every terminal span that is ASCII or ligated non-empty OpenType features (`src/render.rs:1888`; `fonts::features` `src/fonts.rs:240-255` always enables or disables `liga`, `clig`, `calt`, `dlig`). harfrust 0.5.2 puts user features only in the OpenType map (`hb/ot_shape.rs:170-177`), so the plan's `aat_map` is built without them (`:184-189`), and `aat::layout::substitute` builds and compiles a new AAT map from the features on every call that has any (`hb/aat/layout.rs:502-527`). cosmic-text keeps 6 shape plans (`shape.rs:84-91`, `:173-198`) but still passes the features to `shape_with_plan` (`shape.rs:201`), so on macOS (Menlo and SF Mono carry `morx`) every word pays the compile: 12.4% of main in the t8 flood.
- **What cosmic-text already has.** A per-run cache behind the off-by-default feature `shape-run-cache` (`Cargo.toml` `[features]`; `Shaping::run` `shape.rs:58-77`; `shape_run_cached` `shape.rs:417-474`; `ShapeRunCache` `shape_run_cache.rs:8-43`; field `FontSystem::shape_run_cache` `font/system.rs:162-164`). Its unit is the run `ShapeWord::build` shapes, so it is the word-level cache the investigation asks for, and its result does not depend on font size (glyphs are stored in em units, `shape.rs:131`, `:216-219`). Termurion does not enable it. As shipped it is not usable: (1) its key (`ShapeRunKey`: run text, default attributes, attribute spans) leaves out the direction, so the same text shaped in an RTL span and an LTR span (a `(12)` or `!?` inside Hebrew, mirrored and reversed glyphs) shares one entry and draws wrong; (2) nothing bounds it (`trim` is never called by cosmic-text and there is no size limit or `len`); (3) loading a font (`db_mut`, `font/system.rs:291-294`) clears the font match cache but not this one, so a cached run can name a stale fallback.
- **Choice: vendor cosmic-text 0.19.0 and fix its run cache; Termurion trims it per frame and clears it on font changes.** It removes shaping, the AAT compile and font fallback for every repeated run with no change to the glyph output (a hit returns the exact `ShapeGlyph`s the shaper made for the same key). Rejected: caching the AAT map per font and features (needs a vendored harfrust and saves only the 12.4%, while the word cache takes the whole 60% down to the miss rate, the compile included); skipping the shaper for pure ASCII in a monospace font (Menlo and SF Mono have `morx`, a ligature font's `calt` changes plain ASCII, and the word cache gets the same saving without the risk); a whole-line cache (every flood line is unique).
