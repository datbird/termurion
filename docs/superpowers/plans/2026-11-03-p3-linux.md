# P3 Linux Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Termurion on Linux is a real desktop app: a menu bar and pop-up menus drawn in the window, desktop notifications, the Secret Service as the credential store with a password gate, system-wide hotkeys and the hotkey window on X11, working downloads, and an AppImage, with Windows and macOS behavior unchanged. Exit: it runs on a Linux desktop (X11 and Wayland).

**Architecture:** The P0 to P2 facades stay. Linux-only backends go in `src/platform/linux/` and the facade picks them on Linux; anything macOS shares stays in `src/platform/unix/`. Menus keep `muda` as the one menu model on every OS: on Linux muda is built without GTK (its no-op backend), and an OS-free egui overlay (`src/menu_overlay.rs`) reads muda's item tree each frame and sends the chosen id down the same `UserEvent::Menu` path the native menus use. D-Bus facilities (notifications, Secret Service, screen lock) share one `zbus` major.

**Tech Stack:** Rust 2024, winit 0.30.13, egui/egui-wgpu/egui-winit 0.36, muda 0.20 (`default-features = false` on Linux), notify-rust 4 (feature `z`, no libdbus), secret-service (blocking API, pure-Rust crypto, no OpenSSL), zbus (the one major notify-rust and secret-service share), global-hotkey 0.9 (X11), pam-client or pam (the system libpam, linked dynamically), appimagetool with the static type2 runtime.

**Spec:** `docs/superpowers/specs/2026-10-31-macos-linux-port-design.md` (binding). Conventions follow `docs/superpowers/plans/2026-11-03-p2-macos.md`. Parked items come from `.superpowers/sdd/2026-11-03-p2-macos/progress.md` and the "Deferred after P2" list in `docs/port/unix-test-gaps.md`. iTerm2 source for wording: `~/gitrepos/iterm2-ref`.

## Global Constraints

- "Windows behavior unchanged. Every step keeps the Windows build and its tests green." Every task ends with `scripts/win-check` at `windows: 0 errors` and no new warning (the two `fetch_update` deprecations in `session_log.rs` are known). The xt hold is cleared (2026-11-03): a task that changes a file Windows compiles runs `scripts/xt test --lib` (full PASS; the known flakes `find::tests::find_over_a_large_buffer_is_quick` and `host::tests::host_launches_and_echoes` may be rerun once); the P3 final review runs it once more at the head.
- "No second copy of any logic. If Mac and Linux need the same thing, it lives once in `platform/unix`." macOS behavior is unchanged in P3: `scripts/check-unix` passes on both hosts after every task, and the macOS counts in the gaps doc do not get worse.
- "No `#[cfg(windows)]` sprinkled through `app/`." A cfg lives only in `src/platform/`, `src/lib.rs`, `src/bin/`, `Cargo.toml`, `*_win.rs`, or a `scripts/cfg-audit.allow` entry; `scripts/cfg-audit` exits 0 after every task. App code asks a platform constant or facade.
- Unix code never claims success for something it did not do: a missing facility returns `platform::Unsupported` or an error naming the missing piece (the daemon, Wayland, the Secret Service), never a silent `Ok`. The one allowed no-op class is a call with no meaning on that OS, with a doc comment saying why.
- No D-Bus call blocks the UI thread without a bound: each call has a 5 s timeout, and the calls that can wait on a person (a Secret Service unlock prompt, the PAM check) run off the UI thread and answer through a `UserEvent`.
- Menu item names and labels match iTerm2's exact wording where an equivalent exists (`schema/menus.toml`). Linux shortcut text is Windows' (`Ctrl+Shift+T`), since Linux shares Windows' shortcut keys.
- No Win key (Super) chord runs a Termurion action on Windows or Linux, tests and scripts included. A system-wide hotkey the owner records with Super is the one exception (it is his chord, not ours).
- Every new process spawn, URL or file open, or fetch funnel gets a `SINKS` token, a `NOT_PANE_TEXT` entry and a planted case in `src/app/semantic_ui.rs`. `dlog!` arguments are `LogSafe`; any task that adds or moves a `dlog!` updates `dlog::CALL_SITES`.
- New dependencies go under `[target.'cfg(all(unix, not(target_os = "macos")))'.dependencies]` with only the features used; `cargo tree --target x86_64-unknown-linux-gnu -i gtk` finds nothing; `cargo tree -d` shows one `zbus` line; `licenses::tests::every_dependency_is_listed` passes on Linux and macOS.
- Builds: Linux with `~/.cargo/bin/cargo`; macOS on `ssh funtimes` through `scripts/check-unix`; Windows type check through `scripts/win-check`. GUI checks run under Xvfb through `scripts/unix-gui-check`, and the Wayland ones under a headless `weston`.
- Short human comments, no em dashes or emoji anywhere, commits with no host or user names and no attribution lines, work on `main`, do not push until the owner says. Commit messages start `Port P3: `.

## Decisions (the spec's open calls and the gaps it leaves)

1. **The menu model is muda on every OS (call).** muda 0.20 keeps item text, enabled, checked and children in its own state whatever the backend, so on Linux it is built with `default-features = false` (no GTK, no libxdo) and the app builds its menus exactly as on Windows. No second menu builder exists. The egui overlay reads `Menu::items()`, `text()`, `is_enabled()`, `is_checked()` live each frame, so a setter the app calls shows at once.
2. **One bar per terminal window, inside the window, on the top edge (call).** It takes a strip above the tab bar (above the caption strip in a Minimal or Compact window), like Windows' native bar. "Hide menu bar" (`hide_menu`/`show_menu`) removes the strip. In full screen the bar is hidden, as macOS and iTerm2 do. Shortcut text sits right-aligned after the item's tab (`menu_text` keeps the tab, since `NATIVE_ACCELERATORS` stays false on Linux).
3. **The menu is opened by the mouse; once open, the keyboard works it** (arrows, Enter, Esc, Left and Right between menus). No Alt mnemonics and no F10: Alt is Meta and F10 is a key for programs in the pane (mc, htop). Every item is reachable by its own shortcut anyway.
4. **Pop-up menus are drawn by the same overlay.** `platform::chrome::popup` on Linux queues the menu and the position for that window and returns true; the window's next frame draws it. Its facade argument becomes `&M where M: PopupMenu`, a small trait (`entries(&self) -> Vec<muda::MenuItemKind>`) with impls for `muda::Menu` and `muda::Submenu`; Windows and macOS ignore it and call muda as today.
5. **Notifications through `notify-rust` on the `zbus` backend.** A click on a notification runs `on_click` (the `default` action). The resident tray icon stays Unsupported in P3 (StatusNotifierItem is a later step). With no notification daemon on the bus, `show_with` returns an error naming it.
6. **The Secret Service through the `secret-service` crate, not `keyring` (the same deviation as macOS Decision 13).** An item has the label `Termurion: <target>` and the attributes `application = termurion`, `target = <Credential Manager target>`, `user = <user>`; the password manager lists by `application = termurion`. A locked default collection is unlocked through the service's own prompt, off the UI thread. No service on the bus is an error naming the Secret Service, never "nothing stored".
7. **The password manager gate on Linux is the account password, checked by PAM (call).** An egui prompt asks for it; `pam_authenticate` runs under service `login` (present on every common distribution, and `pam_unix` checks the password without root through `unix_chkpwd`). Three wrong answers fail the gate. A system with no PAM `login` service fails with a reason the alert shows. iTerm2's reason text stays: "open the password manager".
8. **Screen lock on Linux comes from logind.** `org.freedesktop.login1.Session.Lock` for the app's session (`XDG_SESSION_ID`, else the caller's session from `GetSessionByPID`), plus `org.freedesktop.ScreenSaver.ActiveChanged(true)` where that interface is on the bus. Either one locks the password manager, as on Windows and macOS.
9. **System-wide hotkeys on X11 through `global-hotkey` (the code in `platform/unix/global_keys.rs` widens from macOS to X11).** On a Wayland session (`WAYLAND_DISPLAY` set and winit on Wayland) they report "System-wide hotkeys need X11; Wayland has no global shortcut grab yet". The portal (`org.freedesktop.portal.GlobalShortcuts`) is later. Double-tap hotkeys report Unsupported on Linux.
10. **The hotkey window on X11 is the X window id.** `platform::window::view_of` returns it on X11 (winit's `RawWindowHandle::Xlib`), None on Wayland. `foreground` reads `_NET_ACTIVE_WINDOW`, `order_front` sends `_NET_ACTIVE_WINDOW` as a client message, `ours` compares against our windows, `set_alpha` sets `_NET_WM_WINDOW_OPACITY`, `cloak` maps and unmaps. Through `x11rb` (already pulled by arboard's X11 path; no new X library).
11. **Downloads on Linux are marked with the freedesktop origin attributes**, `user.xdg.origin.url` and `user.xdg.referrer.url` (what Chromium and Firefox write), not a quarantine. A file system without user extended attributes keeps the download and logs the miss once: the download is the user's ask, the mark is not. This ends the "Failed to quarantine" download failure on Linux.
12. **The AppImage carries `termurion` and `termurion-host`, a `.desktop` file and the icon.** The app id is `dev.termurion.Termurion` (macOS's bundle id), set through winit's `with_name` on X11 and `with_name` app id on Wayland, and it is the `.desktop` name and `StartupWMClass`. The static type2 runtime is used, so the AppImage runs without libfuse2. GTK is not bundled (Decision 1 removed it); glibc, libxkbcommon, Wayland, X11, Vulkan and libpam come from the system. x86_64 only.
13. **No CI matrix in P3**, as in P2 (Decision 17 there): adding workflows means pushing.

## Review Focus

1. A Wayland session (GNOME, KDE) with no X11. Expect the app to start, the menu bar, pop-ups and notifications to work, and the hotkey setting to say Wayland has no global grab yet, never a crash or a silent no-op. Pinned by `hotkeys_on_wayland_name_wayland` in Task 6 and the weston step in Task 8.
2. No Secret Service on the bus (a bare window manager, KWallet without the bridge), or its unlock prompt dismissed. Expect the password manager and the AI key reads to say why, and a key read to be an error, never "nothing stored". Pinned by `a_missing_secret_service_is_an_error_not_empty` in Task 4.
3. No notification daemon, or a dead session bus. Expect `show_with` to return within the timeout with a reason; the UI never stalls. Pinned by `notifications_without_a_daemon_say_so` in Task 3.
4. A click outside an open menu, a focus loss, or a resize while the menu is open. Expect the menu to close and that click not to reach the pane (no selection, no paste). Pinned by `a_click_outside_an_open_menu_closes_it_and_stays_with_the_menu` in Task 1.
5. Glyphs the egui font lacks (the P2 parked "boxes" in the Settings key lists and the check marks). Expect every menu and key-list character to draw, not a box. Pinned by `menu_and_key_text_glyphs_are_in_the_font` in Task 1, which also closes the parked Settings font item on every OS.
