**Goal:** a browser session shows iTerm2's pages everywhere iTerm2 does: a failed load shows the "Server Not Found" style page with Try Again; a `file:` link shows the styled listing or the file; the first browser tab walks through the onboarding and can make the Web Browser profile; Menu > Settings opens `iterm2-about:settings`, whose every control (clear cookies and data, search engine, ad blocking with its statistics and Update Now, proxy, link opening, saved passwords, site permissions) works; a download lands in Downloads with a notification; Add Bookmark opens Edit Bookmark for tags and the bookmarks page filters by them; Win-click on a remote file in an ssh-integrated session offers View, which shows the file in a browser tab; extensions placed in the profile's extensions folder load into browser sessions exactly as iTerm2 loads them.

The app side: `src/app/browser_pages_app.rs` (serving every new page, error and file redirects, onboarding, settings actions), `src/app/browser_download_app.rs`, `src/app/bookmark_tags_app.rs`, `src/app/ssh_page_app.rs`, `src/app/browser_extensions_app.rs`. ### Decisions (each goes in `m13x8-rulings.txt`)

- Emoji in copied pages become Segoe Fluent Icons glyphs at serve time. Cost: a glyph code may read differently from the emoji.
- `cert-error.html`, `dev.html` and the Demos pages are not shipped (unused or debug-only in iTerm2). Cost: none for release parity.
- Certificate errors cancel the navigation and show iTerm2's error page (no "continue anyway"). Cost: a self-signed local server cannot be visited, as in iTerm2.
- `describe(status)` texts are Tandem's (no system source for WebKit's descriptions). Cost: wording differs from macOS.
- The error page escapes the failed URL in both slots (iTerm2 inserts it raw). Cost: none.
- `file:` navigations redirect to `iterm2-file:` in `NavigationStarting` (WebView2 can show `file:` itself). Cost: WebView2's own file viewers (PDF) are not used for `file:` URLs; the page shows the bytes as text.
- An `iterm2-file:` failure answers an empty 404 (iTerm2 fails the scheme task and shows nothing). Cost: a blank page instead of the previous page staying.
- Files over 64 MB are not served as file pages. Cost: large logs cannot be viewed this way.
- Onboarding's Switch uses `remarry` (the session takes the profile) instead of iTerm2's divorce-and-copy keeping the session guid. Cost: a session-local override made before switching is dropped.
- Settings page alerts quote the message as a JSON string. Cost: none.
- The secret-less `clearCookies`/`clearAllData` copies iTerm2 injects at commit are not injected (the page's own win in iTerm2 too). Cost: none.
- Download decisions are WebView2's (Chromium's) rules; the name and destination are iTerm2's. Cost: some types iTerm2 downloads (for example audio/ogg) play in the page instead.
- Downloads report through 14d's banner and notifications (no transfer list window). Cost: no list of past downloads.
- Tags parsed from a comma-separated field. Cost: a tag cannot contain a comma.
- The key-value table is created and never read. Cost: none.
- The SSH page buffers the remote file, up to 64 MB, before answering (review I5). Cost: no progressive display; larger remote files cannot be viewed this way.
- `iterm2-file:` and `iterm2-ssh:` pages are sandboxed (R13x8-1): an opaque origin, no connections, no form posts, subresources only from the top document's folder tree, no script-started navigation. Cost: a local HTML file that fetches its own data files or posts a form does not work as it does in iTerm2.
- Only the person, Tandem or an `iterm2-about:` page can start a `file:`, `iterm2-file:` or `iterm2-ssh:` load; redirects to them are refused (review I4). Cost: a web page's script cannot open a local file view, which iTerm2 allows.
- Download names go through 14d's `clean_name` and must land directly in Downloads (R13x8-2). Cost: a name with a Windows-forbidden character is changed (`a:b` becomes `a_b`).
- Foreign keys stay off as in iTerm2 and a bookmark's tags are deleted explicitly (R13x8-3, an iTerm2 bug fix). Cost: none.
- The proxy host must be a hostname, IPv4 or bracketed IPv6 (review I10). Cost: a host iTerm2 would pass through with odd characters is refused.
- A failed navigation is 13x's one `Event::Navigated { ok: false }`, now carrying the URL (review I3). Cost: none.
- Extensions whose folder left the root are removed from the WebView2 profile at the next sync (review I6). Cost: an extension installed into the profile by other means is removed too.
- Extensions use WebView2's built-in browser extension support, not a port of `WebExtensionsFramework` (Q39). Cost: Chromium's full extension API instead of iTerm2's three APIs (more extensions work); extension storage is Chromium's, not the key-value table.
- One active list per WebView2 profile (`Store::Browser` and `Store::BrowserDevNull` separately), the last synced pane's Tandem profile winning. Cost: two Tandem browser profiles with different active lists share one set in WebView2.
- No extensions folder watcher; resync on view creation and on the settings request. Cost: a folder added while running loads with the next browser view.
- The settings section for extensions stays hidden (the writer's question, ruled accepted with Q1 to Q48). Cost: extensions are managed by editing the profile.

### Pitfalls for the implementer

- Custom schemes are registered only when an environment is created; adding `iterm2-file` and `iterm2-ssh` changes the options, so the Browser environments must be created with all three from the start (WebView2 refuses a second environment with different options on the same folder, 13x's Host notes).
- `DownloadStarting` must take a deferral and complete it from `web_tick` (as 13x's `WebResourceRequested`); never block in the handler. Setting `Handled` true hides Edge's download bubble; forgetting it shows both.
- `ClearBrowsingDataAll` is per WebView2 profile: it clears the Browser store for every browser pane of that store, as iTerm2's per-user data store does.
- Never turn `PRAGMA foreign_keys` on (R13x8-3): the tag table's parent key is the implicit `rowid`, which SQLite refuses as a parent key, so every tag insert and bookmark delete would fail with "foreign key mismatch".
- `ServerCertificateErrorDetected` also fires for subresources; only the main-frame navigation shows the error page (the load failure event is main-frame only).
- `NavigationStarting` also fires for `iterm2-file:` itself; redirect only `file:`.
- 14d's `ssh_transfer_apply` must offer each `Size`, `Write` and `Done` to `ssh_page_job` first, or a page's bytes land in Downloads.
- Extension folders are read by WebView2 from disk; never add a folder from a UNC root (the implementer rules).
- The sandbox header must be on every `iterm2-file:` and `iterm2-ssh:` response, the 403s and error texts included; a response built without `sandbox_headers()` is the bug R13x8-1 closes.
- `navigate_tandem` is only for Tandem's own loads; a URL from a page, a link or the model goes through `navigate`, or 13x's `navigation_allowed` no longer means anything.
- `remove_extension` must wait for pending adds (`sync_plan` leaves `remove` empty while `add` is not), or a freshly added extension is removed before its completion names it.
