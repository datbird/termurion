**Goal:** a turn built by 12c (or a one-shot call built by 12e, or Test Connection in Settings) reaches the configured provider exactly as iTerm2's request does, over Windows' own HTTP stack with the system proxy and TLS, streams its answer back as the bytes arrive, runs tool calls through a seam 12c fills, and fails with iTerm2's own texts; no key ever reaches a private host, a log or a test's output, and no test touches the network.

**Architecture:** pure models first, each a plain `pub mod` tested on the Windows test machine. `ai_model.rs` resolves the model and vendor for a request from the globals, 12a's catalog and the discovered Ollama tags, and holds the display names, attachment rules and token arithmetic (the host tests, vendor classification and key policy are 12a's `ai_policy` and `ai_models`). `ai_transport.rs` is the transport contract: `HttpRequest`, `HttpEvent`, `Transport` and `Call` traits, URL and proxy parsing, the UTF-8 carry for chunk boundaries, iTerm2's error texts, and (`#[cfg(test)]`) the `Recorded` fake that answers recorded bytes. `ai_winhttp.rs` (`#[cfg(windows)]`) is the real transport: one worker thread per call, synchronous WinHTTP, events posted through a channel and the loop's wake. `ai_wire_log.rs` is the wire log (record formats, redaction, the per-launch file) and the console log. `ai_msg.rs` is iTerm2's `LLM.Message` (bodies, merge rules, token estimate, truncation); `ai_json.rs` the sorted-key encoder and the byte-level history splice; `ai_sse.rs` the SSE and NDJSON splitters; `ai_turn.rs` the request state machine (`Turn`), the `Dialect` trait every wire format implements, the tool seam, and the `Runner` that joins a `Turn` to a `Transport` and the wire log. Dialects: `ai_responses.rs`, `ai_chat.rs` (Chat Completions, Early O1, legacy Completions, the modern parsers), `ai_anthropic.rs`, `ai_gemini.rs`, `ai_deepseek.rs`, `ai_ollama.rs`. `ai_discovery.rs` is Ollama discovery and its cache over the `Transport`; `ai_files.rs` OpenAI files and vector stores; `ai_test_conn.rs` Test Connection. App side: one app-wide field (`ai_discovery`), none in `swap_live`; the Settings pieces go into 12a's AI settings panels.

**Tech Stack:** no new crates. `windows-sys` gains the feature `Win32_Networking_WinHttp` (ruling 4); `serde_json` (bodies and parsers; note `preserve_order` is on, so sorted output is built explicitly), `base64` (data URLs, multipart), `sha2` (the discovery bucket key), `fancy-regex` (the wire log's look-behind patterns), `uuid` (wire log call ids, multipart boundaries), `std::sync::mpsc` and threads (the m11a "threads, not async" ruling). No `curl.exe` anywhere in AI (ruling 4).

## Review Focus

1. A multi-byte UTF-8 character split across two network chunks reaches the parser whole (iTerm2 drops such a chunk; Tandem carries the partial bytes, ruling 12b-2). Test: Task 2 `utf8_carry_keeps_split_characters`, Task 3 `any_chunking_parses_the_same`.
2. Streams whose events straddle chunk boundaries (a `data:` line cut in the middle, CRLF line ends, `event:`, `id:`, `retry:` and comment lines, blank keep-alives, a chunk of only `\r`) give the same outputs as the whole body delivered at once, for every dialect. Test: Task 3 `any_chunking_parses_the_same`, and each dialect task's `*_stream_any_chunking` over its recorded fixture split at every byte offset.
3. No key where it must not go: a private host gets "Placeholder for self-hosted"; the review key "placeholder" contacts nothing; the wire log fingerprints `Authorization`, `x-api-key`, `api-key`, `x-goog-api-key` and any `sk-...` or `AIza...` token in URLs and bodies; error texts built from a Gemini URL never contain the key. Test: Task 3 `key_policy_on_the_wire`, `review_key_contacts_nothing`, Task 2 `wire_log_redacts_follows_iterm2`, Task 7 `gemini_errors_hide_the_key`.
4. The timeout is idle time between bytes, not a total cap: a slow reasoning model that keeps sending survives past `AI Timeout`; a stalled one fails with "HTTP request failed with The request timed out.". Test: Task 2 `winhttp_idle_timeout_is_between_bytes`.
5. Cancelling one request stops only that request (not whichever started last, iTerm2's single-slot quirk, ruling 12b-4), no event arrives after the cancel, and the worker thread ends. Test: Task 2 `winhttp_cancel_stops_only_its_call`, Task 3 `cancel_follows_iterm2`.
6. Tool-call arguments that arrive in fragments (OpenAI `function_call_arguments.delta` and `tool_calls` deltas, Anthropic `input_json_delta`, DeepSeek) are dispatched whole, once; the end-of-stream reparse wins when it holds the longer call; six consecutive failures (or unknown tool names) end the turn with the error; a success resets the count. Test: Task 3 `tool_loop_follows_iterm2`, `end_of_stream_reparse_follows_iterm2`, Task 4 `responses_stream_follows_iterm2`, Task 6 `anthropic_stream_follows_iterm2`.
7. A refused request reads as iTerm2's: "Error from Anthropic: HTTP request failed with status 401. invalid x-api-key", plus the withheld-key advice when the request went to a private host with no credential header, and a streaming turn also streams "\n\n**Request failed**\n\n" with the details indented four spaces. Test: Task 3 `provider_errors_follow_iterm2`.
8. Token arithmetic: `max_tokens` is `min(model max response, AiMaxTokens - tokens(query) - tokens(functions))` with tokens = UTF-8 bytes / 2; under 2 throws "AI token limit exceeded because the conversation reached its maximum length"; tool continuations are truncated to `AiMaxTokens - min(AiMaxTokens / 2, AiResponseMaxTokens)` by dropping the oldest non-system messages and halving the last around "\u{2026}[truncated]\u{2026}"; Ollama's `num_ctx` sizing and its two detail texts. Test: Task 1 `max_tokens_follows_iterm2`, Task 3 `truncate_follows_iterm2`, Task 8 `ollama_num_ctx_follows_iterm2`.
9. The proxy: `aiProxy` "host:port" is an HTTPS-only proxy for model requests (plain `http://` to a local Ollama goes direct); a value without a numeric port is ignored; discovery never uses it and follows the system proxy. Test: Task 2 `proxy_follows_iterm2`, Task 9 `discovery_ignores_ai_proxy`.
10. Header assembly: auth headers per dialect, `Content-Type: application/json`, then custom headers that replace a built-in one differing only in case; an invalid name or a value with CR, LF or NUL is skipped; the Azure host sends `api-key`. Test: Task 3 `headers_follow_iterm2`.
11. Model resolution never silently crosses vendors: recommended Ollama with nothing discovered goes to the pending placeholder at `http://localhost:11434/api/chat`, a chosen Regular tag that vanished waits (placeholder), a manual entry shadows a catalog entry of the same name, and hosts are compared lowercased. ### WinHTTP (ruling 4)

- One worker thread per call, synchronous WinHTTP: `WinHttpOpen("Tandem", access, proxy, bypass, 0)` with access `WINHTTP_ACCESS_TYPE_AUTOMATIC_PROXY` (4, Windows 8.1 and later: WPAD, PAC and the Windows proxy settings) for `Proxy::System`, `WINHTTP_ACCESS_TYPE_NAMED_PROXY` (3) with the proxy string "https=host:port" and no bypass list for `Proxy::HttpsOnly` (WinHTTP applies an "https=" entry to https URLs only, so a plain `http://` Ollama request goes direct, as iTerm2's HTTPS-only proxy), `WINHTTP_ACCESS_TYPE_NO_PROXY` (1) for `Proxy::Off` (tests only).
- `WinHttpSetTimeouts(session, t, t, t, t)` with `t` the idle time in milliseconds clamped to `i32::MAX`, or 0 (infinite) for `Duration::ZERO` (resolve, connect, send, receive; the receive timeout applies to each wait for data, which is iTerm2's idle rule). `WinHttpSetOption(session, WINHTTP_OPTION_DECOMPRESSION, WINHTTP_DECOMPRESSION_FLAG_ALL)` (URLSession decodes gzip too). Redirects follow WinHTTP's default, as URLSession's.
- `WinHttpConnect(session, host, port, 0)` (an IPv6 host without brackets); `WinHttpOpenRequest(connect, method, path, null, WINHTTP_NO_REFERER, WINHTTP_DEFAULT_ACCEPT_TYPES, WINHTTP_FLAG_SECURE when https)`; all headers in one `WinHttpAddRequestHeaders` call as "Name: value\r\n" lines with `WINHTTP_ADDREQ_FLAG_ADD | WINHTTP_ADDREQ_FLAG_REPLACE`; `WinHttpSendRequest(request, null, 0, body, len, len, 0)` (WinHTTP writes `Content-Length`); `WinHttpReceiveResponse`; the status from `WinHttpQueryHeaders(WINHTTP_QUERY_STATUS_CODE | WINHTTP_QUERY_FLAG_NUMBER)`; then `WinHttpQueryDataAvailable` / `WinHttpReadData` into a 64 KiB buffer until 0 bytes.
- Streaming 200: every read goes through the call's `Utf8Carry` and is posted as `Chunk` if non-empty; at the end `Done { body: full body lossy, error: None }`. Non-200: read everything, post only `Done` with `status_error` (Decision 4). A WinHTTP failure: `Done { body: received so far, error: Some(transport_error(error_text(code))) }`. After `cancel`: nothing more is posted; the worker closes the connect and session handles and exits.
- Handles are `*mut c_void` in windows-sys 0.59: keep them as `usize` inside a `Send` struct; check each constant's exact name in the windows-sys 0.59 source before use (`WINHTTP_ACCESS_TYPE_AUTOMATIC_PROXY` in particular; if absent, the value is 4).

### Corrections to the research (the source wins)

1. Facts 2.3 says every chunk is passed up as it arrives; a chunk that is not valid UTF-8 on its own is silently dropped from the live stream (`JF:38-41`, `String(data:encoding:)` fails), so a multi-byte character split across reads loses the whole chunk until the end-of-stream reparse (Question 2).
2. Facts 2.11 names `response.done` as the end event; OpenAI sends `response.completed`, which iTerm2 treats as unknown and ignores; the stream ends at `[DONE]` or when the body ends (`RS:631-633`, `RS:677-680`). No visible difference; kept.
3. Facts 2.4 (truncation): the turn truncates only tool continuations (`T:1422-1424`, `T:1455-1457`); the first request's truncation is the conversation's (12c).
4. Facts 2.6: Responses always sends `tools` (possibly `[]`) with `tool_choice` "none" when there are no tools, and has no token-limit check (`RQ:1911-1920`); Chat Completions always sends `stream` (also `false`) and always writes `role` and `content` (`null` when absent) (`CO:24-32`, `MP:93-149`).
5. Facts 2.4: the provider name in "Error from %@" falls back to "server" (`T:548`); the reason is appended after one space only when non-empty (`T:377-379`).
6. Facts 2.7: `message_start.message.content` is decoded as `[String]` (`AN:671`); Anthropic sends `[]` there, which decodes, but a non-empty array of blocks would fail the event and lose the prompt-token count; Tandem reads fields leniently (Global Constraints) and keeps the usage either way.
7. Facts 2.13: a Test Connection failure is the parsed reason or the bare transport error, not "Error from ..." (`CT:193-215`).
8. Facts 2.14: `logFailure` writes the error text unscrubbed (`WL:137`); Tandem scrubs it (Decision 7).
9. Facts 2.9: discovery never checks the HTTP status (`OD:218-249`), and the names path reports an unparseable or empty body as "No installed models were found on the Ollama server.".
10. Facts 2.12: the batch poll merges the model's custom headers into a request to api.openai.com while the upload does not (`LV:25-31`, `LF:74-78`); kept as iTerm2 does.

### Decisions (each goes in `m12b-rulings.txt`)

1. Lenient decoding: parsers read `serde_json::Value` fields; a missing optional field is absent instead of failing the event (Correction 6; also a Responses `response.failed` missing iTerm2's required fields still shows its message). Cost if wrong: a malformed event iTerm2 would ignore is used.
2. The sorted encoder does not escape "/" (Swift's `JSONEncoder` writes "\/"): bytes differ from iTerm2's only there, and both are valid JSON. Cost if wrong: a spliced iTerm2 blob and Tandem's new tail differ in escaping inside one body, which servers accept.
3. Chunks and completion arrive in order on one channel, so iTerm2's completion-before-last-chunk race cannot happen; the end-of-stream reparse is kept (pinned by a `Recorded` race fixture), and iTerm2's known tail-splice bug (`T:975-986`) becomes unreachable. Cost if wrong: none visible.
4. A non-200 body is not fed to the stream parser (iTerm2 feeds it; no dialect turns an error body into visible text, so nothing changes); the body still reaches `error_reason`. Cost if wrong: none visible.
5. WinHTTP failures read as Apple's texts for the five common codes, otherwise the system's WinHTTP message. Cost if wrong: rarer errors read as Windows words.
6. The verbose console log goes to `OutputDebugStringW` with "Tandem AI: " (DebugView or a debugger shows it; there is no system console log a person reads on Windows). Cost if wrong: a person without DebugView sees nothing.
7. The wire log scrubs the failure record too. Cost if wrong: none.
8. The discovery cache persists to `%APPDATA%\Tandem\ollama-models.json` (iTerm2's shape under its `NoSyncOllamaDiscoveredModels` key), not `settings.toml`, so a refresh every five minutes never rewrites the settings file. Cost if wrong: a second file in Tandem's folder.
9. Every Responses function schema gets `additionalProperties: false` (iTerm2 loses it for raw-JSON schemas). Cost if wrong: a tool whose schema allows extra properties is rejected by strict mode; none of the 26 tools does.
10. An Apple Intelligence model reaching the turn (an imported manual entry with api 8) fails with "Apple Intelligence is not available on Windows." (ruling 7). Cost if wrong: none.
11. The App Review text says "your PC" for "your Mac" and keeps iTerm2's "Settings > AI" path. Cost if wrong: one sentence of wording.
12. The user agent is "Tandem". Cost if wrong: none.
13. Userinfo in a model or discovery URL is dropped on the wire (WinHTTP's `WinHttpConnect` takes no userinfo; URLSession sends it as Basic auth); it is kept in server labels. Cost if wrong: a `user:pass@host` Ollama URL needs an `Authorization` custom header instead.
14. String lengths in `truncate`'s halving and in fingerprints count Rust `char`s (Swift counts grapheme clusters). Cost if wrong: a cut can fall inside a combining sequence.
15. An `AI Timeout` of 0 or below means no idle timeout (WinHTTP's 0 is infinite); 12a leaves the value unbounded and gives 12b the choice. Cost if wrong: a dead connection with that setting hangs until the person presses Stop.
16. Test Connection passes 12a's consent gate for the probe's host before its request (ruling 1: no request leaves without consent for its host; iTerm2's Test Connection likewise went through the plugin gate); Ollama discovery and the probe sheet do not (iTerm2 calls URLSession directly for discovery, and it sends no user content). Cost if wrong: discovery reaches a configured Ollama server before any consent was given for that host.

### Questions for the controller (answered: rulings 12b-1 to 12b-5 confirm each default below, in order; Decision 16 is ruling 12b-5)

1. The WinHTTP transport's own tests talk to a `TcpListener` on `127.0.0.1` port 0 inside the test with the proxy forced off; nothing resolves a name or leaves the machine. Is loopback allowed under "tests never touch the network"? Recommendation: yes; otherwise the real transport (timeouts, cancellation, chunking) has no automated test at all and rests on the manual checklist.
2. iTerm2 drops a streamed chunk that splits a multi-byte UTF-8 character (Correction 1): fix (carry the partial bytes, the plan's default) or keep? Recommendation: fix, recorded as an iTerm2 bug in the ruling-10 style; without it any non-ASCII answer can lose words mid-stream.
3. An Anthropic mid-stream `error` event (for example `overloaded_error`) is dropped by iTerm2, leaving an empty or cut-off answer with no error: surface it as "Error from Anthropic: <message>" with the streamed "Request failed" block (the plan's default), or keep? Recommendation: surface it; it is the same class as ruling 10's fixes.
4. Cancellation: iTerm2 has one global task slot, so cancelling (for example a Composer suggestion) cancels whichever request started last, possibly a chat turn. The plan cancels per request (each `Call` owns its handle). Recommendation: per request, recorded as a fixed iTerm2 bug.
5. Consent for Ollama discovery: iTerm2's discovery bypasses the plugin gate, and it sends no user content, so the plan leaves `/api/tags` and `/api/show` ungated (Decision 16) while Test Connection and every model request pass 12a's per-host consent. Recommendation: ungated, as iTerm2; the alternative asks for consent before the Regular/Budget pickers can even fill.

### Pitfalls for the implementer

- `serde_json` has `preserve_order`: `Value` equality ignores key order (compare bodies as `Value`s for the unsorted dialects), but `to_string` keeps insertion order, so Responses and Anthropic must go through `ai_json::sorted` and their tests compare bytes.
- Swift's `trimmingLeadingCharacters(in: .whitespacesAndNewlines)` in the splitters trims "\r" and "\n" too; `str::trim_start` matches.
- `tokens` is integer division of the UTF-8 byte count; `max_tokens` can go to zero or below (Responses sends it anyway).
- Never format a `HttpRequest` header value, a URL holding a Gemini key, or a `Secret` into an error, a log line, a panic message or a test assertion message; assert on `contains`/`!contains` with a message that names only the header.
- Closing a WinHTTP request handle from the UI thread is the supported way to abort a synchronous call; close it exactly once (the worker must not close it again after a cancel), and keep the body buffer alive until `WinHttpSendRequest` returns.
- `Recorded` must produce events through the same `events_for` the WinHTTP worker uses, or the dialect tests stop describing the real transport.
- The settings window only repaints on input unless asked: while a probe, a fetch or a test runs, request a repaint each frame (`ctx.request_repaint_after(100 ms)`), and wake the loop from the transport's `notify`.
- A 12a panel function signature change ripples into its callers in `settings_ui.rs`; change them all, never add a parallel panel.
