**Scope (read first):** research `.superpowers/research/m13-facts.md` section 2 (the last bullet: "Tandem closes every pane the moment its shell exits"), section 5 "13q Session end, archives, logging" (all 8 items), section 6 R3 and R5, and the 26 Appendix A rows whose Part is `13q`; `.superpowers/research/m13-rulings.md` (R2, R3, the parity-corrections line); and the Resume notes below, and nothing else: what happens when a session's program ends ("After a session ends": No Action, Close, Restart), the in-buffer end message with its divider, the restart offer and its suppression, Restart Session keeping the pane's contents, the short-lived session warning and its per-profile switch, tmux panes after a detach and the "Close tmux windows after detaching?" question, git's single-use windows ending with "Finished", session logging (automatic and Session > Log > Log to File; raw, plain text, HTML and asciicast; file names, appending, timestamps, compact logging with the Auto Composer), session archives (Shell > Archives > Save Archive of Current Session..., Restore Archive..., the recent archives, Archive On Closure), killing hosted sessions at logoff, and the two session-server rows (`Multiserver`, `UseNewContentFormat`) under ruling R5. The warnings pane rows are 13b; the Advanced pane's own search and popups are 13a.

**Goal:** a person whose shell exits sees what iTerm2 shows: with a profile set to "No Action" the pane stays with a blue "Session Ended" divider and a "Session ended (command exited). Restart it?" offer; "Close" closes it (warning first when it lived under three seconds); "Restart" starts the program again a second later in the same pane with its history kept; a detached tmux window stays or closes as they choose; they can log any session to a file in four formats, automatically or from the Session menu, and save, reopen and auto-save session archives from the Shell menu.

**Architecture:** pure models first, each a plain `pub mod` tested on the Windows test machine. `session_end.rs` is the end action, the outcome of an exit and of a tmux detach, the end message line, the short-lived rule, the logoff rule, and every text. `session_log.rs` is logging: styles, file names, the cooked-text parser (a `vte::Perform`), iTerm2's timestamp and HTML encodings, the asciicast records, and a `Logger` over a `Sink` (a real file sink writes on its own thread). `archive.rs` is archive names, the archive window table and the recent list. `Screen::append_end_message` (in `src/trigger_eval.rs` beside `print_message`) draws the message. The app side: `src/app/session_end_ui.rs` (the exit, the restart, the bars, the short-lived warning and its alert queue), `src/app/log_ui.rs` (starting, stopping, the menu), `src/app/archive_ui.rs` (save, auto-save, restore, the recent menu), `src/app/logout_ui.rs` (`#[cfg(windows)]`, WM_ENDSESSION). Per-pane state (`ended`, creation times, `auto_log_id`, the logger, `archived`) lives on the `Pane`; the pending restarts, the alert queue and the recent archives are app-wide; no new field is per window, so `swap_live` is untouched.

**Tech Stack:** as milestones 0 to 12 (winit 0.30, egui 0.36, muda). No new crates: `alacritty_terminal::vte` (the `Parser` and `Perform` of the vendored vte 0.15, for cooked text), `unicode-width` (`Cargo.toml:14`, divider widths), `serde_json` with `preserve_order` (`Cargo.toml:28`, asciicast), `rfd` (save and open dialogs), `plist` through `arrangement::{to_plist, from_plist}` (archives), `getrandom` (the auto-log id), `windows-sys` `Win32_UI_Shell` (`SetWindowSubclass`, already enabled).

### Decisions (each goes in `m13q-rulings.txt`)

- R5 (ruled as recommended): `Multiserver` and `UseNewContentFormat` are stored and shown and read by nothing. Tandem always runs one tandem-host.exe for every shell (iTerm2's YES), and its restoration keeps capped styled contents while archives keep everything. Cost: a person who turns either off sees no change.
- `sessionShouldAutoClose` is always true (Tandem has no split drag that a close could break; 13h's pane moves are modal). Cost: a pane ending mid-drag closes under the drag.
- An empty `SessionEndMessageDividerCharacter` draws U+2500 in iTerm2's divider blue in place of the BrokenPipeDivider image (Tandem has no inline native images in the grid). Cost: a thin line instead of iTerm2's picture.
- The end message restores the default colors, not the program's (the program has ended; a restart resets modes anyway). Cost: none visible.
- `TmuxWindowsShouldCloseAfterDetach` is a 13a optional bool (unset, false, true; shown as 13a's Unspecified/No/Yes popup), as iTerm2's DEFINE_SETTABLE_OPTIONAL_BOOL; the 13p-r ruling's enum stand-in is not needed because 13a lands first (build order). Cost: none.
- `_tmuxWindowClosingByClientRequest` is always false (Tandem closes tmux windows through tmux, never by detaching). Cost: none known.
- Restart Session over a live shell ends the old shell and starts the new one at once, instead of waiting for the old one's broken pipe. Cost: the old shell's last output after the kill is not shown.
- A relaunch failure shows the error as the end message and "Session failed to start." as a bar with no buttons (iTerm2 shows it without a question). Cost: none.
- The login-shell "shell does not exist" warning is not built (Tandem's default shell is found before the pane starts, and a missing one never starts). Cost: none.
- The short-lived warning and every logging question go through 13b's queued alert windows (the 13b ruling), not sheets on the pane's window. Cost: one can open over another window.
- The logging style question names the last used style in its text ("Last used: HTML") because 13b's alert has buttons, not a popup with a preselected item. Cost: one more line of text than iTerm2's popup.
- A log or archive folder on a network share is never checked or created (UNC invariant): no "Logging Folder Not Found" question and no Replace/Append question for a UNC path; the writer thread opens it (replacing unless appending was chosen) and a failure shows "Couldn\u{2019}t write to session log". Cost: a missing share folder is reported only as a write failure.
- Log file names replace Windows-invalid characters with "_" after iTerm2's "/" to "__". Cost: a name with ":" differs from iTerm2's.
- `LogTimestampFormat` is applied as a pattern, not localized as a template (`cacheableFormatterWithTemplate` localizes, UNVERIFIED which pattern it yields). Cost: the default shows 12-hour "hh" with no AM/PM, as the pattern says.
- HTML logs escape `&`, `<` and `>` (iTerm2 writes the text raw, which lets output inject markup into the log). Cost: a byte-for-byte diff with iTerm2's HTML.
- The HTML stylesheet's properties are in a fixed order (Swift's dictionary order is unspecified). Cost: none.
- Log to File asks the style in a second small window after the save dialog, remembered under `NoSyncLoggingStyle` (rfd has no accessory view). Cost: one more click.
- Cooked text comes from a vte parse of the output (printable characters and line feeds), not from the grid's appended text. Cost: text an app draws by cursor movement is logged in output order, as iTerm2's appended-string hook also does.
- Archive On Closure writes at the close, also for a close kept for Undo Close (iTerm2 writes when the undo time runs out). Cost: an undone close leaves an archive file behind.
- The automatic archive name uses iTerm2's en-US short date and medium time with ":" made "." ("9-27-26_3.04.05_PM"), since Windows file names cannot hold ":". Cost: differs from iTerm2 in other locales.
- A restored archive window opens at its saved frame; `Archive.columns` and `rows` are kept but not applied (Tandem has no resize-to-cells). Cost: an archive restored on a smaller display wraps.
- An ended pane keeps its `Io` (ConPTY handles, OpenConsole or the host session record) until it closes or restarts, as the plan's `relaunch_from` expects (review recommendation considered, not taken). Cost: many ended panes each hold a console host process.
- The logoff hook kills hosted sessions from inside the window procedure (Windows may end the process right after WM_ENDSESSION returns). Cost: a slow host round trip delays sign-out briefly.
- Parity rows are found by title.

### Pitfalls for the implementer
