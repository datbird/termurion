The rest of the request surface (SendText through Screenshot, VariableRequest and VARIABLE_CHANGE, keystroke, prompt and screen notifications) is milestone 11b; registered functions and RPCs are 11c; the Scripts menu, Script Console, runtimes, AutoLaunch, `CustomScriptsFolder` and the other Advanced > Scripting rows are 11d; the utilities, `TERM_PROGRAM` / `LC_TERMINAL`, the utilities PATH and the `CSI 1337 n` version are 11e.

**Goal:** with "Enable Python API" on, the stock `iterm2` pip package, unmodified, connects to Tandem over `ws://localhost:1912` from any Tandem session (cookie in its environment) or from anywhere when "Allow all apps to connect" is chosen, and `await iterm2.async_get_app(connection)` returns an `App` whose windows, tabs, sessions, focus and broadcast domains match Tandem's and stay current as they change; every refusal is iTerm2's, with its code and reason.

**Architecture:** pure models first, each a plain `pub mod` tested on Linux and on EXTREME. `api_pb.rs` is prost code generated once from the vendored `proto/api.proto` by `tools/protogen` (a separate crate using prost-build with protox, so no `protoc` anywhere) and checked in; `api_proto.rs` holds the codec helpers. `api_http.rs` is the HTTP request parser and iTerm2's upgrade checks as a pure function. `api_peer.rs` maps a loopback TCP connection to its owning process (`GetExtendedTcpTable`, pure row matching plus a `#[cfg(windows)]` reader) and compares its user SID and elevation with Tandem's through `winpipe`. `api_auth.rs` is the cookie jar, the allow-all file's path and magic, the authorization decision and every alert text. `api_server.rs` (`#[cfg(windows)]`) owns the sockets: an exclusive listener per loopback family, a thread per connection that runs the peer check, reads the request, validates it, waits for the UI thread's verdict, answers 101 and then carries binary frames with tungstenite (`WebSocket::from_raw_socket`, framing only). Events reach the UI thread through a channel and the existing wake (`Notify`). `session_env.rs` builds the session variables and the Windows environment block. `api_dispatch.rs` is subscriptions and transactions. `api_vars.rs` is the variable store. `api_model.rs` is a pure snapshot of windows, tabs, sessions, focus and broadcast domains, the three answers built from it, and the diff that yields notifications. The app side is `src/app/api_ui.rs` (server lifetime following the setting, alerts, the event pump, the transaction freeze, the model snapshot, the notification tick). All App fields it adds are app-wide, not per window, so none goes in `swap_live`.

**Tech Stack:** as milestone 10b, plus: `prost = "0.14"` (runtime and derive only); `tungstenite = { version = "0.28", default-features = false, features = ["handshake"] }` (framing, `derive_accept_key`, and the test client); `getrandom = "0.4"` (already in `Cargo.lock` through `uuid`; 16 random bytes per cookie); the `windows-sys` feature `Win32_Networking_WinSock` (new feature, not a new crate: `WSASocketW`, `setsockopt` with `SO_EXCLUSIVEADDRUSE` and `IPV6_V6ONLY`, `AF_INET`/`AF_INET6`). `GetExtendedTcpTable` is in `Win32_NetworkManagement_IpHelper`, already enabled (`Cargo.toml:46`). `tools/protogen` (not a dependency of Tandem) uses `prost-build 0.14` and the `protox` release that targets it.

- iTerm2 checks the peer before reading the request (`S:457-472`), validates, asks the main thread to authorize, and only then upgrades (`S:529-592`); the connection waits for the answer. ### Peer check

- `GetExtendedTcpTable(buf, &mut size, FALSE, AF_INET or AF_INET6, TCP_TABLE_OWNER_PID_CONNECTIONS, 0)`; rows `MIB_TCPROW_OWNER_PID { dwState, dwLocalAddr, dwLocalPort, dwRemoteAddr, dwRemotePort, dwOwningPid }` and `MIB_TCP6ROW_OWNER_PID { ucLocalAddr[16], dwLocalScopeId, dwLocalPort, ucRemoteAddr[16], dwRemoteScopeId, dwRemotePort, dwState, dwOwningPid }`. Ports are in network byte order in the low 16 bits; IPv4 addresses are the in-memory bytes of the address (so `0x0100007F` read as little-endian is 127.0.0.1).
- The table holds both ends of a loopback connection: the client's row (local = the peer's address) and Tandem's own (local = 1912). Only the first names the peer.

### Corrections to the research (the source wins)

- Upgrade refusals other than a too-old library are 400 Bad Request, not 401; only the peer check and authorization answer 401 (`S:470`, `S:581`, `S:604-608`).

### Decisions (each goes in `m11a-rulings.txt`)

- The peer check is the owning process of the loopback connection (`GetExtendedTcpTable`) with the same user SID and the same elevation as Tandem, as research section 10 proposes, instead of the process-ancestry check the brief mentioned: iTerm2's check is the peer's euid, not its ancestry, and ancestry would refuse scripts started from Explorer or a scheduler. Cost: any program running as the user at the same elevation passes the peer check (then needs a cookie or allow-all), exactly as any same-euid process reaches iTerm2's socket.
- Elevation must match too (a Windows addition): a normal process may not drive an elevated Tandem, nor the reverse. Cost: a script started elevated cannot reach a normal Tandem.
- Protobuf: `prost` 0.14 with the generated code checked in (`src/api_pb.rs`), made by `tools/protogen` (prost-build plus protox, no `protoc`), rather than a build script: EXTREME has no `protoc`, and a checked-in file keeps Tandem's build free of code generation. Cost: regenerating after a proto change is a manual `scripts/xt run --manifest-path tools/protogen/Cargo.toml` and an `scp`; `proto_is_vendored_unchanged` catches a forgotten one.
- Websocket: `tungstenite` 0.28, framing only (`WebSocket::from_raw_socket`, `derive_accept_key`), with Tandem's own HTTP parsing so iTerm2's checks, order, reasons and 400/401/406 answers are exact (tungstenite's own handshake refuses with its own errors and no HTTP response). Cost: one new crate with its small dependency set (`sha1`, `http`, `httparse`, `rand`, `data-encoding`, `utf-8`).
- Threads, not async: an accept thread per listener and a thread per connection, events posted to the UI thread through a channel and the existing wake, as tandem-host's pipe threads do. Connection threads poll their socket every 10 ms to interleave writes. Cost: up to 10 ms added latency on a reply; a thread per connected script.
- `getrandom` 0.4 (already in the lock through `uuid`) makes cookies; `Win32_Networking_WinSock` is enabled for the exclusive bind. Cost: none.
- Loopback only, both families, port 1912, `SO_EXCLUSIVEADDRUSE` (the analog of iTerm2's `socket.lock`), backlog 5; a V6 stack that is missing is tolerated, a port in use is fatal and shows "The Python API could not start: ..." (Tandem's own text). Cost: WSL2 in NAT mode cannot reach the API (mirrored networking can).
- `X-iTerm2-Protocol-Version` is iTerm2's 1.19, so the package enables the same features; requests Tandem does not handle yet answer iTerm2's malformed error ("Invalid request. Upgrade Tandem to a newer version."), and so do NotificationRequests of types beyond the five. Cost: a script using an 11b request fails with an RPC error until 11b.
- Session cookies are reusable for the pane's life (removed when the pane is dropped for good), not single-use: the package deletes the cookie only from its own process, and Windows has no AppleScript fallback for the second script run from the same shell (research surprise 5). Cost: any process that reads a Tandem session's environment can connect as often as it likes while that session lives.
- There is no Windows twin of AppleScript's `request cookie and key`; the allow-all file and session cookies replace it. Cost: a script started outside Tandem needs "Allow all apps to connect", or it crashes in the package with FileNotFoundError for `/usr/bin/osascript` (kept, research surprise 3).
- "Allow all apps to connect" is stored as iTerm2's allow-all file at `%USERPROFILE%/Library/Application Support/iTerm2/disable-automation-auth` with the magic the package checks (research surprise 4), and Tandem reads the choice from that file as iTerm2 does; no administrator prompt. Cost: any program running as the user can turn allow-all on by writing that file (on macOS it must be root-owned); such a program could equally rewrite Tandem's settings.
- The popup's first item is "Require a cookie" and the allow-all warning's second paragraph is Windows text (no Automation permission and no administrator step exist); reasons naming a Settings location use Tandem's ("Settings > General > Python API"). More Info links stay iTerm2's pages (Tandem has no documentation site). Cost: those pages describe macOS.
- "Reveal In Finder" is "Show in Explorer" (m10b's Windows-words ruling). Cost: none.
- Session ids are the pane id in decimal (as the `id` variable and arrangements' "Session GUID" already are), window ids `pty-<UUID>` minted by the Registry, tab ids the stable `Tab.id`. Cost: session ids are not stable across a restart (iTerm2 keeps GUIDs through restoration).
- The session environment in 11a is `ITERM2_COOKIE`, `ITERM_SESSION_ID`, `TERM_SESSION_ID` and `ITERM_PROFILE`; `TERM_PROGRAM`, `TERM_PROGRAM_VERSION`, `LC_TERMINAL`, `LC_TERMINAL_VERSION`, `COLORTERM` and the utilities PATH wait for 11e with the version fix they depend on. The window, tab and pane numbers are those at launch (iTerm2 does the same). Cost: tools that look for `TERM_PROGRAM=iTerm.app` do not see Tandem until 11e.
- The host protocol goes to version 3, meaning "honors Launch's env"; no new message. A running older tandem-host keeps serving and its new sessions lack the variables until it restarts. Cost: after an upgrade without a host restart, scripts in new hosted sessions have no cookie.
- Notifications come from a diff of a pure model built on each loop pass while any connection subscribes (not from hooks at every call site): order NEW, TERMINATE, LAYOUT, FOCUS, BROADCAST; layout compares structure (ids, order, split trees, selected tab, active sessions, buried and minimized, tmux ids), never frames, grid sizes or titles. Cost: several changes in one pass arrive together, and a pure resize posts no layout change.
- Binary splits flatten same-axis chains into one split view, matching iTerm2's n-ary split views; a single pane is a vertical root with one leaf. Cost: none.
- Frames are Windows physical pixels with y down (the window's outer frame, a pane's rect within the window). Cost: scripts doing macOS screen arithmetic are off.
- Windows are listed by window number (iTerm2 lists its terminal order). Cost: none visible.
- A transaction freezes the UI thread as iTerm2's does (no output drawn, no input handled) until its end or the owner's disconnect; new connections wait. Cost: a script that never ends its transaction hangs Tandem until the script exits.
- The Log keeps accept and refuse reasons in memory for the Script Console (11d). Cost: none.
- Parity rows are found by title.

### Pitfalls for the implementer

- Never bind `0.0.0.0` or `::`, not even in a test; use `Ipv4Addr::LOCALHOST` and `Ipv6Addr::LOCALHOST`.
- Set `SO_EXCLUSIVEADDRUSE` before `bind`; std's `TcpListener::bind` cannot, which is why `bind_exclusive` builds the socket itself. Set `IPV6_V6ONLY` on the V6 socket.
- `GetExtendedTcpTable` ports are big-endian in the low 16 bits of a `u32`; compare after `port_from_table`, never the raw value. The first call is only for the size; the table can grow between calls, so retry.
- Match the client's row (local == peer), not Tandem's own row for the same connection, or every connection looks like Tandem itself.
- prost omits `None`: set every status explicitly, or the Python side reads the default and misses a field presence iTerm2 always sends.
- The package deletes `ITERM2_COOKIE` from its own environment after connecting; a test that connects twice needs the cookie set again (or a Session cookie).
- Recent `websockets` releases drop the legacy client the package imports first; if the stock-package test fails with an `extra_headers` TypeError, pin `websockets<14` in the venv.
- `api_freeze` must still take `Closed` events, or a script that dies mid-transaction hangs Tandem for good.
- A cookie is a secret: never put it in `Log`, a banner, a panic message or a test's printed output.
- `ConfirmResult` gains a variant: add the arm in every `match` over it (the compiler lists them); `matches!` uses are unaffected.
- Every new App field here is app-wide; do not add them to `WinSlot` or `swap_live`. `api_model` enters windows to read their tabs: restore the window that was current before returning, as `snapshot_all` does.
- `variables_with` changes `tab.id` from the tab's index to its stable id (iTerm2's value); grep for consumers of `tab.id` (badges, titles, triggers) and check none relied on the index.
