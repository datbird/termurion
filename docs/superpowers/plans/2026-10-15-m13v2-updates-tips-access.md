### Decisions (each goes in `m13v2-rulings.txt`)

- Updates come from the GitHub releases API of `datbird/tandem` with no token; the URL is one constant for the controller to change. Cost: while the repository is private every check finds nothing, silently (a 404 or 401 is no update information, the 13v/13w ruling); other HTTP errors and transport failures show "Update Error!" only for a manual check (R13vw-1).
- The update window is Sparkle's informational form (Learn More opens the release page); nothing is downloaded, installed or replaced. Cost: updating is manual.
- A leading "v" in a tag is dropped before comparing; release names are ignored. Cost: tags must carry the version.
- Before the second-launch question is answered, no automatic check runs although the checkbox shows iTerm2's default (checked); `SUEnableAutomaticChecks` is read raw and kept even when it equals the default (`EXPLICIT_KEYS`, R13vw-2). Cost: the checkbox and the behavior differ until answered, as in iTerm2.
- Sparkle's em dash in the update text becomes parentheses (no em dashes in Tandem). Cost: the text differs from Sparkle's.
- Two macOS-only tips (`0066`, `0105`) are dropped; Mac key glyphs become Windows words by a fixed table. Cost: tip keys no longer match iTerm2's set exactly (the keys that remain are iTerm2's).
- The tip card takes Esc only while it has focus. Cost: Esc in another app does not dismiss it.
- Share copies the tip to the clipboard. Cost: no share sheet.
- The Dynamic Profiles folder is read recursively, as iTerm2's `enumeratorAtPath:` (`DP:293-295`), and a subfolder's own entry fails to read and adds iTerm2's "Ignoring dynamic profiles in ..." error, as in iTerm2. Cost: a person who keeps subfolders there sees that error, as iTerm2 users do.
- Dynamic profile removal keeps sessions on their session copies; browser profiles in files are kept until 13x. Cost: a removed profile's sessions keep its settings until closed.
- (Superseded in the M13 integration pass: 13b's `Kind::Temporary` gives the "Changes Will Be Lost" and "Dynamic Profiles Error" warnings iTerm2's ten-minute silence, so no session-only Decision remains.)
- Menu tips are text in a tooltip; images are left out. Cost: less than iTerm2's picture tips.
- Menu tips find their item by its shown label and its parent's label (the Win32 menu does not carry muda's ids), then by iTerm2's identifier. Cost: two items with the same label under the same parent would share a tip (none do today).
- The license list is gathered by `build.rs` from the crates' own license files. Cost: a crate without a license file shows only its SPDX line.
- Copy Mode Shortcuts opens the page in the default browser until 13x. Cost: not a Tandem tab.
- UI Automation: each pane is a Text control named "shell" in a Pane control for the window; Format units are words, Paragraph units lines, Page units the document; iTerm2's announcements are notification events with processing ImportantAll. Cost: a screen reader may speak differently from VoiceOver.
- Only the current window publishes snapshots; parked windows answer from their last one. Cost: a parked window's text is stale until it is current.

### Pitfalls for the implementer

- Tests never run `curl.exe` against anything but the loopback listener of `curl_reports_the_status`; the `Checker` test uses a fake `Fetch`.
- Never pass `--fail` to curl: the status must come back in `--write-out` so a 404 or 401 can be told from a real error (R13vw-1).
