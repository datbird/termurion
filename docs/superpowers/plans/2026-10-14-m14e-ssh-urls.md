Every new App field is app-wide or keyed by pane; none goes in `swap_live`.

## Review Focus

1. Hostile or odd URLs: a user name with a space, `;`, `$(`, a quote or a non-ASCII letter; a host starting with `-` (an ssh option), holding `/`, `@` or a space; a port that is not a number; a path with a quote, backslash, CR, LF or NUL (the cd part silently dropped, iTerm2's); `/~` paths; percent-escapes; an IPv6 host; a URL with a password; a URL that does not parse. Test: Task 1 `usernames_follow_iterm2`, `hostnames_follow_iterm2`, `url_parse_follows_iterm2`, `ssh_commands_follow_iterm2`.
2. The two command forms: with integration on the profile becomes the SSH type, without it a Custom command; both are Windows command lines whose arguments reach `it2ssh.exe` or ssh.exe as iTerm2's shell would have passed them (no `\+`, no `\$SHELL`, the cd path POSIX-escaped for the remote shell), `sshSchemePath` used unless it is "ssh" or has no letter or digit; a bound profile with its own custom command keeps it. Test: Task 1 `ssh_commands_follow_iterm2`, `profile_for_url_follows_iterm2`.
3. Scheme binding: the profile control's check follows "bound here and Tandem is the default"; binding asks only when Tandem is not the handler, with "There is currently no handler." or "The current handler is: <name>"; unticking only unbinds; a handler Windows' user choice protects is reported, not overwritten. Test: Task 2 `scheme_binding_follows_iterm2`, `registration_follows_windows`.
4. Receiving: `tandem.exe --url <url>` with Tandem running hands the URL over the pipe to that instance (only one run by the same user, never an elevated one to a normal one) and exits; with none running it starts and opens the tab after the first window; a Win-click on an `ssh:` link opens the tab only when a profile is bound, else stays refused. Test: Task 3 `url_arguments_follow_windows`, `pipe_message_follows_the_rule`, `url_pipe_carries_one_url`, `url_open_follows_iterm2`.
5. The host stack: a new host pushes the previous host's key mode and title; returning to a host on the stack pops to it and restores the key mode; a user-only change, two local hosts, a first host report, or the setting off do nothing; the title offer honors "Allow Title Setting" and the remembered Always or Never. Test: Task 4 `host_stack_follows_iterm2`, `title_offer_follows_iterm2`.

- A bad host name opens nothing silently (iTerm2's). Cost: a mistyped link seems to do nothing.
- Win-click on an `ssh:` link with no bound profile stays refused (Tandem does not pass `ssh:` links to Windows). Cost: an unbound link does nothing.
- `$$` URL substitutions in a bound profile's custom command are not ported (the command is used unchanged unless it is exactly "$$"). Cost: `$$HOST$$` stays literal.
- The host stack saves and restores Tandem's one title for iTerm2's icon and window names. Cost: an icon-only title change is not seen.
- Kept iTerm2 quirks: kitty key flags are not restored; the `-t` stays when an unsafe path's cd part is dropped. Cost: as iTerm2.
- Parity rows are found by title.

### Pitfalls for the implementer

- Never build a command line from URL parts that did not pass `username_ok` and `hostname_ok`; a host starting with `-` would be an ssh option.
- Percent-decoding can produce CR, LF or NUL: the path check runs after decoding, as iTerm2's `url.path` is decoded.
- Do not write `HKLM` and never touch a `UserChoice` key; Windows resets associations written there.
- The URL pipe must be bound only by a Tandem that is actually listening; a second instance that fails to bind must still start normally when it has no URL, and hand over when it has one.
- Read `std::env::args_os` before the event loop exists (`run`), and exit before any window opens when the URL was handed over.
- The URL's session copy is one per opened URL; never change the bound shared profile itself.
- `host_stacks` is keyed by pane and dropped with it; it is not in `swap_live`.
- The title offer bar and its pending title are per pane; Always and Never must also resolve other panes' pending offers.
