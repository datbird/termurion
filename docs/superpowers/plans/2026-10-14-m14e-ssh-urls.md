### Decisions (each goes in `m14e-rulings.txt`)

- Remote host can control iTerm2 (`03:73`) n/a (ruling 3); wrap (`03:383`) and `channelsEnabled` (`02:1122`) n/a (ruling 4); `channelsEnabled` is not stored. Cost: none.
- Only the `ssh` scheme is handled in milestone 14. Cost: other schemes still missing.
- Both ssh: command forms are Windows command lines (the user and host unescaped, the remote command with `$SHELL`, only the cd path POSIX-escaped), since 14a hands `Command` to `it2ssh.exe` or ssh.exe through `CreateProcessW`; iTerm2's `\+` and `\$` exist for its local shell. Cost: the profile's Command text differs from iTerm2's for the same URL.
- `Run Command In Login Shell` is set as iTerm2 sets it and has no effect on Windows. Cost: none.
- Registration writes only `HKCU` keys after the person's OK; a scheme Windows' protected user choice gives another app is reported with Tandem's text and not bound. Cost: the person must pick Tandem in Default apps.
- Registering overwrites another program's `HKCU\Software\Classes\ssh` command without keeping it, so unticking cannot restore it. Cost: the other program must be re-registered by its own installer or settings.
- The handler command stays `"<exe>" --url "%1"`, and `tandem.exe` accepts only the exact argv `[exe, "--url", one ssh URL without a quote]`; a bare URL, extra arguments, a second `--url` or a quote are refused and logged (R14de-9; the classic protocol-handler argument injection). Cost: a launcher that passes the URL bare does not work.
- The URL pipe reads with a 2 s overlapped wait then `CancelIoEx`, so a client that connects and sends nothing is dropped (R14de-10). Cost: a client slower than 2 s loses its URL.
- `URLHandlersByGuid` is a `Globals` value with no settings row, pruned of deleted profiles; the "URL schemes:" control is a custom control on Profiles > General that stores nothing in the profile (R14de-11). Cost: none.
- Unticking leaves Tandem registered, so browser `ssh:` links still open with the default profile (iTerm2's `getUrl`, `AD:2303-2306`, the same); only a Win-click in a pane is refused again. Cost: as iTerm2.
- A URL that does not parse opens nothing (iTerm2 opens bare `ssh` in the default profile, `SL:489-493`). Cost: a malformed link seems to do nothing.
- With integration on and no host, nothing opens (iTerm2 runs `it2ssh` with no host, which prints its usage; Tandem's blank SSH Command would start the default shell). Cost: none.
- `sshSchemePath` is inserted raw, as iTerm2 (`SL:578`), so it may carry arguments and a path with spaces must be quoted by the person. Cost: an unquoted `C:\Program Files\...` value fails to start.
- The cd path always uses the backslash escaping; iTerm2's `escapeWithQuotes` (`AS:860`, default NO) is not ported. Cost: none at the default.
- Host locality is decided when a host is reported and kept (a user-only report copies it; OSC 7 reports too), and two local hosts compare by user only, as iTerm2 (R14de-8). Cost: none.
- A clicked `ssh:` link opens a tab, not the click's style (iTerm2 opens a tab or window as the click says, `UH:293-299`, `PS:3713-3730`). Cost: a window-style click opens a tab.
- A URL handed to a running Tandem uses a per-user pipe (elevated and normal Tandems each have their own); the URL is limited to 8 KiB and one line. Cost: a huge URL does not open.
- Tandem raises its window for an opened URL (Windows does not activate the app as macOS does). Cost: focus moves.
- A hotkey-window profile bound to `ssh` opens a tab like any other (no hotkey window shown). Cost: differs for that setup.
- A bad host name opens nothing silently (iTerm2's). Cost: a mistyped link seems to do nothing.
- Win-click on an `ssh:` link with no bound profile stays refused (Tandem does not pass `ssh:` links to Windows). Cost: an unbound link does nothing.
- `$$` URL substitutions in a bound profile's custom command are not ported (the command is used unchanged unless it is exactly "$$"). Cost: `$$HOST$$` stays literal.
- The host stack saves and restores Tandem's one title for iTerm2's icon and window names. Cost: an icon-only title change is not seen.
- Kept iTerm2 quirks: kitty key flags are not restored; the `-t` stays when an unsafe path's cd part is dropped; `ssh://h/~/w` runs `cd \~/w`, which the remote shell does not expand (`SL:617-624`, `NS:162`). Cost: as iTerm2.
- Parity rows are found by title.

### Pitfalls for the implementer

- Never build a command line from URL parts that did not pass `username_ok` and `hostname_ok`; a host starting with `-` would be an ssh option.
- Percent-decoding can produce CR, LF or NUL: the path check runs after decoding, as iTerm2's `url.path` is decoded.
- Do not write `HKLM` and never touch a `UserChoice` key; Windows resets associations written there.
- The URL pipe must be bound only by a Tandem that is actually listening; a second instance that fails to bind must still start normally when it has no URL, and hand over when it has one.
- Read `std::env::args_os` before the event loop exists (`run`), and exit before any window opens when the URL was handed over or the command line was refused. Accept only the exact `[exe, "--url", url]` form; never add a second way to pass a URL (R14de-9).
- Never read the URL pipe with the blocking `Pipe::read`; use `read_timeout` so a silent client cannot stall the listener (R14de-10).
- Locality comes from `Remote::local`, set when the host was reported; never call `host_is_this_machine` at change time (R14de-8).
- The URL's session copy is one per opened URL; never change the bound shared profile itself.
- `host_stacks` is keyed by pane and dropped with it; it is not in `swap_live`.
- The title offer bar and its pending title are per pane; Always and Never must also resolve other panes' pending offers.
