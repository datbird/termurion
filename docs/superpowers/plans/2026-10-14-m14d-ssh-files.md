### Pitfalls for the implementer

- Never build a remote path with `Path::join`: `C:` rules and backslashes corrupt it. Use `remote_file::{posix_join, posix_parent, posix_standardize}`.
- The unique id of a fetch is local only; do not put it on the wire (iTerm2 does not).
- A reply for a finished job must be ignored, not panic: a premature failure leaves up to seven fetches in flight.
- `ssh_send` returns false with no framing conductor; feed the engine a -1 reply at once or the job waits forever.
- `App::ssh_apply(pane)` is 14b's effect loop; the transfer engine's applier is `ssh_transfer_apply`. Do not merge them.
- 14b's timeout fails the whole conductor: never leave a file command in flight that the remote will not answer (the zip exemption is the only one).
- Remove the Downloads temp on every failure path; it is a hidden file the person never sees.
- Keep Both or Replace is asynchronous (the alert queue): keep the finished temp until the answer; a silenced answer finishes at once.
- `SHOpenFolderAndSelectItems` needs COM on the UI thread; winit's drop target already initializes OLE there. If it returns `CO_E_NOTINITIALIZED`, call `CoInitializeEx(COINIT_APARTMENTTHREADED)` once first.
- Unzip only into the destination folder; never pass `-P` to tar.exe (it would allow absolute paths).
- The panel and its batches are app-wide fields; none goes in `WinSlot` or `swap_live`.
- A conductor that stops framing while the panel shows must update its hosts (`hosts_changed`), and pending panel requests for it complete with -1 through 14b.
- Search notifications arrive unasked; acknowledge every one, even for an old search, or the remote stops after 16.
