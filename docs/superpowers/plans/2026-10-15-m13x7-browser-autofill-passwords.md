**Scope (read first):** the shared contract of the 13x follow-up plans (`.superpowers/research/m13x-followups-contract.md`, restated in Global Constraints below), `docs/superpowers/plans/2026-10-15-m13x-webview2.md` (its names are consumed), `docs/superpowers/plans/2026-10-15-m13x2-browser-foundations.md` (only the contract names listed under Global Constraints), `docs/superpowers/rulings/m10b-rulings.txt` (the password manager and its secret rules), rulings `.superpowers/research/m13-rulings.md` (the 13x/13y section: full 1:1 parity, the "Browser sessions" partial row; "Browser follow-up plans ... questions 1-48", every recommendation accepted; R13x23-1 and R13x23-2, the isolated world; R13x67-2), and the Resume notes below, and nothing else: iTerm2's `sources/Browser/Autofill/` (the contact-card autofill buttons in pages, Fill All through Session > Open Autocomplete in a browser session, the field writer) and `sources/Browser/PasswordManager/` (the in-page password manager button, filling a user name and password into the page, the browser flavor of the password manager with its own source choice and items, HTTP basic authentication: the coordinator state machine, the credential store over the browser password manager, the sign-in prompt and the password manager picker). WebView2's own address autofill and password saving are turned off so only Tandem's path runs (the writer's recommendation, accepted with questions 1-48). The Settings page's "Manage Passwords" button is 13x8's; this plan gives it the call it needs.

**Goal:** in a browser pane a person sees iTerm2's autofill button on name, address, email and phone fields and fills the whole form from their contact card with one click (or with Session > Open Autocomplete); a key button on password and user name fields opens the browser password manager, whose Enter User Name, Enter Password and Enter Username & Password buttons type into the page (asking first when the focused field is not a password field); a site that asks for HTTP authentication gets iTerm2's sign-in prompt with Remember this password and Password Manager, a remembered credential signs in silently next time, and a wrong remembered password is never retried in a loop.

**Architecture:** pure models first, each a plain `pub mod` tested on the Windows test machine without a web view. `browser_autofill.rs` holds the autofill scripts (iTerm2's JS copied into `resources/browser/`), the request parser, the contact card and its field values, iTerm2's `prepareAutofillData`, the write script builder and a small per-pane operation queue (`Queue<T>`, iTerm2's `AsyncMutex`). `autofill_card_ui.rs` is the contact card editor (an `EguiHost` window). `browser_password.rs` holds the password button's handler parsing, the probe, write and focus scripts and the probe classification. `pwm_source.rs`, `pwm_credman.rs`, `pwm_cli.rs` and `pwm_adapter.rs` learn a `Scope` (Terminal or Browser) exactly as iTerm2's `PasswordManagerDataSourceProvider(browser:)` does, and `pwm_app.rs` opens the manager in browser mode with its own worker, source choice and authentication. `browser_basic_auth.rs` is a line-for-line port of iTerm2's `BrowserBasicAuthCoordinator` plus the account-name, challenge and origin helpers and `NavTracker` (WebView2's navigation events translated to the coordinator's events). `basic_auth_ui.rs` is the sign-in prompt window. The app side is `src/app/browser_autofill_app.rs`, `src/app/browser_password_app.rs` and `src/app/browser_basic_auth_app.rs`; every new App field is app-wide and keyed by pane (no `swap_live` entry), except that the password manager window keeps living in `pwm_window` (already in `WinSlot`).

**Tech Stack:** as milestones 10b, 13x and 13x2. No new crate: `serde`/`serde_json` (the card file, messages), `webview2-com` 0.39.1 (13x) for `ICoreWebView2Settings4`, `ICoreWebView2_10` (BasicAuthenticationRequested), `ICoreWebView2_2` (WebResourceResponseReceived) and the NavigationStarting / ContentLoading events, `egui` through `EguiHost`.

### Navigation mapping (Decision)

- WebView2 events stand for WebKit's delegate calls, keyed by `NavigationId` (carried on 13x2's `Event::Starting` and 13x's `Event::Navigated` by Task 10's cross-plan change; no second navigation event is added): NavigationStarting (main frame, `IsRedirected` false) is `didStartProvisionalNavigation` with the URI as the origin (iTerm2 reads the origin from the navigation action, `BAM:147-150`, `:313-319`); NavigationStarting with `IsRedirected` true and the same `NavigationId` is `didReceiveServerRedirect`; ContentLoading of the live `NavigationId` is `didCommit`; NavigationCompleted with `IsSuccess` false and no ContentLoading is `didFailProvisionalNavigation`; WebResourceResponseReceived whose request URI, without its fragment, is the live main navigation's current URI without its fragment (a request URI never carries the fragment the NavigationStarting URI can) and whose status is not 3xx is `decidePolicyForNavigationResponse` for the main frame (`BAM:155-162`). WebView2 does not order that response before ContentLoading, so `NavTracker` holds the commit until the live navigation's response or its NavigationCompleted and always delivers the response first (WebKit asks the response policy before committing). BasicAuthenticationRequested (ICoreWebView2_10) is the challenge; its `Challenge` string is the `WWW-Authenticate` (or `Proxy-Authenticate`) value (scheme word and realm parsed), its `Uri` gives scheme, host and port. Per Microsoft's documentation it covers Basic, NTLM and proxy authentication; whether Digest reaches it is unverified, so every scheme other than Basic is prompt-only and never remembered (`BAC:276-279`), and a challenge from the configured browser proxy (13x's `BrowserProxyHost`/`BrowserProxyPort`) is prompt-only and never looked up or saved (Task 10 verifies which `Uri` WebView2 reports for a proxy; the fail-safe is prompt-only for every challenge while the proxy is on).

### Decisions (each goes in `m13x7-rulings.txt`)

- WebView2's own general autofill and password autosave are off in every view (`ICoreWebView2Settings4`), so Tandem's buttons and the password manager are the only paths, as WKWebView has none of its own. Cost: people who liked Edge's address bubble lose it inside Tandem (writer's recommendation, accepted with questions 1-48).
- The contact card replaces the macOS Contacts "me" card: a Tandem-held card in `autofill-contact.json`, opened for editing the first time a fill finds it empty. Cost: a person must type their details once; no label preferences (work, home, mobile) because the card holds one value per field (writer's recommendation, accepted).
- Scripts and ids reaching page scripts are JSON-escaped (iTerm2 substitutes field ids, names and the focus id raw). Cost: none; a page can no longer break Tandem's scripts with a crafted id.
- The autofill and password handlers use the view's 13x2 secret for iTerm2's `sessionSecret` (iTerm2 has one per manager and one app-wide). Cost: none.
- The in-page button emoji stay as iTerm2 draws them (web content, rendered with the system emoji font), not Segoe Fluent Icons. Cost: the buttons look like iTerm2's rather than Tandem's chrome (writer's recommendation, accepted).
- The browser password manager has its own worker thread, source choice and authentication (iTerm2's two providers). Cost: a person who uses 1Password for both unlocks it once for each.
- Basic-auth store jobs run on the browser worker with no manager window; a source that needs a master password prompt during a save fails the save with iTerm2's toast. Cost: with 1Password locked, Remember needs the manager unlocked once first.
- WebView2 navigation events stand for WebKit's (Navigation mapping); a 3xx main response is never treated as final. Cost: a server that answers the final page with a 3xx never confirms a saved credential (fail-safe, as flaw D).
- `DefaultHandling` answers Cancel (WebView2's own dialog is never shown). Cost: none; the coordinator never emits it today (`BAC:33-35`).
- Nothing logs a basic-auth user name, a card value or a password. Cost: fewer debug details than iTerm2.
- Autofill and the password button act only on trusted events (R13x67-2): Tandem's copies of `autofill-detector.js` and `password-button.js` return early from their click handlers unless `event.isTrusted`, each with a comment; it is the only edit to any copied file. iTerm2 has the flaw: a page script's `.click()` on the injected button made it post a genuine request, and autofill then filled the form from the contact card for the page to read. Cost: none for a person; a page can no longer trigger a fill or open the manager.
- Page-controlled ids and names and secret values go into script templates through `fill_once`, one pass that never rescans inserted text. Cost: none.
- The "not a password field" confirm has OK first and Enter answering OK (`ConfirmWindow::ok_cancel`), as iTerm2's NSAlert. Cost: none.
- Autofill writes, the password writer and Fill All all run through `browser_js_call` with `"return " + script`, where iTerm2 runs the writes in `.page` and Fill All in `.defaultClient`. Cost: none known; one call path keeps the no-log rule in one place.
- The autofill queue is per pane across requests, where iTerm2 makes a new writer and mutex per request (`AH:73`). Cost: a second request waits for the first to finish instead of interleaving.
- `autofill-fill-all.js` trusts `window.iTermAutofillDetectorLoaded` (`AFJ:27`); the flag lives in Tandem's isolated world beside the detector (R13x23-1), so a page cannot set it and Fill All cannot be made to report a false success (review M12's flaw exists only in a shared world). Cost: none.
- Basic-auth store jobs carry no owner window (`Job::Auth`); their replies and a browser-scope `info` are routed before any window lookup, so they never need a manager window and never overwrite the terminal manager's source info. Cost: none.
- A basic-auth picker whose window's one `pwm_window` slot is taken answers `PickerResult(None)`, bringing the prompt back with what was typed; iTerm2 opens a separate picker window. Cost: with a manager already open in that window, the person closes it before picking.
- Challenges other than Basic (Digest, NTLM, Negotiate) and every challenge from the configured browser proxy are prompted each time and never looked up or saved. Cost: a proxy password is typed once per session (WebView2 keeps it for the session).
- `origin_of` and `space_of` answer None for schemes other than http and https (iTerm2's default port is -1 there, `BAM:325`); such a challenge is cancelled. Cost: none (WebView2 raises basic authentication for http and https).
- WebView2's response and commit events are joined by `NavigationId`, the commit held until the response, fragments ignored when matching a response to its navigation. Cost: none known.
- Copied iTerm2 files stay in `resources/browser/` with their headers and iTerm2's GPL-2.0 license text beside them (ruling Q5 as amended, PROVISIONAL pending Robert). Cost if wrong: rewriting the eight copied scripts before a public release.

### Pitfalls for the implementer

- Never put a `Secret` into a format string, a banner, a toast, `Debug` output or a log line; a script text holding a password is itself a `Secret` and is dropped right after `browser_js_call` takes it.
- `BasicAuthenticationRequested` needs its deferral taken in the handler and completed exactly once from `answer_basic_auth`; a view closed with deferrals pending completes each with `Cancel`, or WebView2 keeps the navigation hanging.
- WebResourceResponseReceived fires for every request: compare the URI in `webhost_win` against the live main navigation's URI before posting, or the event channel floods.
- The pwm worker's replies route by window today (`pwm_reply`, `src/app/pwm_app.rs:1018-1066`) and store `info` first for every reply (`:1020-1022`): the new `Done::AuthLooked`/`AuthSaved` arms must be matched before the window lookup, or they are dropped when no manager is open, and a browser-scope `info` must go to `browser_info`, never `self.pwm.info`.
- The `isTrusted` check is the first statement of each copied click handler; do not move it after `preventDefault` or add other edits to the copied files.
- `pwm_window` is swapped per window: a picker opened for a basic-auth challenge lives in the browser pane's window; the challenge must still be answered (None) if that window closes.
- Client-world handler arms check both `World::Client` and the body's `sessionSecret`; a Page-world message is a page script and is ignored.
- The detector is main-frame only but the password button runs in every frame: a frame's message arrives as a 13x2 frame message; the host is still the main page's.
- `select` fields fill by option value, then option text containing the value (`AWJ:34-56`): keep iTerm2's order even though a short value can match a longer option.
