### Isolated world (R13x23-1; reverses writer question 1)

- iTerm2 injects its scripts into two WebKit content worlds: `.page` (the cloak, polyfills, the console wrapper, local pages, notifications, geolocation, the page half of audio) and `.defaultClient` (everything that must be invisible to the page: graph discovery, selection and context menu monitors, hover links, triggers, editing detector, the client half of audio, find, copy mode, named marks, autofill, passwords), registering a message handler by name in each (`BM:225-420`; graph discovery's and find's `world` is `WKContentWorld.defaultClient`, `iTermBrowserGraphDiscoveryHandler.swift:7`, `iTermBrowserFindManager.swift:71`). A `.defaultClient` script shares the DOM with the page but not its JavaScript globals or builtins.
- WebView2's `AddScriptToExecuteOnDocumentCreated` and `ExecuteScript` run only in the page's world. Chromium's DevTools protocol has isolated worlds, the mechanism Puppeteer's utility world uses: `Page.addScriptToEvaluateOnNewDocument { source, worldName }` runs a script at document start in a named isolated world of every new document of the target; `Page.createIsolatedWorld { frameId, worldName, grantUniveralAccess }` creates one in an existing document and answers its `executionContextId`; `Runtime.addBinding { name, executionContextName }` exposes a function `name(payload: string)` only in contexts with that name (including ones created later), and each call raises `Runtime.bindingCalled { name, payload, executionContextId }`; `Runtime.enable` makes the target raise `Runtime.executionContextCreated { context: { id, origin, name, uniqueId, auxData: { frameId, isDefault, type } } }` (`type` "isolated" for these worlds), `Runtime.executionContextDestroyed` and `Runtime.executionContextsCleared`; `Runtime.evaluate { expression, contextId, awaitPromise, returnByValue }` evaluates in one context and answers the value or `exceptionDetails`; `Target.setAutoAttach { autoAttach, waitForDebuggerOnStart, flatten: true }` attaches out-of-process (cross-site) iframes as child sessions (`Target.attachedToTarget { sessionId, targetInfo }`), each set up with the same calls and resumed with `Runtime.runIfWaitingForDebugger`. WebView2 reaches all of it: `ICoreWebView2::CallDevToolsProtocolMethod`, `ICoreWebView2_11::CallDevToolsProtocolMethodForSession`, `ICoreWebView2::GetDevToolsProtocolEventReceiver` with `add_DevToolsProtocolEventReceived`, and `ICoreWebView2DevToolsProtocolEventReceivedEventArgs2::SessionId` (all in `webview2-com-sys` 0.39.1).
- Tandem's equivalent of `.defaultClient` is the isolated world `tandem-client` (Task 0 and Task 1). It is set up before the view's first navigation; a failure leaves the view with no Client scripts (`ClientWorld::Unavailable`), never with Client scripts in the page world.

Tandem's suppression is native (`receiving_broadcast`), because DevTools `Input.*` events are trusted in the target page.

### Corrections to the research (the source wins)

- 13x said browser panes are excluded from broadcast; iTerm2 broadcasts typing between browser sessions (not to terminals) (`BM:882-899`, `PSB:398-407`).
- The selection helpers of iTerm2's browser menu are shared with its terminal menu (`CMH:440-460`); Tandem's terminal menu lacks them today (`src/app/semantic_ui.rs:236-285` has none).
- `GraphDiscovery` is not a WebKit replacement but iTerm2's own frame-tree protocol used by find and copy mode; it is ported with WebView2 frame ids behind it.
- The browser's Smart Selection uses UTF-16 counts and its own matcher (`WVA:306-377`), not the terminal's `select_at`.
- WebView2 does have an isolated-world path (the DevTools protocol's, as Puppeteer uses); the research's "WebView2 has no content worlds" holds only for `AddScriptToExecuteOnDocumentCreated`/`ExecuteScript` (R13x23-1 reverses writer question 1).
- iTerm2 copies the page selection only when "Copy to pasteboard on selection" is on (`iTermBrowserWebView.swift:78`); parity row `02:113` ("always on") is stale.

### Decisions (each goes in `m13x2-rulings.txt`)

- iTerm2's `.defaultClient` scripts run in Tandem's DevTools isolated world `tandem-client`, its messages arrive through `Runtime.bindingCalled`, and native calls into it use `Runtime.evaluate` (R13x23-1, reversing writer question 1). Cost: the DevTools protocol's isolated-world and binding methods are marked experimental in places (`worldName`, `executionContextName`); a runtime that drops them makes `ClientWorld::Unavailable` and those features inert, never unsafe.
- The probe is Task 0, numbered so the contract's task numbers stay valid; a skipped probe is not a pass. Cost: none.
- With the isolated world unavailable (probe failed, or setup failed on one machine), no Client script is injected; nothing that holds the secret runs in the page world. Cost: selection copy, hover URLs, the editing rule, pointer bindings in pages, broadcast, iframe find and copy mode are inert there (recorded partial).
- `Runtime.enable` is on for every browser view (the context events need it). Cost: if the probe reports a page can detect it, challenge pages may treat Tandem as automated (recorded with the probe's answer; the alternative, context ids from `Page.createIsolatedWorld` answers without `Runtime.enable`, is left to the controller).
- `window.webkit` is never defined; iTerm2's scripts are rewritten textually at load, at identifier boundaries only. Cost: a copied file whose string literal says "window.webkit" is rewritten too (none does); `webkitAudioContext` is untouched.
- Five contract names change for R13x23-1 (`wrap`, `route`, `Routed.source`, `call_js`, and `RESULT_HANDLER`/`result_of` removed); 13x's `web_tick`/`browser_event` carry `event_loop` and 13x's `Event::Message` its source (13x produces both since the M13 integration pass). Cost: none left; the integration pass updated the other plans' consumed-name lists.
- One gate for opens (R13x23 fix pass item 3): `gate_refusal` is the network rule `nav_gate`, `nav_gate_tab` and the terminal's `semantic::guard_open` all run first. Cost: a percent-encoded or `\\?\UNC\` network link in a terminal, which Tandem opened before, is refused with a banner.
- `Event::Starting` is posted from Task 1, not Task 9, so the navigation resets of Tasks 1 and 2 have it. Cost: none.
- The frame graph uses 13x3's names (ruling Q2). Cost: none.
- Missing template includes panic only in debug builds. Cost: a packaging mistake shows as a broken feature instead of a crash in release.
- The context menu monitor is not installed; WebView2 reports the selection. Cost: none.
- "Search with <engine>" sits right after WebView2's items (WebView2 has no web search item to replace). Cost: a slightly different position.
- WebView2's own "Save as" and "Print" items are removed so iTerm2's items are not doubled. Cost: WebView2's own save dialog is reachable only through 13x4's Save Page As.
- The "Open Context Menu" pointer action shows Tandem's items only (no API opens WebView2's menu). Cost: no Back/Reload/Inspect in that menu.
- Color helpers are labeled with the color text and a swatch icon (WebView2 items need a label). Cost: text where iTerm2 shows only a swatch.
- Numbers group with "," and dates use a fixed form in the local time zone. Cost: not localized.
- Smart Selection action titles are the rule action's title, as Tandem's terminal menu. Cost: captures are not substituted into titles.
- Browser toasts and the hovered URL use a small non-activating popup window. Cost: one more window class.
- The hovered URL clears on hide, tab change, navigation and focus loss, not on the pointer leaving the view (WebView2 reports no pointer exit). Cost: the URL can linger while the pointer sits outside a focused view until the page's own mouseout fires.
- Sending text into a page falls back to DevTools `Input.insertText`, and copy uses the selection text instead of `execCommand('copy')`. Cost: rich formatting is not copied.
- Pointer bindings reach Tandem only for trusted presses in the gate table, which is pushed live into every world. Cost: none.
- Key bindings on unmodified character keys do not reach a focused page (WebView2 raises `AcceleratorKeyPressed` only for Ctrl/Alt chords and keys without a character). Cost: such bindings act only when the page does not have focus.
- "Run Command in Window" from a page refuses captures holding `% ^ & | < > "` or a control character (13p-r) and otherwise runs as Tandem's terminal runs it (`cmd.exe /c`, no terminal window). Cost: a legitimate capture with those characters is refused with a banner.
- Browser broadcast replays text and editing keys through DevTools, suppresses loops natively and never moves focus. Cost: IME composition and shortcut chords are not broadcast.
- A forged `IFRAME_GRAPH_DISCOVERY` window message can name frames to the graph, as in iTerm2; it cannot choose code or reach unregistered frames. Cost: at worst a find or copy-mode call runs in a frame of the same page that a page asked for.
- WebView2 redirects are recorded as iTerm2's Redirect (4); form submissions are recorded as Link or Other. Cost: history transition types differ slightly.
- A browser arrangement keeps the URL, not the back-forward list. Cost: Back after a restore does nothing.
- The page color comes from computed CSS. Cost: pages that paint with a canvas or an image report their CSS color.
- `session.mouseInfo` is not set by browser clicks (Tandem has no such variable yet). Cost: scripts reading it see nothing, as in terminals today.
- Console logging makes no Script Console entry (iTerm2 makes one only in debug builds). Cost: none in release.

### Pitfalls for the implementer

- The bridge capture must run before any page script: it is part of the document-start script itself, never deferred; a DocumentEnd script still captures at injection.
- `Runtime.addBinding` without `executionContextName` exposes the binding to the page's own world too: always pass it, and still check every `Runtime.bindingCalled` against `Contexts` (a page can create no context named `tandem-client` of type "isolated", but the check costs nothing).
- The world must exist before the first document: send the setup calls in order, wait for each answer, and only then run 13x's pending navigation; `Page.addScriptToEvaluateOnNewDocument` does not reach a document that already exists (that is what `Page.createIsolatedWorld` is for).
- Context ids are per session (and die with their document): key everything by session and id, clear on `Runtime.executionContextsCleared` and on `Target.detachedFromTarget`, and look the context up again for every call.
- A child session attached with `waitForDebuggerOnStart` stays paused until `Runtime.runIfWaitingForDebugger`: send it last, and on any setup failure still send it (the frame then just has no Tandem world).
- Never put the secret into the DOM, an attribute, a window message or a page-world script: only Client scripts and `Runtime.evaluate` expressions carry it.
- `AddScriptToExecuteOnDocumentCreated` runs in every frame; `main_frame_only` is the wrapper's `window.top !== window` check.
- `ICoreWebView2Frame` objects die with their frame: drop them on `Destroyed`, never keep a COM pointer in the app.
- `ContextMenuRequested` must take a deferral and return at once; complete it from `web_tick` through `answer_context_menu`; a view closed with a menu pending completes it with the native menu.
- The key gate runs inside the COM handler: no App borrow there; it reads only its `Rc<RefCell<KeyTable>>` and never blocks.
- DevTools `Input.*` calls target the page's focused element; never focus the target view or move OS focus to replay broadcast input (use `Emulation.setFocusEmulationEnabled` if a target drops unfocused input).
- A child web view covers anything the scene draws in its rectangle: announcement bars shrink the web view; toasts and hovered URLs use the popup window.
- `select-text.js` and the counts are in UTF-16 units; convert byte offsets from `fancy_regex` before passing them.
- Never pass a page-provided path to `ShellExecute` without `semantic::guard_open` and the confirmation.
