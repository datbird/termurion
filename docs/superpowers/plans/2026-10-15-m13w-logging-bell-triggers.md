### Decisions (each goes in `m13w-rulings.txt`)

- The debug log file is `%TEMP%\debuglog.txt` and the Stopped alert names the full path. Cost: the path differs from iTerm2's text.
- The header and footer carry Tandem's facts (version, monitors, Windows version, windows) in iTerm2's layout; no pinned messages exist. Cost: less detail than iTerm2's view dumps.
- `logToSyslog` writes to `OutputDebugStringW` (the prefix only, as iTerm2). Cost: needs a debugger or DebugView to read.
- The automatic-start notification's click is its "Disable" action. Cost: no separate button.
- Tandem logs a curated set of sites (Resume notes "Log sites"), never typed text or secrets. Cost: far fewer lines than iTerm2's thousands.
- Timer logs drop iTerm2's emoji and write "-" for its en dash. Cost: none.
- State sizes are written when saved windows are read, sorted by keypath. Cost: iTerm2's order is unordered.
- R5 (ruled in the 13v/13w rulings of `m13-rulings.md`, as this plan recommended): Capture GPU Frame exists only in debug builds (iTerm2 removes it from release builds) and uses wgpu's graphics-debugger capture; Check Settings Control Truncation is never shown (iTerm2 builds it only for development; egui Settings wrap); `debugShowPromptMarkRangesInLegacyRenderer` works in Tandem's one renderer without red excluded ranges (Tandem does not record them). Cost: none beyond the ruling.
- The Windows machine identity is "{MachineGuid}:{BootId}" hashed with iTerm2's key and algorithm; the PowerShell integration computes it once per session start. Cost: two registry reads per PowerShell start.
- The badge goes on every terminal window's taskbar button. Cost: several buttons show the same number.
- `.it2triggers` export writes each trigger in its canonical form (`dictionaryValue`, what iTerm2's own import stores) rather than the raw stored dictionary. Cost: a stored `performance` histogram or a key no trigger reads is not exported; iTerm2's importer drops them anyway.
- Tandem's Triggers editor selects one row, so Export to File writes a one-element array. Cost: exporting several triggers takes several files (import accepts several files at once).
- A trigger class without its own `-description` (iTerm2 would print its object dump) is described by its catalog title in the import list. Cost: that line reads differently from iTerm2's.
- The profile chooser for an opened `.it2triggers` file is a small egui window with 13t's multi-select profile list, in place of an alert with a list accessory; its parse and JSON error texts carry serde_json's error message where iTerm2 has NSError's. Cost: the error wording after the colon differs.
- Mark sounds take a Windows sound name or a .wav in `%WINDIR%\Media`; the default stays the system beeps. Cost: iTerm2's own success and error sounds are not shipped.

### Pitfalls for the implementer

- `dlog!` must cost one atomic load while off: build the message only inside the enabled branch.
- Never log a cookie, key, password, clipboard text, typed keys or trigger match text; review every new `dlog!`/`rlog!` for that.
- The debug log's mutex is taken from any thread; never call into `App` or a window while holding it.
- `OutputDebugStringW` is slow when a debugger listens: call it only with `LogToSyslog` or `LogDrawingPerformance` on.
- The bell badge must be cleared on the taskbar when Tandem becomes active, including when the focus comes from a hotkey window.
- `ITaskbarList3` needs `HrInit` and the `TaskbarButtonCreated` message has passed for the window; set the overlay after the window is shown, and again when a window is made.
- `PlaySoundW` with `SND_ASYNC` must not be given a temporary string that is freed before the sound starts: `SND_FILENAME` copies the path, but keep the call's buffer alive until it returns.
- The idempotent check must not run while triggers are active (the normal path already runs them), or matches fire twice.
- `TriggerRequest::Notify` changes shape: update every match on it (the compiler lists them).
- `MaximumNumberOfTriggerCommands` below 1 must not make a pool that never runs anything: clamp to at least 1. `IdempotentTriggerModeRateLimit` is not clamped (iTerm2 does not clamp it): the check runs only from the instant-trigger timer (`INSTANT_EVERY`, 500 ms), so 0 cannot make a busy loop.
- An `.it2triggers` file is untrusted: `parse` never runs a trigger, a refused element fails the whole file, a UNC path is refused before any read, and nothing is imported until the person picks profiles and presses OK.
- `crate::dlog!`/`crate::rlog!` always with the `crate::` path (Task 1).
