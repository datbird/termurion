### Pitfalls for the implementer

- `render` sets the title every frame; the evaluated custom title must not allocate a new interpolation per frame when the format has no `\(`: return it as is.
- The sizing subclass runs inside winit's window procedure and must never borrow `App`; read the published `Snap` from its thread-local map, and answer `DefSubclassProc` first when no snap is published.
- `WM_SIZING`'s rectangle is the outer frame in screen pixels; convert the published decoration from the current outer and inner sizes exactly as `apply_window_style` does, or the snap drifts by the border width.
- Hiding the menu bar changes the client area; the Resized event that follows lays out, so do not relayout twice.
- `Request::WindowTitle` copies titles with `set_title`, which must not push another request, or two panes ping-pong.
- The profile popup's value mapping (`profile_menu_value`) must keep a stored cells id (8 to 11) unchanged until the user picks something; displaying it as its edge entry must not rewrite the profile.
