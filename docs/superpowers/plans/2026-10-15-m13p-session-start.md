> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Scope (read first):** research `.superpowers/research/m13-facts.md` section 0 (the `01` "Saved and shown ... later milestone" bullet and the stale `01:21` note), section 4 "13p Session start and environment" (all 9 items), section 6 R3, R5 and R6, and the 22 Appendix A rows whose Part is `13p`; `.superpowers/research/m13-rulings.md` (R2, R3, the parity-corrections line); and the Resume notes below, and nothing else: what a new session's shell is given before and just after it starts. The locale variables (`LANG`, `LC_CTYPE`) with the four Set Locale Variables modes, the Change Locale picker and its warnings, `FallbackLCCType` and `DoNotSetCtype`; `COLORFGBG` with its fallback; `TERMINFO_DIRS` with Tandem's shipped terminfo; forwarding those to WSL through `WSLENV`; the initial working directory's Advanced mode (per window, tab and pane) and interpolated custom directories; Send text at start; Load shell integration automatically (PowerShell); the offscreen command line (and for the current command); OSC 9;4 progress bars in the pane and in the tab bar with their height and color scheme; Prevent Sleep with `PreventSleepOnBatteryToo`; `IdleTimeSeconds`; `JiggleTTYSizeOnClearBuffer`; event-driven foreground job updates (`FastForegroundJobUpdates`). What happens when a session ends is 13q; bash, zsh and fish injection is not here (Decisions).

**Goal:** a person who sets any of these profile or Advanced settings sees exactly iTerm2's effect: a WSL or MSYS2 program started from Tandem gets a working `LANG` and `COLORFGBG` and (in WSL) Tandem's extended terminfo; a profile set to Advanced working directories opens new windows, tabs and splits each in its own folder; text typed at start and PowerShell shell integration arrive without editing `$PROFILE`; a long command's line stays pinned at the top while its output scrolls; `winget`, `cargo` or any program sending OSC 9;4 shows iTerm2's thin progress bar with its colors and animations; a profile with Prevent Sleep keeps the PC awake on power (and on battery when asked); Clear Buffer can redraw the prompt; the idle indicator and the foreground job follow the Advanced timings.

**Architecture:** pure models first, each a plain `pub mod` tested on EXTREME. `locale_guess.rs` is iTerm2's locale guesser over injected facts and a `supported` predicate, the IANA encoding names, the locale picker's list and titles, and the locale texts; `locale_win.rs` (`#[cfg(windows)]`) reads the Windows user languages, region and locale names. `session_env.rs` gains the POSIX variables (`colorfgbg`, `posix_vars`, `wslenv`). `terminfo.rs` embeds iTerm2's compiled terminfo and writes it once under `%APPDATA%\Tandem\terminfo`. `start_dir.rs` is iTerm2's `iTermInitialDirectory` (mode per object type). `shell_inject.rs` decides and builds the PowerShell injection. `offscreen.rs` is the offscreen command line's rules. `progress.rs` is OSC 9;4's state machine, visibility, colors and animation clock. `sleep_guard.rs` is the Prevent Sleep count and texts, with a `#[cfg(windows)]` guard over `SetThreadExecutionState`. `jobwatch.rs` gains the event-driven wait. The app side: `src/app/locale_ui.rs` (the picker window, the warnings, the start-time prompt), `src/app/progress_ui.rs`, `src/app/offscreen_ui.rs`, `src/app/sleep_ui.rs`. Per-pane state (progress, idle time, pending initial text) lives on the `Pane` or the `Screen`; the offscreen command line's click rectangles are per window and go in `swap_live`; everything else is app-wide.

**Tech Stack:** as milestones 0 to 12 (wgpu 30, winit 0.30, egui 0.36, glyphon 0.12). No new crates: `windows-sys` 0.59 features already enabled (`Win32_Globalization` for `GetUserPreferredUILanguages`, `GetUserDefaultLocaleName`, `IsValidLocaleName`, `EnumSystemLocalesEx`, `GetLocaleInfoEx`; `Win32_System_Power` for `SetThreadExecutionState` and `GetSystemPowerStatus`; `Win32_System_Threading` for `OpenProcess` and `WaitForMultipleObjects`), `include_bytes!` for the terminfo files.

### Decisions (each goes in `m13p-rulings.txt`)

- Locale on Windows (R6, ruled as recommended): "automatic" guesses from the Windows user's preferred UI languages and region; a candidate is supported when its language (and script and country) form is a valid Windows locale name (`IsValidLocaleName`), its encoding anything, or it is the encoding name alone (the Mac accepts `LC_CTYPE=UTF-8`). Windows cannot see which locales a WSL distribution has generated. Cost: a WSL distribution without that locale generated prints "setlocale: LC_ALL: cannot change locale" until the user runs `locale-gen` or picks Minimal.
- The locale picker lists each Windows specific locale as `ll_CC.UTF-8` and `ll_CC` (there is no `locale -a`). Cost: a longer list than a Mac's.
- The start-time prompt and mismatch warning do not hold the shell: the session starts with the fallback (`LC_CTYPE`, or the custom `LANG`) and the answer, when remembered, applies to the profile's next sessions. iTerm2 shows them modally before launching. Cost: the first session after a failed guess runs with `LC_CTYPE` only.
- The POSIX variables reach WSL through `WSLENV` (`/p` for `TERMINFO_DIRS`); `TERMINFO_DIRS` is set only when the session's program is `wsl.exe` (or `wslhost.exe`), so MSYS2, Git Bash, Cygwin, cmd and PowerShell never get it (ruling R6; a Windows path list cannot be split on ":"); they inherit `LANG`, `LC_CTYPE` and `COLORFGBG` directly. Cost: no undercurl terminfo in MSYS2, and a profile that starts WSL through a distribution launcher (`ubuntu.exe`) or a wrapper gets no `TERMINFO_DIRS`.
- A `%APPDATA%` on a UNC path (roaming folder redirection) is never written from the UI thread: no terminfo folder, no `TERMINFO_DIRS`, no automatic PowerShell integration. Cost: those users set them up by hand.
- `TERMINFO_DIRS` holds only Tandem's folder, not iTerm2's `:/usr/share/terminfo` (not a Windows path); ncurses still searches its compiled-in directories. Cost: none if ncurses behaves as documented (checklist verifies).
- The terminfo entries use Linux's first-letter layout. Cost: a Darwin-built ncurses would not find them (none runs on Windows).
- `COLORFGBG` compares palette colors as 8-bit sRGB (Tandem's `Palette`), not NSColor floats. Cost: a color differing only below 1/255 matches.
- Load shell integration automatically covers PowerShell only; bash, zsh and fish injection (iTerm2's ZDOTDIR, `ENV`/`--posix`, `XDG_DATA_DIRS` tricks) needs iTerm2's loader scripts inside WSL or MSYS2 and is left for milestone 14, where iTerm2 injects remote shells the same way (13p-r rulings). Cost: WSL users still install it by hand.
- A PowerShell command line that already has `-Command`, `-File`, `-EncodedCommand` or `-NoExit` is not injected (it runs something else or cannot take a second command). Cost: `pwsh -NoExit -Command x` profiles get no automatic integration.
- Initial Text ends with `\r` (Enter to a Windows console), not iTerm2's `\n`. Cost: none for shells; a raw-mode program reading bytes sees CR.
- The custom directory is interpolated without function calls, in the focused session's scope (iTerm2 evaluates in the new session's scope with calls allowed). Cost: a directory text calling a script function is used as written.
- An AWDS option of "Advanced" or an unknown value is Home. Cost: none (iTerm2 would recurse).
- The offscreen command line's click scrolls to the command but draws no mark highlight (Tandem has no mark highlight). Cost: no flash on the line.
- The offscreen band's outline blends the text and background colors in sRGB, not Lab. Cost: a slightly different gray.
- Progress gradients are drawn as vertical slices at most 2 pixels wide. Cost: visible steps on a very wide pane only up close.
- The tab bar's progress bar takes dark mode from Tandem's tab bar color. Cost: none until 13e's tab themes, which should pass the theme's darkness.
- An unknown AC line status counts as on power. Cost: a desktop reporting unknown keeps Prevent Sleep working, a laptop reporting unknown on battery too.
- Prevent Sleep rechecks the power source every 5 s while a session requests it (winit exposes no power broadcast). Cost: up to 5 s late after plugging in.
- Event-driven job updates wait on each shell's foreground job's exit only (at most 63); new jobs are still found by polling. Cost: a new job shows up to 0.5 s late in front, as today.
- Parity rows are found by title.

### Pitfalls for the implementer

- `session_env::vars` output order is tested; append the POSIX variables after it, never interleave.
- `WSLENV` must be merged with Tandem's own inherited value, or a user's `WSLENV` setup is lost for every session.
- Do not change `$PROFILE` or the execution policy from the injection; the install menu keeps doing that, only on request.
- `Invocation::for_template` with `side_effects` true may call registered functions; the answer can arrive after the pane closed: check the pane still exists before writing.
- The offscreen band is drawn after the pane's rows so it covers row 0; put its text in `frame.rows` after `pane_with`'s rows and its quads in `frame.quads` after the pane's backgrounds (never text in `overlay`).
- `offscreen_hits` is per window: add it to `swap_live` or a click in one window hits another's band.
- Progress animation frames must stop when nothing animates (`progress_wake` None), or Tandem never sleeps.
- `SetThreadExecutionState` is per thread: call it only from the UI thread, where `App` lives.
- `WaitForMultipleObjects` takes at most 64 handles and fails on a closed one: open fresh handles each look and close them after the wait.
- `TabLook` gains a field: update every literal in `scene.rs` tests and the app's `tab_look` (`src/app/requests_ui.rs:165`).
- New `Pane` fields (`idle_time`, `progress_anim`, and the `#[cfg(test)]` `resizes_for_test`) go into the three `Pane { .. }` test literals (`src/pane.rs:984`, `:997`, `:1012`) as well as `Pane::with`.
- The AWDS schema change must keep existing profiles that stored "Advanced" loading (the value is kept; it reads as Home).
