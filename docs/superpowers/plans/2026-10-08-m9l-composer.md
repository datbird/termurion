**Goal:** a native multi-line command editor per session, drawn in the pane like the find bar and the Notes editor, that opens from View > Show Composer (Win+Shift+.), key action 64, the Snippets tool and the status bar Composer field, replaces the shell prompt when View > Auto Composer (Win+Alt+Shift+.) is on and shell integration reports prompts, highlights the command line as iTerm2 does, suggests from history and the file system, and sends, sends each, or enqueues commands through Tandem's one input path, with iTerm2's keys, texts, sizes and quirks.

**Architecture:** pure models first, each a plain `pub mod` tested on Linux. `text_edit.rs` (9k's editor) gains multiple carets and a first-line indent so it is the composer's core. `composer.rs` is the per-session composer: text, prompt prefix, saved text, presentation and routing, the key map, sending, send-each and enqueue-each (`take`), the command queue, geometry and texts. `prompt_state.rs` is iTerm2's `PromptStateMachine` plus the clear sequence probe and the backspace bytes; `Screen` feeds it. `command_syntax.rs` is `CommandParser`, the highlight roles and colors, and the command and file checker caches. `composer_suggest.rs` is the suggestion model. The app side: `src/app/composer_ui.rs` (the minimal and Auto Composer: drawing through new `scene::composer` and `scene::composer_popup`, keys through a `TakenKeys` pairing after `toolbelt_key`, Win chords before `dispatch`, sending through `user_write`), and the status bar field in `statusbar_content.rs` / `statusbar_ui.rs`. State lives on the Pane (`Pane.composer`); nothing new goes in `WinSlot`.

**Tech Stack:** as milestone 9k. No new crates. Popovers through `status_popover_ui::InfoPopover` (help) and `prompt_ui::ConfirmWindow` (the explainshell warning with its suppress checkbox); menus through muda; file and PATH checks on a worker thread (`std::thread`, as the git poller does); the browser name through `AssocQueryStringW` (`Win32_UI_Shell`, already enabled).

## Review Focus

1. Sending semantics: Esc in the Auto Composer sends a bare "\n" and empties it, in the minimal composer it dismisses and keeps the text; Shift+Enter with selections sends each selected piece, "\n" after all but the last; an empty minimal send dismisses and keeps the text; enqueue sends at once only when the current command is `Some("")`, else queues, and one queued command goes per new mark. Tests: Task 2 `sends_follow_iterm2`, `queue_follows_iterm2`.
2. Prompt state machine transitions for OSC 133 A, B (with the captured prompt), C, D, a send, output accrued while entering (4096-unit cap, left-of-cursor rejection, first part trimmed), disabled on the alternate screen. Test: Task 3 `prompt_states_follow_iterm2`.
3. Clear sequence: `hex_bytes("0x15 0x0b")` is `[0x15, 0x0b]`, the caret pattern is `(\^U)?(\^K)?`, output within 0.1 s writes one backspace per control byte, a user write before it cancels it. Test: Task 3 `clear_probe_follows_iterm2`.
4. Highlighting: roles per character (command, quoted, argument, quotation marks, unbalanced, paren, subshell), only the first word is a command, the 1024-unit limit with iTerm2's reset range, colors per role with the 35 L* adjustment. Test: Task 4 `roles_follow_iterm2`, `highlight_follows_iterm2`.
5. Keys never leak: a focused composer takes printable keys, Enter, Tab, Esc and its chords, releases paired; Win chords other than its own reach menus; the auto-mode Ctrl chords (C, D when empty, L, R, U) beat the Windows edit chords. Tests: Task 2 `keys_follow_iterm2`, Task 6 `composer_keys_stay_in_the_composer`.
6. Routing: with a status bar, `alwaysUseStatusBarComposer` or a visible Composer component sends Show Composer to the status bar (a temporary right component seeded from the saved text), else the dropdown toggles; the status bar field's Enter sends raw text plus "\n" and clears. Tests: Task 2 `routing_follows_iterm2`, Task 8 `status_bar_composer_follows_iterm2`.
7. Multiple carets: Ctrl+Shift+Up/Down add a caret from the last one at its x, typing and deleting act at every caret in one undo step, a plain click collapses them, Alt+drag makes one range per line, a multi-caret copy pastes back one group per caret. Tests: Task 1 `carets_follow_iterm2`, `box_select_and_groups_follow_iterm2`.
8. Auto Composer placement: from the prompt row down, `(rows + 0.5)` rows high, growing upward only when the rows below the prompt run out, the terminal cursor hidden under it. Test: Task 7 `auto_geometry_follows_iterm2`.

### Decisions (each goes in `m9l-rulings.txt`)

- The composer is drawn natively in the pane (the find bar and Notes precedent, `text_edit` core), not an egui window; the completion popup is a native popup box. Cost: no IME composition and no spell check in the composer.
- Multiple carets are built (Ctrl+Shift+Up/Down, Ctrl+Shift+click, Alt+drag), on `text_edit` so Notes could use them later; the multi-selection clipboard type is kept in-app (the last copy's line groups, used when the clipboard text still matches). Cost: pasting a multi-caret copy into another app gives plain joined lines.
- Windows edit chords (Ctrl+A/C/X/V/Z/Y and the Ctrl moves) work in the composer; in the Auto Composer iTerm2's Ctrl+C, Ctrl+D (empty), Ctrl+L, Ctrl+R, Ctrl+U win (checked first, as `CTV:853-864`), so copy there is Win+C. Cost: Ctrl+C never copies in the Auto Composer.
- The Auto Composer never scrolls the grid (ConPTY owns it): it covers from the prompt row down, and when the text needs more rows than remain it grows upward over earlier output. Ctrl+L uses `Screen::clear_from(prompt line)`, the ConPTY-safe move of the rows above the prompt into history. Cost: a tall command hides output above the prompt instead of pushing it up.
- Accrued type-ahead is read from the grid between the B anchor and the cursor after each read, not from parser tokens. Cost: a shell that redraws the line may accrue its redraw.
- Command validity on Windows: PATH with PATHEXT; builtins, aliases, functions and PowerShell cmdlets show red (kept as iTerm2 treats builtins). Cost: most PowerShell commands read as invalid.
- File completions match case-insensitively and are quoted per shell by `insertable_dir` rules (PowerShell and cmd quoting, backslash escaping for POSIX shells) instead of always backslash escaping. Cost: differs from iTerm2 for a POSIX shell only in quoting style.
- AI: Win+Y, the "AI" button and AI completions answer "AI features come in milestone 12."; the AI warning never shows (`AICompletions` is off).
- `smartLoggingWithAutoComposer` is stored with its help text and has no effect until session logging exists. Cost: none now.
- Show Composer and Auto Composer have no per-state disabling (Tandem menus have none): Show Composer does nothing while an auto composer shows, Auto Composer does nothing before shell history was ever used.
- The explainshell browser name is the https handler's friendly name (`AssocQueryStringW`, `ASSOCSTR_FRIENDLYAPPNAME`); no handler, nothing happens (as iTerm2).
- Help and send-tip texts use Windows key words ("Shift+Enter", "Win+Alt+V") in place of the Mac glyphs, as 9k's menu texts do.
- The status bar composer's temporary right component wins over the paste Progress and the Filter temporaries while it edits; they come back after.
- The prompt state is not saved in arrangements or restored (iTerm2 saves "Prompt State"); the next prompt reveals the Auto Composer again. Cost: a restored session shows no Auto Composer until its shell prints a prompt.
- Composer text lives on the Pane only (`Composer.saved`), as iTerm2 keeps `_saved` in memory. Cost: none.
- Sends and the clear bytes go through `user_write` with `Write::SendText` (broadcast-capable, as `writeTask` and `sendHexCode` with `broadcastAllowed:YES`, `PS:15182-15191`); the probe's backspaces use `Write::SendTextLocal` (as `writeTaskNoBroadcast`). Cost: none.
- The completion popup's icons are Segoe Fluent glyphs: history `\u{E81C}`, file `\u{E8A5}`, folder `\u{E8B7}`, command `\u{E756}`; the expand glyph is `\u{E740}`, the help glyph `\u{E897}` (the 9j set).
- Win+F in either presentation opens the pane's find bar (iTerm2's Auto Composer forwarding, `CTV:610-638`); the dropdown's own text-view find bar is not built. Cost: no find inside a long composed script.
- Parity rows are found by title.
