**Scope (read first):** research `.superpowers/research/m9-facts.md` section 10 part "9f. Toolbelt panel and the list tools", and nothing else: the toolbelt panel (right side of the window, per-window visibility, width and tool heights, the width clamp, `Default Toolbelt Width`, the 3 point drag handle, the split view between tools with title bars, close buttons, minimum and collapsed heights, divider drags, `NoSyncToolbeltProportions`, the empty-state label, the hamburger button); View > Toolbelt (Show Toolbelt Win+Shift+B, Set Default Width, the tool list as check items); the global `ToolbeltTools`; the profile key "Open Toolbelt"; `toolbeltFont` and `toolbeltFontSize`; the arrangement keys; window grow and shrink on show and hide; and seven tools: Profiles, Paste History, Snippets, Actions, Command History, Recent Directories, Named Marks. **Goal:** a native toolbelt drawn by Tandem's own renderer at the right of each terminal window, taken from the window's room before the panes and the tmux size report, with iTerm2's geometry, split view, menus, persistence and window growth, and the seven list tools with iTerm2's rows, search fields, buttons, click and double-click semantics, modifiers, context menus, alerts and undo.

**Architecture:** pure models first, each a plain `pub mod` tested on Linux. `toolbelt.rs` is the tool registry, the global tool list, the width clamp, window growth and the arrangement keys. `toolbelt_layout.rs` is the split view math (minimums, collapse and expand, divider limits, proportions) and the panel layout and hit test. `tool_list.rs` is the one native list widget every tool uses (search field, selection, scroll, button strip, keys, layout, hit test, tail truncation). `toolbelt_tools.rs` is each tool's rows, filter and pick rules. The app side is `src/app/toolbelt_ui.rs` (panel, menus, drags, keys, arrangement) and `src/app/toolbelt_tools_ui.rs` (the seven tools), drawn by `scene::toolbelt` and `scene::tool_list` like the Clippings panel (`scene::clippings_panel`).

**Tech Stack:** as milestone 9i. No new crates. Menus through muda (the right-click menu's path), alerts through `close_ui::confirm`, editors through Settings > Shortcuts.

**Spec:** `docs/superpowers/specs/2026-09-23-tandem-design.md`. iTerm2 facts: `.superpowers/research/m9-facts.md` sections 3.0 to 3.5, 3.7, 4.3, 4.4, and the Resume notes below (the source wins where they differ). ## Global Constraints

- Everything from milestones 0 to 9i still holds. Read `.superpowers/sdd-templates/implementer-rules.md` first; its invariants bind every task.
- The toolbelt is drawn natively: quads in `Frame.quads` and text in `Frame.rows`, like the Clippings panel. No egui in the terminal window. It sits beside the panes, never over them, so it needs no `cut_out`; any popup box that does cover terminal text goes in `Frame.popups` with `scene::cut_out`, never in `overlay`.
- The toolbelt's room comes out of `App::window_area` (`src/app/mod.rs:749`), which `content_area_for` (`src/app/statusbar_ui.rs:299`) and so `tmux_report_sizes` (`src/app/tmux_tabs_ui.rs:875`) read. tmux is told the size without it.
- Per-window state is ONE new field, `belt: toolbelt_ui::Belt`, in `WinSlot` (`src/app/windows_ui.rs:11`), `WinSlot::new`, `new_empty` and `swap_live` (`:85`). The tool list (`ToolbeltTools`), the saved proportions and the default width are globals.
- Strings, sizes, modifiers, alerts and orders are iTerm2's, verbatim (Resume notes). Characters outside ASCII are `\u{...}` escapes in code. iTerm2 bugs are kept and each gets a checklist line (the 9c ruling); the ones here: the Snippets reorder index bug, the proportions name check that accepts a prefix, Command History's unescaped `cd`, the close button of the only tool hiding the toolbelt in every window.
- Win is Cmd and Alt is Option. Double-clicks use the Windows double-click time (the 9f ruling). Ctrl+click toggles a row and Shift+click extends (Windows list convention, as Settings' lists do).
- Reuse, do not duplicate: `snippets::search` and its tokens, `shell_history::Store`, `paste_history::History`, `user_actions::load`, `marks_ui::named_marks`, `shell_history::insertable_dir`, `settings_shortcuts` editors, `PromptWindow`, `show_menu_at`, `run_key_action`, `open_advanced_paste`, `user_paste`, `user_write`, `new_tab`, `split`, `COMPOSER_REFUSAL`.
- New pure code is a plain `pub mod`; app code is `#[cfg(windows)]`. Tests run on EXTREME with `scripts/xt test --lib <filter>`. Do not launch the GUI.

### Decisions (each goes in `m9j-rulings.txt`)

- The toolbelt and its lists are drawn natively (quads and text rows); no egui in the terminal window.
- 9j shows seven tools; the menu and the hamburger list only them; stored names of other tools stay in `ToolbeltTools` untouched.
- Toolbelt font: `toolbeltFont` when installed, else Consolas (Windows' monospaced system font); size 0 is 11 points. Title bars use the prose font at 13 points.
- Glyphs (Segoe Fluent Icons): close `\u{E711}`, hamburger `\u{E712}`, Send/Apply/Open `\u{E768}`, Advanced Paste `\u{E77F}`, Add `\u{E710}`, Remove `\u{E738}`, Edit `\u{E70F}`, Clear `\u{E74D}`, Help `\u{E897}`, snippet `\u{E8BD}`, folder `\u{E8B7}`, disclosure `\u{E76C}`/`\u{E70D}`.
- Background: `#252528` in dark, white in light; no vibrancy. Selection 17, 108, 214.
- The panel is subtracted in `window_area`; banners and the tab bar keep their places.
- Only a Normal or No Title Bar window that is not maximized, full screen or size-locked grows; others give the toolbelt content room.
- Show Toolbelt and Set Default Width stay enabled; with no tools Show Toolbelt shows the empty label, and Set Default Width does nothing while hidden.
- Keyboard: a click in a tool's field or list takes the keyboard; a click in a terminal, or Esc, gives it back; Tab moves between field and list; Ctrl, Alt and Win chords pass except Ctrl+V into a field; Win+Z undoes the last Snippets or Actions change while that tool has the keyboard (Edit > Undo stays disabled in sessions).
- Ctrl+click toggles a row and Shift+click extends; the Profiles double-click with Ctrl still means a horizontal split.
- Alerts are MessageBox OK/Cancel (`close_ui::confirm`) with iTerm2's heading and text.
- Add and Edit open Settings > Shortcuts with the existing sheet open; no new editors.
- Snippets' Shift path shows `COMPOSER_REFUSAL` in an info bar with OK (the 9h precedent) until 9l.
- Named Marks: no in-place editing; Edit and Enter open the Set Named Mark prompt with the name; renaming adds no annotation (Tandem's Set Named Mark adds none).
- Profiles: no tags pane; the "Toolbelt" arrangement dictionary is kept as read and written back unchanged.
- No drag to other applications and no text drop onto Snippets (no OLE drag and drop); reorder within Actions and the Snippets root only.
- No tooltips (the scene has none): Recent Directories' full-path tooltip and the Profiles row tooltip are dropped.
- The Paste History secure-keyboard warning never shows (Windows has no Secure Keyboard Entry).
- The Command History prefixes are drawn through font fallback; the April 1 variant is kept.
- Directory abbreviation splits on `/` and `\`; a Windows drive path keeps its own form without the leading `"/"`.
- tmux's per-window `toolbelt=` setting is parsed and ignored as today, not written (deferred).
- Snippet folders start collapsed; their state is per window and not saved.
- A Command History use is this session's when the focused pane's own `shell.history` has that command at that start time; its mark is the one with that command and start.
- Parity rows are found by title.
