**Architecture:** pure models first, each a plain `pub mod` tested on the Windows test machine. `expr.rs` is the language: a hand-written tokenizer and precedence parser into an `Expr` tree (calls numbered by `site` in pre-order), JSON values (`serde_json::Value`), and a synchronous evaluator that asks a `Calls` hook for every call and may answer `Pending`; `interp.rs` keeps its public `evaluate`/`has_calls` for today's callers on top of it. `script_fn.rs` is the registry and the RPC wire (validation, namespaces, signatures, resolution of defaults, request ids, deadlines, result decoding, providers). `script_eval.rs` is the invocation engine: an `Invocation` replays the parsed calls against a memo of finished calls, so an asynchronous script call is a `Pending` that a later `step` resumes; it owns the timeout texts and the error report texts, and InvokeFunctionRequest's target checks. `builtin_fns.rs` is the built-in catalog (names, argument types, optional arguments, defaults, side-effect placeholders) and its pure functions. `script_statusbar.rs` is the script component's model (configuration, knobs, invocation, variants, texts). The app side is `src/app/script_ui.rs` (running invocations, the host that routes a call to a built-in or a script, the error alert, InvokeFunction, the callers) and `src/app/builtin_ui.rs` (built-ins with side effects and their dialogs); status bar, title, context menu and toolbelt changes go into the existing files. ### Corrections to the research (the source wins)

- Tandem's `??` is not iTerm2's: iTerm2 has `x?` (and `expr ?`) to make an undefined value null and no `??` operator; Tandem keeps `??` as an extension (Decision).
- The call parser accepts only calls and call sequences; the "Expected a function call, not a value" branches of `SFC:220-231` are unreachable through it (a value is a syntax error).
- Namespaces replace only `-` with `_` in the unique id; dots stay (`H:165-178`).
- Key, pointer, trigger and Open Quickly calls have no invocation timeout, but the RPC layer still stops waiting after the registration's timeout or 5 s and fails with "Timeout" (`H:1323-1342`); research section 9 item 8 says they never time out. The context menu's 30 s default is the invocation timeout; the RPC default still applies inside it.
- `session_title`, `window_title` and `session_name` are in the private namespace `iterm2.private` (`BF/iTermSessionTitleBuiltInFunction.m:87,118`), not callable as `iterm2.*` as research section 3 lists them.
- A missing capture in `matches[n]` beyond the capture count is an index error in iTerm2 (`EP:450-457`), not the empty string Tandem gives today.
- `move_tab_to_window`'s default `tab_id` path is `id`, which in a session scope is the session's id (`Language/iTermVariables.m:42,53`): from a key binding it finds no tab (kept).
- The status bar script error alert's heading is assigned twice; the second, "Status Bar Script Error", is the one shown (`RPC:557-588`).
- Research line numbers checked at `64791fc`; the parser rules are `EP:465-807` (research: `465-802`).

### Decisions (each goes in `m11c-rulings.txt`)

- Web views are deferred: no WebView2 host in 11c (no `webview2-com` or `wry`, no new crate). RegisterTool answers iTerm2's statuses, writes `NoSyncDynamicTools`, and the tool joins the Toolbelt menu and toggles like iTerm2's, but a shown dynamic tool draws nothing (iTerm2's own path when its web view cannot be made); StatusBarComponentRequest opens a plain popover with the HTML's text; HTML-format components show their text. Cost: dynamic web tools are invisible and popovers lose markup, styling and scripts until a later milestone hosts WebView2 (the WebView2 runtime, a child window over the wgpu surface that popups drawn in the scene cannot cover, per-window ownership under `swap_live`, a user data folder); flagged to Robert.
- Evaluation replays the parsed invocation against a memo of finished calls instead of iTerm2's callbacks. Cost: an invocation walks its tree once per finished call (small trees).
- `??` stays a Tandem extension, split before parsing, first non-empty wins. Cost: none for iTerm2 expressions, which never contain it.
- A dotless name in Tandem's string lookups still tries `session.<name>`. Cost: none (Tandem's session variables are keyed `session.` in trigger code).
- Trigger parameters (evaluated in screen code) get the full language but refuse calls ("Function calls are not allowed here.") and are always lax; badges, APS rules, coprocess templates and Copy Interpolated String refuse calls too. Only status bar strings, title providers and the invocation callers run calls. Cost: an imported trigger parameter or badge with a function call shows the refusal.
- Type names in messages are Tandem's ("string", "number", "array", "dictionary", "null") instead of Objective-C class names; syntax errors list expected tokens in Tandem's order and names. Cost: those messages differ in wording from iTerm2's.
- Numbers print as NSNumber does (`3`, `0.5`, a top-level boolean as `1`); kept. Cost: none.
- Built-ins ported are the list in the Resume notes; the rest answer as unregistered functions. Cost: scripts using `get_poly_modal_alert`, panels, layouts, moves, tab groups, `tmux_format`, companion notifications or annotations get an error until they are ported.
- A method receiver id is a window id when it starts `pty-`, else a pane, else a tab, choosing the object whose catalog has the method. Cost: a pane and a tab with the same decimal id and a method both have is sent to the pane.
- The function-call alert has OK only and no suppress box (iTerm2's temporary silencing is not ported); "Reveal in Script Console" waits for 11d; the console text goes to 11a's `Log` under the connection's key. Cost: repeated failures show repeated alerts, one at a time.
- Status bar Launch Script and Reveal buttons wait for 11d (scripts are launched there). Cost: the error alert has OK only.
- The unread count is a red rounded badge with the number at the component's right edge. Cost: its look differs from iTerm2's.
- The Title Function row becomes a popup of "Built-in components" and the registered providers (Tandem's Title Components stays a number field); choosing "Built-in components" writes Title Components 2 (Job). Cost: returning from Custom resets the components to Job.
- Scopes for script calls are 11b's `scope_values` over `variables_with`; dependencies are the values of the paths an evaluation read, compared once per loop pass. Cost: a change and change-back inside one pass does not re-evaluate.
- The `selection` cap counts characters, not UTF-16 units. Cost: text outside the Basic Multilingual Plane is capped slightly later than iTerm2's.
- `set_status`'s `background_tasks` is accepted and ignored. Cost: none visible (Tandem has no background task count).
- `run_coprocess` from the API uses a new `coprocess::Entry::Api` refused like a key binding. Cost: none.
- The Open Quickly invocation item uses the Segoe Fluent Icons Code glyph. Cost: none.
- Parity rows are found by title.

### Pitfalls for the implementer

- Take a `Run` out of `script_runs` while stepping it (the host borrows the App); put it back when it still waits.
- A built-in that shows a dialog must answer `Started(token)`, never block the UI thread; deliver the dialog's answer like a script result.
- While another connection's transaction freezes the UI thread (11a Task 7), that connection's RPC results are held; a call waiting on one finishes after the transaction ends (iTerm2 documents the same limit).
- Never send an RPC notification to any connection but the registration's owner, and never for a name starting "iterm2.".
- prost omits `None`: ServerOriginatedRpcResultResponse is an empty message but must still be sent with the request's id; InvokeFunctionResponse's `error.status` is always set on failure.
- The memo key is the call's `site` plus the JSON of its arguments: a side-effect built-in must never run twice for one invocation.
- `interp`'s tests change in place for the two source-driven differences; do not add duplicates.
- `SCRIPT_REFUSAL` is used by a fixture in `statusbar_ui.rs:1249`; give that fixture another text when the constant goes.
- Status bar content is computed every frame: `App::template` and the script component lookup must never start an evaluation when one is already running for that key.
- Every new App field here is app-wide; none goes in `WinSlot` or `swap_live`. Forget a pane's entries (`script_templates`, `script_components`, `script_titles`, `unread_session_counts`) where the pane is dropped for good.
- A cookie is never logged; the console log gets reasons and invocations only.
