Every new App field is app-wide (keyed by pane or token); none goes in `swap_live`.

### Decisions (each goes in `m13x-ai-browser-tools-rulings.txt`)

- m12 ruling 8 lifted: the five browser tools are declared whenever Act in Web Browser is allowed for the chat's browser session. Cost: none (iTerm2's behavior).
- A browser call on a terminal pane (or the reverse) answers the kind error as the tool's output with no notice (iTerm2 throws and the call is dropped, leaving the model waiting). Cost: the model sees a text iTerm2 never delivers.
- A closed browser pane answers every waiting browser call (`PANE_GONE`); iTerm2 never answers. Cost: none known.
- A web search whose URL cannot be built answers `SEARCH_UNAVAILABLE` (iTerm2 never calls back). Cost: none known.
- `read_web_page_section` with a negative start answers out of bounds and a negative count gives an empty slice (iTerm2 traps). Cost: none known.
- `load_url` takes only `http` and `https` URLs without control characters (R13xai-3); every other scheme, `file:`, `iterm2-file:`, `iterm2-ssh:`, `about:` and `javascript:` included, answers the not-well-formed text; accepted URLs go to WebView2's navigation, whose failure answers with Tandem's error table (iTerm2's `URL(string:)` rules and WebKit's `NSURLError` texts have no Windows equivalent). Cost: the model cannot open local files or other schemes, which iTerm2 allows.
- A browser call never starts while the chat's AI gate is closed, and a waiting one is forgotten when the gate closes or the turn ends (R13xai-2). Cost: none.
- On the orchestration path a kind refusal answers "Error executing command: " + the text and a waiting mirror times out after 30 s with `SESSION_TIMEOUT` (iTerm2's dispatcher, `OD:1356-1380`). Cost: none.
- A fragment-only `load_url` waits until Stop, the gate closing or the pane closing (iTerm2 waits the same way). Cost: a stuck call the person must stop.
- Find and section lengths count `char`s, not grapheme clusters (12c's `truncate32` precedent). Cost: context windows differ on combining text.
- The find JSON keeps struct order and escapes `/` as Swift's `JSONEncoder` does. Cost: none.
- The browser picker is drawn in the browser toolbar strip, not centered over the page (the writer's recommendation, ruled accepted with Q1 to Q48). Cost: a different look.
- "Ask AI\u{2026}" carries no icon. Cost: a different look.
- `ToolStart::Waiting(token)` is 12c's (integration pass 2); this plan keys waiting browser calls by token in `ai_browser_calls`, not in 12c's pane-keyed `ai_pending_tools`, because two chats can wait on one browser pane. Cost: one more App map.

### Pitfalls for the implementer

- Never call `browser_page_markdown` or `navigate` for the model outside `ai_browser_start`; grep your diff.
- `Event::Navigated` also arrives for a person's own navigations: finish only a token that `Waits` holds.
- A web view may not exist yet (13x Task 5 creates it asynchronously): write `pending_url`, never unwrap `view`.
- `pane_gone` runs before the view closes; answer the waiting tokens there, then let 13x close the view.
- The `/` escaping runs on the serialized JSON text only, never on the markdown before serializing.
- Never finish a browser call except through `ai_tool_finished`; a direct call into the driver, the broker or `orch_resume` skips `Engine::tool_finished`'s gate (R13xai-2).
- Bind the token (`ai_browser_bind`) in `ai_run_tool` right after `ai_tool_start` answers `Waiting`; an answer for an unbound token is dropped by `ai_browser_finish`.
- Never use 13x's `navigate_tandem` for a model's URL.
