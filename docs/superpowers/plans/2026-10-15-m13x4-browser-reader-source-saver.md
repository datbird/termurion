**Goal:** in a browser pane a person can open the toolbar menu and choose Reader Mode (the article alone, styled, Escape to leave) or Remove Distractions (click away overlays, Escape to leave); right-click a page and choose Remove Element, View Source (the page's original source with highlighting and clickable links on `iterm2-about:source`), Save Page As\u{2026} (a folder holding `index.html` and a `resources` folder, then shown in Explorer); and other code can ask for the page's plain text and markdown exactly as iTerm2 computes them.

**Architecture:** pure models first, each a plain `pub mod` tested on the Windows test machine without a web view. `browser_reader.rs` (pure) holds the reader scripts built from iTerm2's copied files through 13x2's `browser_js::fill_template` (function bodies for 13x2's isolated-world script runner; none carries a secret), the per-pane reader `State` (injected, reader on, distraction removal on, cached plain text), the toolbar offer rule and the texts. `devtools.rs` (pure) builds and parses the two Chrome DevTools Protocol calls 13x4 makes (`Page.getResourceTree`, `Page.getResourceContent`), sent through 13x2's `App::browser_devtools` behind 13x4's own allowlist check. `view_source.rs` (pure) is iTerm2's source page generator and the choice between the cached original and the DOM. `mime_ext.rs` (pure) is iTerm2's generated extension-to-MIME table and its inversion. `page_saver.rs` (pure) is the save job as a state machine: filenames, CSS `url()` rewriting, the saved-attribute scripts, the resource fetch order, the files to write. The app side is `src/app/browser_reader_app.rs` (reader, distraction removal, remove element, plain text, markdown, the toolbar entries), `src/app/devtools_read_app.rs` (the allowlisted DevTools reads), `src/app/view_source_app.rs` and `src/app/page_saver_app.rs`. Scripts iTerm2 runs in `.defaultClient` run in Tandem's isolated world through 13x2's runner; scripts iTerm2 runs in `.page` run in the page world with no bridge and no secret (R13x23-1, R13x45-1, R13x45-2). Everything per pane lives on 13x's `BrowserView` (app-wide `browser_views`, keyed by pane, no `swap_live` entry).

**Tech Stack:** as 13x and 13x2. No new crate: `serde_json`, `base64` (`Cargo.toml:10`, DevTools base64 bodies), `regex` (`Cargo.toml:11`, CSS `url()`), `rfd` (`Cargo.toml:25`, the save dialog). Vendored third-party JavaScript: Readability.js (Apache-2.0, Arc90 and Mozilla) and turndown (MIT, Luc Thevenard), copied from iTerm2 with their headers.

### Decisions (each goes in `m13x4-rulings.txt`)

- Reader, distraction removal, Remove Element, plain-text and markdown scripts run in Tandem's isolated world through 13x2's isolated-world runner (R13x23-1, R13x45-1: iTerm2's `.defaultClient`); their results come back from `Runtime.evaluate` itself and their later posts only through the world's binding; no 13x4 script holds a secret. Cost: none visible; if 13x2's probe failed, these features are inert and recorded partial rather than moved into the page world.
- The three saver scripts and the View Source DOM read run in the page world through 13x2's page-world runner with no bridge and no secret (R13x45-2; iTerm2's `.page`). Cost: a hostile page can lie to them about its own content, as it can in iTerm2.
- iTerm2 bug fixed (as the Q13, Q18, Q22, Q31, Q35 and Q47 rulings allow): iTerm2's Reader Mode, Remove Distractions and Remove Element never run at `64791fc` (`makeSafe` puts `return ` before files whose first line is a `//` comment, `BWV:151-160`; `RMM:88-91`, `:147-149`); Tandem runs them (statement files followed by `return true;`, expression files through `expression_body`). Cost: their on-page behavior cannot be compared with a running iTerm2; the checklist states the expected behavior instead.
- Saver bodies are `return (\n<file>\n)` expressions (`expression_body`) so a leading `//` comment cannot turn them into `return;`; the mapping JSON replaces only the placeholder inside `new Map(...)` and escapes U+2028 and U+2029 (R13x45-2). Cost: none (iTerm2 also replaces the comment's mention, which has no effect).
- View Source and Save Page As read the page's own loaded resources through two read-only DevTools methods instead of downloading them again with a separate HTTP client (iTerm2's `URLSession`). Cost: a resource the page did not load (lazy images not yet shown, a CSS `url()` never applied) is skipped, and so is every resource of a cross-origin iframe (it lives in another DevTools target); the source of a page whose document is not in the resource cache falls back to the DOM, as iTerm2's network failure does.
- `App::devtools_read` accepts only the two read-only methods (13x2's `browser_devtools` stays general for its own `Input.*` calls). Cost: none.
- Resource file names follow iTerm2's replacement set and then Windows rules: control characters to `_`, trailing dots and spaces removed, `.`/`..`/empty to `resource`, a `_` before reserved device stems (`CON`, `PRN`, `AUX`, `NUL`, `COM0`-`COM9`, `LPT0`-`LPT9` and the superscript forms), at most 240 UTF-16 units keeping a short extension (review I3). Cost: a saved page's resource names can differ from iTerm2's for those names.
- A resource whose file write fails is skipped and the page keeps its live URL; only the folder creation and `index.html` failures show Save Failed (iTerm2's policy, `PSV:219`, `:228-231`). Cost: none.
- The cached plain text is answered as cached, "" included, as iTerm2's `if let cached` (`RMM:36-38`): the first empty extraction answers None, later calls answer "". Cost: none.
- The inverted MIME table answers the last extension in source order for a MIME listed several times (iTerm2's is hash-order dependent). Cost: "jpg" rather than, sometimes, "jpe".
- Template keys are filled in slice order and never rescanned; the view source URL is filled before the source, so a page containing "{{URL}}" shows it literally (iTerm2's unordered dictionary can replace it). Cost: none.
- The fallback source page shows an empty URL line instead of the literal "{{URL}}" (iTerm2 bug, fixed). Cost: none.
- An `iterm2-about:source` URL with a query or fragment answers None (13x's 404) with "Invalid source URL" logged, since 13x's `local_page` carries no status (review M4d). Cost: the 404 body is 13x's, not iTerm2's text.
- The view-source header's emoji becomes a Segoe Fluent Icons glyph at serving time (m12 "UI glyphs"). Cost: a different look.
- A linkified `javascript:`, `data:`, `vbscript:` or `file:` URL on the view-source page opens nothing (13x2's `nav_gate` on `NewWindow`; iTerm2 skips only lower-case `javascript:` and `data:` in attributes and nothing in CSS). Cost: none.
- The page saver breaks CSS reference cycles (iTerm2 recurses forever) and processes non-ASCII CSS whole (iTerm2 may stop early). Cost: none.
- A CSS file referenced from another CSS file is inlined into `url('...')` as iTerm2 does (quirk kept). Cost: that nested reference is broken in the saved page, as in iTerm2.
- Save Page As saves to local folders only; a network or device path, or a folder reached through a link to one, is refused (`scripts::is_network_path`, `scripts::ancestors_stay_local`). Cost: no SSH or network destinations until milestone 14 (writer questions 1-48).
- Percent decoding reuses `marks::percent_decode`, which keeps a malformed escape as text where iTerm2 keeps the raw segment. Cost: a name differs only for malformed URLs.
- Remove Element writes a non-finite coordinate as `0.0` (Swift would print `nan`). Cost: none.
- The reader offer counts Rust characters where iTerm2 counts grapheme clusters. Cost: a text of 11 combining characters may be offered where iTerm2 would not.
- View Source decodes the DevTools text as UTF-8 (DevTools answers text already decoded). Cost: none known.
- "Ask AI\u{2026}" is shown disabled until the AI browser tools plan enables it (writer questions 1-48, accepted as stated). Cost: a visible disabled entry meanwhile.
- `rewrite-resources.js` is not copied (unused in iTerm2). Cost: none.
- Reader mode's Escape listener acts only on trusted events: the one edit to a copied file, with a comment (R13x23 fix pass item 6, the fix class of R13x67-2; iTerm2 accepts a page's synthetic Escape). Cost: none for people; a page can no longer leave reader mode for them.
- `enter_reader_mode` is its own entry point, iTerm2's `enterReaderMode` (ruling Q48), so the Enter Reader Mode browser trigger (13x5 Task 10) never toggles reader mode off. Cost: none.

### Pitfalls for the implementer

- Runner bodies are function bodies: a copied expression file goes through `expression_body` (never `"return " +` the text: a leading `//` comment or `;` makes that return `undefined`); a statement file (`load-readability.js` filled, `load-reader-mode.js`, `distraction-removal.js`, `remove-element-at-point.js`) gets `\nreturn true;` after it. Never edit the copied file to add either.
- No 13x4 body may hold the view secret or touch `window.chrome.webview`; `on_demand_bodies_carry_no_secret` and `saver_bodies_never_return_a_comment` guard it. `.defaultClient` scripts go through the isolated-world runner, `.page` scripts through the page-world runner; never swap them (the reader objects exist only in the isolated world, and the enter and exit scripts must run in the world that loaded them).
- The reader scripts guard their posts with `window.webkit && window.webkit.messageHandlers && window.webkit.messageHandlers.readerMode` (`RMS:72`, `:96`) and `window.webkit?.messageHandlers?.readerMode` (`DR:62`); after the isolated-world runner's rewrite both guards must be truthy there, or "entered" and "exited" are silently never posted. `reader_mode_runs_in_a_page` catches a miss; the fix goes into 13x2's rewrite (one path), never into a copied file.
- `reader-mode-with-styles.js` puts the CSS inside a template literal: if `reader-mode.css` ever gains a backtick or `${`, the script breaks (true in iTerm2 too); the Task 1 test checks the copied CSS has neither.
- Readability on a large page can take hundreds of milliseconds: the runner answers asynchronously; never block `web_tick`.
- Reset the reader state on navigation start, not on `Navigated`: a toggle issued while a new page loads must not mark the new page as in reader mode. The isolated world is recreated for each document, so the reader scripts must be loaded again after every navigation (`injected` is reset with the rest).
- DevTools answers come through `browser_devtools`'s `JsDone`; 13x4 keeps no token maps.
- `std::fs::create_dir` on an existing folder errors (wanted); do not switch to `create_dir_all` for the top folder.
- Resource names come from the web: always `sanitize` (with the Windows rules), always join under `resources\`, and assert in code that the joined path's parent is the resources folder and its file name equals the sanitized name before writing.
- `NavigateToString` is capped at 2 MB (13x Pitfalls): the view source page is served through `local_page` (a resource response), never `navigate_to_string`, so large sources work.
