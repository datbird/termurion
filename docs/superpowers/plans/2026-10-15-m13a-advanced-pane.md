The app side is `src/app/prefs_ui.rs` (custom folder load, save and quit) and `src/app/settings_export_ui.rs` (the three flows). Alerts go through 11d's alert queue (`scripts_alerts::{Ask, Then}`, `App::ask_scripts`), which gains variants; no second queue. The settings window's pane state lives in `SettingsWindow` (app-wide); every new App field is app-wide; none goes in `WinSlot` or `swap_live`.

### Decisions (each goes in `m13a-rulings.txt`)

- New Advanced keys use iTerm2's capitalized defaults key; existing keys keep their names and the plist import tries both spellings. Cost: two spellings in the schema until a later sweep renames the old ones.
- Optional bools are `type = "bool"` rows with no default; Unspecified removes the key. Cost: none known.
- The 20 non-Advanced keys move to tab "Stored" (no pane), each with the section naming where iTerm2 keeps it. Cost: those without a Tandem control elsewhere can only be changed by editing `settings.toml` (as in iTerm2 with `defaults write`).
- Typed numbers are stored on each keystroke and saved when the field loses focus; floats parse as f64 (iTerm2 stores `floatValue`, a 32-bit float); float display is Rust's `{}`. Cost: a typed "0.1" shows "0.1" where iTerm2 could show 0.100000001.
- The search field shows the hint "Search" (macOS draws that placeholder in an empty search field). Cost: none.
- "Show indicators for non-default values" lives in a search-glyph menu at the right of the page bar (Tandem has no settings search field). Cost: a different place.
- The Experimental Bidi checkbox keeps iTerm2's unrelated tooltip. Cost: a confusing tooltip, as in iTerm2.
- `PreferredBaseDir` is stored and shown and moves nothing. Cost: a person expecting it to move Tandem's folder finds it inert.
- Legacy plist keys are consumed on import (Control fills both remaps, tag 1 becomes Right Control); dynamic hotkey profiles and the children warning are not migrated. Cost: a legacy dynamic hotkey profile needs setting by hand.
- The custom folder holds one `tandem-settings.toml` with `default`, `[[profile]]` and `[settings]` (syncable keys only). Cost: not interchangeable with iTerm2's plist.
- The URL is fetched with `curl.exe` (`--fail --location --proto =http,https`, `--max-time` the timeout); exit code 28 is the timeout. Cost: depends on curl.exe (Windows 10 1803 and later).
- The remembered-URL question and load failures show after the first window opens; a Discard answer applies the remote settings to the running app as an import does. Cost: windows opened before the answer start with the local settings.
- "Try Again Without Timeout" fetches on a worker thread. Cost: none.
- UNC custom folders are invalid. Cost: a settings folder on a network share must be mapped to a drive letter.
- Snippets, global notes and icon customizations do not sync through the folder (iTerm2's Data subfolder). Cost: they stay per machine (ruling question).
- Export: `Tandem State.tandemexport`, a gzip tar of python-runtimes, user-defaults (`UserDefaults.toml`, syncable keys), app-support (`%APPDATA%\Tandem` minus the exclusions) and scripts (11d's unsigned zips); no secure-settings or automation-auth entity, and the Python API consent marker is never exported. Cost: an import never re-enables the Python API by itself.
- Import stages in `%TEMP%\.tandem-import-<uuid>`, restarts Tandem once (iTerm2 twice) through `TANDEM_WAIT_PID`, and finishes before anything loads. Cost: a Tandem started by hand during the restart would run a second copy.
- The erase dry run logs with `OutputDebugStringW`; "Console.app" reads "the debug output". Cost: a person needs DebugView to see the lines.
- The erase confirmation drops iTerm2's "Secure settings" bullet, the `~/.iterm2` path and the networked-home sentence (Tandem has neither) and names Windows Credential Manager for the Keychain. Cost: none.
- Erase ends the host's shells (`leave_host(false)`) before removing files, then exits without saving. Cost: running shells end, as the text says Tandem quits.
- Alerts use 11d's queue (`ask_scripts`) with new `Then` variants. Cost: the queue's name says scripts.
- Parity rows are cited by line.

### Pitfalls for the implementer

- `Globals::set` drops a value equal to the default; an optional bool has no default, so `set(false)` stores false: use `unset` for Unspecified, never `set` of a sentinel.
- The non-default filter must not drop the row being edited (its value may pass through the default while typing).
- `schema_page` must no longer be called for "Advanced"; the new pane owns that page, including the `macos_only` and `row_enabled` rules.
- Never probe a UNC `PrefsCustomFolder` or Scripts folder (`remote_prefs::is_unc` first); `writable` writes a file, so it is never called for a URL either.
- A URL fetch never runs in tests; `load_at_start` takes `fetch` as an argument.
- The quit question must not run after `event_loop.exit()`; `prefs_before_exit` returns false and the exit comes from `prefs_tick`.
- `finish_import` runs before Store and Globals load, so it edits the files, not the in-memory values.
- Erase resolves the Scripts folder before anything is removed (the settings that name a custom folder are erased with the rest).
- `std::process::exit(0)` after the erase must come before any save path (`save_globals`, `save_now`, `save_state`) can run.
- Each new App field is app-wide; none goes in `WinSlot` or `swap_live`.
