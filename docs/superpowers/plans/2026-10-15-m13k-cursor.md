The frame scheduler, FPS meter and power rows are 13l; this plan only hands 13l a wake deadline.

**Goal:** a person who changes any cursor setting in Settings (profile Colors and Text tabs, Advanced > Terminal and Advanced > Drawing) sees the cursor change exactly as in iTerm2: a thin 1-point bar and a 2-point underline at any DPI, a cursor that no longer fills the line spacing, a 0.5 s blink that stays solid while the cursor moves, a breathing smooth blink with presets, a smart box cursor that stays readable on any colors, dimmed surroundings with Cursor Boost, a shadow, an outline, a sliding and smearing cursor; and they can type Japanese or Chinese through the Windows IME with the composition drawn at the cursor in the IME cursor color.

**Architecture:** pure models first, each a plain `pub mod` tested on EXTREME. `cursor_look.rs` is the per-frame cursor description (`CursorLook`), the geometry (`cursor_rect`, `solid_rect`), Smart Cursor Color, Cursor Boost's muting, the shadow and the outline. `cursor_anim.rs` is time: the blink phase and its move rule, the smooth-blink fade with its curves and presets, the slide and the smear (polygon keyframes and CoreAnimation's ease-in-ease-out curve), and each pane's `Motion`. `ime.rs` lays a composition string over the grid. `scene::pane_with` takes a `&CursorLook` in place of its `cursor_on: bool` and draws everything the look asks for; `scene::cursor_cell` and `scene::fill_polygon` are new helpers. The app side: `src/app/cursor_ui.rs` (`tick_cursor`, `cursor_wake`, `cursor_look_for`, the motion updates) and `src/app/ime_ui.rs` (the `WindowEvent::Ime` arm, the IME area). Per-pane state (`Motion`, the preedit) lives on the `Pane`; the blink phase and fade are app-wide (only the key window's focused pane blinks); no new field is per window, so none goes in `swap_live`. One vendored alacritty patch: programs change the cursor's blink only when allowed.

**Tech Stack:** as milestones 0 to 11 (wgpu 30, winit 0.30, egui 0.36, glyphon 0.12). No new crates: `unicode-width` (`Cargo.toml:14`, IME cell widths), winit 0.30's `WindowEvent::Ime`, `Window::set_ime_allowed` and `Window::set_ime_cursor_area`.

**Spec:** `docs/superpowers/specs/2026-09-23-tandem-design.md`. iTerm2 facts: `.superpowers/research/m13-facts.md` Appendix A 13k rows and the Resume notes below (the source wins where they differ; see Corrections). ### Decisions (each goes in `m13k-rulings.txt`)

- IME composition is built here (Task 9), with the caret in "IME Cursor Color", because the rulings put features with no row in the sub-part that owns the area and `01:63` cannot work without it. Cost: a larger 13k; a Windows IME quirk (keys during composition) found only in the checklist.
- `UnderlineCursorOffset` and `DrawOutlineAroundCursor` are honored though iTerm2's default Metal renderer ignores them (legacy renderer only); Tandem has one renderer and a person who sets them expects an effect. Cost: differs from iTerm2 with Metal on (the default).
- Lengths in points multiply the window scale factor, with iTerm2's Metal rounding of the centering offset; the rest is not rounded. Cost: sub-pixel edges at fractional scales.
- The smooth-blink fade blends the cursor cell's text color toward `cursor_text` by the alpha (one color per cell) instead of drawing the glyph twice. Cost: a fading glyph over a colored cell differs slightly from iTerm2's two-pass drawing.
- The unfocused hollow box frames `box_rect` (the spacing-free box), as iTerm2's legacy frame; the Metal frame texture is cell sized. Cost: a shorter frame with vertical spacing above 100%.
- Smart Cursor Color reads the cell's own colors from `Palette::cell` (before selection and find highlights); iTerm2's Metal path passes selection and match state. Cost: a smart cursor over a selection picks colors from the unselected cell.
- Smart colors' black and white are pure black and white (iTerm2's `cursorBlackColor`/`cursorWhiteColor` through dimming). Cost: none with dimming off.
- The smear is a filled convex hexagon drawn as one-pixel bands in the overlay (no path renderer). Cost: a stair edge at steep angles.
- The Presets pull-down and the six timing rows sit inline on the Text tab instead of in a popover (no Configure button). Cost: a longer Cursor section.
- The blink phase and fade are app-wide and drive only the key window's focused pane; other panes draw a solid cursor (iTerm2's blink condition requires the key window and the active session). Cost: none.
- A slide or smear starts only from a cursor drawn in the previous frame at a visible place; the first frame after a tab switch never animates. Cost: none visible.
- IME composition belongs to the focused pane (`Pane.preedit`); switching panes clears it without committing. Cost: a half-typed composition is lost on a pane switch.
- Keys are held from the session while a preedit is non-empty; an empty preedit hands keys back. Cost: an IME that reports composition late could let one key through.
- `HDR Cursor` is stored and shown and does nothing (P3/HDR ruling: Tandem renders sRGB). Cost: HDR display users get a normal cursor.
- DECRQSS ` q` and DECRQM `?12` answers change for programs at the stock profile, since "Allow Change Cursor Blink" defaults to false: a program's blink request is refused and reported as refused (the screen does not change, Tandem read blink only from the profile before). Cost: a program that checks its own blink request sees it refused, as in iTerm2.
- `Profile::float_for` is shared with 13m Task 1 (same signature; the later plan reuses it). Cost: none.
- Parity rows are found by title.

### Pitfalls for the implementer

- `pane_with`'s signature changes at 22 call sites (including `src/app/screenshot_ui.rs:41` and the `scene::pane` test at `src/screen.rs:1626`); change them all in Task 2, never add a second function beside it.
- The block cursor quad must go into `frame.quads` after that row's background runs, or the next run paints over it; the text stays in `frame.rows` (drawn after quads).
- `Beam` and `Underline` stay in `frame.overlay`, so the Auto Composer's `skip_covered` (`src/app/mod.rs:2524`) still removes them; the shadow, outline, smear and IME caret go in the overlay too and must fall inside the same `overlay_from..` range.
- Do not read the profile's "Blinking Cursor" in `tick_cursor` any more: the terminal's `cursor_style().blinking` already defaults to it and carries allowed program changes.
- `Globals::number` returns `Option<f64>` (None for an unknown key); every read in the steps is written `unwrap_or(<iTerm2 default>)`, cast to `f32` where the field is `f32`; every new key has a schema default, so the fallback only guards a typo.
- `Motion` is per pane (on the `Pane`), `Blink` and `Fade` are app-wide; nothing here is per window, so `swap_live` is untouched.
- Every animation asks for frames only while it runs; when nothing blinks, fades, slides or smears, `cursor_wake` is None and Tandem sleeps (`ControlFlow::Wait`).
- winit delivers `Ime::Preedit` with an empty string to end a composition; treat it as clearing, not as an empty composition to draw.
- `set_ime_cursor_area` takes physical coordinates relative to the window's client area; pass the caret rect, not the pane rect.
- The alacritty patch must leave upstream behavior when `cursor_blink_change` is true (its default), so Tandem's other tests keep passing; `Screen` sets it from the profile.
