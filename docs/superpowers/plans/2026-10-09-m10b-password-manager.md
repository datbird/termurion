# Tandem Milestone 10b: The Password Manager

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Scope (read first):** research `.superpowers/research/m10-facts.md` sections 0, 5 to 10, 11 (items 8, 9, 12) and 12 (the last five bullets), and nothing else: the password manager window (table, search, Enter Password, Enter User Name, Enter Username & Password, the 2-Factor Code field, Broadcast, add, remove, edit, the gear menu, the row menu with Append OTP, Reveal Password and Copy Password, the New Account and Edit Account panels, the busy scrim with Cancel, every alert), the sources (Windows Credential Manager in the keychain's place, 1Password through `op`, LastPass through `lpass`, and the adapter protocol that iTerm2 speaks to its KeePassXC, Bitwarden and Keeper adapters), the authentication gate (Require Authentication to Open, after Screen Locks, on Every Open), entering a password through the echo probe (Probe Before Sending Password, `echoProbeDuration`, Automatically Send Return Key after Password, the "Are you really at a password prompt?" check), broadcast-safe entry (probe every broadcast session, send only to those at a prompt, iTerm2's warning), opening it (Window > Password Manager Win+Alt+F, the Open Password Manager trigger with its account pop-up, Open Password Manager Automatically on a password prompt, a click on the cursor at a password prompt), password prompt detection on Windows (console input mode, `detectPasswordInput`, `detectPasswordInputDebounce`) and the key cursor, and the Advanced rows `echoProbeDuration`, `disablePasswordManagerAnimations`, `detectPasswordInput`, `detectPasswordInputDebounce`, `lastpassGroups`. Instant Replay is milestone 10a (`2026-10-09-m10a-instant-replay.md`). Browser password filling does not apply: Tandem has no browser sessions. Secure Keyboard Entry stays with milestone 13.

**Goal:** a password manager window per terminal window that lists accounts from Windows Credential Manager or a third-party manager, types the chosen password into the session only after checking the session is at a password prompt (or into every broadcast session that is), types user names and one-time codes, adds, edits and removes accounts, and opens by menu, trigger, click, or by itself at a password prompt, with iTerm2's texts, keys, rules and quirks, and without ever logging, printing or writing a secret to disk.

**Architecture:** pure models first, each a plain `pub mod` tested on Linux. `pwm.rs` is the window's model (accounts, display strings, filter and sort, button rules, the edit commit rules, random passwords, the busy counter) plus `Secret`, a string that zeroes itself when dropped and never prints. `echo_probe.rs` is iTerm2's echo probe over raw output bytes and the broadcast round. `pwm_source.rs` is the source trait, the source kinds and the Credential Manager naming; `pwm_credman.rs` is its Win32 side. `pwm_cli.rs` builds and parses `op` and `lpass` commands; `pwm_adapter.rs` is the adapter protocol; `pwm_run.rs` runs a CLI with secrets on stdin only. `pwm_prompt.rs` is password prompt detection (console mode rule and debounce). The app side: `src/pwm_ui.rs` (the egui host window and its panels), `src/app/pwm_app.rs` (opening, authentication, the source worker thread, entering text, the trigger, automatic opening, the click, the key cursor). Per-pane state (the probe, the prompt state) lives on the Pane; the window handle is a per-window App field in `swap_live`.

**Tech Stack:** as milestone 10a. No new crates. `windows-sys` features added: `Win32_Security_Credentials` (`CredEnumerateW`, `CredReadW`, `CredWriteW`, `CredDeleteW`, `CredFree`, `CredUIPromptForWindowsCredentialsW`, `CredUnPackAuthenticationBufferW`) and `Win32_System_RemoteDesktop` (`WTSRegisterSessionNotification`); `LogonUserW` is in `Win32_Security` (enabled). `serde_json` for CLI and adapter JSON; `std::process::Command` with `CREATE_NO_WINDOW` for the CLIs; `rfd` for Locate.

**Spec:** `docs/superpowers/specs/2026-09-23-tandem-design.md`. iTerm2 facts: `.superpowers/research/m10-facts.md` sections 5 to 10 and the Resume notes below (the source wins where they differ). Rows: `03-features-and-menus.md` Window > Password Manager, Triggers Open Password Manager trigger, the twelve password manager rows; `01-profile-settings.md` Open Password Manager Automatically, Open Password Manager (trigger action); `02-global-settings.md` echoProbeDuration, disablePasswordManagerAnimations, detectPasswordInput, detectPasswordInputDebounce, lastpassGroups; rows found by title.

## Global Constraints

- Everything from milestones 0 to 10a still holds. Read `.superpowers/sdd-templates/implementer-rules.md` first; its invariants bind every task. Precedents: `docs/superpowers/rulings/m9l-rulings.txt` and `m10a-rulings.txt`: menu- and gear-only globals have no settings row; Tandem menus do not disable, so a disabled item does nothing; popovers and panels are egui host windows.
- Secrets: a password, OTP, master password or session token is a `pwm::Secret` from the moment it is read until it is written to the pty or the store, and is dropped (zeroed) at once after. Never in `Debug`, logs, banners, toasts, test output, panic messages, command lines (always stdin or an environment variable of the child), files Tandem writes, the clipboard (except Copy Password and Reveal's Copy), or the undo and paste histories. Tests assert `format!("{:?}", secret)` is `"Secret(<redacted>)"`.
- Reuse, do not duplicate: `App::user_write` with `Write::SendTextLocal` for probe bytes and the password (never broadcast), `Write::SendText` for user names (broadcast-capable, as iTerm2's `writeTask`); `prompt_state::backspace_bytes` is the probe's backspace; `App::show_toast` (3 s) is the unobtrusive message; `prompt_ui::{ConfirmWindow, PromptWindow}` and `App::ask` for questions; `EguiHost` for windows; `broadcast::Broadcast::targets` for the broadcast sessions; `jobwatch`'s `CONSOLE` mutex for any `AttachConsole`; `triggers::ActionInfo` and `TriggerRequest` for the trigger.
- Strings, sizes, orders and alerts are iTerm2's, verbatim (Resume notes), with "iTerm2" in user text replaced by "Tandem", "macOS Keychain" by "Windows Credential Manager", and key names in Windows words ("Broadcast (Win+B)", tooltip "Win+U"). Characters outside ASCII are `\u{...}` escapes in code. iTerm2 bugs are kept, each with a checklist line: the probe's own space showing the "Password sent" toast, Enter User Name with Broadcast on typing the name once per broadcast session into each, the screen-lock item shown checked and disabled when every-open is on, a failed source choice falling back to the default source silently after its alert.
- Win is Cmd and Alt is Option. New pure code is a plain `pub mod`; app code is `#[cfg(windows)]`. Tests run on EXTREME with `scripts/xt test --lib <filter>`; no test touches the real Credential Manager, runs `op`, `lpass` or an adapter, or prompts for credentials (the Win32 and process sides sit behind the `Source` trait and a `Runner` trait with fakes). Do not launch the GUI.

## Review Focus

1. Secrets never leak: `Secret`'s `Debug` is redacted, it zeroes on drop, CLI and adapter requests carry secrets only on stdin or in the child's environment, and nothing secret reaches a toast, banner or log line. Tests: Task 1 `secret_never_prints`, Task 4 `cli_commands_follow_iterm2`.
2. The echo probe's state machine over output bytes: "*" alone, then BS or `CSI 1 D`, then " " and BS or `CSI K`; timeout sends from Waiting and BackspaceOverSpace, fails from the rest; " " plus backspace bytes written first; probe off or 0 s sends at once. Test: Task 2 `probe_follows_iterm2`.
3. Broadcast entry: sessions without backspace bytes skip the probe; all succeed sends to all; failures ask with iTerm2's heading, one-name and many-name texts and buttons; OK or Cancel sends to none. Test: Task 2 `broadcast_round_follows_iterm2`.
4. The window's rules: button titles and enabling, Tab to the 2FA field, double-click by column, the combined password (trimmed 2FA field, else the account's OTP), the edit commit (empty or unchanged password means no change), the add refusals. Test: Task 1 `window_rules_follow_iterm2`, `edit_rules_follow_iterm2`.
5. Credential Manager naming round-trips iTerm2's keychain keys: `Tandem/<account>\u{2002}\u{2014}\u{2002}<user>`, one-part legacy names with an empty user, display strings equal to iTerm2's. Test: Task 3 `credman_names_follow_iterm2`.
6. CLI and adapter parsing: `op`'s concatenated JSON objects, the "iTerm2" tag, "iTerm2-no-otp", password from "password" else "credential" with a trailing CR dropped, `lpass ls` lines with id "0" skipped and groups filtered, adapter handshake version 0 only and its error texts. Tests: Task 4 `cli_parsing_follows_iterm2`, Task 5 `adapter_follows_iterm2`.
7. Authentication: cached reuse unless every-open, no prompt when not required, screen lock revokes only with after-screen-locks, a failed prompt closes the window. Test: Task 7 `auth_follows_iterm2`.
8. Password prompt detection: echo off with line input on, held for `detectPasswordInputDebounce`, off when `detectPasswordInput` is off; opening automatically only on the rising edge and only with the profile setting; the click opens only on the cursor cell without Alt or Win. Test: Task 8 `prompt_detection_follows_iterm2`.
9. One manager per terminal window, none while that pane's probe runs, focus reports held off while it opens and closes, and the window handle swapped with the window (`swap_live`). Test: Task 7 `auth_follows_iterm2` plus review of `swap_live` and `no_focus_reports`.

### Windows notes

- `CREDENTIALW` for a write: `Type = CRED_TYPE_GENERIC`, `TargetName` the target, `UserName` the user name (shown in Control Panel), `Comment` "Tandem password manager", `CredentialBlob` the UTF-8 password (at most `CRED_MAX_CREDENTIAL_BLOB_SIZE`, 2560 bytes; a longer password is refused with an error), `Persist = CRED_PERSIST_LOCAL_MACHINE`. `CredEnumerateW` with filter `Tandem/*` and flags 0; every returned array freed with `CredFree`.
- `CredUIPromptForWindowsCredentialsW` returns a packed buffer that holds the typed password; unpack it into `Secret`s and zero and free the buffer (`CoTaskMemFree`) at once; `LogonUserW` with `LOGON32_LOGON_INTERACTIVE`, then `CloseHandle` on the token.
- `AttachConsole` is process-wide: every attach (console events and mode reads) goes through `jobwatch`'s `CONSOLE` mutex, and Tandem's ignore-Ctrl handler stays installed.
- Processes: `CREATE_NO_WINDOW` so no console flashes; a CLI that wants a terminal (an `op` or `lpass` login that prompts on its own tty) cannot run this way, which is why sign-in goes through Tandem's prompt and stdin.

### Pitfalls for the implementer

- Never derive `Debug` on a struct holding a `Secret` field without checking the output (the `Secret` impl keeps it redacted; a manual `Debug` elsewhere could leak).
- The probe consumes raw output bytes in `Pane::pump` before `screen_filter` and the tmux hook's screen output, but after tmux control mode is recognized: a tmux gateway pane never probes.
- The worker thread owns the `Source`; the UI thread never blocks on a CLI or on Credential Manager.
- Keep `known_statuses`, `triggers.rs`' later test and `DONE` in step with the new statuses.

### Decisions (each goes in `m10b-rulings.txt`)

- The backing store is Windows Credential Manager (generic credentials, target `Tandem/<account>\u{2002}\u{2014}\u{2002}<user>`, per-user, `CRED_PERSIST_LOCAL_MACHINE` so it does not roam); the stored source name stays "Keychain" so iTerm2-shaped settings import unchanged. Cost: none.
- Secrets live in `pwm::Secret` (zeroed on drop, redacted `Debug`) and cross process boundaries only on stdin or the child's environment; Tandem never logs, prints or writes them to disk, and CLI stderr is never shown for a command that can echo a secret. Cost: an `op` or `lpass` failure message may be less specific.
- 1Password (`op.exe`, winget or PATH) and LastPass (`lpass`, Locate only on Windows) keep iTerm2's tag "iTerm2" and group "iTerm2", so vaults shared with iTerm2 on a Mac show the same items. Cost: the tag name mentions iTerm2.
- The adapter protocol is built to iTerm2's JSON, but the KeePassXC, Bitwarden and Keeper adapter executables are not ported in 10b (they are Swift programs wrapping `keepassxc-cli`, `bw`, Keeper Commander); choosing them shows "Adapter not found." and falls back. Cost: those three managers do not work until the adapters are ported (a later task, flagged to Robert).
- Adapter settings that are not secret and the database path persist in the globals; master passwords and secret settings are kept in memory for the run only (iTerm2 can persist them in the keychain). Cost: KeePassXC-style adapters ask for the master password once per run.
- Authentication is the Windows credential prompt for the signed-in user (`CredUIPromptForWindowsCredentialsW` with `CREDUIWIN_ENUMERATE_CURRENT_USER`, checked with `LogonUserW`), not Windows Hello biometrics (WinRT is not in `windows-sys`). Cost: a PIN-only account without a password may not pass the prompt; turning Require Authentication off is the escape.
- The "secure" defaults (Require Authentication to Open, on Every Open) are ordinary globals on Windows (iTerm2 keeps them admin-protected). Cost: another program running as the user can turn the gate off.
- Password prompt detection reads the shell console's input mode (echo off, line input on) through `AttachConsole` on the job watcher thread at its 500 ms rate, debounced by `detectPasswordInputDebounce`. Cost: detection lags up to half a second; programs that read passwords key by key with line input off (PowerShell `Read-Host -AsSecureString`) are not detected; a pane whose shell has exited is never at a prompt.
- The password manager is an egui host window owned by the terminal window (iTerm2 uses a sheet); its panels and alerts are modals inside it. Cost: none.
- The key cursor is the Segoe Fluent Icons key glyph `\u{E8D7}` drawn in the cell (iTerm2 draws a key image). Cost: none.
- `disablePasswordManagerAnimations` is stored with its help and has nothing to disable. Cost: none.
- User text replaces "iTerm2" with "Tandem", "macOS Keychain" with "Windows Credential Manager", "Option" with "Alt", and Mac key glyphs with Windows words.
- Parity rows are found by title.
