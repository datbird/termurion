### Decisions (each goes in `m13g-rulings.txt`)

- Transparency uses a DirectComposition swapchain (wgpu DX12 `DxgiFromVisual`) with `WS_EX_NOREDIRECTIONBITMAP` only on windows that need transparency or blur, served by a second wgpu instance created lazily; opaque windows keep today's instance and swapchain (13g renderer ruling). The need is decided at creation from every profile the window shows (Transparency above 0 or Blur, ignoring the toggle); a window that needs alpha later is recreated on the second instance with its state carried over; an alpha window that stops needing it stays on the second instance with an opaque alpha mode. Cost: two devices in memory while a see-through window exists; a recreate flickers once; RenderDoc cannot capture the visual swapchain.
- The surface is premultiplied only while some visible pane's alpha is below 1; otherwise it is opaque as today. Cost: one surface reconfigure when transparency turns on or off.
- The backdrop's color is exactly premultiplied for the sRGB target (`premultiplied`), and every pixel gets exactly one background layer (margins from the backdrop, the grid from `pane_with`'s runs), so the composited alpha equals iTerm2's (0.7 at Transparency 0.3, tested on the composited pixel); text blends in linear space over it. Cost: a faint color difference in text over see-through cells.
- The tab bar, status bars, toolbelt, dividers and popups stay opaque (the backdrop's chrome strips); only pane areas (margins included) are see-through. Cost: none known (iTerm2's tab bar is opaque).
- Background images stay opaque under transparency (the image pipeline has no per-quad alpha). Cost: a pane with a background image is not see-through where iTerm2 fades the image.
- The inactive-pane dim quad keeps its alpha, so a dimmed see-through pane is a little more opaque. Cost: a visible difference only with split panes and transparency.
- Transparency outside 0..=1 is clamped. Cost: none.
- The cursor is always opaque. Cost: none (iTerm2's cursor is drawn over the background).
- Blur is Windows 11 22H2 acrylic (`DWMSBT_TRANSIENTWINDOW`); older Windows get none; Blur Radius is stored, shown and averaged but has no effect. Cost: no blur on Windows 10; the radius slider does nothing.
- The large radius warning shows as iTerm2's (with the Segoe glyph for the emoji) though the radius has no effect. Cost: a warning about a slider that does nothing.
- `DisableTransparencyForKeyWindow` is a menu-only global under 13a's hidden tab "Stored". Cost: it shows in no Settings page, as in iTerm2.
- Space maps to Windows virtual desktops: 1 to 9 is the n-th desktop in Task View order from the registry list; the window is moved there and activated, which switches desktops; a missing desktop notifies once per run. Cost: the registry list is undocumented; a future Windows could move it (every failure means "current desktop").
- All Desktops follows: a window with Space -1 is moved to the current desktop when it shows (hotkey windows) and within a second after a desktop switch; it is never pinned. Cost: a visible move up to a second late after a switch.
- Only new windows apply Space (as iTerm2); new tabs never switch desktops. Cost: none.
- Restore windows to same desktops stamps `Tandem Virtual Desktop` into the saved state only and moves windows back at launch when that desktop still exists; enabled under the system restore policy only. Cost: arrangements never restore desktops (iTerm2's never do either).
- Display changes are seen through a subclass on each terminal window (`WM_DISPLAYCHANGE`, `WM_SETTINGCHANGE` with `SPI_SETWORKAREA`); one refit runs `UpdateScreenParamsDelay` after the last message. Cost: a taskbar move also refits edge windows (their work area changed, which is right).
- Exclusion from the taskbar and Alt+Tab is `WS_EX_TOOLWINDOW` on every terminal window, re-applied whenever winit rewrites the style. Cost: tool windows draw a slimmer caption on some themes.
- The status bar item is a notification-area icon sharing the notification icon; its menu is iTerm2's, with Check For Updates disabled until 13v and Main Menu without check marks. Cost: the tray's copy of the main menu shows no checks.
- The dock icon click is a left click on the notification-area icon (the only app-level icon Tandem has); an unhandled click focuses the last window or opens one. Cost: the hotkey dock preference does nothing while the icon is absent (13v's resident icon will call the same code).
- The warnings reuse the scripts alert queue (`ask_scripts`) with 13b's `Spec` shape, which is Tandem's one iTerm2-warning queue (13b ruling). Cost: none.
- Parity rows are found by title.

### Pitfalls for the implementer

- Every surface must get an explicit alpha mode: under `DxgiFromVisual`, `caps.alpha_modes[0]` is `Auto`, and an egui window that gets a premultiplied surface turns see-through wherever egui writes alpha below 1.
- winit rewrites `GWL_EXSTYLE` from its own flags on every flag change (`window_state.rs:407`): never set `WS_EX_TOOLWINDOW` once and forget it; `presence_tick` compares every pass.
- A style change that adds or removes `WS_EX_TOOLWINDOW` does not move a visible window's taskbar button until the window is hidden and shown again; use `SW_SHOWNA` so focus does not jump.
- `MoveWindowToDesktop` works only for Tandem's own top-level windows; never call it with a foreign `HWND`. `GetWindowDesktopId` of a hidden (cloaked) window may fail: follow a hotkey window just before it shows, not while hidden.
- Registry values can be missing (one desktop, or Windows 10): `list()` then returns an empty list and Space 1 is "missing"; never panic on a short or odd-length value.
- The first `RegGetValueW` call asks for the size; allocate and call again; values may grow between calls (retry once).
- `set_blur` must be called with the frame extension; the backdrop without `DwmExtendFrameIntoClientArea` shows nothing. Turn both off together.
- `premultiplied` divides by alpha: alpha 0 must return zeros, not NaN.
- A display message burst (docking a laptop sends several) must refit once: push `display_due` back, never queue a refit per message.
- `snapshot_all` has three callers; only `save_state` passes `state: true`, or saved arrangements start carrying desktop ids.
- The tray menu needs a real window for `TrackPopupMenu`: use the current terminal window's hwnd, never the message-only notification window.
- `commands.rs` tests may list the transparency items as `Later(7)`; update them to `Done` rather than weakening the test.
- Full screen is set in five places today (the menu, the API, the key action, tmux and `apply_window_style`); route all through `App::toggle_fullscreen` or the transparency state machine misses a full screen change.
- New per-window fields (`win_alpha_surface`, `win_transparency`, `win_follow_desktop`, `win_anchor`) go in `WinSlot`, `WinSlot::new` and `swap_live`; `alpha_gpu`, `blur_state`, `presence_seen`, `display_due`, `desktop_due`, `space_complained`, `tray_on`, `ui_element_confirmed`, `desktops` and `transparency_unavailable` are app-wide.
- Never move an opaque window to the second instance, and never change `init_gpu`'s backends: the renderer ruling keeps today's path for every window that does not need alpha.
- `WS_EX_NOREDIRECTIONBITMAP` cannot be added to a live window; a window that needs alpha later is recreated (`recreate_window_for_alpha`), and every map keyed by the old window id is re-keyed.
- Do not draw a default-background layer under cell runs in a see-through pane: two layers of alpha 0.7 compose to 0.91. The composited-pixel test is the guard.
