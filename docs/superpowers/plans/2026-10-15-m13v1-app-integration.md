**Goal:** Tandem behaves as an installed Windows terminal the way iTerm2 behaves as a Mac one: a second `tandem.exe` hands its request to the running Tandem; opening a script or folder with Tandem runs it or opens a session there after iTerm2's question; ssh:, telnet: and ftp: links open sessions with the profile bound to the scheme; Tandem can be the Windows default terminal; the taskbar Jump List is iTerm2's dock menu with its recent profiles; closing the last window leaves Tandem running with its notification-area icon unless "Quit when all windows are closed" is on; and a Windows shutdown asks exactly when iTerm2 would.

**Architecture:** pure models first, each a plain `pub mod` tested on EXTREME. `launch.rs` is the command line and the forwarding message; `instance_win.rs` (`#[cfg(windows)]`) is the per-user named pipe that makes one Tandem take every request. `open_file.rs` classifies opened paths, picks the open style and builds the text a script runs with. `url_open.rs` parses a URL and turns a profile into the session iTerm2 makes for it; `url_schemes.rs` is the scheme list, the per-profile bindings and the registry entries that make Tandem a handler. `reg.rs` is a small `Registry` trait (a fake for tests, `HkcuRegistry` for Windows) used by every task that registers something. `default_term.rs` is the Windows delegation pair and the COM registration; `handoff_win.rs` (`#[cfg(windows)]`) is the `ITerminalHandoff3` COM server whose handed-off console becomes a pane. `jumplist.rs` is the dock menu as a Jump List and the recent-profiles store; `jumplist_win.rs` (`#[cfg(windows)]`) commits it through `ICustomDestinationList`. `resident.rs` is the quit, grace-period, reopen and shutdown decisions. The app side is `src/app/launch_ui.rs`, `src/app/open_file_ui.rs`, `src/app/url_ui.rs`, `src/app/default_term_ui.rs`, `src/app/jumplist_ui.rs` and `src/app/resident_ui.rs`. Every new App field is app-wide; none goes in `WinSlot` or `swap_live`.

### Decisions (each goes in `m13v1-rulings.txt`)

- A second `tandem.exe` forwards its request to the running Tandem over a per-user, per-elevation named pipe and exits; with no answer within 2 s it runs as its own Tandem. Cost: a hung Tandem makes launches wait 2 s.
- Opening a script runs it after iTerm2's permanently silenceable "OK to run" question, the one exception to "programs are never run from documents": the person chose Tandem to open the file. Cost: a silenced question runs any script opened with Tandem (as in iTerm2).
- The run text quotes for the profile's shell family (PowerShell, cmd, POSIX) instead of POSIX only. Cost: a shell Tandem classifies wrongly gets the wrong quoting.
- The run text is joined to the profile's own Initial Text with `\r` (13p's Enter ruling) rather than iTerm2's `\n`, and the whole combined text has its backslashes doubled before it becomes the session copy's "Initial Text" (`AD:860-861`, the profile's part included, a faithful quirk: an interpolation the person wrote in Initial Text is sent literally when a script is opened with `OpenFileOverridesSendText` off). Cost: as in iTerm2.
- The "OK to run" title shows the path as the run text quotes it for the profile's shell (iTerm2 shows its escaped form). Cost: PowerShell users see the single quotes.
- Explorer integration is "Open with" only (`Applications\tandem.exe`), never a default association or a folder context menu. Cost: opening a folder in Tandem needs "Open with" on a script, a drop on `tandem.exe`, or the command line.
- ssh:// cd runs `exec $SHELL -l` (no backslash) because Tandem starts the command directly. Cost: none known.
- x-man-page is not offered and opens the profile unchanged (the macOS `man` command). Cost: none on Windows.
- A scheme Windows guards (UserChoice) is set in Settings > Default apps, which Tandem opens after registering. Cost: one more step than iTerm2.
- Tandem is the default terminal by pairing Windows Terminal's console host with Tandem's own terminal class, so Windows Terminal must be installed; the old pair is saved and restored; handed-off shells are not hosted in tandem-host. Cost: no default-terminal support without Windows Terminal; handed-off shells end with Tandem.
- The Jump List is the dock menu (Tasks plus four categories); Windows' slot limit cuts long profile lists; the process keeps its default AppUserModelID. Cost: very long profile lists are truncated in the Jump List.
- The renamed-profile question keeps iTerm2's button-to-action mapping. Cost: the buttons read the other way round from what they do, as in iTerm2.
- Running with no window keeps the last window hidden (its GPU device lives on) and shows 13g's notification area icon whatever `statusBarIcon` says. Cost: a hidden window's memory while resident.
- `OpenUntitledFile` off with no window means the icon's left click opens nothing (the right-click menu still has Main Menu > Shell > New Window). Cost: as in iTerm2.
- On a shutdown Tandem asks through Windows' block-reason screen; Cancel keeps Tandem and Windows does not retry by itself. Cost: the person restarts the shutdown.
- `ShowSuiteNameInDockIcon` is stored and does nothing (no `-suite` instances); the 13v/13w ruling adds a "-suite isolated instances" row for 13y. Cost: the setting has no effect.
- Mac words in help texts (Homebrew paths, `open iTerm2 file.command`, `$HOME/Downloads`) become Windows ones. Cost: the help differs from iTerm2's.

### Pitfalls for the implementer

- Forward before building the event loop and before `connect_or_start`: a second process must not start or attach to tandem-host.
- `AllowSetForegroundWindow` must come from the process the user started (it has the foreground right); calling it after writing is too late.
- Never forward `-Embedding`, and register the handoff class object before the first `resumed` returns, or COM times out the activation.
- `EstablishPtyHandoff` runs on an RPC thread (only because the class object is registered from the dedicated MTA thread; registering from winit's main thread, an OLE STA, would route every call through the UI message loop): never touch `App` there; send the handles through the proxy and own them from that point (close them if the send fails).
- `TERMINAL_STARTUP_INFO` holds BSTRs owned by the caller: the struct declares them as `*const u16`, read only through the pointer COM passed (never moved or copied into a `BSTR`); copy the strings, never free them.
- Every `self.tabs[self.active]` (`src/app/mod.rs` five, `src/app/menu.rs` one) must tolerate empty tabs while resident; input never reaches a hidden window, but menu commands from the tray do.
- `ICustomDestinationList::BeginList` must be followed by `CommitList` or `AbortList` on every path; `AppendCategory` with a removed item fails the whole category.
- The registry writes are per user: never write `HKLM`, never delete a key Tandem did not create (`delete_tree` only on `Software\Tandem\...`), and never write `Software\Classes\http`, `https` or `mailto` directly.
- `WM_QUERYENDSESSION` arrives on the window thread with a short timeout: decide synchronously and post the question; never show a dialog inside the subclass proc.
- A UNC path given to `tandem.exe` is refused before any file probe.
