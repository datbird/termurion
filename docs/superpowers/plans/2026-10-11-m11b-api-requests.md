### Decisions (each goes in `m11b-rulings.txt`)

- 11a's dispatcher already passes `event_loop` (`api_tick`, `api_message`, `api_closed`, `api_answer`, and `AppHost` for `serve` and the freeze) and answers through `Answer::{Now, Later}`, so requests can open windows, close panes and wait for tmux; 11b fills `api_answer` in through `api_request` and keeps per-connection cleanup in `api_forget`. Cost: none.
- Ids: "active" is the current window's focused pane; "all" is every pane in a window by window number (buried excluded); decimal ids reach buried panes. Cost: none.
- SendText goes through `user_write` with `Write::SendText` or `Write::SendTextLocal` after entering the pane's window, so broadcast domains, gateways and tmux panes behave as typed text. Cost: none.
- `activate_app` calls `bring_forward` on the target window (or the current one); `raise_all_windows` and `ignoring_other_apps` have no Windows meaning and are ignored. Cost: from a background script Windows may flash the taskbar button instead of bringing Tandem forward.
- Close without force asks Tandem's own confirmations (`confirm_close`, modal), and every API close is undoable like the menu's. Cost: none.
- Custom profile properties become a session copy of the profile (`store.sessions`) made before launch, so a Command or directory applies; `Guid` and the original-guid key are ignored; a JSON null removes the key. Cost: a script setting "Guid" sees no effect.
- CreateTab without a window (or a profile that never opens in a tab) opens a window that comes to the front even with `select_tab` false; in an existing window `select_tab` false keeps the active tab and does not raise. Cost: a background new window takes focus.
- CreateTab with a custom property whose JSON does not parse answers MISSING_SUBSTITUTION (iTerm2's status for no session). Cost: a script sees that status where iTerm2 may launch with an odd profile.
- SplitPane `before` is a split followed by a swap of the two panes; each new pane gets its own session copy. Cost: none.
- GetBuffer treats trailing default blank cells as uninitialized; wide-character spacers have 0 code points; `blink` and `guarded` are false (alacritty keeps neither) and `image` is NONE (Tandem draws images as placements, not cell attributes). Cost: scripts cannot find images or blinking text through styles; trailing typed spaces with default colors are dropped.
- Prompt ids are the mark id in decimal (unique per session); `excluded_subranges` is always empty (Tandem does not track PS2 or right-prompt cells). Cost: scripts that subtract excluded subranges get the whole command range.
- Screenshot renders the pane's visible screen with the current window's renderer after entering the pane's window (a buried pane uses the current window and its font). Cost: a buried pane's picture may use another window's font size.
- Session-scope user variables set by the API live in 11a's store and win over SetUserVar values of the same name until the script sets null. Cost: a shell's later SetUserVar of the same name is hidden (iTerm2's last writer wins).
- "*" returns every name the scope resolves (`scope_values`) with string values. Cost: the key set differs slightly from iTerm2's frame enumeration.
- VARIABLE_CHANGE comes from a per-pass diff of scope values while any subscription exists (11a's approach for other notifications). Cost: a value set and reset within one pass posts nothing; watching "all" costs one variables build per session per pass.
- SetProperty `grid_size` grows or shrinks the window by the cell difference so that the pane gets the size; IMPOSSIBLE in full screen, with Lock Size, for tmux panes and for buried sessions; never DEFERRED. Cost: with splits, other panes change size too (as iTerm2's fitWindowToTab).
- iTerm2's quirks are kept: `grid_size` get minus one, "all" setting one session, window "all" not found, repeated "all" variable subscriptions posting twice. Cost: scripts see iTerm2's same behavior.
- SetProfileProperty guid-list values must pass `prompted::valid` like session values (Tandem's profiles are typed; iTerm2 stores anything). Cost: an illegal value for a saved profile is refused where iTerm2 would store it.
- NOTIFY_ON_PROFILE_CHANGE and NOTIFY_ON_LOCATION_CHANGE are routed exactly as iTerm2 routes them and are never posted. Cost: none (the stock package cannot subscribe to profile changes).
- Preferences store any key with a non-null JSON value in `settings.toml` and apply it as a Settings edit; an unknown key reads unset. Cost: a script can store keys Tandem never reads (as iTerm2).
- SavedArrangement save replaces an existing name without asking (iTerm2's API path); restore with a window id restores as tabs in that window. Cost: none.
- RestartSession refuses tmux panes, gateways and loaded recordings (iTerm2's `isRestartable`: no program). Cost: none.
- SetTabLayout sets split ratios from the requested grid sizes and leaves the window size alone (iTerm2 refits the window); a tmux tab answers OK and changes nothing. Cost: scripts that relied on the window growing see ratios only; tmux layouts cannot be set through the API yet.
- ReorderTabs refuses (INVALID_ASSIGNMENT) to move a tab holding a loaded recording to another window, keeping Tandem's rule. Cost: none realistic.
- MenuItem uses XIB identifiers verbatim (some still say "iTerm2"; they are identifiers, not user text); enabled is Tandem's static rule (not a later-milestone command, not in `DISABLED_IN_SESSION`), checked comes from the menu bar's check items. Cost: items iTerm2 disables dynamically may report enabled; selecting one does what the command does now.
- Selection handles one sub-selection (alacritty keeps one); a set with more is REQUEST_MALFORMED; column windows are validated and then ignored; SMART maps to Semantic, WHOLE_LINE to Lines; `connected` is false. Cost: multi-part selections cannot be set or read.
- Tmux CreateWindow answers when the new window's tab opens, matched by the command's tag; SendCommand answers on the reply; a gateway that goes away answers both empty. Cost: none.
- ColorPreset lists no presets and finds none until milestone 13 (iTerm2's own answers for a missing preset). Cost: scripts cannot read presets yet.
- Keystroke notifications carry macOS key codes (`mac_keycode`, `mac_modifier_keycode`) and FUNCTION for keys whose character is in U+F700 to U+F8FF; KEY_DOWN and the filter run just before key routing, so keys taken earlier (Copy Mode, the completion list, a shortcut, the find bar) are neither posted nor filtered; FLAGS_CHANGED comes from modifier key events. Cost: those consumed keys are invisible to monitors.
- Screen updates are posted once per loop pass for each pane that got output. Cost: a change without output (a resize, Clear Buffer) posts nothing.
- COMMAND_START is posted only when a command really started (Tandem's C returns early otherwise), with its text or unset when empty. Cost: a bare C with no command posts nothing.
- The Custom escape sequence now needs its colon for both the API and the Custom Escape Sequence trigger event, as iTerm2. Cost: a program that omitted the colon no longer fires the trigger.
- Parity rows are found by title.

### Pitfalls for the implementer

- 11a's `routes_follow_iterm2` asserts that SendText answers malformed; Task 1 changes that assertion, it does not add a second test.
- prost omits `None`: set statuses where iTerm2 sets them and nowhere else (the unset ones are listed in Global Constraints).
- `user_write` reads the current window's broadcast view: enter the pane's window first, or text broadcasts by the wrong window's domains.
- `api_model` and `api_ids` enter windows to read their tabs: restore the window that was current before returning, as `snapshot_all` does.
- Tmux replies cannot arrive while a transaction freezes the UI thread (iTerm2 documents the same: "This may not be called from within a Transaction"); an `Answer::Later` inside a transaction waits for its end.
- `gen-menus.py` rewrites the whole file: diff it; only `identifier` lines may be added. TOML strings take the escape `\u2026`, not the character itself.
- `Mark::new` gains fields: update every literal construction (the compiler lists them, `src/marks.rs:1158` builds a `Captured`, not a `Mark`).
- `import::from_json` drops nulls silently; `custom_values` and `preference_value` must look for nulls before converting.
- The alacritty `Selection` end is inclusive with `Side`; the API's end is exclusive: `Side::Left` at the end column, and the last column with `Side::Right` when the end is the width.
- `api_events` must only fill while `api_watch` is on: screens outside panes (Porthole, replay copies) never drain them.
- A filtered key must still be posted to keystroke monitors before returning.
- Every new App field here is app-wide; none goes in `WinSlot` or `swap_live`.
