Everything else in `sources/Browser/` belongs to the other 13x follow-up plans.

**Goal:** in a browser pane, Win+F opens Tandem's own find bar, typing highlights every match on the page (iframes included) in iTerm2's yellow with the current match in orange, Return, Find Next and Find Previous move through them exactly as iTerm2 does for web pages, Esc clears the highlights, Find URLs labels the page's links with shortcut bubbles that open the link, Find Globally lists page matches with context beside terminal matches and reveals the picked one; Edit > Copy Mode shows iTerm2's copy-mode cursor on the page and the same vi keys as in a terminal move it, select, and copy with y.

**Architecture:** pure models first, each a plain `pub mod` tested on EXTREME without a web view. `browser_find.rs` is the find side: the four browser modes and iTerm2's smart-case rule, the assembled `custom-find.js` (13x2's `fill_template` expands its includes through `browser_js::resource`, ruling Q2), the command JSON, the per-pane `Model` (iTerm2's `iTermBrowserFindManager` with its default and global states), result parsing, the counter label, the global-search snippet, and the find-family selector table. 13x2 Task 2's `browser_frames.rs` and `src/app/browser_frames_app.rs` are iTerm2's graph-discovery native half (frame registry, evaluation in a named frame, the two-phase report), consumed here. `browser_copymode.rs` maps the shared copy-mode `Action` (extracted from `copymode.rs` so the terminal and the browser read one key table) to the page API, and holds the page-side key capture script. The app side is `src/app/browser_find_app.rs` (the find bar, menus and global search reaching a browser pane) and `src/app/browser_copymode_app.rs` (copy mode in a browser pane). iTerm2's JS is copied unchanged into `resources/browser/` and embedded with `include_str!`; every script is a Client-world script registered through 13x2's `App::browser_user_scripts` and wrapped by `browser_js::wrap`, so it runs in Tandem's isolated world `tandem-client` (R13x23-1, 13x2 Task 0 and Task 1), never in the page's world; every message arrives through 13x2's `App::browser_message` (World::Client only through the isolated world's binding), and every native call into those scripts goes through `App::browser_js_call` (the main frame's world) or `App::browser_js_call_in_frame` / `App::browser_eval_in_frame` (a named frame's world), all `Runtime.evaluate` in Tandem's context; `WebView::execute_script` and `execute_script_in_frame` (the page world) are never used for them. Per-pane state lives in new fields of 13x's app-wide `BrowserView` (keyed by pane, so no `swap_live` entry).

**Tech Stack:** as 13x and 13x2; no new crate. `serde_json` (commands and results), `arboard` (the copy mode copy, the clipboard already held by `App.clipboard`, `src/app/mod.rs:554`), `regex` (the include pattern). WebView2 through 13x's `webhost_win::WebView` and 13x2's extensions only (the isolated world and `Runtime.evaluate` through 13x2's `browser_devtools`; no DevTools call of its own). Windows crate features this plan uses, listed explicitly (R13vw-6): `windows-sys` `Win32_UI_Input_KeyboardAndMouse` (`SetFocus`, Task 4) and `Win32_Foundation` (`HWND`); both are in `Cargo.toml` today.

### Corrections to the research (the source wins)

- iTerm2's browser find is not WebKit's find: it is a custom JS engine with iTerm2's four modes, iframe search through its own frame graph, and match contexts for global search (`FM`, `FE`).
- In a browser, Return in the find bar always searches forward, unlike the terminal (`PS:9158-9160`).
- iTerm2's browser find counter does not move on Find Next (partial updates are dropped, `FM:128-132`); fixed here (writer question 3, ruled as recommended).
- Browser copy mode ignores line and box modes for the selection itself (`CMI:721-754`).

### Decisions (each goes in `m13x3-rulings.txt`)

- Find on page uses iTerm2's JS engine, not WebView2's native find (`ICoreWebView2Find`): regex modes, iframe results, contexts for Find Globally and the shortcut bubbles need it (writer question 4, ruled as recommended). Cost: a large page script in every browser page.
- The find engine, graph discovery and copy mode run in Tandem's isolated world (R13x23-1 to -3; 13x2's DevTools world), so `window.iTermCustomFind`, `window.findNav`, `window[Symbol.for('iTermGraphDiscovery')]` and `window.iTerm2CopyMode` do not exist in the page's world. Cost: none against iTerm2 (its `.defaultClient` hides them the same way); the highlight and cursor DOM nodes stay visible, as in iTerm2.
- Without the isolated world, neither find nor copy mode is installed (R13x23 fix pass item 1 removed the page-world fallback). Cost: no find and no copy mode on such a view (recorded partial).
- An include 13x2's `fill_template` leaves unexpanded (a missing resource in a release build) makes `find_script` or `script` answer `Err`, which logs and injects nothing instead of crashing (iTerm2 crashes). Cost: none for shipped files.
- The include expansion, the frame graph and its copied files are 13x2's (ruling Q2); this plan appends its own files to 13x2's `resource` table. Cost: none.
- The frame graph's evaluations are accepted only from `World::Client` messages, which only Tandem's isolated world can produce (13x2's binding and context check; R13x23-2). This restates the earlier premise, false in the page world, that the secret alone made a message Client. Cost: none (iTerm2's handler lives in the client world, unreachable by pages); forged `IFRAME_GRAPH_DISCOVERY` window messages can name frames, as in iTerm2 (13x2's Decision).
- The find bar sits in a strip above the page while open (a child window cannot be covered by the scene). Cost: the page moves down by one bar height while finding (writer question 5, ruled as recommended).
- The browser counter keeps iTerm2's formula (backward when the swap is off). Cost: an odd count with the swap off, as in iTerm2.
- The partial-update bug is fixed (writer question 3, ruled as recommended). Cost: none visible except a correct counter.
- Find Globally reveals a page match without the highlight animation. Cost: no animation (Tandem has none for terminals either).
- Copy mode copies through Tandem's clipboard (writer question 6, ruled as recommended). Cost: none visible; works on http pages where iTerm2's page call would fail in WebView2.
- Copy mode keys are taken by a Tandem key listener in the isolated world of every frame (capture phase on `window`, trusted events only, a world-local switch) (writer question 7, ruled as recommended; I4). Cost: none known; the listener is added at document start, before any page listener on `window`.
- Copy mode on a browser keeps Tandem's terminal key set (Task 7). Cost: keys iTerm2's dict has and Tandem's table lacks stay missing in both until the terminal copy-mode rows fix them.
- A key action 73 parse error in a browser shows Tandem's existing banner, not iTerm2's suppressible announcement. Cost: no "do not show again".
- `withoutForceSearch` (`FM:461-467`) has no caller in Tandem and is not built. Cost: none.
- Find URLs validates a custom pattern with fancy-regex (13s's `find_urls_regex`) while the page runs it as a JavaScript `RegExp`; a pattern one accepts and the other rejects (for example the inline flag `(?i)`) is searched as literal text in a browser pane. Cost: such a pattern shows no bubbles in browsers.

### Pitfalls for the implementer

- Commands must go to the page in order (iTerm2's mutex, `FM:270`): send the next only when `browser_js_call` answers the previous.
- `find-security.js` captures the bridge at load; if the find script is injected after the page's scripts (DocumentEnd), the capture sees nothing and results never arrive. Keep `Inject::DocumentStart`.
- The script sizes: `find-engine.js` alone is 2022 lines; `AddScriptToExecuteOnDocumentCreated` accepts it, but build the string once per pane, not per navigation.
- `graph-discovery.js` is registered once, by 13x2 Task 2; this plan never adds a second "GraphDiscovery" script.
- The find bar's typing flag cannot see page clicks through winit (the page is a child window): use `Event::Focus(view, true)`.
- Cross-origin iframes: they get Tandem's world only through 13x2's `Target.setAutoAttach` child sessions, and nested same-origin frames through `Page.addScriptToEvaluateOnNewDocument`; a frame without a Tandem context contributes no matches.
- Never pass a find match's text to a shell or `ShellExecute`: the open shortcut goes through the page's `window.open`, which 13x routes to a browser tab.
