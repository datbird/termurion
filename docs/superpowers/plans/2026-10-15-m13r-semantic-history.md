### Decisions (each goes in `m13r-rulings.txt`)

- Command Info (`02:618`) and the selected-command buttons (`02:771`) are built here, over 13s's command selection, rather than recorded as dependencies (13p-r rulings, built after 13s Task 9 and 13j Task 6). Cost: a larger 13r; if 13s Task 9 slips, Task 8 waits.
- iTerm2's IDN character table is approximated by Unicode letters and digits plus its ASCII extras. Cost: a rare symbol iTerm2 counts (or not) as a URL character differs.
- The character sets are read at each click, not cached until restart as iTerm2's help says. Cost: none (the help's restart note stays, harmless).
- The URL preview shows the URL alone in the "hover" banner (iTerm2's hover view shows only the URL). Cost: Tandem's "Win-click opens" wording goes.
- `PathsToIgnore` prefixes compare ignoring case with `/` read as `\`. Cost: a case-sensitive folder on a WSL mount matches more.
- A drive's remote status is cached per letter for the run. Cost: a drive remapped while Tandem runs keeps its first answer.
- UNC paths are never probed, even with `EnableSemanticHistoryOnNetworkMounts` on (implementer invariant). Cost: a UNC path in output cannot open by Win-click.
- Smart Selection interpolated parameters are evaluated without function calls, synchronously (iTerm2 allows calls, asynchronously). Cost: a parameter calling a script function does not run.
- Captures for command actions are quoted for cmd.exe (`cmd_quote`), not backslash-escaped for sh. Cost: a rule written for iTerm2's sh escaping quotes differently.
- SECURITY (13p-r ruling): the URL handler is never run through `cmd.exe /c` with the URL in its command line. The evaluated command is split with `CommandLineToArgvW` rules into a program and arguments and started with one `CreateProcessW` (Rust's `Command`); `\(url)` is bound to a private-use marker during evaluation and replaced by the raw URL inside its argument afterwards (appended as the last argument when absent), so a URL can never add arguments, choose the program or reach a shell; a `.cmd`/`.bat` handler (found through `PATH` and `PATHEXT`) or cmd.exe itself refuses a URL holding `% ^ & | < > "` or a control character; every handler refuses control characters. iTerm2 runs the string through the user's shell with the URL substituted. Cost: a handler that relied on shell syntax (`start`, pipes, `&&`) must be written as a program with arguments (`cmd.exe /c start "" \(url)` still works for URLs without cmd.exe's special characters, since cmd.exe gets the batch rule; `explorer.exe \(url)` works for all); a rare URL is not passed to a batch handler.
- The handler's help text drops `cmd.exe /c`, says the command is split into a program and arguments with the URL as its own argument, gives `explorer.exe \(url)` as the example, names the batch-file refusal, and "option" becomes "Alt". Cost: differs from iTerm2's text where it would mislead on Windows.
- Run Command in Window runs `cmd.exe /c <command>` in a single-use window of the default profile. Cost: a POSIX command needs `wsl` in the rule.
- Command Info's stop sign and check mark are Segoe Fluent Icons glyphs (`\u{E711}`, `\u{E73E}`), not emoji (no emoji in Tandem). Cost: a slightly different look.
- The Command Info time uses the Windows user's time format with seconds; the date is `MMM d, yyyy` in English. Cost: a non-English user sees English month names (as iTerm2's fixed format does).
- The draggable folder icon and "Open Share Sheet\u{2026}" are not offered (no macOS share sheet; the OLE drag source is 13s's text drag). Cost: two missing affordances.
- The selected-command Share menu offers only "Add Command as Snippet", "Save Command & Output\u{2026}" and "Copy Command URL to Clipboard". Cost: no share sheet items.
- The command URL keeps iTerm2's `iterm2:/command?...` form; Tandem registers no handler for it yet (13v). Cost: pasting it elsewhere does nothing until then.
- The composer text and navigator `cd` quote for the session's shell: PowerShell single quotes (doubled inside), cmd.exe double quotes, POSIX shells backslash escapes (iTerm2 always backslash-escapes). Cost: an unknown shell gets cmd.exe quoting.
- Prompt paths also start at a drive letter followed by `:\` or `:/`. Cost: `C:` inside other prompt text may be read as a path when it names an existing folder.
- The navigator list draws at the cursor, not beside the path. Cost: a long prompt puts the list away from the clicked path.
- Parity rows are found by title.

### Pitfalls for the implementer

- `semantic::url_like`'s signature is 13s's: do not change it again; add fields through `UrlPrefs` passed alongside.
- `ClickContext` is built in several places (`clicked`, `open_text`, labels): give every new field a `Default` and set it only where the setting matters.
- Never call `Path::exists` or `is_dir` before `netpath::may_probe`; the existing UNC test must stay under 2 s.
- `execute` now needs the event loop for `Run::Window`: thread it through `open_target` and `context_picked` rather than storing a pending window elsewhere.
- `cmd_button_hits` is per window: add it to `swap_live`, or a click in one window presses another's button.
- The path sniff runs at every prompt end: keep it to the prompt rows (at most 5) and local folders, or a slow drive stalls typing.
- The Command Info window ticks only while its command runs; stop asking for frames when it closes or the command ends.
- Emoji must not appear in code or text; use the glyph escapes.
- 13j replaces `update_hover`'s `set_cursor`; merge with its `refresh_pointer_shape` call if it has landed.
