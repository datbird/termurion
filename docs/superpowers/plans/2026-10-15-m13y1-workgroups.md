**Goal:** a person can define a workgroup (a main session with peers, splits and tabs, each with its command, mode and toolbar), enter it from Shell > Workgroups or a trigger, switch between peers in one pane with the mode switcher or Alt+Win+[ and ], review a coding agent's changes in a Diff peer that waits for changes and a Code Review peer that asks for a prompt, have reviews sent back automatically, and find everything again after a restart; the Claude Code integration installs its workgroup and triggers exactly as iTerm2's does.

**Architecture:** pure models first, each a plain `pub mod` tested on the Windows test machine. `workgroup.rs` is the data model with iTerm2's Codable JSON form, presets, the Claude Code template and the migrations. `workgroup_edit.rs` is the editor's model (tree rows, labels, the item rules per session kind and mode, undo snapshots); `workgroup_editor_ui.rs` draws it inside Settings. `workgroup_run.rs` is the entry model: dispositions and refusals, the spawn plan (peers buried, splits and tabs around the leader), teardown order, the close warning, provenance. `workgroup_peers.rs` is the peer port's model (members, activation, offsets, digit shortcuts, busy flags). `workgroup_toolbar.rs` is the toolbar's model (items to views, layout at 40 points, labels, the shortcut dispatch rule). `workgroup_git.rs` is the git side (the poller's cadence, the changed-file groups, "All Files (n)", the base selector's recents, per-file command substitution with shell quoting per shell); the git runs themselves are 9i's `git_state`, extended in Task 6 with iTerm2's per-file statuses, the base and the diff stats. `code_review.rs` is Code Review mode (saved prompts, the overlay model, the auto-send and auto-request rules). `workgroup_restore.rs` is the arrangement descriptor. The app side: `src/app/workgroup_app.rs` (instances, entering, exiting, the menu, peers, triggers), `src/app/workgroup_toolbar_ui.rs` (drawing and clicks in each member pane's toolbar strip), `src/app/workgroup_git_app.rs`, `src/app/code_review_app.rs`, `src/app/workgroup_restore_app.rs`. Instances are app-wide (`App.workgroups: crate::app::workgroup_app::Instances`, keyed by instance id); every member pane keeps a back-pointer `Pane.workgroup: Option<String>`. The toolbar strip takes its 40 points inside 13h's `pane_chrome`, so pty sizes, hit tests and the tmux size report follow. No new App field is per window.

### Decisions (each goes in `m13y1-rulings.txt`)

- The stored JSON is iTerm2's, shortcuts included (`Keystroke::serialized` is iTerm2's form, R13xy-9). Cost: none.
- `\(iterm2.appBundlePath)/Contents/Resources` in commands maps to Tandem's resources folder. Cost: a hand-written command that uses the bundle path for other files finds only Tandem's.
- Substituted file names and bases are quoted for the session's shell as 12c's `ai_shell::shell_kind` reports it (cmd, PowerShell, POSIX; Unknown as POSIX); cmd refuses values with `"` or `%`. Cost: a shell 12c misdetects gets the wrong form; a file named with `%` cannot be picked in a cmd session.
- iTerm2's libgit2 calls for the per-file statuses, the base diff and the diff stats are git commands in `git_state` (Task 6's list), with `--no-ext-diff --no-textconv` and the existing hardening. Cost: a git older than the one `git_state` already needs may lack `--find-renames` on status; renames then show as a delete and an add.
- The AI Usage item's built-in command finds only `claude.exe` (12f ruling 12f-5). Cost: an npm install needs the item's command set by hand.
- The AI Usage item's default runs `claude -p /usage` and parses it in Tandem (no bundled shell script). Cost: a change in Claude Code's output format needs a Tandem update, as the script does for iTerm2.
- Peers swap in place in the layout tree; focus moves only when the swapped-out member had it. Cost: none known.
- The Diff waiting overlay and the Code Review prompt are in-pane panels drawn in `Frame.popups`. Cost: a different look from iTerm2's views.
- Browser workgroup triggers are built by 13x5 on this plan's names. Cost: none once 13x5 lands.

### Pitfalls for the implementer

- Every map keyed by pane or instance must be cleaned on `pane_gone` and on teardown; a member ending during entry must not leave a half-registered instance.
- The toolbar's 40 points must come out of the pane before the pty and tmux sizes are computed (13h's rule); a peer swap must not resize the pty of the shown member.
- Never type a per-file command into a session whose program is not the configured one: send Ctrl+C first, as iTerm2 does, and only for the owning session.
- The auto-send Return must be a separate literal write after the bracketed paste has fully drained; a timer from the start of the paste loses the Return on large reviews (`WPP:309-330`).
- The Enter trigger's side effect runs after the trigger pass, never inside it (entering spawns panes).
- Restored buried peers are not in Tandem's buried list until adopted; the Buried Sessions menu must not show them twice.
