**Architecture:** pure models first, each a plain `pub mod` tested on the Windows test machine. `src/wheel.rs` is iTerm2's scroll accumulator (modern and legacy paths, one per axis and purpose, on the Pane), the reporting and arrow step counts, and the alternate-scroll decision; `src/input.rs`'s `wheel` becomes the router over it. `src/alt_infer.rs` is iTerm2's alternate-scroll inferrer. `src/stuck_mouse.rs` is the turd detector (the pattern a shell echoes back from a mouse report). `src/pointer_shape.rs` chooses the pointer shape. `src/firstmouse_win.rs` (`#[cfg(windows)]`) subclasses each terminal window to see `WM_MOUSEACTIVATE`. The vendored alacritty_terminal gets one patch (DECSET 1007 off at start and gated). ### Corrections to the research (the source wins)

- DECSET 1007 is implemented: the vendored alacritty handles it (`term/mod.rs:2087`, `:2139`, `:2179`) and starts with it ON (`:113-120`). The research's "DECSET 1007 not implemented" is wrong; the mismatch is the default and the missing profile gate. Tandem's wheel code ignores the mode entirely (`src/input.rs:77-97`).
- `02:605`, `02:606`: the custom strings are unreachable for vertical scrolling in 64791fc. `MH:1618` returns NO for a vertical scroll when alternate scroll is off (its log says "Horizontal", the condition tests vertical), and when it is on, `TV:8362-8369` sends arrows, not the strings. The only effect: in the alternate screen, with the feature off and a string set, a horizontal wheel is swallowed (an empty legacy string is "sent" and nothing scrolls). The research cites `TV:8392` as if the strings were sent.
- The inferrer (no parity row) is fed only from that same final branch, so in 64791fc it sees horizontal-dominant wheel events only; its question is nearly unreachable. Ported as written (kept quirk).
- `02:619` `SensitiveScrollWheel` acts only on the legacy accumulator (`SA:160`); with the default modern accumulator it does nothing. The research's "default NO behavior ... no ceil path" is right about Tandem, not about where iTerm2 reads it. `02:1072` `UseModernScrollWheelAccumulator` was marked n/a; it is two portable delta formulas and is the switch that makes `02:619` do anything, so it applies (Decisions).

### Decisions (each goes in `m13j-rulings.txt`)

- Windows has no gesture phases: a `LineDelta` whose notch count is not a whole number (`(d * 120).round() % 120 != 0`) or any `PixelDelta` is a precise (touchpad) event and takes iTerm2's trackpad path; whole notches take the wheel path. The trackpad accumulator is never reset at a gesture start (turnaround still rounds). Cost: a leftover fraction can carry into the next swipe; a touchpad that sends whole notches scrolls like a wheel.
- Lines stay notches times `WHEEL_LINES` (3, Windows' default) for both paths; iTerm2's `deltaY` and `scrollingDeltaY` are both that value. Cost: the Windows "lines per notch" setting is not read (as before).
- Units for the reporting division are points (the cell size divided by the scale), as iTerm2's. Cost: none known.
- The wheel remainders move from the window (`WinSlot`, `swap_live`, the m7a ruling) onto the Pane, three accumulators per pane as iTerm2's text view and scroller hold them. Cost: two windows can no longer share a remainder (they never should).
- `02:1072` is brought into 13j (applies; Settings shows it) because `02:619` depends on it. Cost: one more row than the research counted.
- R3 fixes, each a behavior change users will see: the alternate-screen wheel scrolls (nothing moves in most full-screen apps) unless 1007, the profile or the Advanced switch asks for arrows; DECSET 1007 starts off; a notch reports once and sends one arrow; horizontal wheel steps need ten times the movement (0.1); the activating click is not reported. Cost: users used to Tandem's arrows lose them until they turn on "Automatically enable alternate mouse scroll" (the inferrer question almost never offers it, as in iTerm2).
- Kept iTerm2 quirks: the inverted vertical check and the swallowed horizontal wheel with a custom string set; the inferrer fed only by horizontal events; `pow(0, 0) * -1` for a zero delta with acceleration 0; truncation before the double-report check. Cost: as iTerm2.
- Ctrl+wheel with no other modifier is the pinch gesture (a precision touchpad pinch arrives as Ctrl+wheel); one notch is magnification 0.5, so one notch is one font step; with `PinchToChangeFontSizeDisabled` on, Ctrl+wheel is reported or scrolls like any wheel. Cost: Ctrl+wheel no longer reaches a mouse-reporting app by default.
- Font size changes are app-wide (Tandem shares one font; `commands.rs:82`), where iTerm2 changes the session's. Cost: as for the menu items.
- First mouse is a client-area `WM_MOUSEACTIVATE` on a window that is not the foreground window, seen through a window subclass. Cost: a click that Windows does not route through `WM_MOUSEACTIVATE` (none known) is never first mouse.
- `StealKeyFocus` maps to `SetForegroundWindow` from the pointer entering a Tandem window while another app is in front; Windows' foreground lock may refuse and flash the taskbar button instead. Cost: partial; the row stays partial.
- Plain focus follows mouse now makes another Tandem window key when the pointer enters it while Tandem is in front (iTerm2's non-steal path), which Tandem did not do. Cost: a window can take focus from a window the user was typing in (as in iTerm2).
- Stuck-report matching is a byte substring over the pane's output stream (with a carry across chunks) within 100 ms, where iTerm2 matches an escaped regex through its expectation engine. Cost: output that reorders the echo (cursor moves between the characters) is missed.
- The pointer shape omits iTerm2's open hand (Tandem has no modifier pane drag; 13h) and OSC 22 app pointers (Tandem has none); the rectangle crosshair uses Tandem's Ctrl+Alt block-selection chord. iTerm2's `IBarCursor*.png` images are GPL-2.0 and are not shipped (13j-l ruling, same reasoning as the 13n Powerline ruling): the plain I-beam is the system `IDC_IBEAM` (`UseSystemCursorWhenPossible`, the default) or an I-beam Tandem draws; the circled I-beam is always Tandem's drawing at `IBarCursorXMR`'s sizes (Windows' I-beam image cannot be composited without reading the system cursor bitmap). Cost: the drawn cursors do not match a themed system I-beam.
- `02:471` Open URL in background and `02:491` QuickLook are final partial rows (ruling R7; no code in 13j). Cost: none.
- R3 addition (13j-l rulings): the profile schema default of "Mouse Reporting" becomes true, iTerm2's stock profile. Cost: new profiles report the mouse to programs that ask; profiles that stored false keep it.
- With the first-mouse click held, hover motion (DEC 1003) is not reported either, as `mouseReportingAllowedForEvent` blocks every report but the wheel. Cost: none known.
- Aggressive focus follows mouse and the saved refusal point act only when Tandem as an app gains or loses activation, never on a switch between two Tandem windows. Cost: none known.
- Move Pane's pointer action answers `Later(13)` (13h) instead of the stale `Later(7)`. Cost: none.
- Parity rows are found by title.

### Pitfalls for the implementer

- The composer, toolbelt, clip and porthole wheel handlers take the raw delta before any accumulator; keep them first and keep passing them the same values they get today.
- `vertical` is strict: a diagonal event with equal axes is horizontal.
- Arrows go through `Pane::input` as typed text, never through `write_mouse_report` (they must not arm the stuck detector); iTerm2 writes them Latin-1 encoded, and they are ASCII.
- Do not read `HorizontalScrollingSensitivity` in `route_wheel`: it is fixed per pane at creation (`install_pane` and the tmux setup overwrite the constructor's `PaneWheel::new(0.1)`).
- `first_mouse_down` must be cleared by the next press, not by the release, so a drag after an activating click stays unreported.
- `WM_MOUSEACTIVATE` also arrives for clicks on the tab bar and the status bar; the flag is only taken by the terminal-view part of `mouse_press`, so clear it (take and drop) at the top of `mouse_press` when the press lands elsewhere.
- tmux panes: wheel reports for an `Io::Tmux` pane go to tmux as today; the alternate-screen decision uses the pane's own screen mode.
- A custom cursor needs the `ActiveEventLoop`: build `Cursors` in `resumed` and keep them; `mouse_move` has no event loop.
- The stuck detector must see output before any screen filter or tmux routing drops it, but after the tmux hook splits control mode off (feed it where `echo_probe.output` is fed).
