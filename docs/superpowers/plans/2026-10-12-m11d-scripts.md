**Goal:** a person can make, run, stop, import, export and edit Python API scripts from the Scripts menu exactly as in iTerm2: a new script from a template opens in their editor and runs from the menu with a check mark while it runs; its output, connection and every API message show in the Script Console; AutoLaunch scripts start with Tandem when the API is on; Open Python REPL gives a connected asyncio REPL; every download is a named, confirmed user choice.

**Architecture:** pure models first, each a plain `pub mod` tested on EXTREME. `scripts.rs` is the Scripts folder rule, the tree scan (through an `Fs` trait) and its texts; `scripts_scan.rs` (`#[cfg(windows)]`) watches the folder and scans on a worker thread. `script_runtime.rs` is Python: layout, versions, markers, `setup.cfg`, command builders, consent and error texts, the pinned uv source. `script_provision.rs` is the provisioning job model over a `Runner` trait, with a `#[cfg(windows)]` real runner (curl.exe, tar.exe, uv, python) and a worker thread. `script_history.rs` is the Script Console's data (entries, timestamped log lines, calls, running state) and replaces 11a's `api_auth::Log`. `script_launch.rs` classifies a path and builds the launch; `script_proc.rs` (`#[cfg(windows)]`) runs one script in a Job Object. `script_new.rs` holds the templates and New Python Script's paths; `script_archive.rs` the import and export layout; `script_deps.rs` the dependency editor's rules. Windows (egui, through `EguiHost`): `script_new_ui.rs` (picker), `script_console_ui.rs`, `script_inspector_ui.rs`, `script_export_ui.rs`, `script_deps_ui.rs`. The app side is `src/app/scripts_alerts.rs` (the alert queue), `src/app/script_runtime_ui.rs`, `src/app/scripts_app.rs` (launching, the menu, AutoLaunch, New Python Script, REPL, import and export), `src/app/script_console_app.rs` and `src/app/script_deps_app.rs`. Every new App field is app-wide; none goes in `swap_live`.

**Tech Stack:** as milestones 11a to 11c (prost 0.14, tungstenite 0.28, getrandom 0.4). No new crates: `serde_json` (markers, uv's JSON), `sha2` (`Cargo.toml:27`, the uv download check), `rfd` (`Cargo.toml:25`, file dialogs), `regex` (PEP 508 names), `std::process::Command` and `std::io::pipe` (scripts, uv, pip), `windows-sys` `Win32_System_JobObjects`, `Win32_Storage_FileSystem` and `Win32_UI_Shell` (already enabled). ### Decisions (each goes in `m11d-rulings.txt`)

- Python comes from Tandem's own uv (`%APPDATA%\Tandem\uv`) when installed, else the first installed Python 3 by 11e's rule (py launcher, then `python.exe`/`python3.exe` on PATH outside WindowsApps); an installed Python builds venvs with `-m venv` and `-m pip`, marker backend "venv". Cost: two provisioning paths to keep right.
- `pythonRuntimeUsesUV`, `pythonRuntimeDownloadURL`, `uvManifestDownloadURL`, `pythonRuntimeBetaDownloadURL` and `setIT2AppPath` are stored with iTerm2's defaults and do nothing: the manifests serve macOS runtimes, there is no legacy runtime and no AppleScript target. Cost: changing them has no effect.
- uv comes from a pinned GitHub release (`UV_VERSION`, x64 and arm64 zips) whose SHA-256 is checked before unpacking; downloaded with `curl.exe`, unpacked with `tar.exe`. Cost: a newer uv needs a Tandem update; Windows before 10 1803 lacks those tools.
- Every download asks first and names its source: iTerm2's "Download Python Support?" text names github.com/astral-sh/uv and python-build-standalone and loses "Additional Python versions are downloaded automatically later if a script needs them."; package installs get Tandem's "Download Python Packages?"; Check for Updated Runtime asks first; AutoLaunch and other non-user paths never download and log iTerm2's environment-missing line instead. Cost: one more dialog per new environment.
- Environments get `iterm2` and `certifi`, not `pyobjc` (no Windows build). Cost: scripts that import objc fail (they cannot work on Windows).
- `UV_LINK_MODE` is not set (clone is APFS-only; uv's Windows default applies); the other five uv variables are iTerm2's. Cost: none known.
- Scripts run directly as `<venv>\Scripts\python.exe <script> args` through `std::process::Command` (hidden, stdout and stderr on one pipe, in a Job Object killed with Tandem), not `$SHELL -c` with the wrapper; the environment adds `ITERM2_COOKIE`, `ITERM2_KEY`, `PYTHONUNBUFFERED=1`, `PYTHONIOENCODING=utf-8`, `SSL_CERT_FILE`, removes `PYTHONPATH` and `IT2_SUITE`, and sets neither `HOME` nor `SHELL`. Cost: scripts end when Tandem quits (they would lose their connection anyway).
- Only `.py` files and full-environment folders are scripts; `.scpt`, `.app` and `AutoLaunch.scpt` are ignored; a path that is not a script is never opened (the implementer-rules invariant), where iTerm2 opens it with its app. Cost: none usable on Windows.
- Exit codes at or above 0xC0000000 read "Script was killed by a signal"; Terminate is `TerminateJobObject` with code 1. Cost: a script exiting with such a code reads as killed.
- Alt held at the pick reveals a script (m7a's `GetKeyState` precedent); Windows menus have no alternate items, so "Reveal %@" is not shown. Cost: the reveal is undiscoverable from the menu.
- Menu titles show "Finder" as "Explorer" at display time; `schema/menus.toml` keeps iTerm2's titles and identifiers. Cost: none.
- Install Already-Downloaded Python Runtime is disabled, as iTerm2 under its default uv setting. Cost: no offline install from a hand-downloaded zip.
- `.its` archives are refused with Tandem's text: verifying their certificate chain would need X.509 code or a new crate. Export writes iTerm2's unsigned `.zip`; the code-sign row is not offered. Cost: signed archives from iTerm2 users cannot be installed.
- Zips are read and written with `tar.exe` (bsdtar, `--format zip`). Cost: depends on tar.exe.
- The folder is watched with a subtree change notification and scanned on a worker thread, 500 ms after the last change (iTerm2 scans on its main thread). Cost: a change shows up to half a second late.
- AutoLaunch does not suppress the startup window: Tandem's standing Windows rule opens a window when nothing else would show (`startup.rs`), and with a hotkey window the window is already suppressed; the Always open help keeps its text. Cost: an AutoLaunch user without hotkey windows gets a startup window iTerm2 would not open.
- Temporarily silenceable warnings show no checkbox (as 11c); permanently silenceable ones remember under iTerm2's identifier keys (`id`, `id_selection`), and "do not remember" buttons are never remembered. Cost: repeated warnings.
- Console timestamps are "M/d HH:mm:ss.SSS" and the Started column "M/d HH:mm:ss" (iTerm2 follows the locale). Cost: a different look.
- The Calls tab shows prost's pretty `Debug` text of each message, cut at 16 KiB, instead of the protobuf text format. Cost: a different shape; long buffers are cut.
- Script output is decoded as UTF-8 with split sequences carried and invalid bytes as U+FFFD (iTerm2 drops a chunk that is not valid UTF-8). Cost: none.
- The APS log moves into the Script Console's "Automatic Profile Switching" entry and `automatic-profile-switching.log` is no longer written. Cost: no persistent APS file.
- The Script Console has no find bar; its text is selectable and the Filter narrows lines. Cost: no Find Next in the console.
- Picker boxes and Inspector rows use Segoe Fluent Icons glyphs instead of iTerm2's emoji (the no-emoji rule). Cost: a different look.
- New Python Script's dependencies and Python version are asked in the picker, before the save dialog (Windows save dialogs take no accessory view); the save dialog opens in the Scripts folder and a Full Environment outside it is refused afterwards. Cost: fields come before the name.
- "Open new script in %@?" names the `.py` edit verb's app and opens with the "edit" verb, never "open" (which runs the file); with no edit verb the file is revealed. Cost: users with no editor association only get the reveal.
- Kept iTerm2 quirks: full-environment items are never checked and choosing one launches another copy; "Offer to launch automatically during installation" has no effect on unsigned exports (metadata is written but not zipped); `setup.cfg` keeps dependency order and drops repeats (iTerm2 orders them by a set, so its order is arbitrary). Cost: as iTerm2.
- Provisioning progress is a banner plus log lines in the "Tandem App" entry, not a progress window. Cost: no modal progress.
- The spaces rules stay (a custom folder with a space is invalid; a new name with a space is refused) though CreateProcess does not need them. Cost: fewer allowed names.
- Mac words and places in texts become Windows ones (Resume notes "Texts"); "Move to Trash" stays and uses the Recycle Bin. Cost: none.
- The REPL window uses the default profile, `start_command_override` and a new `start_env_override` read by 11a's `App::session_env`. Cost: none.
- Inspector rows and registered functions are sorted (iTerm2 lists functions in dictionary order). Cost: none.
- Parity rows are found by title.

### Pitfalls for the implementer

- A cookie is a secret: `launch_env`'s result, the REPL's `start_env_override` and `console_line` must never be logged; `console_line` holds only the python, the script and the arguments.
- Never run a download or pip install in a test; `FakeRunner` answers every step. The ignored test only uses an existing `target\api-venv`.
- Check the uv zip's SHA-256 before `tar.exe` sees it; remove the zip on every failure.
- Never open a `.py` with the "open" verb or `shell_open`: on Windows that runs it.
- `std::process::Command` inherits Tandem's console handles by default: set stdin to null and pass `CREATE_NO_WINDOW`, or scripts flash consoles.
- Assign the Job Object right after spawn; `terminate` must also close the script's API connections by key (11a `Server::close`).
- `api_reply` becoming `&mut self` touches every 11a to 11c caller; change them all (the compiler lists them).
- `api_auth::Log` goes; do not keep a copy beside `History`.
- The menu's check marks must refresh when a script starts or stops (`refresh_scripts_menu` from `scripts_tick` and `closed`), not only after a scan.
- The picker, console, inspector, export and dependency windows are app-wide `Option` fields; none goes in `WinSlot` or `swap_live`.
- `tar.exe -xf` refuses absolute paths and `..` by default; do not pass `-P`.
- A full environment's `.venv` build emits many file events: `scripts_scan` must not rescan while the provisioner is busy (iTerm2 skips them), then rescan once after.
- `py -0p` output order is the launcher's; resolve with `resolve`, never take the first line blindly.
