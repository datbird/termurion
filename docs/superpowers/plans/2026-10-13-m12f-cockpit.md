### Decisions (each goes in `m12f-rulings.txt`)

- The Cockpit is an egui window, always on top, off the taskbar, hidden while no Tandem window is in front (polled as the Instant Replay panel is, no `WM_ACTIVATEAPP` hook); it takes the focus when clicked. Cost: it floats over other apps for one pass after Tandem loses the front.
- The frame persists as "x y w h" under Tandem's `NoSyncCockpitFrame` (iTerm2's `frameAutosaveName` has no Windows store); a frame off every monitor is recentered. Cost: none.
- Workgroup grouping, role prefixes, workgroup peers and the Workgroup double-click wait for milestone 13; the grouping shows an empty list as iTerm2 does with no workgroup. Cost: the third segment does nothing useful yet.
- Chips are a strip above the command field, not inline attachments (egui has no inline widgets in a text field). Cost: a different look; the `@` flow is the same.
- The command field uses egui's monospace font at the default profile's size, not the profile's font family. Cost: a different face.
- Window > Notify on Status Change becomes per window (`WinSlot.status_armed`), fixing 9k's app-wide flag to match iTerm2; session watches become a set. Cost: none.
- Session titles fall back to the pane id's text (iTerm2's guid) and the synthetic workgroup name to the stable id. Cost: none.
- Session state: an empty Tandem `Status` counts as iTerm2's absent tab status (unknown). Cost: a status cleared at a prompt reads unknown where iTerm2 reads idle.
- Stable ids are minted per pane at creation, saved in arrangements and the restoration state as "Session Stable ID", and restored when valid. Cost: none.
- `cc-status.exe` is its own console program beside tandem.exe (not a name in 11e's `tandem-utils.exe`; ruling 12f-4, the tandem-git precedent), talks to the API itself (no `it2`), authenticates with the session's `ITERM2_COOKIE` (or the allow-all file) and sends `x-iterm2-disable-auth-ui` so a hook never raises a dialog; its failures print "cc-status: could not update Tandem for <event>: <reason>" and exit 0. Cost: a session started before the API and `setCookie` were on reports nothing.
- The onboarding's Enable step also turns `setCookie` on (the hook needs a cookie in new sessions), and the step's text says so (ruling 12f-1). Cost: every new session gets a cookie, as with the setting on.
- The hook folder is `CLAUDE_CONFIG_DIR` from Tandem's own environment (`~` expanded), else `%USERPROFILE%\.claude` (no login shell to ask). Cost: a value set only inside one shell's profile is missed.
- The hook command is the exe's path with forward slashes in double quotes, a form cmd and Git Bash run as a program (PowerShell would need its call operator; ruling 12f-3 confirms this form, and the checklist verifies it with real Claude Code). Cost: if Claude Code needs another form, the hook does not run.
- A settings.json that does not parse is refused with `not_json(path)`, not replaced (iTerm2 silently replaces it; ruling 12f-2, recorded as a fixed iTerm2 bug). Cost: a user with a broken file must fix it first.
- Menu items are disabled, not hidden (muda has no hide; ruling 12f-6: Install greyed when installed, Reinstall and Uninstall greyed before). Cost: all three items always show.
- Onboarding step glyphs are Segoe Fluent Icons (check mark, play, ring) instead of iTerm2's emoji. Cost: a different look.
- The workgroup and trigger steps, their bullets and their uninstall clauses are dropped until milestone 13. Cost: none now.
- WSL sessions: a Linux claude inside WSL reads its own `~/.claude` and gets no `TERM_SESSION_ID` unless `WSLENV` carries it; the integration covers Windows-native Claude Code only; npm installs (`node.exe`) are not detected either (ruling 12f-5, a documented gap). Cost: WSL and npm users install nothing.
- The Cockpit's window rows print `Registry::number` as is, so the first window reads "Window 0", as iTerm2's `terminal.number` (`CW:2740`); the raw title is the window title or else the active session's title. Cost: "Window 0" looks odd, as in iTerm2.
- Stable ids never repeat (ruling R12f-6): a saved "Session Stable ID" is adopted only at startup restoration or with saved contents (iTerm2's rule, `PTYSession.m:2403-2436`) and never when a live or buried pane already holds it; every pane constructor mints one through `Pane::with`. Cost: a user's second Restore Window Arrangement gets new ids, so chat bindings follow only the first copy.
- `send_text` and `session_execute_command` share one typed-text chokepoint (`orch_type_gated`, ruling R12f-1, as iTerm2's `gateTypedText`, `DI:1302-1325`, `DI:2645-2654`), so a command staged by send_text and finished by execute_command is classified as one line; the accumulator advances only after an allowed verdict and a send raced by another during the check fails closed (ruling R12f-2, `resolveConcurrentSend`). Cost: none; this is iTerm2's defense.
- A session-bound chat's watches follow its linked terminal's View Contents and Check Terminal State with the one-time watch consent (ruling R12f-3). Cost: none; iTerm2 does the same.
- settings.json: only a missing file counts as empty; every other read error (permission, a lock, bytes that are not UTF-8) refuses with "Could not read <path>: <error>", a parse failure with `not_json(path)`, and the file is left unchanged (rulings 12f-2 and R12f-7); a leading byte order mark is dropped and an empty file reads as `{}` (older Windows editors write a BOM; an empty file holds nothing to lose). Cost: a user with an unreadable file must fix it first.
- The health monitor waits while another alert shows (`HM`). Cost: none.
- 12f owns the chat queue rule that a person's message pre-empts queued watcher events (`ChatService.swift:365-403`), added to 12c's broker in Task 11 (12c's queue holds only waiting messages, so iTerm2's index is shifted by the in-flight head). Cost: one edit in 12c's code.
- Orchestration offers 14 tools: notify and request_notification_permission need the iPhone companion (n/a). start_code_review answers iTerm2's not-the-Code-Review-role error (no workgroups). Cost: none beyond iTerm2 without workgroups.
- "cmd" joins the foreground-is-shell list (ruling 9). Cost: none.
- Clipping tools work on `session:` ids through each pane's clippings panel; `wg-` ids are unknown. Cost: none.
- `start_session`'s login-shell flag has no Windows meaning; the command runs as the profile's command. Cost: none.
- `screen_last_changed` uses `Screen.last_output` (the last output time), not a content-change time. Cost: output that changes nothing still counts.
- A screen watch with no economy or chat model answers `Unsupported("No AI model is configured to watch a screen.")`. Cost: none.
- The snapshot and tool results use serde_json's pretty form with sorted keys, not Swift's `"key" : value` spacing. Cost: none (the model reads either).
- Integration pass 2: the typed-text accumulator is 12c's `ai_staged` (one per pane for every AI path, the R12cd fix-pass ruling); `TypedState` is only a view of it, and a residual left after a submit is stored against the prompt it lands on so it stays part of the next line. Cost: a residual typed into a program that never shows a new prompt stays in the accumulator until a later prompt, so the next send is classified with it (fail closed).

### Pitfalls for the implementer

- A cookie is a secret: `cc-status` never prints it, and `api_client` never logs its headers.
- `swap_live` must list `status_armed`, and `new` and `new_empty` must set it; forgetting one leaks one window's arm into another.
- The Cockpit rebuilds rows from `cockpit_world` each redraw; keep expansion and selection in `View` keyed by `RowKey`, never by row index.
- `reveal_pane` does not disinter: call `disinter` first for a buried pane.
- Write to panes through `user_write` after `enter_pane_window`: the Cockpit's command bar with `Write::SendTextLocal`, orchestration's `orch_type` (send_text, interrupt, the delayed CR) with 12c Task 6's `Write::Agent` (the AI's own typing, ruling 12c-6); a raw `Pane::input` skips the replay guard and a broadcast write types into every broadcast pane.
- `Screen::alt_screen` is `pub(crate)`: read it inside the crate only.
- The mention regex needs a lookahead: use `fancy_regex`, not `regex`.
- Never touch the real `%USERPROFILE%\.claude` in tests; pass paths.
- Write settings.json atomically in its own folder (rename over the old), never truncate in place.
- A hook runs once per Claude Code event: `cc-status.exe` must connect, call and exit fast (5 s timeout) and never block on stdin past its end.
- Orchestration's safety verdicts arrive later: park the tool call and resume it through 12c, never block the UI thread on a model.
- The typed-text accumulator is per pane and must be cleared by `interrupt` and by a submit that leaves no residual; port `planTypedGate` exactly, including the leading-newline case.
- Never classify `session_execute_command`'s command on its own and never type model text into a prompt line outside `orch_type_gated` (ruling R12f-1); never write `ai_staged` (12c's one accumulator per pane) before the verdict (ruling R12f-2), and never add a second accumulator (the R12cd fix-pass ruling).
- A session-bound watch reads the screen only through `may_read_screen` (ruling R12f-3); orchestration chats read freely.
- `serde_json` keeps insertion order here (`preserve_order`): sort keys explicitly for settings.json, the snapshot and watcher records.
- A stable id is minted in `Pane::with` only; adoption goes through `stable_id::adopt` with the in-use check (ruling R12f-6).
- Watcher records in the chat's `watchers` column use seconds since 1970; the `timestamp` inside a stored `WatcherEvent` message uses seconds since 2001-01-01 (Swift's default for message content). Mixing them shifts times by 31 years.
