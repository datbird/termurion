**Goal:** a program running in Tandem meets iTerm2's terminal: CSI 3 J asks before it erases history, the alternate screen keeps scrollback, emoji with VS16 and lone flags take two cells, U+200B advances the cursor, and every Terminal Advanced knob and every profile emulation switch named above changes what programs see exactly as in iTerm2.

**Architecture:** one pure module, `src/emu.rs`, holds `Rules` (every global Advanced knob this plan reads, built from `Globals`) and the small pure decisions (the clear-history decision, the DECRQCRA checksum, the title-report text, the print guard, width tables). The app side is `src/app/requests_ui.rs` (new `Request` arms), `src/app/prompted_ui.rs` (the two questions), `src/app/emu_ui.rs` (new: rules wiring, printing, OSC 72 drops). No new App field is per-window; none goes in `swap_live`.

### Decisions (each goes in `m13o-rulings.txt`)

- Program sequences that a setting may drop or rewrite are caught by Tandem's existing scanner and held back from vte (a CAN first when their start was already fed), instead of patching vte. Cost: one more pass over output bytes; a CSI longer than 32 bytes is never held.
- CSI 3 J's question uses the pane's bar, as the other nagging questions do; the sequence that asked is dropped. Cost: none known.
- Alternate-screen history is the alternate grid's own history, moved into the primary history when the program leaves; while the alternate screen is up, scrolling back shows only lines it pushed. Cost: iTerm2 shows the older primary history above them too.
- The above-prompt save uses Tandem's C mark and a printed-since-command flag; CUP is held only while a command runs and nothing has been printed. Cost: none known.
- Width rules live in a `WidthRule` handed to the `Term`, with iTerm2's version 8 and 9 tables copied into `src/widths.rs`. Cost: the tables must be refreshed by hand when iTerm2 changes them.
- `AggressiveBaseCharacterDetection` is stored and shown only: unicode-width already gives spacing combining marks their own cells, so both values behave like iTerm2's YES. Cost: NO has no effect.
- DECRQCRA counts a blank cell as 0 (a written space and an untouched cell look alike in alacritty). Cost: a checksum over written spaces differs from iTerm2's by 32 per space.
- Title reports send Tandem's one title for both CSI 20 t and CSI 21 t. Cost: none (Tandem has no separate icon title).
- While a print capture runs, escape sequences are dropped from the captured text and never reach the screen. Cost: colors set inside a print job are lost.
- Encodings use Windows code pages through `MultiByteToWideChar`/`WideCharToMultiByte` (no new crate); normalization uses `NormalizeString` and is applied where text leaves the grid, not stored. Cost: a code page Windows lacks shows as undecodable; stored text stays unnormalized.
- OSC 72 covers the local accept-drop direction with winit's hover and drop events; directory handles and drag-out are not built. Cost: programs that drag out or walk dropped folders get nothing.
- `BufferDepth` is stored and shown and does nothing (ruled, 13m-o rulings): Tandem's reader drains ConPTY without a queue bound on purpose (`start_reader`), and a bound would block ConPTY. Cost: the knob has no effect; the row is partial.
- The OSC 7 conflict warning is latched once per run on the App (`Osc7Latch`); each screen tracks its own proprietary-code flag. Cost: none (iTerm2's process-wide latch and per-session flag).
- The OSC 7 conflict and "Allow Printing?" warnings go through 13b's shared warning path (the 13a-c ruling), not a hand-built `ConfirmWindow`. Cost: none.
- DEC mode 2048 is a vendored alacritty patch (`PrivateMode::Unknown(2048)`) so it works inside DECSET lists and DECRQM, and the report is written after the pty resize with the text area's physical pixels. Cost: none known.
- OSC 72 drops use the last cursor position winit reported before the drag; no drag-move reports are sent (winit 0.30 has no drag-move event and no `CursorMoved` during an OLE drag). Cost: a program sees only the entry position and the drop, not the path in between.
- TERM is set from the profile's Terminal Type only when the environment has none; the stock profile is seeded "xterm-256color". Cost: Windows programs ignore it; a user who set TERM globally keeps theirs.

### Pitfalls for the implementer

- Never feed a held sequence's bytes and then drop its tail: vte would stay inside the CSI and eat the next text. Use `held_bytes`.
- `Screen::clear` must keep calling `clear_screen(ClearMode::Saved)` directly; only program output passes the gate.
- `Look` is `Copy`; keep strings out of it (`set_answerback`).
- `set_tab_width` resets every stop: call it only before the first byte of a new session, never on a settings change.
- Moving alternate history into the primary grid must go through `append_history`, which counts dropped rows (patch 15's `dropped`), or API line numbers jump.
- The VS16 widening must write the spacer cell and move the cursor; a wide flag without a spacer corrupts selection and copy.
- ENQ is 0x05 only in the ground state; inside OSC, DCS or APC strings it is data.
- The print guard's "Disable Permanently" writes the saved profile, not the session copy (`store.get` plus `shared_guid`).
- Encoding sits before the tmux hook in `pump`; tmux control mode is always UTF-8, so a tmux gateway pane never gets a decoder.
