The settings rows come first (Task 1), so every later task reads real keys.

### Decisions (each goes in `m13c-rulings.txt`)

- The tab number reads "Win+1" (Windows words for iTerm2's "\u{2318}1", from `SwitchTabModifier`: Win, Alt, Alt+Win, Ctrl, none). Cost: wider than iTerm2's glyph.
- Tab labels use the prose font (Segoe UI) at iTerm2's 11 points, measured with the renderer. Cost: a label font different from the terminal's.
- The close button's hover fades in at once (iTerm2 animates `highlightAmount`). Cost: no fade.
- The spinner is a rotating arc drawn at the activity tick. Cost: a different look from AppKit's spinner.
- The overflow menu lists plain titles (iTerm2's popup button shows the hidden tabs' labels). Cost: no icons in it.
- The tooltip shows 500 ms after the pointer settles. Cost: a different delay from macOS.
- Tab Color is a popup of swatch items plus "Choose Color\u{2026}" (Windows' color dialog) instead of iTerm2's in-menu color grid with recent colors, opened by 13d's menu entry for a tab or a group (`ColorTarget`). Cost: a different look, no recent colors.
- Choosing a tab color drops a program's tab color for that tab's panes. Cost: none known.
- The tab's right-click menu is 13d's (`src/tab_menu.rs`, 13d-f and 13a-c rulings); 13c builds only the color picker it opens. Cost: 13c's `02:584` is partial until 13d.
- `HideTab` is added here (13a-c rulings: 13c owns bar layout); 13d reads it. Cost: none.
- `SwitchTabModifier` value 6 is labeled "Win+Alt+Number" in `schema/global.toml:40` while the tab number reads "Alt+Win+" (iTerm2's glyph order, Option before Cmd, and R11's example "Alt+Win+1"); both are right, neither is changed to match the other. Cost: none.
- `ScrollableSideTabBar` is added here because the horizontal bar reads it (13d-f rulings). Cost: 13d must not add it again.

### Pitfalls for the implementer

- Every new per-window field (`tab_bar`, `tab_scroll`, `tab_hover`, `tab_keep_selected`, `tab_press`, `tab_tip`) goes in `swap_live` and `WinSlot`; forgetting one makes a second window's bar use the first window's state.
- The layout works in points and the app multiplies by the window scale once; do not mix pixel and point values in `tab_layout`.
- A press on the close button must not select on release when the pointer slid off it (iTerm2's `closeButtonDoesNotInterfere`).
- Closing through the close button must take the same path as Close Tab (tmux tabs, the close confirmation), not remove the tab directly.
- Do not build a tab menu, `tab-menu:` ids, `show_tab_menu` or a right-button branch on the bar: 13d owns them. The picker's ids are `color-pick:<n>` only.
- The status no longer prefixes the title; update `tab_look` and the three old scene tests, do not keep both.
- Measuring text calls into the renderer; cache per title and font size (the renderer's own cache does) and do not measure every tab on every mouse move.
