The app side is `src/app/metrics_ui.rs` and `src/app/git_ui.rs`, reached from 9h's `statusbar_content.rs` and `statusbar_ui.rs`.

## Global Constraints

- Everything from milestones 0 to 9h still holds, including 9g's geometry (bar height `statusBarHeight` 21 points times scale, margins 10, left 6, icon column 17) and 9h's text rules (`Renderer::text_width(text, true, scale)` over the scale, rounded up to points; icons are one Segoe Fluent Icons glyph tinted with the text color).
- Knob keys, labels, defaults and strings are iTerm2's, verbatim (Resume notes). Characters outside ASCII are `\u{...}` escapes in code.
- iTerm2 bugs are kept and each gets a checklist line (the 9c ruling). The ones here: the git Polling Interval knob takes effect only at the next bump; Battery reserves the charging icon's room on the right even when not charging; Battery's time-as-left-text gets no left inset; the git timed-out text always uses its long variant, then truncates; the recent-branches list is cut to 7 before the current branch is skipped.
- The git CLI never runs on the UI thread. The UI thread only sends requests and drains a channel. Every git process runs hidden (`CREATE_NO_WINDOW`), in its own Job Object with kill-on-close, and is killed with its children at the deadline. The deadline is `gitTimeout` (Advanced, default 4) truncated to whole seconds like iTerm2, and never under 1.
- NTLM leak rule: git never runs in, or reads from, a path that fails `prompted::local_path_ok`. That covers the session directory, a `.git` file's `gitdir:` target, the git directory `rev-parse` reports, and the `gitSearchPath` git program. A refused path is "not a repository", silently: no git runs and the component is empty.
- git runs with `--no-optional-locks`, `-c core.fsmonitor=false`, `GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0`, stdin null, and without `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` from Tandem's environment. The status bar never runs a repository's hooks.
- Graph texts and git use the layout font or the prose font at 12 points; neither has a Custom Font knob (`ATXT:289-291`, `SPK:436-437`).
- New pure code is a plain `pub mod` tested on Linux; Win32 and app code is `#[cfg(windows)]`. Tests run on EXTREME with `scripts/xt test --lib <filter>`. Ship `tandem-git.exe` beside `tandem.exe` and `tandem-host.exe`.

## Review Focus

1. A session whose directory is a UNC path (`\\server\share\repo`, `//server/share`), or a local folder whose `.git` file says `gitdir: \\server\x`, or a `gitSearchPath` of `\\server\tools`: git never starts, nothing opens the share, the git component is empty. Test: Task 4 `git_never_runs_off_local_paths`.
2. A repository where git hangs (a huge tree, a dead network drive letter): the poll ends at the deadline with its whole process tree killed, the bar keeps drawing meanwhile, and "\u{26A0} timed out" shows only while this directory has never answered. Tests: Task 4 `timeouts_are_remembered_per_directory`, Task 5 `hung_git_is_killed_at_the_deadline`.
3. `cd` to another repository while a poll of the old one is in flight: the old answer is thrown away, never shown for the new directory. Test: Task 4 `stale_poll_results_are_dropped`.
4. A VPN connects or an adapter appears between two network samples: no spike; the previous rates are published again. The first sample is 0. Test: Task 2 `network_rates_follow_iterm2`.
5. A detached HEAD, an unborn branch (a fresh `git init`), a branch with no upstream, and one whose upstream is gone: the branch is the full 40-hex commit id when detached; an unborn branch has no state (empty component); no ahead or behind arrows without a live upstream. Test: Task 4 `porcelain_parses_like_libgit2`.

### Sparkline (`SPK`)

- Ceiling: `MAX(1, ceiling)` when drawing (`SPK:291`); the base ceiling is the largest value in the whole model (all stored samples, every series) or 1.0 (`SPK:332-343,365-367`); Battery overrides it with 1.0 (`BAT:110-112`); Network recomputes it from both series on each sample (`NET:139-141,203-206`). Fraction series are therefore drawn against 1.0.
- View layout (`SPK:447-543`), Cocoa y-up turned y-down: left text at x 0; right text at `view_w - right_reserve`; both vertically centered with a -1 fudge, which is 1 point above 9h's centered text (`SPK:436-445`). Content rect: x = `4 + left_reserve` when that reserve is over 0, else 0; right inset likewise; y 2.5; h = `view_h - 5`. Baseline: the text color at alpha 0.5, the content rect's full width, 1 point tall, 2 points above its bottom (y-down: top at `bottom - 3`). Right image at `view_w - image_w - 2`, vertically centered, tinted with the text color.
- Path (`SPK:267-306`): `bar_w = rect_w / (60 - 1)`; `n` values right-aligned: `x0 = rect.max_x - (n - 1) * bar_w`; y-down `y_i = rect.bottom - 2.5 - v_i * (rect_h - 4) / ceiling`; a polyline, then one more segment to `(rect.max_x + 1, rect.bottom - 2.5)`. - Animation (`SPK:158-251`): with `animateGraphStatusBarComponents`, each new sample slides the path left one `bar_w` over 1.0 s; the preferred frame rate is 5 a second (1 in macOS Low Power Mode, which Tandem ignores). Equivalent drawing: the new path shifted right by `bar_w * (1 - elapsed / 1 s)`. Off: the new path replaces the old at once.
- Graphs do not handle clicks and have no Copy (`statusBarComponentCopyableString` is not implemented by `GFX`/`SPK`). Their text uses the layout font or 12 points (`SPK`, `BAT:130-132`).

### Samplers and schedule

- iTerm2 (`CPUS:38-107`, `MEMS:36-136`, `NETS:69-190`, `PWR:215-273`): one process-wide sampler per kind, a repeating 1 s timer (tolerance 0.2) while it has subscribers, history kept when the last one leaves. Memory and Network take a sample at once on the first subscriber; CPU does not (first sample after 1 s); Battery samples at once, then every 60 s. AC plug or unplug (`IOPSCreateLimitedPowerNotification`) and wake only redraw Battery; they publish no sample (`BAT:245-247`, `PWR:96-106,277-279`).
- CPU tick (`CPUS:66-86`): `delta = current - last; last = current; value = (last.total == 0) ? 0 : 1 - delta.idle / delta.total`; NaN is not published. Because `last` is set before the test, the first tick publishes the since-boot average; only a failed read (ticks 0) gives 0.
- Memory (`MEMS:64-120`): fraction = used / physical memory; a failed read is used 0.
- Network (`NETS:98-172`): skip interfaces whose name starts with `lo`, and with the setting on, `utun`; sum in and out bytes; rate = (current - last) / seconds since the last publish (INFINITY before the first, so the first is 0, `PUB:154-156`); when the interface set (name plus MAC) changed, publish the previous sample again (or zeros) instead; a failed read publishes nothing. Rates are doubles and are not clamped (a counter reset gives a negative rate, kept).
- Battery data (`PWR:148-212`): first InternalBattery or UPS source; percentage = CurrentCapacity, 100 when missing; charging = IsCharging; time = TimeToFullCharge when charging else TimeToEmpty, minutes times 60, -1 unknown; no source = no battery. Connected = providing power source is AC (`PWR:50-53`).
- Windows (`metrics_win.rs`): CPU `GetSystemTimes(&idle, &kernel, &user)`, kernel includes idle, so `idle = idle`, `total = kernel + user`. Memory `GlobalMemoryStatusEx`: used = `ullTotalPhys - ullAvailPhys`, total = `ullTotalPhys`. Network `GetIfTable2`: skip `Type == 24` (IF_TYPE_SOFTWARE_LOOPBACK) and NDIS filter rows (the `FilterInterface` bit, bit 1 of `InterfaceAndOperStatusFlags`; windows-sys 0.59 names the byte `_bitfield`, check on EXTREME); with the setting on also skip `Type == 131` (IF_TYPE_TUNNEL) or `TunnelType != 0`; sum `InOctets`, `OutOctets`; the interface key is `InterfaceLuid.Value` bytes plus `PhysicalAddress[..PhysicalAddressLength]`. Power `GetSystemPowerStatus`: no battery when `BatteryFlag` is 128 or 255; percentage `BatteryLifePercent` (255 means missing, so 100); connected `ACLineStatus == 1`; `CallNtPowerInformation(SystemBatteryState, ...)` fills `SYSTEM_BATTERY_STATE`: charging = `Charging != 0`; time when charging = `(MaxCapacity - RemainingCapacity) * 3600 / Rate` seconds when `Rate > 0`, else -1; when not charging = `BatteryLifeTime` seconds (`0xFFFFFFFF` is -1).
- Tandem's schedule: samplers run on the UI thread from `tick_status_bars` (the calls take microseconds). The AC line is read every 1 s while Battery is wanted; a change redraws.

### git: polling (`GP`, `GIT:245-282,636-667`, `GPW`)

- One timer per component at `cadence` (tolerance 10 percent), started at creation. `bump` = poll now, then restart the timer at the current cadence. The knob change only sets `cadence`; the running timer keeps its interval until the next bump (kept). Tandem keeps one poller per pane (the first git component's knob).
- `poll`: needs enabled, a known directory, and `gitPollerShouldPoll`: not in the setup UI (Tandem's setup window has no live components, so never), visible, then: YES on the first poll; YES when the last newline sent is later than `last_poll - 3 s`; YES when over 60 s passed since the last poll and output came after it; else NO.
- Bumps: moved to a window (`GIT:258-261`), a finished menu command (`GSM:304-307`), `lastCommand` changing to one whose first word (it needs a space) has basename `git` (`GIT:267-282`; Tandem also splits on `\` and drops a trailing `.exe`, case-insensitively). A directory change (`GP:170-194`) calls `poll`, not `bump`, resets `hasSuccessfullyFetched` and `lastPollTimedOut`, and invalidates the worker cache for the new path through a 0.5 s rate limiter.
- A reply for a path other than the current directory is dropped (`GP:118-124`). A reply that did not time out marks the directory fetched, even with no state (`GP:129-138`).
- Worker (`GPW:94-201`): cache keyed by path (Tandem needs only the basic key), TTL 1 s; concurrent requests for a key join the pending one; a reply older than the cached state is replaced by the cached state but keeps the reply's timed-out flag; `invalidate` clears the path's cache and pending entries. - The helper takes `gitTimeout` as an int (`pidinfo.m:842-900`, `PIDInfoGitState.m:16-26`) and SIGKILLs itself at it.
- Tandem's git command lines (the CLI stands in for libgit2's `GCL:590-690`):
  - State: `git --no-optional-locks -c core.fsmonitor=false -c core.quotepath=false status --porcelain=v2 --branch --untracked-files=all --ignore-submodules=all --no-renames -z` with the session directory as the working directory. Exit 128 (not a repository, or `safe.directory` refused) is no state, not a timeout. Parse NUL-separated records: `# branch.oid <sha>|(initial)` ((initial) is an unborn branch: no state, as `git_repository_head` fails); `# branch.head <name>|(detached)` (detached: the branch is the full oid, as `branchAt:` does); `# branch.ab +A -B` gives ahead "A" and behind "B", and its absence gives `""` for both (no upstream, or it is gone); entries `1 XY ...`, `2 XY ... <path>` NUL `<orig>` (skip the extra field), `u XY ...`, `? <path>` (`!` never appears without `--ignored`). dirty = any entry; adds = the `?` count (WT_NEW with untracked recursion, `GCL:281-314`); deletes = entries whose second status letter (worktree) is `D` (WT_DELETED).
  - Repo operation: then `git --no-optional-locks rev-parse --absolute-git-dir`, trimmed; only when it passes `local_path_ok`, look in it in libgit2's `git_repository_state` order (libgit2 `repository.c`; the source is not in iterm2-ref): file `rebase-merge/interactive` or dir `rebase-merge` or file `rebase-apply/rebasing` is Rebase; file `rebase-apply/applying` or dir `rebase-apply` is Apply; `MERGE_HEAD` Merge; `REVERT_HEAD` Revert; `CHERRY_PICK_HEAD` Cherrypick; `BISECT_LOG` Bisect; else None (`GCL:660-689` maps the sequence variants the same way).
  - Recent branches: `git --no-optional-locks for-each-ref --count=8 --sort=-committerdate --format=%(refname:short) refs/heads/` (`pidinfo.m:936-975` does this with libgit2, newest first), one per line.
  - Log: `git log` in the component's directory, 5 s timeout (`GIT:472-505`).
- Program: `gitSearchPath` empty means `git` from PATH; else its first `;`-separated entry plus `git.exe` (iTerm2 takes the first `:` entry plus `/git`, else `/usr/bin/git`, `GIT:407-414`); a program path that fails `local_path_ok` means no git.
- Guard before any run: the directory passes `local_path_ok`; walking up from it, the first `.git` found is a folder, or a file whose `gitdir: <p>` is relative or passes `local_path_ok`.

### Corrections to the research (the source wins)

- CPU's first sample is the since-boot average, not 0 (`CPUS:66-86`: `_last = current` comes before the `_last.total == 0` test). CPU takes no sample on subscribe; Memory and Network do (`CPUS:38-64`, `MEMS:46-56`, `NETS:79-90`).
- Battery's AC-change and wake paths only redraw; they publish no sample (`BAT:245-247`, `PWR:96-106`).
- The ceiling is taken over the whole stored history (up to 120 samples, both Network series), not the 60 drawn (`SPK:332-343`, `NET:203-206`), and the drawn path drops the oldest stored sample (`SPK:196-200`).
- A directory change polls; it does not bump (no timer restart) (`GP:170-194`).
- The recent-branch list is cut to 7 before the current branch is skipped, so a menu shows at most 7 and usually 6 (`GIT:361-400`).
- Menu commands run whatever `git` the wrapper's PATH finds; only Log uses `gitSearchPath` (`GIT:407-433`, `iterm2_git_wrapper.sh`). `gitSearchPath` is a PATH list whose first entry is used.
- `gitTimeout` reaches the helper as an int (`pidinfo.m:842-900`).
- A remote state needs all six required `user.git*` variables (`GSMA:37-42`).
- Graphs have no Copy, and git's Copy is the branch, not the widest text (`GIT:284-286`).

### Decisions (each goes in `m9i-rulings.txt`)

- The git CLI (porcelain v2, `rev-parse`, git-dir files) stands in for libgit2.
- `tandem-git.exe`, a console bin, is the wrapper; it runs the `gitSearchPath` git (iTerm2's wrapper runs PATH's git).
- `gitSearchPath` is `;`-separated with `git.exe` appended; a UNC entry is refused.
- `gitTimeout` truncates to whole seconds with a floor of 1; recent branches use it too (iTerm2 passes 0.5 s that never reaches the helper); the menu opens when the branches arrive.
- One git poller per pane; one worker thread per path in flight.
- git hardening: `--no-optional-locks`, `-c core.fsmonitor=false`, the environment in Global Constraints.
- The git images are text: `\u{25CF}`, `\u{2191}`, `\u{2193}`; the warning sign is U+26A0 without U+FE0F (the prose renderer has no emoji presentation).
- The timeout warning, Send Command and Debug Info are pane info bars (their headings dropped, no "don't ask again"); Log is a small egui window.
- Metrics sample on the UI thread, while any session with the bar enabled has the component (on screen or not).
- Battery: no battery when `BatteryFlag` is 128 or 255; time to full from `SYSTEM_BATTERY_STATE`'s rate; AC changes by polling each second.
- Network: loopback and NDIS filter rows skipped; the utun analog is tunnel interfaces (Wintun-based VPNs are still counted).
- Animation at 5 frames a second for 1 s after each sample; Low Power Mode has no Windows analog.
- Sparkline lines are pixel-column quads.
- Parity rows are found by title (line numbers moved).
