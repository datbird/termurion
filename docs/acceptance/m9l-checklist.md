# Milestone 9l acceptance checklist

Close any open Tandem window. Copy `tandem.exe`, `tandem-host.exe`, `tandem-git.exe`,
`conpty.dll`, and `OpenConsole.exe` from `C:\Users\datbi\src\tandem\target\release\` together,
then run `tandem.exe`.

Setup: install shell integration in the PowerShell session (milestone 4a). On the profile you
use, add a Composer component to its Status Bar Layout (Prefs > Profiles > Session > Status Bar >
Configure Status Bar; drag in Composer) so it is placed on the bar. Set up a second profile with
no status bar at all. In Settings > Shortcuts add a snippet whose text is a short multi-line
command (for example `echo one` then a newline then `echo two`). In Settings > Keys > Key
Bindings add a global key mapped to "Open Composer" with some starter text. Have a tmux session
attached in one pane, and a second pane sharing Broadcast Input with the focused one. None of this
has been checked on a real screen before this pass (every task deferred launching the GUI on
EXTREME, since the rules forbid it while the machine may be in use), so this pass is the first
look. Mark each line pass or fail.

## Kept bugs and rulings a person can see

| # | Item | Result |
|---|---|---|
| 35 | Composer syntax highlighting colors PowerShell cmdlets, aliases and shell builtins (`cd` included) as valid commands: a deliberate Controller Ruling departure from iTerm2's own kept bug of coloring every builtin red, made because most everyday PowerShell input is a cmdlet (see check 15). | |
| 36 | Send-each and enqueue-each (Alt+Shift+Enter / Alt+Enter) on a non-last selected line send that line's own trailing newline plus another appended one, so two newlines go out for every line but the last (kept iTerm2 bug, see check 6). | |
| 37 | The 1024 UTF-16 unit highlighting window resets starting at the fixed literal 1024, not at `range.start + 1024`, matching iTerm2's own reset math exactly (kept iTerm2 bug: a rare highlighting hiccup on a very long single command). | |
| 38 | Toggling Auto Composer off while one is currently shown leaves it up until the next prompt (kept iTerm2 bug, see check 20). Turning it on for the first time on a profile that has never used command history does nothing (kept iTerm2 bug, see check 16). | |
| 39 | An empty Enter in the status bar Composer field still sends a bare newline to the shell (kept iTerm2 bug, see check 26). | |
| 40 | Ctrl+C, Ctrl+D (only when the composer is empty), Ctrl+L, Ctrl+R and Ctrl+U inside the Auto Composer always win over the Windows edit chords of the same letters; copying there is Win+C instead. | |
| 41 | A tab switch or pane switch inside the same window always releases a composer's keyboard, even one you did not click away from (iTerm2's own PTYTab makeFirstResponder behavior, see check 22). | |
| 42 | The top drag handle (shown only when the dropdown sits at the bottom of its pane), the Win-hover underline and pointing-hand cursor over a clickable command, and Leader-key routing into a focused composer are not built this milestone (checklist deferrals, not bugs). | |
| 43 | Ctrl+L in a tmux client pane's Auto Composer only clears the local grid, never the remote tmux pane's own scrollback (parity limitation, not a bug; see check 32). | |
| 44 | The Auto Composer stays anchored to the prompt's actual grid row even when the pane is scrolled back to review earlier output, so it can appear to sit mid-screen until you scroll back down. | |
| 45 | Filter and Zoom views are not specially handled by the Auto Composer's row math this milestone (a narrow gap, not exercised by any test). | |
